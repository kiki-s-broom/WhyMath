## 왜 A0003에 합치지 않았나

A0003 은 이미 런북 과제 A 와 게이트 `G-const-sources-registry-adopt` 의 성공 기준(`SOURCES_COUNT=9`)이
고정돼 있다. 건수를 바꾸면 사람이 따라가는 확인 값이 바뀐다. 또 헌법 제11조는 개정마다 개정 기록을
남기도록 하므로 별도 번호가 맞다.

## 추가하는 3건과 근거 (모두 저장소 실측)

| 원본 | 정본 경로 | 근거 |
|---|---|---|
| 프로젝트 규칙 | `CLAUDE.md` | 규칙 본문은 여기에만 있다. `backlog/rules.ndjson`(85줄)은 집행 메타를 **규칙 제목 문자열**로 대응시키고, `docs/standards/rule_index.md` 는 "자동 생성 — 손편집 금지" 렌더다. 제목이 어긋나면 `scripts/harness/rules.py` 린트가 red 를 낸다(`tests/infra/test_rule_index_lint_wiring.py` 가 배선 존재를 가리킨다 — CI 실행 자체는 이번에 확인하지 않았다) |
| LLM 모델 핀(로컬) | `src/backend/whymath_backend/l3/router.py` | `LOCAL_MODEL_MATRIX`·`QUALITY_MODEL_ID` 를 `l3/providers/ollama.py`·`l3/generation_seed.py` 가 읽는다 |
| LLM 모델 핀(클라우드) | `src/backend/whymath_backend/config.py` | `l3/providers/factory.py` 가 `openrouter_model_mid/high`·`anthropic_model_mid/high` 를 읽는다 |

모델 핀을 로컬·클라우드 두 항목으로 나눈 이유: 등록부 항목은 `path` 가 하나뿐이고, 두 값은 서로 다른
파일이 정본이다.

## 추가하지 않는 것 — 규칙 등록부 4번째 사본

`constitution/rules.yaml` 은 **코딩 헌법**의 규칙(적용 후 14건, A0002 후 95건)이고 `CLAUDE.md` 규칙(85건)과
다른 집합이다. 같은 데이터의 사본이 아니므로 "프로젝트 규칙" 항목의 파생에 넣지 않았다. 두 집합의 서열은
게이트 `G-const-precedence-declaration` 의 결정이 소유한다.

## 결정 대기 — 단원·소단원 위계는 등록하지 않았다

위계의 정본이 선언된 적이 없다. 서로 다른 것을 센 네 가지다 — `atom_graph_v1`(단원 217·소단원 643, 우리 원자
백본) · `achievement_criteria_v1`(평가원 보고서의 단원 트리) · `units_v1`(소단원 명세 1건) · 교과서 단원(출판사
구조). 같은 코퍼스 한 항목 안에서도 `unit_hierarchy` 는 "(1) 문자와 식", `achievement_levels_by_unit` 은
"(1) 다항식"으로 서로 다르다. 지금 등록하면 존재하지 않는 정본을 선언하게 되어 심사가 고칠 수 없는 위반을
계속 보고한다. 정본 선언은 태스크 `CONST-11` 이 추적하고, 선언되면 A0005 로 등록한다.

## 알려진 어긋남 (이 개정과 별개로 이미 존재)

`CLAUDE.md` 스택 표는 QUALITY 모델을 `qwen3.5:27b` 로 적고 있었으나 코드(`QUALITY_MODEL_ID`)는 OPS-48
판정(2026-08-22)에 따라 `qwen3:30b-a3b` 다. 표는 2026-10-02 에 정정했다(CLAUDE.md v0.2.36). 같은 옛 값이 `.claude/agents/llm-architect.md` A.0 매트릭스와 `l3/queue/`·`l3/models.py` 의 docstring 에도 남아 있다 — 이번 범위 밖이며 후속 정정 대상이다. 등록만으로는 이런 어긋남이 잡히지 않는다 —
잡는 장치는 규칙 R4-03(문서에 적힌 핵심 숫자·값은 원본과 같다)이며 `CONST-03` 몫이다.
