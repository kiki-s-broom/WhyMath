## 2. 집계 재현 방법

저장소 루트에서 실행한다(읽기 전용 · DB·네트워크 접속 없음). 필요한 패키지는 `pydantic-settings`, `sqlalchemy`, `greenlet`, `pgvector`, `pyyaml`과 백엔드 의존성이다.

```bash
PYTHONPATH=src/backend python3 scripts/analysis/ped17_t1_study_404_count.py; echo "EXIT=$?"
```

종료 코드 0은 "404 아님 후보 0건"(지금 상태), 1은 "404 아님 후보가 생겼다"는 뜻이다.

**변별력 확인(2026-11-06 실행):** 메모리에서만 콘텐츠 2행(K-12 `H:12미적Ⅰ02-01`, 대학 `GALOIS-U1-S1`)을 `reviewed`로 바꿔 넣고 다시 돌렸다. 학습목표 3개(미분계수 단원 OBJ-01~03)와 원자 개념 4개(고등 3 · 대학 1)가 "404 아님 후보"로 옮겨졌다. 집계가 통과 상태를 실제로 구분해 낸다는 뜻이다. 저장된 `study_404_count.json`은 이 주입 실행 전후로 바이트 단위까지 같았다(`cmp`로 확인).

**한계:**

- 운영 DB에서 K-12 `atom_codes` 이전(크로스워크)을 실행하지 않았다면, 운영에서는 일부 개념의 사유가 `UNREVIEWED` 대신 `NO_DSL`로 나온다. 어느 쪽이든 404이므로 404 개수는 같다.
- 검수 게이트를 통과한 개념도 렌더 단계에서 실패할 수 있다. 그래서 통과 수는 "404 아님 후보"로만 센다.
