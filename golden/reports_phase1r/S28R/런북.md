# S28R Kiki 머신 런북 — T2R 적용 + AI 회귀: 720세션 플래그 0 → 플래그 1 → 숫자 한 장

> 이 런북은 저장소의 아무것도 바꾸지 않는다. Kiki PC에서 실행 결과(숫자·뒤집힌 입력 예시)만 클립보드로 받는다.
> 1회차 S28과 달라진 점이 세 가지 있다.
> - Kiki PC에서 숫자 파일을 커밋·푸시하지 않는다.
> - 실행마다 **새 데이터베이스**를 만든다(1단계 S33 · DECISIONS_AUTO S33 줄과 같은 이유).
> - 두 실행을 한 블록 안에서 연달아 돈다.

## 사전 브리핑 (6항목)

1. **과제 명칭:** S28R — 채점 앞말·꼬리 처리(`GOLDEN_T2R_GRADE`)를 **끈 채(플래그 0)·켠 채(플래그 1)** 실제 LLM으로 720세션씩 돌린다(30문항 × 페르소나 8 × 3회).
2. **목적:** S27R이 만든 새 채점 규칙이 실제 LLM 학생의 말투에서 무엇을 바꾸는지 잰다. 핵심은 둘이다.
   - 판정 오류율(M3)이 플래그 1에서 늘지 않는가.
   - 원래 오답이 정답으로 뒤집힌 입력이 있는가.
   - 결과는 S29R(AI 학생 15건 손 판정 · 플래그 1 기록 사용)과 S30R(T2R 판정)의 근거다.
3. **구체적 절차**
   - **블록 A**(약 30초): 작업 폴더 `WhyMath-cal`을 main에 맞추고 점검한다.
   - **블록 S**(약 10~60초): 시연용 Postgres(`whymath-demo-db` · 55432)를 켠다.
   - **블록 R**(**약 4~10시간**): 플래그 0으로 720세션을 돌린다. 끝까지 돌았으면 플래그 1로 720세션을 돈다.
     - 1회차 S28 실측은 한 번에 약 2시간이었다.
     - 각각 새 데이터베이스를 쓴다.
     - 튜터는 OpenRouter, 학생은 로컬 Ollama `qwen2.5:7b`다.
     - PC가 잠들지 않게 한다(전원 설정 → 절전 안 함).
     - 매일 03:30 야간 작업(`WhyMath-sim-nightly`)과 시간이 겹쳐도 DB가 달라 기록은 섞이지 않는다. 다만 느려질 수 있다.
   - **블록 X**(약 1~3분 · 읽기 전용): 추출기가 두 실행을 검사하고 숫자 한 장을 만든다. 그 결과를 클립보드에 넣는다.
     - 검사 항목: 실제 모드인가, 끝까지 돌았는가, 플래그가 정말 그 값이었는가.
4. **성공 기준**
   - **블록 A:** `READY=True` 줄이 보인다. `STAGE`는 `run`(처음) 또는 `f1`(플래그 0만 끝남)이다. `STAGE=extract`면 블록 X로 바로 간다.
   - **블록 S:** `DB_READY=True`.
   - **블록 R:** `RUN f0 COMPLETE=True`와 `RUN f1 COMPLETE=True`가 보인다.
     - 각 실행은 `SIM_DONE_LINES=1`이고, `JSONL_LINES`와 `SKIPPED`의 합이 720이어야 한다.
     - `SIM_EXIT`는 0 또는 1이면 된다. `SIM_EXIT=1`은 차단 메트릭 위반을 잰 결과일 수 있어 정상 종료로 친다.
     - f0이 끝까지 돌지 못하면 f1은 돌지 않는다(로그 끝 5줄이 찍힌다).
   - **블록 X:** 화면 첫 줄이 `S28R_CHECK ok=True`이고, `CLIPBOARD_CHARS`가 `OUT_CHARS`와 같다. 그다음 이 세션 대화창에 **Ctrl+V로 붙여넣는다**.
   - **실패 시 대처:** 각 블록의 `…=False`·`REFUSED` 줄이 무엇이 틀렸는지 알려 준다. 그 줄만 세션에 보낸다.
5. **실행 환경:** Phaiakes9(이 PC) · Windows PowerShell.
   - 공유 작업 사본 `C:\Users\kiki\Desktop\__AI\WhyMath`: 읽기만 한다. `.venv`·시드·compose 파일을 빌려 쓴다.
   - 작업 폴더 `C:\Users\kiki\Desktop\__AI\WhyMath-cal`: S20·S23·S28·S33 때 만든 것을 재사용한다.
   - 결과 폴더 `C:\Users\kiki\Desktop\__AI\sim-s28r`(f0·f1 하위 폴더). `sessions.jsonl`은 이 PC에만 둔다. S29R이 플래그 1 기록을 읽는다.
   - 선행 조건: Docker Desktop 가동 · Ollama 앱 가동 · `WHYMATH_OPENROUTER_API_KEY` 사용자 환경변수(S28·S33과 같은 것) · S16 시드 파일 · **S27R·S28R PR이 main에 병합됨**(블록 A의 `HAS_T2R`·`SCRIPT_OK`가 확인한다).
6. **창 구분:** **새 PowerShell 창 하나(창 A)**에서 블록 A → S → R → X를 차례로 붙여넣는다.
   - A·S·R은 앞 블록의 변수를 쓰므로 같은 창이어야 한다. 블록 X는 혼자서도 돈다(새 창도 된다).
   - 블록 R이 도는 동안(**4~10시간**) **이 창은 건드리지 않는다.** Ctrl+C는 복사가 아니라 중단이다. 다른 작업은 다른 창에서 한다.
   - 각 블록의 판정 줄을 눈으로 본 다음에 다음 블록을 붙여넣는다. 쓰기 블록(R)은 앞 조건이 틀리면 스스로 거부한다.
   - 블록 R이 중간에 끊겼으면 블록 A부터 다시 붙여넣는다. `STAGE=f1`이면 플래그 1만 돈다.

## 블록 A — 준비·점검 (창 A · 새 창)

```powershell
# [창 A · 블록 A — S28R 준비·점검] Windows PowerShell — 작업 폴더 WhyMath-cal을 main에 맞추고 점검(공유 작업 사본은 바꾸지 않음)
cd C:\Users\kiki\Desktop\__AI\WhyMath
$Root = "C:\Users\kiki\Desktop\__AI"
$Main = "$Root\WhyMath"
$Wt = "$Root\WhyMath-cal"
$RunDir = "$Root\sim-s28r"
$Model = "qwen2.5:7b"
git fetch origin main
git worktree prune
$Expected = git rev-parse "origin/main"
if (Test-Path "$Wt\.git") { git -C $Wt checkout -q --detach --force $Expected } else { git worktree add -q --detach $Wt $Expected }
$WtHead = git -C $Wt rev-parse HEAD 2>$null
$Ready = $false
$Stage = "none"
if ($WtHead -eq $Expected) {
git -C $Wt log -1 --oneline
$Py = "$Main\src\backend\.venv\Scripts\python.exe"
$PyOk = Test-Path $Py
$SeedDir = "$Main\golden\sim\seed"
$SeedOk = (Test-Path "$SeedDir\utterances.txt") -and (Test-Path "$SeedDir\distributions.json")
$ScriptOk = Test-Path "$Wt\golden\reports_phase1r\S28R\extract_s28r.txt"
$Tags = @(ollama list 2>$null | Select-Object -Skip 1 | ForEach-Object { ($_ -split '\s+')[0] } | Where-Object { $_ })
$HasModel = $Tags -contains $Model
$KeyOk = (-not [string]::IsNullOrEmpty($env:WHYMATH_OPENROUTER_API_KEY)) -or (-not [string]::IsNullOrEmpty($env:OPENROUTER_API_KEY))
Set-Location "$Wt\src\backend"
$ModFile = ""
if ($PyOk) { $ModFile = & $Py -c "import golden.grade_tail as m; print(m.__file__)" 2>$null }
$HasT2r = [string]$ModFile -like "$Wt\*"
git -C $Wt diff --quiet -- golden src/backend/golden; $TreeClean = ($LASTEXITCODE -eq 0)
$F0Done = Test-Path "$RunDir\f0\run_meta.json"
$F1Done = Test-Path "$RunDir\f1\run_meta.json"
if ($F0Done -and $F1Done) { $Stage = "extract" } elseif ($F0Done) { $Stage = "f1" } else { $Stage = "run" }
Write-Host "WORKTREE_HEAD=$WtHead  EXPECTED=$Expected"
Write-Host "PY_OK=$PyOk  SEED_OK=$SeedOk  SCRIPT_OK=$ScriptOk  HAS_T2R=$HasT2r  HAS_MODEL=$HasModel  KEY_OK=$KeyOk  OLLAMA_TAGS=$($Tags.Count)  TREE_CLEAN=$TreeClean  F0_DONE=$F0Done  F1_DONE=$F1Done  STAGE=$Stage"
$Ready = $PyOk -and $SeedOk -and $ScriptOk -and $HasT2r -and $HasModel -and $KeyOk -and $TreeClean
if ($Ready -and ($Stage -eq "extract")) { Write-Host "READY=True  STAGE=extract — 두 실행이 이미 끝났다 · 블록 R을 건너뛰고 블록 X로" } elseif ($Ready) { Write-Host "READY=True  STAGE=$Stage — 블록 S로(DB가 이미 켜져 있으면 블록 R로)" } else { Write-Host "READY=False — HAS_T2R=False 또는 SCRIPT_OK=False면 S27R·S28R PR이 아직 main에 없다(세션에 알리기) · PY_OK=False면 .venv 없음 · SEED_OK=False면 S16 시드 없음 · HAS_MODEL=False면 'ollama pull qwen2.5:7b' 뒤 이 블록 다시 · OLLAMA_TAGS=0이면 Ollama 앱 켜기 · KEY_OK=False면 OpenRouter 키 없음 · TREE_CLEAN=False면 작업 폴더의 골든 파일이 손으로 바뀜(세션에 알리기)" }
} else { Write-Host "READY=False — REFUSED — HEAD=$WtHead  EXPECTED=$Expected (작업 폴더를 main으로 맞추지 못했다 — 이 줄을 세션에 알리기)" }
```

# [창 A · 블록 S — DB 서버] Windows PowerShell — 시연용 일회용 Postgres(whymath-demo-db · 55432)를 켜고 준비될 때까지 최대 60초 기다림

## 블록 R — 720세션 플래그 0 → 플래그 1 (창 A · 약 4~10시간 · 이 창은 건드리지 않는다)

```powershell
# [창 A · 블록 R — S28R 720 × 2] Windows PowerShell — READY·DB_READY가 True이고 STAGE가 run 또는 f1일 때만: 플래그마다 새 데이터베이스를 만들고(아무것도 지우지 않음) 720세션 실행
$Date = Get-Date -Format "yyyy-MM-dd"
$RunOk = $Ready -and $DbReady -and (($Stage -eq "run") -or ($Stage -eq "f1"))
if ($RunOk) {
Remove-Item Env:GOLDEN_FAKE_LLM, Env:GOLDEN_T1_RUBRIC, Env:GOLDEN_T2_MISCONCEPTION, Env:GOLDEN_MASTERY_ENGINE -ErrorAction SilentlyContinue
$env:SIM_FULL = "1"
$env:GOLDEN_SIM_SEED_DIR = $SeedDir
$env:GOLDEN_SIM_STUDENT_MODEL = $Model
$env:PYTHONUTF8 = "1"
$env:PYTHONIOENCODING = "utf-8"
Set-Location "$Wt\src\backend"
ollama run $Model "hi" 2>&1 | Out-Null
$Flags = @("0", "1")
if ($Stage -eq "f1") { $Flags = @("1") }
$Stop = $false
foreach ($F in $Flags) {
if ($Stop) { break }
$OutDir = "$RunDir\f$F"
$SimLog = "$RunDir\sim_f$F.txt"
New-Item -ItemType Directory -Force -Path $OutDir | Out-Null
$DbName = "whymath_s28r_f" + $F + "_" + (Get-Date).ToUniversalTime().ToString("yyyyMMddHHmm")
docker exec whymath-demo-db createdb -U whymath $DbName
$DbCreated = ($LASTEXITCODE -eq 0)
Add-Content -Path "$RunDir\db_names.txt" -Value "f$F $DbName" -Encoding ASCII
$env:WHYMATH_DATABASE_URL = "postgresql+asyncpg://whymath@127.0.0.1:55432/" + $DbName + "?ssl=disable"
$env:GOLDEN_T2R_GRADE = $F
$SchemaOk = $false
if ($DbCreated) { & $Py -c "import asyncio; from golden import store; asyncio.run(store.ensure_schema()); print('SCHEMA_OK')"; $SchemaOk = ($LASTEXITCODE -eq 0) }
if ($DbCreated -and $SchemaOk) {
$T0 = (Get-Date).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")
cmd /c "$Py -m golden.sim.run --sessions 720 --date $Date --out-dir $OutDir > $SimLog 2>&1"
$SimExit = $LASTEXITCODE
$T1 = (Get-Date).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")
Get-Content -Path $SimLog -Encoding UTF8 | Where-Object { $_ -like "SIM_DONE*" }
$DoneLines = @(Get-Content -Path $SimLog -Encoding UTF8 -ErrorAction SilentlyContinue | Where-Object { $_ -like "SIM_DONE*" }).Count
$JsonlLines = @(Get-Content -Path "$OutDir\sessions.jsonl" -Encoding UTF8 -ErrorAction SilentlyContinue | Where-Object { $_.Trim() }).Count
$Skipped = -1
if (Test-Path "$OutDir\run_meta.json") { $Skipped = [int](Get-Content -Path "$OutDir\run_meta.json" -Raw -Encoding UTF8 | ConvertFrom-Json).skipped_sessions }
$Complete = (($SimExit -eq 0) -or ($SimExit -eq 1)) -and ($DoneLines -eq 1) -and ($Skipped -ge 0) -and (($JsonlLines + $Skipped) -eq 720)
Write-Host "RUN f$F COMPLETE=$Complete  DB=$DbName  SIM_EXIT=$SimExit  SIM_DONE_LINES=$DoneLines  JSONL_LINES=$JsonlLines  SKIPPED=$Skipped  WINDOW=$T0~$T1"
if (-not $Complete) { $Stop = $true; Write-Host "RUN f$F 끝까지 돌지 않았다 — 아래 로그 끝 5줄을 세션에 알리기(다음 플래그는 돌지 않는다)"; Get-Content -Path $SimLog -Encoding UTF8 -Tail 5; if (Test-Path "$OutDir\run_meta.json") { Rename-Item -Path "$OutDir\run_meta.json" -NewName "run_meta.incomplete.json" } }
} else { $Stop = $true; Write-Host "RUN f$F REFUSED — DB_CREATED=$DbCreated SCHEMA_OK=$SchemaOk (이 줄을 세션에 알리기)" }
}
Remove-Item Env:GOLDEN_T2R_GRADE, Env:SIM_FULL -ErrorAction SilentlyContinue
} else { Write-Host "RUN_REFUSED=True — READY=$Ready DB_READY=$DbReady STAGE=$Stage (블록 A·S 판정 줄 확인 · STAGE=extract면 블록 X로)" }
Set-Location $Root
```

- 끝까지 돌지 못한 실행은 `run_meta.json`을 `run_meta.incomplete.json`으로 이름만 바꾼다(지우지 않는다). 그러면 블록 A가 다시 그 실행부터 돌게 판단한다. 다시 돌면 같은 폴더의 기록 파일은 러너가 새로 쓴다.

## 블록 X — 숫자 한 장 → 클립보드 (창 A 또는 새 창 · 약 1~3분 · 읽기 전용)

```powershell
# [블록 X — S28R 추출] Windows PowerShell — 읽기 전용(두 실행 기록을 검사해 숫자 한 장을 만들고 클립보드에 넣는다 · 저장소·DB를 바꾸지 않음)
$Root = "C:\Users\kiki\Desktop\__AI"
$Main = "$Root\WhyMath"
$Wt = "$Root\WhyMath-cal"
$RunDir = "$Root\sim-s28r"
$Py = "$Main\src\backend\.venv\Scripts\python.exe"
$Both = (Test-Path "$RunDir\f0\run_meta.json") -and (Test-Path "$RunDir\f1\run_meta.json") -and (Test-Path "$Wt\golden\reports_phase1r\S28R\extract_s28r.txt")
if ($Both) {
$env:GOLDEN_SIM_SEED_DIR = "$Main\golden\sim\seed"
$env:PYTHONUTF8 = "1"
$env:PYTHONIOENCODING = "utf-8"
Set-Location "$Wt\src\backend"
$Out = "$RunDir\s28r_summary.txt"
& $Py "$Wt\golden\reports_phase1r\S28R\extract_s28r.txt" "$RunDir\f0" "$RunDir\f1" $Out
$ExtractExit = $LASTEXITCODE
$Text = Get-Content -Path $Out -Raw -Encoding UTF8
Set-Clipboard -Value $Text
Start-Sleep -Milliseconds 500
$Clip = Get-Clipboard -Raw
Write-Host "EXTRACT_EXIT=$ExtractExit  OUT_CHARS=$($Text.Length)  CLIPBOARD_CHARS=$($Clip.Length)  (두 숫자가 같으면 이 대화창에 Ctrl+V · 다르면 메모장으로 $Out 을 열어 전체 복사)"
Set-Location $Root
} else { Write-Host "EXTRACT_REFUSED=True — f0·f1의 run_meta.json 또는 추출기 파일이 없다(블록 R이 둘 다 COMPLETE=True였는지 확인)" }
```

- 붙여넣을 것: 클립보드 전체다. 숫자 줄과, 판정이 뒤집힌 입력 예시(최대 80줄 · 시드와 같은 문장은 가려져 있다)가 들어 있다.
- `CLIPBOARD_CHARS`와 `OUT_CHARS`를 비교하는 것은 1단계 S35의 클립보드 확인이 결과가 다 나왔는데도 False를 낸 일(LATER S35 줄) 때문이다. 내용 검사 대신 글자 수를 그대로 보여 준다.

## 클라우드 시험(이 런북을 쓰기 전)

- 추출기 `extract_s28r.txt`를 이 세션의 가짜 120세션 두 번(플래그 0 · 1) 기록에 돌렸다. 시험하려고 `run_meta.json`의 mode만 live로 바꾼 사본과 합성 시드 20줄을 썼다.
  - 정상: 플래그 검증 `flag_mismatch=0` · 뒤집힘 0이 나왔다. 가짜 대본에는 앞말·꼬리 입력이 없다.
  - 건수 검사: 720이 아니라 120이라 `S28R_CHECK ok=False`를 냈다. 건수 검사가 살아 있다는 뜻이다.
- 변이 시험: f1 기록 한 줄을 `f(0)은 8이에요?`(정답 처리)로 바꿨다.
  - f1로 넘기면 `flag_mismatch=0`·`FLIP P4=1`이 나왔다.
  - 같은 기록을 f0으로 넘기면 `기록 판정 ≠ 플래그 0 재채점 1턴`으로 거부했다. 플래그가 바뀐 실행을 가려낸다는 뜻이다.
