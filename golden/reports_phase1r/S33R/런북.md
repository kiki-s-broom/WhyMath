# S33R Kiki 머신 런북 — T3R 적용 + AI 회귀: 720세션 플래그 0 → 플래그 1 → 숫자 한 장 + 15건

> 이 런북은 저장소의 아무것도 바꾸지 않는다. Kiki PC에서 실행 결과(숫자 한 장 · 15건 대화 글)만 클립보드로 받는다.
> 모양은 S28R 런북과 같다(블록 A → S → R → X). 달라진 점은 넷이다.
> - 켜고 끄는 플래그가 `GOLDEN_T3R_LEAK_GUARD`(S32R 튜터 응답 유출 검사)다. `GOLDEN_T2R_GRADE`는 S30R 판정(효과 없음)대로 꺼 둔다. S30R이 연결을 되돌려 이 값은 채점에 영향이 없다.
> - 결과 폴더는 `sim-s33r`다.
> - 추출기가 실행 때 쓴 DB의 `golden.eval_log`를 **읽기만** 해서 재생성·고정 문장 횟수와 플래그 값을 확인한다. 그래서 블록 X가 도는 동안 DB 컨테이너(`whymath-demo-db`)가 켜져 있어야 한다.
> - 블록 Y가 하나 더 있다. 플래그 1 실행의 15건 대화 글을 두 번째로 클립보드에 넣는다(S29R과 같은 고르는 규칙).

## 사전 브리핑 (6항목)

1. **과제 명칭:** S33R — 튜터 응답 유출 검사(`GOLDEN_T3R_LEAK_GUARD`)를 **끈 채(플래그 0)·켠 채(플래그 1)** 실제 LLM으로 720세션씩 돌린다(30문항 × 페르소나 8 × 3회). 이어서 플래그 1 실행에서 15건을 뽑는다.
2. **목적**
   - S32R 검사기가 실제 LLM 튜터에서 무엇을 바꾸는지 잰다.
     - 유출 세션 수(M1)와 그 출처(ⓐ 새로 말함 · ⓑ 학생 값 되짚음 · ⓒ 부호 반대 오답 되짚음).
     - 재생성 횟수와 고정 문장 대체 횟수.
   - 15건은 이 세션이 1회차 S24처럼 손으로 판정한다(C3 정답 비노출을 특히 본다).
   - 결과는 S34R(T3R 판정)의 근거다. **S34R 판정 숫자는 "M1 유출 세션 수와 ⓐ 세션 수가 둘 다 줄었다"이다.** S31R 기록 1,285세션에서 ⓐ가 0이었으므로, 이 실행 전에 그 기준을 그대로 둘지 Kiki가 정한다(S31R 보고 6절). 기준을 바꾸지 않아도 이 실행은 그대로 쓸 수 있다.
3. **구체적 절차**
   - **블록 A**(약 30초): 작업 폴더 `WhyMath-cal`을 main에 맞추고 점검한다.
   - **블록 S**(약 10~60초): 시연용 Postgres(`whymath-demo-db` · 55432)를 켠다.
   - **블록 R**(**약 4~10시간**): 플래그 0으로 720세션을 돌린다. 끝까지 돌았으면 플래그 1로 720세션을 돈다.
     - S28R 실측은 두 실행 합쳐 약 4시간이었다.
     - 각각 새 데이터베이스를 쓴다(이름은 `sim-s33r\db_names.txt`에 남는다).
     - 튜터는 OpenRouter, 학생은 로컬 Ollama `qwen2.5:7b`다.
     - PC가 잠들지 않게 한다(전원 설정 → 절전 안 함).
     - 플래그 1은 걸린 응답을 한 번 다시 만들기 때문에 OpenRouter 호출이 조금 늘 수 있다. 상한은 걸린 턴마다 1회다.
   - **블록 X**(약 1~3분 · 읽기 전용): 추출기가 두 실행과 두 DB를 검사하고 숫자 한 장을 클립보드에 넣는다.
   - **블록 Y**(약 5초 · 읽기 전용): 블록 X가 같이 만든 15건 글을 클립보드에 넣는다.
4. **성공 기준**
   - **블록 A:** `READY=True` 줄이 보인다. `STAGE`는 `run`(처음) 또는 `f1`(플래그 0만 끝남)이다. `STAGE=extract`면 블록 S(DB 켜기) 뒤 블록 X로 간다.
   - **블록 S:** `DB_READY=True`.
   - **블록 R:** `RUN f0 COMPLETE=True`와 `RUN f1 COMPLETE=True`가 보인다(조건은 S28R과 같다 — `SIM_DONE_LINES=1` · `JSONL_LINES`+`SKIPPED`=720 · `SIM_EXIT` 0 또는 1).
   - **블록 X:** 화면 첫 줄이 `S33R_CHECK ok=True picked15=15`이고, `CLIPBOARD_CHARS`가 `OUT_CHARS`와 같다. 그다음 이 세션 대화창에 **Ctrl+V로 붙여넣는다**.
   - **블록 Y:** `CLIPBOARD_CHARS`가 `OUT_CHARS`와 같다. 그다음 두 번째로 붙여넣는다.
   - **실패 시 대처:** 각 블록의 `…=False`·`REFUSED` 줄, 또는 `S33R_CHECK ok=False … problems=…` 줄이 무엇이 틀렸는지 알려 준다. 그 줄만 세션에 보낸다. `DB … 읽기 실패`면 블록 S를 다시 붙여넣은 뒤 블록 X를 다시 붙여넣는다.
5. **실행 환경:** Phaiakes9(이 PC) · Windows PowerShell.
   - 공유 작업 사본 `C:\Users\kiki\Desktop\__AI\WhyMath`: 읽기만 한다. `.venv`·시드·compose 파일을 빌려 쓴다.
   - 작업 폴더 `C:\Users\kiki\Desktop\__AI\WhyMath-cal`: S28R·S29R·S31R 때 쓴 것을 재사용한다.
   - 결과 폴더 `C:\Users\kiki\Desktop\__AI\sim-s33r`(f0·f1 하위 폴더). `sessions.jsonl`은 이 PC에만 둔다.
   - 선행 조건: Docker Desktop 가동 · Ollama 앱 가동 · `WHYMATH_OPENROUTER_API_KEY` 사용자 환경변수(S28R과 같은 것) · S16 시드 파일 · **S32R·S33R 런북 PR이 main에 병합됨**(블록 A의 `HAS_T3R`·`SCRIPT_OK`가 확인한다).
6. **창 구분:** **새 PowerShell 창 하나(창 A)**에서 블록 A → S → R → X → Y를 차례로 붙여넣는다.
   - A·S·R은 앞 블록의 변수를 쓰므로 같은 창이어야 한다. 블록 X·Y는 혼자서도 돈다(새 창도 된다).
   - 블록 R이 도는 동안(**4~10시간**) **이 창은 건드리지 않는다.** Ctrl+C는 복사가 아니라 중단이다. 다른 작업은 다른 창에서 한다.
   - 각 블록의 판정 줄을 눈으로 본 다음에 다음 블록을 붙여넣는다. 쓰기 블록(R)은 앞 조건이 틀리면 스스로 거부한다.
   - 블록 R이 중간에 끊겼으면 블록 A부터 다시 붙여넣는다. `STAGE=f1`이면 플래그 1만 돈다.

## 블록 A — 준비·점검 (창 A · 새 창)

```powershell
# [창 A · 블록 A — S33R 준비·점검] Windows PowerShell — 작업 폴더 WhyMath-cal을 main에 맞추고 점검(공유 작업 사본은 바꾸지 않음)
cd C:\Users\kiki\Desktop\__AI\WhyMath
$Root = "C:\Users\kiki\Desktop\__AI"
$Main = "$Root\WhyMath"
$Wt = "$Root\WhyMath-cal"
$RunDir = "$Root\sim-s33r"
$Model = "qwen2.5:7b"
git fetch origin main
git worktree prune
$Expected = git rev-parse "origin/main"
if (Test-Path "$Wt\.git") { git -C $Wt checkout -q --detach --force $Expected } else { git worktree add -q --detach $Wt $Expected }
$WtHead = git -C $Wt rev-parse HEAD 2>$null
$Ready = $false
$Stage = "none"
if ($WtHead -eq $Expected) {
git -C $Wt log -1 --oneline
$Py = "$Main\src\backend\.venv\Scripts\python.exe"
$PyOk = Test-Path $Py
$SeedDir = "$Main\golden\sim\seed"
$SeedOk = (Test-Path "$SeedDir\utterances.txt") -and (Test-Path "$SeedDir\distributions.json")
$ScriptOk = Test-Path "$Wt\golden\reports_phase1r\S33R\extract_s33r.txt"
$Tags = @(ollama list 2>$null | Select-Object -Skip 1 | ForEach-Object { ($_ -split '\s+')[0] } | Where-Object { $_ })
$HasModel = $Tags -contains $Model
$KeyOk = (-not [string]::IsNullOrEmpty($env:WHYMATH_OPENROUTER_API_KEY)) -or (-not [string]::IsNullOrEmpty($env:OPENROUTER_API_KEY))
Set-Location "$Wt\src\backend"
$ModFile = ""
if ($PyOk) { $ModFile = & $Py -c "import golden.eval.leak_guard as m; print(m.__file__)" 2>$null }
$HasT3r = [string]$ModFile -like "$Wt\*"
git -C $Wt diff --quiet -- golden src/backend/golden; $TreeClean = ($LASTEXITCODE -eq 0)
$F0Done = Test-Path "$RunDir\f0\run_meta.json"
$F1Done = Test-Path "$RunDir\f1\run_meta.json"
if ($F0Done -and $F1Done) { $Stage = "extract" } elseif ($F0Done) { $Stage = "f1" } else { $Stage = "run" }
Write-Host "WORKTREE_HEAD=$WtHead  EXPECTED=$Expected"
Write-Host "PY_OK=$PyOk  SEED_OK=$SeedOk  SCRIPT_OK=$ScriptOk  HAS_T3R=$HasT3r  HAS_MODEL=$HasModel  KEY_OK=$KeyOk  OLLAMA_TAGS=$($Tags.Count)  TREE_CLEAN=$TreeClean  F0_DONE=$F0Done  F1_DONE=$F1Done  STAGE=$Stage"
$Ready = $PyOk -and $SeedOk -and $ScriptOk -and $HasT3r -and $HasModel -and $KeyOk -and $TreeClean
if ($Ready -and ($Stage -eq "extract")) { Write-Host "READY=True  STAGE=extract — 두 실행이 이미 끝났다 · 블록 R을 건너뛰고 블록 X로" } elseif ($Ready) { Write-Host "READY=True  STAGE=$Stage — 블록 S로(DB가 이미 켜져 있으면 블록 R로)" } else { Write-Host "READY=False — HAS_T3R=False 또는 SCRIPT_OK=False면 S32R·S33R PR이 아직 main에 없다(세션에 알리기) · PY_OK=False면 .venv 없음 · SEED_OK=False면 S16 시드 없음 · HAS_MODEL=False면 'ollama pull qwen2.5:7b' 뒤 이 블록 다시 · OLLAMA_TAGS=0이면 Ollama 앱 켜기 · KEY_OK=False면 OpenRouter 키 없음 · TREE_CLEAN=False면 작업 폴더의 골든 파일이 손으로 바뀜(세션에 알리기)" }
} else { Write-Host "READY=False — REFUSED — HEAD=$WtHead  EXPECTED=$Expected (작업 폴더를 main으로 맞추지 못했다 — 이 줄을 세션에 알리기)" }
```

## 블록 R — 720세션 플래그 0 → 플래그 1 (창 A · 약 4~10시간 · 이 창은 건드리지 않는다)

```powershell
# [창 A · 블록 R — S33R 720 × 2] Windows PowerShell — READY·DB_READY가 True이고 STAGE가 run 또는 f1일 때만: 플래그마다 새 데이터베이스를 만들고(아무것도 지우지 않음) 720세션 실행
$Date = Get-Date -Format "yyyy-MM-dd"
$RunOk = $Ready -and $DbReady -and (($Stage -eq "run") -or ($Stage -eq "f1"))
if ($RunOk) {
Remove-Item Env:GOLDEN_FAKE_LLM, Env:GOLDEN_T1_RUBRIC, Env:GOLDEN_T2_MISCONCEPTION, Env:GOLDEN_MASTERY_ENGINE, Env:GOLDEN_T2R_GRADE -ErrorAction SilentlyContinue
$env:SIM_FULL = "1"
$env:GOLDEN_SIM_SEED_DIR = $SeedDir
$env:GOLDEN_SIM_STUDENT_MODEL = $Model
$env:PYTHONUTF8 = "1"
$env:PYTHONIOENCODING = "utf-8"
Set-Location "$Wt\src\backend"
ollama run $Model "hi" 2>&1 | Out-Null
$Flags = @("0", "1")
if ($Stage -eq "f1") { $Flags = @("1") }
$Stop = $false
foreach ($F in $Flags) {
if ($Stop) { break }
$OutDir = "$RunDir\f$F"
$SimLog = "$RunDir\sim_f$F.txt"
New-Item -ItemType Directory -Force -Path $OutDir | Out-Null
$DbName = "whymath_s33r_f" + $F + "_" + (Get-Date).ToUniversalTime().ToString("yyyyMMddHHmm")
docker exec whymath-demo-db createdb -U whymath $DbName
$DbCreated = ($LASTEXITCODE -eq 0)
Add-Content -Path "$RunDir\db_names.txt" -Value "f$F $DbName" -Encoding ASCII
$env:WHYMATH_DATABASE_URL = "postgresql+asyncpg://whymath@127.0.0.1:55432/" + $DbName + "?ssl=disable"
$env:GOLDEN_T3R_LEAK_GUARD = $F
$SchemaOk = $false
if ($DbCreated) { & $Py -c "import asyncio; from golden import store; asyncio.run(store.ensure_schema()); print('SCHEMA_OK')"; $SchemaOk = ($LASTEXITCODE -eq 0) }
if ($DbCreated -and $SchemaOk) {
$T0 = (Get-Date).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")
cmd /c "$Py -m golden.sim.run --sessions 720 --date $Date --out-dir $OutDir > $SimLog 2>&1"
$SimExit = $LASTEXITCODE
$T1 = (Get-Date).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")
Get-Content -Path $SimLog -Encoding UTF8 | Where-Object { $_ -like "SIM_DONE*" }
$DoneLines = @(Get-Content -Path $SimLog -Encoding UTF8 -ErrorAction SilentlyContinue | Where-Object { $_ -like "SIM_DONE*" }).Count
$JsonlLines = @(Get-Content -Path "$OutDir\sessions.jsonl" -Encoding UTF8 -ErrorAction SilentlyContinue | Where-Object { $_.Trim() }).Count
$Skipped = -1
if (Test-Path "$OutDir\run_meta.json") { $Skipped = [int](Get-Content -Path "$OutDir\run_meta.json" -Raw -Encoding UTF8 | ConvertFrom-Json).skipped_sessions }
$Complete = (($SimExit -eq 0) -or ($SimExit -eq 1)) -and ($DoneLines -eq 1) -and ($Skipped -ge 0) -and (($JsonlLines + $Skipped) -eq 720)
Write-Host "RUN f$F COMPLETE=$Complete  DB=$DbName  SIM_EXIT=$SimExit  SIM_DONE_LINES=$DoneLines  JSONL_LINES=$JsonlLines  SKIPPED=$Skipped  WINDOW=$T0~$T1"
if (-not $Complete) { $Stop = $true; Write-Host "RUN f$F 끝까지 돌지 않았다 — 아래 로그 끝 5줄을 세션에 알리기(다음 플래그는 돌지 않는다)"; Get-Content -Path $SimLog -Encoding UTF8 -Tail 5; if (Test-Path "$OutDir\run_meta.json") { Rename-Item -Path "$OutDir\run_meta.json" -NewName "run_meta.incomplete.json" } }
} else { $Stop = $true; Write-Host "RUN f$F REFUSED — DB_CREATED=$DbCreated SCHEMA_OK=$SchemaOk (이 줄을 세션에 알리기)" }
}
Remove-Item Env:GOLDEN_T3R_LEAK_GUARD, Env:SIM_FULL -ErrorAction SilentlyContinue
} else { Write-Host "RUN_REFUSED=True — READY=$Ready DB_READY=$DbReady STAGE=$Stage (블록 A·S 판정 줄 확인 · STAGE=extract면 블록 X로)" }
Set-Location $Root
```

- 끝까지 돌지 못한 실행은 `run_meta.json`을 `run_meta.incomplete.json`으로 이름만 바꾼다(지우지 않는다). 그러면 블록 A가 다시 그 실행부터 돌게 판단한다. 다시 돌면 같은 폴더의 기록 파일은 러너가 새로 쓴다.


- 숫자 한 장 줄:
  - `S33R_RUN`: M1~M5, 되묻기 턴 수, DB 되묻기 수, DB T3R 기록 수.
  - `S33R_LEAK`: 유출 세션 수와 출처 칸 ⓐ·ⓑ·ⓒ.
  - `S33R_GUARD`: 처리별 건수(pass · regenerated · replaced* · skipped_degraded), 고정 문장 턴 수, 축별 건수.
  - `S33R_M2` · `S33R_FINAL` · `S33R_BREAK1`: S28R과 같다.
- **플래그 검증:** `run_meta.json`에는 플래그 칸이 없다. 그래서 추출기는 실행 DB의 T3R 기록 수로 확인한다.
  - f1이면 되묻기 턴 수와 같아야 하고, f0이면 0이어야 한다.
  - DB의 되묻기 수가 기록의 되묻기 수와 다르면 다른 실행의 DB로 보고 거부한다.
- 15건 글에는 학생·튜터 문장이 들어 있다. 시드와 같은 학생 문장은 가려져 있다. 저장소 밖 파일이라 커밋되지 않는다.

## 클라우드 시험(이 런북을 쓰기 전)

이 세션의 가짜 120세션 두 번(플래그 0 · 1)을 새 DB 둘에 돌렸다. 그 기록을 mode만 live로 바꾼 사본과 합성 시드 20줄로 추출기를 시험했다. DB 주소만 시험용 환경변수 `S33R_DB_URL`로 이 컨테이너의 Postgres를 가리켰다.

- 정상:
  - f0은 DB 되묻기 225 · T3R 0, f1은 DB 되묻기 225 · T3R 225(`pass=225`)였다. 15건은 15/15를 골랐다.
  - 기록이 120이라 `720` 건수 검사가 `ok=False`를 냈다. 15건의 튜터 문장은 가짜 모드라 거부됐다. 둘 다 검사가 살아 있다는 뜻이다.
- 뮤테이션 — 모두 걸렸다:
  - DB 이름 뒤바꿈 → `f0 T3R 기록 225 ≠ 기대 0` · `f1 T3R 기록 0 ≠ 기대 225`.
  - f1 기록 사본에 유출 3종 주입 → `leak_sessions=3 src_a=1 src_b=1 src_c=1`. 주입은 ⓐ 새로 말함 · ⓑ 학생 값 되짚음 · ⓒ 부호 반대 오답 되짚음이다.
  - 없는 DB 이름 → `읽기 실패 InvalidCatalogNameError`.
- 원본 기록은 바뀌지 않았다(sha256 대조).
