- 이 묶음(RS)이 하는 일은 다섯 가지다: ①진단 — 코드를 읽지 않고 도구로 등급을 붙인다 ②판정 — 패키지 단위로 처분(연결·수리·재작성·격리·삭제)을 정하고 Kiki가 승인한다 ③입고 준비 — 다음에 들여올 자산 셋의 명세 카드와 특성화 테스트를 만든다 ④잠금 — 새 구역이 다시 끊기지 않게 자동 검사를 건다 ⑤축소 준비 — 삭제 증거를 모은다.

## 공통 규칙 (작업보다 먼저 지킨다)

규칙과 작업 지시가 충돌하면 규칙이 우선한다.

1. **읽을 범위:** 이 지시문과, 이 지시문이 "선행 산출물"로 적은 결과물만 읽는다. 다른 작업 번호의 일은 하지 않는다.
2. **선행 작업 확인:** 선행 작업마다 `golden/reports_rescue/<번호>/보고.md`가 있고 결과가 "완료"인지 확인한다. 관문 작업(J1, F1)은 판정이 go인지도 확인한다. 하나라도 아니면 시작하지 말고, 비어 있는 번호를 보고하고 멈춘다.
3. **옛 코드는 한 줄도 고치지 않는다:** 쓸 수 있는 곳은 `golden/`(문서·보고), `src/backend/golden/rescue/`(도구 코드), `tests/golden/`(테스트)뿐이다. `src/backend/whymath_backend/`, `scripts/`, `src/data-pipeline/`, `src/mobile/lib/`(golden 폴더 제외), `src/web/`, `tests/`(golden 폴더 제외), `.github/`, `.claude/`, `constitution/`, `CLAUDE.md`는 읽기 전용이다. 고쳐야 한다고 판단하면 고치지 말고 보고에 "제안"으로 적는다.
4. **컨텍스트 예산 ① 읽기 상한:** 한 세션에서 옛 코드·옛 테스트·목차 출력을 합쳐 **2,000줄**까지만 읽는다. 읽을 때마다 보고의 「읽기 장부」에 `경로 · 줄 범위 · 줄 수 · 누계`를 한 줄씩 적는다. 이 지시문과 선행 카드는 상한에 넣지 않는다.
5. **컨텍스트 예산 ② 큰 파일:** 1,500줄이 넘는 파일(백엔드에 27개 — 공유 계약 「큰 파일」)은 통째로 열지 않는다. 먼저 목차 도구(`python -m golden.rescue.outline`)나 `grep -n "^def \|^class \|^async def "`로 줄 번호를 얻고, 필요한 함수 구간만 연다. `MEMORY.md`(약 3.8MB)는 어떤 세션도 통째로 열지 않는다 — `grep`만 쓴다.
6. **컨텍스트 예산 ③ 도구 출력:** 도구의 원본 출력은 파일로 보낸다(`> 파일 2>&1`). 대화창에는 요약 **50줄**까지만 올린다(`head -50`은 요약 표에만 쓰고, 판정은 종료 코드로 한다 — 규칙 10). 200KB가 넘는 원본은 저장소에 커밋하지 않고 보고에 "재생성 명령"만 적는다.
7. **컨텍스트 예산 ④ 인계는 카드로:** 다음 세션에 넘길 내용은 `golden/reports_rescue/<번호>/카드.md` 한 장(**150줄 이하**)에 적는다. 다음 세션은 코드가 아니라 카드를 읽고 시작한다. 카드 형식은 공유 계약 「카드 형식」을 따른다.
8. **컨텍스트 예산 ⑤ 멈춤 규칙:** 읽기 누계가 **1,600줄**(상한의 80%)에 닿으면 새 파일을 열지 않는다. 그때까지의 결과로 카드와 보고를 쓰고, 결과를 "일부 완료"로 적고, 남은 일을 "다음 작업이 알아야 할 것"에 `남은 대상 · 예상 줄 수`로 적는다. 예산을 넘겨 끝내는 것보다 나눠 끝내는 것이 옳다.
9. **컨텍스트 예산 ⑥ 한 세션 한 가지 · PR 크기:** 진단·명세·테스트 작성·구현을 한 세션에 섞지 않는다. PR 하나는 **변경 300줄·파일 5개**까지다(생성된 CSV·TSV·카드는 세지 않는다). 넘으면 PR을 나누고 보고에 나눈 이유를 적는다. 옛 코드 탐색을 하위 에이전트에게 맡길 수 있으면 맡기고, 결론 30줄만 돌려받는다.
10. **판정은 종료 코드로:** 검사 명령은 `-q`·`| tail`로 자르지 않고, 끝에 `; echo "EXIT=$?"`를 붙여 종료 코드로 판정한다. 파이프를 쓰면 `${PIPESTATUS[0]}`을 본다. 0건이라는 결과는 "내가 쓴 명령으로 0건"이라고 범위를 밝혀 적는다.
11. **검증은 CI와 같은 명령으로:** 코드를 쓴 세션(R0·R1·G1·G2·X1~X3)은 `src/backend`에서 `python -m ruff check golden ../../tests/golden`, `python -m black --check --line-length 100 golden ../../tests/golden`, `python -m mypy --strict golden`, `lint-imports`, `python -m pytest ../../tests/golden`을 돌린다(CI `golden-path` 잡과 같은 스텝). 빨간불이면 PR을 만들지 않는다. 환경 준비는 `cd src/backend && python -m pip install -e ".[dev]" && python -m pip install -e ../data-pipeline`이다.
12. **보호 장치는 일부러 어겨 본다:** 검사·게이트·테스트를 만들었으면 그것이 막으려는 상태를 실제로 넣어 **실패하는 것**을 확인한다. 넣기 전에 `cp`로 백업하고 `cp`로 되돌린다(`git checkout --`·`git stash`로 되돌리지 않는다). 보고에 "주입 N종 중 실패 N종"을 적는다.
13. **모르는 값은 추정 금지:** 이 문서의 "사전 실측(2026-11-17 · main `d7466d84`)" 값도 세션에서 다시 확인하고 다르면 보고 첫머리에 **[차이]**로 적는다. 못 찾으면 "미확인"으로 적고 그 부분만 멈춘다. 이름을 못 찾았다고 기능이 없다고 적지 않는다 — 역할(하는 일)로 한 번 더 찾는다.
14. **범위 고정:** 이 묶음은 골든 패스(중2 일차함수 30문항 · GP-1~GP-6)에 기능을 더하지 않는다. 옛 자산을 골든 경로에 **연결하지 않는다** — 연결은 1~3단계 묶음의 슬롯(T1·T2·T3 등) 세션이 한다. 옛 코드를 **삭제하지 않는다** — 삭제는 3단계 S74다. 떠오른 아이디어는 `golden/LATER.md`에 한 줄 적는다.
15. **미성년자 데이터:** 실제 학생 발화·로그(`golden/logs/`, `golden/sim/seed/`)는 이 묶음의 어떤 세션도 읽지 않고, 어떤 도구에도 넣지 않는다. 테스트 입력은 합성 데이터로 만든다.
16. **하네스·커밋·PR:** 파일을 바꾸는 세션은 첫 행위로 `python3 scripts/harness/backlog.py add`로 태스크를 받고(`--id`는 CLI가 거부하면 제안하는 번호를 쓴다 — 번호를 눈으로 짓지 않는다 · `--track math-completion --stage S1 --layer backend --eos-priority P1` · 제목 `RS-<번호> <작업 제목>`) `backlog.py start <ID>`를 실행한다. 커밋 메시지는 `RS-<번호>: <한 줄>` 형식이다. 끝나면 PR을 열고 본문 첫 질문(전진시키는 학생 단계)에 "해당 없음 — 옛 코드 살리기 RS-<번호>(Kiki 지시 2026-11-17)"라고 적는다. main 머지는 Kiki가 한다.

3. 하위 패키지(폴더 또는 단독 파일 묶음)마다 공유 계약 「카드 형식」의 열을 채운다. "하는 일 한 줄"은 모듈 설명 첫 줄들에서 뽑는다. 설명이 없어 알 수 없으면 `--level 2`로 함수 이름을 보고, 그래도 모르면 "미확인"이라고 적는다(본문을 열어 추측하지 않는다).
4. "자산/접착제/도구" 판단 기준: 수학·교수학 지식이나 규칙이 들어 있으면 자산, 다른 모듈을 이어 붙이기만 하면 접착제, 저작·검수·측정·운영용이면 도구.
5. 처분을 **제안**한다(공유 계약 「처분 정의」 · 정하지 못하면 격리). 제안마다 근거 한 줄(등급·건수·중복 중 무엇을 봤는지)을 붙인다.
6. 자산으로 본 것 가운데 상위 3개에만 `--level 2`를 돌려 "가져올 만한 함수·클래스 이름"을 5개 이하로 적는다.
7. 「이미 다른 묶음이 맡은 것」에 해당하는 대상은 처분 칸에 `단계 묶음 담당(S__)`이라고 적고 더 보지 않는다.

*명세 카드 쓰는 법 (P1~P3 공통)*

1. `golden/reports_rescue/J1/수확_대기열.md`에서 자기 순위의 항목(파일 경로·함수 이름·줄 수)만 읽는다.
2. `--level 2` 목차로 줄 번호를 얻고, 적힌 함수·클래스 구간만 연다. 그 함수가 부르는 다른 옛 함수는 이름과 경로만 적고 따라 들어가지 않는다(읽기 상한).
3. `명세.md`를 쓴다: ①하는 일 한 문단(입력이 무엇이고 무엇을 돌려주는가) ②공개 함수마다 `이름 · 인자(이름·형식·범위) · 반환(형식·범위) · 예외` ③부작용(DB·네트워크·LLM·파일·전역 상태) ④의존(직접 import하는 옛 모듈 수와 이름 — `python -m golden.rescue.ledger`의 CSV 또는 `grep "^from\|^import"`) ⑤헷갈리는 값(ID 형식, 0~1인지 0~100인지, 단위) ⑥추측한 곳은 "추측"이라고 표시.
4. 특성화 테스트에 쓸 **입력 10개**를 합성해 적는다(정상 6 · 경계 2 · 잘못된 입력 2). 출력은 적지 않는다 — X 세션이 실제로 돌려서 채운다.
5. 의존이 3개 이하면 "import 권장", 넘으면 "복사 권장(의존 과다)"이라고 적는다(1단계 묶음의 다섯 걸음과 같은 기준).

*특성화 테스트 쓰는 법 (X1~X3 공통)*

1. 자기 순위의 `명세.md`만 읽는다. 옛 코드 본문은 테스트가 실패해 원인을 봐야 할 때만, 300줄 이하로 연다.
2. `tests/golden/characterization/test_rs_<자산 짧은 이름>.py`를 쓴다. 옛 함수를 **옛 자리에서 그대로** import해 부른다(테스트에서만 부른다 — `src/backend/golden/` 코드는 그 모듈을 import하지 않는다).
3. 명세의 입력 10개를 실제로 돌려 나온 출력을 기대값으로 고정한다. 예외가 나는 입력은 예외 이름을 고정한다. "맞는 답"으로 고치지 않는다.
4. 부작용이 있는 함수(DB·네트워크·LLM)는 부르지 않는다. 명세가 부작용 있음이라고 적은 함수는 테스트에서 빼고 보고에 "부작용으로 제외"라고 적는다. 10개를 채우지 못하면 채운 수를 적는다.
5. 결정적인지 확인한다: 같은 테스트를 세 번 돌려 세 번 다 통과하는가.
6. 주입(규칙 12): 기대값 하나를 일부러 바꿔 테스트가 실패하는지 본다(테스트 파일만 바꾼다 — 옛 코드는 바꾸지 않는다).
7. `golden/HARVEST.md`에 한 줄을 더한다: `가져온 것 = 없음(특성화 테스트만) · 버린 것 = 없음 · 이유 = RS 입고 준비 · 세션 = RS-X<n>`.
