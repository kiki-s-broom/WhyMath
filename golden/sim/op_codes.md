# OP 코드 — 오답의 오류 유형 (S16 확정 · F-00)

> 주입기(`src/backend/golden/sim/errors.py` · S17)와 보정 검사(`calibrate.py` · S20)가 이 표를 같이 쓴다.
> 코드에서 쓰는 정본은 `src/backend/golden/sim/seed_extract.py`의 `OP_CODES`이고, `tests/golden/test_sim_seed.py`가 이 문서의 표와 글자까지 같은지 검사한다. 표를 바꾸려면 두 곳을 함께 바꾼다.
> 분류기는 `seed_extract.classify_error(problem, student_text)`다. 규칙만 쓰고(LLM 없음) 같은 입력에 늘 같은 코드를 낸다. 모르면 `OP_00`이다.

## 코드 표

| 코드 | 뜻 | 예 |
| --- | --- | --- |
| OP_00 | 미분류 | 어느 규칙에도 안 걸린 오답 |
| OP_01 | 부호 오류(음수 곱·뺄셈) | −3×5=15 · 3−(−5)=−2 · 정답과 부호만 반대인 값 |
| OP_02 | 대입 오류(x 자리에 넣지 않음·곱 대신 더함·자리 붙임) | f(x)=4x+8에서 f(0)을 4+8=12로 · f(2)=2f |
| OP_03 | 기울기 분자·분모 뒤바꿈 | 6/(−9) (x 증가량 ÷ y 증가량) |
| OP_04 | 기울기·y절편 혼동 | y=2x+3의 기울기를 3으로 · 식의 두 수를 바꿔 씀 |
| OP_05 | 계산을 끝내지 않음(식만 쓰거나 중간값에서 멈춤) | 3×5+2 · f(x)=6x−8에서 f(2)를 12(6×2)로 |
| OP_06 | 식 세우기 실패(문제 속 숫자 하나 찍기) | 문제에 적힌 수 "3"을 그대로 냄 |
| OP_07 | x절편·y절편 혼동 | y=−2x+6의 x절편을 6으로 |
| OP_08 | 증가·감소 방향 혼동 | 음의 기울기를 증가로 세어 개수를 거꾸로 냄 |

## 제안값에서 바꾼 것 (실제 오답에 맞춰)

지시서의 제안 표에서 **코드 수와 번호는 그대로**다. 뜻 두 줄만 넓혔다. 근거는 저장소에 이미 올라 있는 사람 출처 기록(S9 보고 · S12 보고)의 오답이다.

- **OP_02**: "f(k)를 k·f로, 자리 바꿈" → "x 자리에 넣지 않음·곱 대신 더함·자리 붙임"까지. 본인 기록에 x를 넣지 않고 두 수를 더한 꼴(4x+8 → 12)이 있었다.
- **OP_05**: "계산 전 식만 쓰고 멈춤" → "중간값에서 멈춤"까지. 본인 기록에 곱까지만 하고 상수항을 처리하지 않은 값(6×2=12)이 있었다. 값이 정답과 같은 식(`3×5+1`)은 채점 계약상 정답이라 오답으로 들어오지 않는다.

## 분류 규칙 (위에서부터 먼저 걸린 것)

답을 낸 것이 아닌 입력은 분류하지 않고 `non_answer`로 따로 센다 — 숫자가 하나도 없는 입력("x가 뭐예요?"·"모르겠어요")과, 한글이 섞여 채점기가 수식으로 읽지 못하는 말("5넣어요?")이다. 미분류(OP_00)는 상위 3개 목록(`top3`)에 넣지 않는다.

1. **두 점의 기울기 문항**: 값이 (x 증가량 ÷ y 증가량) 또는 그 부호 반대 → OP_03.
2. **식에서 기울기 읽기**: 값이 y절편 → OP_04 · 값이 기울기의 역수 → OP_03.
3. **y절편 읽기**: 값이 기울기 → OP_04 · 값이 x절편 → OP_07.
4. **x절편 구하기**: 값이 y절편 → OP_07 · 값이 기울기 → OP_04.
5. **증가·감소 개수 세기**: 값이 (전체 개수 − 정답) → OP_08. **증가 조건의 경곗값 문항**: 값이 경계 반대쪽 정수 → OP_08.
6. **함숫값 f(k)** (f(x)=ax+b): 값이 a·k+b에서 부호를 하나 이상 틀린 값 → OP_01 · 값이 a+b, a+k+b, k·(a+b), (a와 k를 붙여 읽은 수)+b → OP_02 · 값이 a·k(상수항 미처리) → OP_05.
7. **식 정답 문항**: 학생 식의 (기울기, y절편)이 정답과 서로 바뀜 → OP_04 · 절댓값은 같고 부호만 다름 → OP_01.
8. 어느 문항이든: 값이 정답과 부호만 반대 → OP_01 · 수 하나가 아니라 계산 전 식 → OP_05 · 값이 문제에 적힌 숫자 → OP_06.
9. 나머지 → OP_00.

## 알려진 한계

- 규칙은 30문항(LF-01~LF-30)의 본문 꼴에 맞춰 있다. 문항이 바뀌면 `tests/golden/test_sim_seed.py`가 먼저 깨진다.
- 한 오답이 두 유형에 걸리면 위 순서에서 먼저 나온 것 하나만 센다. 예: 4x+8의 f(0)을 4로 낸 답(4×0=4)은 "0을 곱함" 오류지만 규칙 8의 "문제 속 숫자"(OP_06)로 들어간다.
- 계수가 문자인 문항(LF-12·LF-20)과 실생활 문항(LF-29·LF-30)은 규칙 8·9만 적용된다.
- 분류는 사람 출처(본인·성인) 오답으로 맞췄다. **실제 중학생 오답은 0건**이라, 실학생 로그가 생기면(S24 뒤) 이 표를 다시 본다.
