# 예약 실행 지시서 — 지시문 하나를 골라 처리하고, CI 초록이면 머지까지 한다

이 파일은 예약 실행(매시간 새로 뜨는 클라우드 세션)이 **처음에 읽고 그대로 따르는** 지시서다.

- 2026-11-23 Kiki 지시: "github에 올린 지시문을 기반으로 코딩 작업을 자동화" → "작업이 끝나면 다음 작업을 자동으로 진행".
- 머지 권한(Kiki 결정 2026-11-23): **`[자동]` PR은 CI가 전부 초록이면 자동 머지한다**('pr' 단축어와 같은 방식).
  그 밖의 PR(사람이 연 PR)은 이 지시서가 머지하지 않는다.
- **자동 진행 방침(Kiki 지시 2026-11-26 · 정본 `golden/AUTONOMY.md`)**: 추천안이 곧 결정이다. Kiki 결정·확인을 기다리며 멈추지 않는다 —
  추천안으로 진행하고 `golden/DECISIONS_AUTO.md`에 한 줄 적는다. 멈추는 것은 그 문서 2절의 여섯 가지뿐이다.
- 흐름: 매시간 한 세션이 뜬다 → 진행 중인 `[자동]` PR이 있으면 그것을 챙긴다(0절) → 없으면 다음 작업 하나를 잡는다(1~3절).
  앞 작업이 머지되면 다음 시간 실행이 곧바로 다음 작업을 잡는다.

## 0. 열린 `[자동]` PR 먼저 — 한 번에 하나

저장소 `kiki-s-broom/WhyMath`의 **열린 PR 중 제목이 `[자동]`으로 시작하는 것**을 찾는다.
GitHub PR 도구(`mcp__github__*` — 필요하면 ToolSearch로 불러온다)가 없거나 조회가 실패하면 중복을 막을 수 없으므로
**아무 작업도 하지 않고** "PR 도구 없음 — 대기"와 계산기 출력만 보고한다.

| 열린 `[자동]` PR 상태 | 할 일 |
| --- | --- |
| 없음 | 1절로 간다 |
| 초안(draft) · 마지막 커밋이 3시간 이내 | 다른 세션이 작업 중이다. 아무것도 하지 않고 "작업 중 — PR #N" 보고 |
| 초안 · 마지막 커밋이 3시간 넘음 | 멈춘 작업으로 본다. **이어받는다** — 그 브랜치를 받아 보고의 남은 대상부터 2절대로 계속하고 같은 PR에 푸시한다(강제 푸시 금지 · 받을 수 없으면 새 브랜치에서 같은 작업을 다시 하고 옛 PR 번호를 본문에 적는다) |
| 초안 아님 · CI 진행 중 | 아무것도 하지 않는다("CI 대기 — PR #N") |
| 초안 아님 · CI 전부 초록 · 자동 머지 꺼짐 | 자동 머지를 켠다(`enable_pr_auto_merge`, SQUASH). 머지 큐가 처리한다 |
| 초안 아님 · CI 빨강 | **고친다** — 실패 잡의 원인을 찾아 그 브랜치에 고친 커밋을 올린다(테스트를 끄거나 건너뛰지 않는다 · 강제 푸시 금지). 한 실행에서 못 고치면 본문에 원인과 남은 일을 적고 다음 실행이 잇는다 |

## 1. 다음 작업 계산

`cd src/backend && python -m golden.driver.next_task --json` 를 돌리고 **종료 코드로** 판정한다(출력 자르기 금지).

| 판정(`verdict`) | 뜻 | 할 일 |
| --- | --- | --- |
| `RUN` | 열 수 있는 작업이 있다 | 2절 |
| `WAIT_KIKI` | 열 수 있는 것이 사람 작업(H 번호 · `-Kiki`)뿐 | 아무것도 하지 않는다. 끝 보고에 그 작업 번호와 지시문 경로 |
| `ATTENTION` | 진행 중·일부 완료인 작업이 길을 막는다 | **이어서 한다** — `attention`의 첫 `일부 완료` 작업을 골라 그 보고의 "남은 대상"부터 2절대로 계속한다. 남은 것이 Kiki 머신 단계뿐이면 하지 않고 끝 보고에 런북 위치를 적는다 |
| `BOUNDARY` | 앞 단계가 끝났고 다음 단계는 시작 조건(게이트 판정)이 있다 | 앞 단계 게이트 작업의 `보고.md`에서 `판정:` 줄을 읽는다. **go면 넘어간다** — `runnable`의 첫 비-Kiki 작업으로 2절. no-go면 그 게이트 지시문의 no-go 조치를 한다. 판정 줄이 없으면 게이트 지시문의 숫자 기준으로 판정해 적고 진행한다. `golden/DECISIONS_AUTO.md`에 한 줄 |
| `ALL_DONE` | 1~4단계 전부 끝 | 아무것도 하지 않는다 |
| 종료 코드 2 | 지시문 묶음을 읽지 못했다 | 아무것도 하지 않는다. 끝 보고에 거부 문장 그대로 |

## 2. 작업 하나 처리(`RUN`)

1. `runnable`에서 **첫 번째 비-Kiki 작업 하나만** 고른다(`kind`가 `cloud` 또는 `kiki_machine`). 두 개 이상 하지 않는다.
2. **먼저 자리를 잡는다**: `golden/reports_phaseN/<번호>/보고.md`에 제목과 `> **진행 중 — 자동 실행**` 한 줄만 쓰고(`결과:` 줄 없음) 커밋·푸시한 뒤,
   제목 `[자동] <세션 이름>`의 **초안 PR**을 바로 연다. 이 초안 PR이 다음 시간 실행에게 "작업 중"을 알리는 유일한 표시다.
3. 그 작업의 지시문 파일(`file`)을 **처음부터 끝까지 읽고 그 지시문의 공통 규칙·할 일·완료 기준·하지 말 것을 그대로 따른다.**
   지시문이 이 파일보다 구체적이면 지시문을 따른다. 저장소 `CLAUDE.md`도 그대로 적용된다.
4. 세션 제목을 지시문 첫 줄의 세션 이름으로 바꾼다(`set_session_title`).
5. `kind`가 `kiki_machine`이면(할 일에 `(Kiki)` 단계가 있다): 클라우드에서 할 수 있는 부분(도구·런북·보고 초안)까지 하고,
   Kiki 머신 단계는 **런북**(`golden/reports_phaseN/<번호>/런북.md` — CLAUDE.md의 Kiki 블록 규칙 그대로)으로 남긴다.
   보고 맨 위는 `> **진행 중 — Kiki 머신 대기**`로 바꾸고 **`결과:` 줄은 쓰지 않는다**(다음 실행이 "진행 중"으로 읽고 다시 열지 않는다).
6. 완료 기준을 다 채웠으면 보고의 `결과: 완료`, 못 채웠으면 `결과: 일부 완료`와 어디까지인지.
   기준을 **낮추지** 않는다(`golden/AUTONOMY.md` 2절 6번 — 미달이면 미달로 적는다). 기준을 낮추지 않는 계약 변경(이름·형식·순서·도구 선택)은
   기다리지 않는다 — 지시서 원본을 고쳐 진행하고 `golden/DECISIONS_AUTO.md`에 한 줄 적는다.
7. 검사: `python src/backend/golden/check.py`와 `cd src/backend && python -m pytest ../../tests/golden`를 **종료 코드로** 판정한다.
   빨간불이면 고친다. 못 고치면 PR을 초안으로 둔 채 본문에 그대로 적고 끝낸다(자동 머지 안 함).

## 3. PR 마무리 · 자동 머지

- 검사가 초록이면 초안을 **리뷰 준비 상태로 바꾸고 자동 머지를 켠다**(`enable_pr_auto_merge`, SQUASH). 본문은 저장소 PR 템플릿을 따른다.
- 자동 머지를 켜지 않는 경우는 둘뿐이다: **검사 빨강**(고친 뒤 켠다) · **`golden/AUTONOMY.md` 2절의 여섯 가지에 해당**(지우기 · 사람과 법 · 돈과 바깥 계정 · Kiki 머신 · 코딩 헌법 · 기준 낮추기).
  뒤의 경우에만 본문 첫 줄에 "Kiki 확인 필요 — 2절 N번 · 이유"를 쓴다.
- `결과: 일부 완료`인 보고도 머지한다(한 것까지 main에 들어가야 다음 실행이 이어받는다). 지시문이 Kiki 결정·판정을 요구해도
  여섯 가지가 아니면 추천안으로 정하고 `golden/DECISIONS_AUTO.md`에 적은 뒤 머지한다.
- 세션이 끝날 때까지 CI가 끝나지 않아도 된다 — 머지 큐가 처리하고, 다음 시간 실행이 0절에서 결과를 챙긴다.
- main에 직접 푸시 · 강제 푸시 · 다른 세션 브랜치에 푸시하지 않는다.
