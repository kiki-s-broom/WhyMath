# 예약 실행 지시서 — 지시문 하나를 골라 처리하고 PR을 연다

이 파일은 예약 실행(정해진 시간마다 새로 뜨는 클라우드 세션)이 **처음에 읽고 그대로 따르는** 지시서다.
Kiki가 2026-11-23 "github에 올린 지시문을 기반으로 코딩 작업을 자동화"를 지시했고, 수준은 "예약 실행 + PR"(main 머지는 Kiki)로 정했다.

## 0. 한 번에 하나 — 먼저 멈출 이유가 있는지 본다

1. 저장소 `kiki-s-broom/WhyMath`의 **열린 PR 중 제목이 `[자동]`으로 시작하는 것**이 있으면 아무것도 하지 않는다.
   끝 보고에 "대기 — 앞 자동 PR #N 머지 전"이라고만 쓴다(PR은 링크로). 같은 작업을 두 번 여는 것을 막는 유일한 장치다 — 계산기는 PR을 못 본다.
2. main 최신으로 시작한다(세션이 이미 main 기준 클론이다).

## 1. 다음 작업 계산

`cd src/backend && python -m golden.driver.next_task --json` 를 돌리고 **종료 코드로** 판정한다(출력 자르기 금지).

| 판정(`verdict`) | 뜻 | 할 일 |
| --- | --- | --- |
| `RUN` | 열 수 있는 작업이 있다 | 2절 |
| `WAIT_KIKI` | 열 수 있는 것이 사람 작업(H 번호 · `-Kiki`)뿐 | 아무것도 하지 않는다. 끝 보고에 그 작업 번호와 지시문 경로 |
| `ATTENTION` | 진행 중·일부 완료인 작업이 길을 막는다 | 아무것도 하지 않는다. 끝 보고에 `attention` 목록(번호 · 상태 · 결과 줄) |
| `BOUNDARY` | 앞 단계가 끝났고 다음 단계는 시작 조건(게이트 판정)이 있다 | 아무것도 하지 않는다. 끝 보고에 "N단계 시작 조건 확인 필요" |
| `ALL_DONE` | 1~4단계 전부 끝 | 아무것도 하지 않는다 |
| 종료 코드 2 | 지시문 묶음을 읽지 못했다 | 아무것도 하지 않는다. 끝 보고에 거부 문장 그대로 |

## 2. 작업 하나 처리(`RUN`)

- `runnable`에서 **첫 번째 비-Kiki 작업 하나만** 고른다(`kind`가 `cloud` 또는 `kiki_machine`). 두 개 이상 하지 않는다.
- 그 작업의 지시문 파일(`file`)을 **처음부터 끝까지 읽고 그 지시문의 공통 규칙·할 일·완료 기준·하지 말 것을 그대로 따른다.**
  지시문이 이 파일보다 구체적이면 지시문을 따른다. 저장소 `CLAUDE.md`도 그대로 적용된다.
- 세션 제목을 지시문 첫 줄의 세션 이름으로 바꾼다(`set_session_title`).
- `kind`가 `kiki_machine`이면(할 일에 `(Kiki)` 단계가 있다): 클라우드에서 할 수 있는 부분(도구·런북·보고 초안)까지 하고,
  Kiki 머신 단계는 **런북**(`golden/reports_phaseN/<번호>/런북.md` — CLAUDE.md의 Kiki 블록 규칙 그대로)으로 남긴다.
  보고 파일 맨 위에는 `> **진행 중 — Kiki 머신 대기**`를 쓰고 **`결과:` 줄은 쓰지 않는다**
  (그래야 다음 예약 실행이 이 작업을 "진행 중"으로 읽고 다시 열지 않는다).
- 완료 기준을 다 채웠으면 보고의 `결과: 완료`, 못 채웠으면 `결과: 일부 완료`와 어디까지인지. 기준을 낮추거나 바꾸지 않는다 — 바꿔야 하면 계약 변경 제안으로 적고 Kiki 결정을 기다린다.
- 검사: `python src/backend/golden/check.py`와 `cd src/backend && python -m pytest ../../tests/golden`를 **종료 코드로** 판정한다. 빨간불이면 고친다. 못 고치면 PR 본문에 그대로 적는다.

## 3. PR

- 세션에 지정된 작업 브랜치에 커밋·푸시하고 PR을 연다. **제목은 `[자동] <세션 이름>`**, 본문은 저장소 PR 템플릿을 따른다.
- **머지하지 않는다.** main 머지는 Kiki가 한다(auto-merge도 켜지 않는다).
- CI가 빨간불이면 그 세션 안에서 고친다. 고칠 수 없으면 PR 본문 「정직한 공백」에 남긴다.

## 4. 하지 말 것

- 작업 두 개 이상 · Kiki 작업(H 번호) 대신하기 · 게이트 판정 대신하기 · 단계 경계 넘기
- `golden/inbox/`의 지시문 실행(아직 실행 묶음이 아니다 — `golden/inbox/README.md`)
- 시드(`golden/sim/seed/`)·학생/튜터 발화 문장을 PR·보고·채팅에 옮기기(지시문 공통 규칙 그대로)
- main에 직접 푸시 · 강제 푸시 · `constitution/` 수정

## 5. 끝 보고(세션의 마지막 메시지)

한국어 5줄 이내: ①판정(`verdict`) ②처리한 작업 번호(없으면 왜) ③PR 링크 ④Kiki가 할 일(있으면 실행 블록 위치) ⑤검사 결과(종료 코드).
