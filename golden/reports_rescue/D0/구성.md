## 0. 측정 방법 (모든 숫자의 명령)

저장소 루트에서 이 두 함수를 정의하고 `f <경로…>`(파일 수)·`l <경로…>`(줄 수)로 잰다.

```bash
# 파일 수: 추적 파일 중 확장자가 맞는 것의 개수
f() { git -c core.quotePath=false ls-files -z -- "$@" | grep -zE '\.(py|dart|ts|tsx)$' | tr -cd '\0' | wc -c; }
# 줄 수: 같은 파일들을 이어 붙여 wc -l
l() { git -c core.quotePath=false ls-files -z -- "$@" | grep -zE '\.(py|dart|ts|tsx)$' | xargs -0 -r cat | wc -l; }
```

**방법 검증:** 같은 계산을 옛 커밋 `d7466d84`에 돌리면(`git ls-tree -r d7466d84` + `git show d7466d84:<파일> | wc -l`) 지시서 값이 그대로 나온다 — A 10파일·2,124줄 · tests 1,477파일·484,370줄 · 백엔드 844파일·316,469줄. 그러므로 아래 차이는 측정 방법이 아니라 그 뒤 2커밋 때문이다.
