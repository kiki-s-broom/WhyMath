# RS-G3 — 조용한 값 삼키기 AST 게이트 보고

> 판정 기준: 착수 시점 `origin/main` = `64f084fd94a12e80f96123e078cf1544a834f9b5` (2026-11-19).
> 이 문서의 모든 수치는 위 해시의 트리에서 측정했다.
> 태스크: `GOLD-28` (출처 `golden/RUFF_STRICTNESS_DECISION.md` §7 ③ · Kiki 승인 2026-11-18)

## 1. 무엇을 잠그는가

`except` 핸들러가 예외 사실을 **어디에도 남기지 않고**(타입명·`exc_info`·`raise` 없음)
**값도 없이** 넘어가는 자리를 AST로 잠근다.

ruff의 조용한 실패 규칙 네 개(`BLE001`·`S110`·`S112`·`E722`)가 보지 못하는 축이다.

## 2. ① 현행 실측 — 네 규칙은 "무음"을 보지 못한다

### 2-1. 무음 3곳에 네 규칙을 돌린 결과

`RUFF_STRICTNESS_DECISION.md` §5가 지목한 `return None/False` 무음 3곳에
`ruff check --select BLE001,S110,S112,E722`를 돌렸다(CI 고정 `ruff==0.15.22`).

- 결과: **6건 검출 · 전부 `BLE001`(광범위 except)이다. `S110`·`S112`·`E722`는 0건.**
- `BLE001`이 지목하는 것은 "넓은 예외를 잡았다"이지 "삼켰다"가 아니다. 그 규칙의 처방은 예외를 좁히는 것이고,
  **예외를 좁히면 무음은 그대로 남은 채 네 규칙이 전부 조용해진다.**

### 2-2. 좁은 예외 프로브 — 규칙이 0건인데 무음은 남는다

같은 형태를 좁은 예외로 쓴 합성 파일(`except ValueError: return None` · `except (AttributeError, TypeError): return False`)에
네 규칙을 돌리면 **All checks passed · exit 0**이다. 같은 파일을 이 게이트의 `analyze_source`에 넣으면 **위반 2건**이다.

이것이 이 태스크의 존재 이유다 — 네 규칙의 초록불은 무음의 부재를 뜻하지 않는다.

### 2-3. 골든 구역 현재 건수

- 대상 `.py` **25개** · 위반 **5건** · 오탐 후보 **5건**.

## 3. ② 검사 설계

### 3-1. 위반 판정 (둘 다 참일 때만)

1. **신호가 없다** — 핸들러 범위 안(중첩 함수·클래스 안은 제외)에 다음 중 하나도 없다:
   `type(<exc>).__name__` · `exc_info=True` · `.exception(` 호출 · `raise`(재전파).
2. **본문 전부가 값 없이 넘어가는 문장이다** — `pass` · `continue` · `break` · `...` ·
   `return` · `return None` · `return False` · `x = None` · `x = False`.

### 3-2. 경계 — 설계된 강등 vs 무음

- **무음(게이트 대상)**: 아무것도 만들지 않고 넘어간다. 호출자는 "실패했다"와 "원래 그런 값이다"를 구분할 수 없다.
- **설계된 강등(게이트 대상 아님)**: 신호는 없어도 **대체물을 만들어 넘긴다** — `return ""` · `return "OP_00"` ·
  `return fallback()` · `payload = {}` · `result.error = str(exc)`. 호출자가 그 값의 의미를 알 수 있으므로
  무음이 아니라 **선언된 기본값**이다.
- 강등도 **오탐 후보 목록**에 남긴다(게이트는 실패시키지 않는다). 이유: 신호가 없는 강등은
  `CLAUDE.md` 「침묵 실패 금지」와 충돌할 수 있어 사람이 한 번 봐야 한다.

### 3-3. 골든 구역 오탐 후보 5건 (판정)

| 자리 | 형태 | 판정 |
|---|---|---|
| `golden/check.py:440` | `except json.JSONDecodeError: payload = {}` | 강등(빈 payload로 계속). 타입명 미기재 — 개선 후보 |
| `golden/check.py:475` | `except CheckError as exc: print(...); return 3` | 무음 아님(메시지 + 고유 종료코드 3). 타입명 미기재 — 개선 후보 |
| `golden/rescue/ledger.py:305` | `except ValueError as exc: print(...); return 2` | 무음 아님(메시지 + exit 2). 타입명 미기재 — 개선 후보 |
| `golden/sim/seed_extract.py:379` | `except sympy.PolynomialError: return "OP_00"` | 강등(대체 오답 코드) |
| `golden/sim_student.py:256` | `except SimStudentError as exc: result.error = str(exc)` | 강등(예외를 결과 객체에 실어 반환) |

### 3-4. 한계(명시)

- **데이터 흐름 분석이 아니다.** 핸들러 안에 타입명 표현이 있는지만 본다.
- 핸들러가 다른 함수로 위임하면(`_handle(exc)`) 신호를 볼 수 없어 오탐 후보로 나온다.
- 핸들러 본문에 함수 정의만 있으면(`def inner(): ...`) 위반이 아니라 오탐 후보로 분류한다 —
  정의 자체는 아무 값도 만들지 않지만, 이 게이트는 **확실한 무음만** 잠그는 쪽을 택했다.
- 옛 구역 수치는 **후보 건수**이지 결함 건수다. 좁은 예외·의도된 강등이 섞여 있다.

## 5. ④ 주입 — 보호 장치가 실제로 막는지

`cp` 백업 → 주입 → 실행 → `cp` 복원(바이트 동일 sha256 확인) 순서로 5회 확인했다.
