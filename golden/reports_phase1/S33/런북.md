## 지시서와 다르게 한 것 (자동 결정 · `golden/DECISIONS_AUTO.md`)

- **새 데이터베이스에서 돈다.** 시연용 Postgres(`whymath-demo-db`) 안에 `whymath_s33_<UTC 시각>` 데이터베이스를 **새로 만들어** 그곳에서 실행한다.
  - 러너 닉네임은 `sim-P2-1`처럼 고정이다. 같은 DB를 다시 쓰면 이전 실행(S28 등)의 숙련도를 이어받는다.
  - 클라우드 시험에서는 출발점이 이미 1.00이라 궤적이 처음부터 평평했다.
  - 새 데이터베이스는 만들기만 하고 아무것도 지우지 않는다. 기존 `whymath` 데이터베이스는 그대로다.
- **날짜 꼬리표 대신 폴더를 나눈다.** 지시서는 `--date <날짜>-s33`이지만, 러너의 `--date`는 `YYYY-MM-DD`만 받는다. 그래서 결과 폴더를 `--out-dir …\sim-s33\out`으로 지정한다(S28과 같은 처리).
- **세션 수 120:** `--sessions 120 --personas P2,P3,P4,P5`로 돌리면 4종 × 1회차 × 30문항이 된다(`make_plan`). 필요한 것은 그중 LF-01~05 20건이다.
  - 나머지 100건은 궤적 검산(각 페르소나 30문항의 사슬)과 M1~M5 숫자에만 쓴다.
- **플래그는 전부 끈다.** `GOLDEN_T1_RUBRIC`·`GOLDEN_T2_MISCONCEPTION`·`GOLDEN_MASTERY_ENGINE`을 설정하지 않는다.
  - T2는 S30 판정으로 되돌렸다.
  - 숙련도 플래그는 S32 런북대로 기본 simple이다. 섀도 표에는 플래그와 무관하게 두 엔진이 다 쌓인다.

## 사전 브리핑 (6항목)

1. **과제 명칭**: S33 — AI 학생 3차. P2·P3·P4·P5 × 30문항을 실제 LLM으로 120세션 돌린다. 그 결과에서 LF-01~05 20건 대화와 simple·bkt 궤적 표를 세션에 넘긴다.
2. **목적**: 지시서 S33은 같은 세션에서 두 숙련도 엔진의 궤적을 나란히 쌓고, 20건을 세션이 손으로 읽게 한다. 이로써 AI 대체 누적은 15+15+20 = 50건이 된다. 결과는 S34(T3 판정)의 근거다.
3. **구체적 절차**
   - 블록 A(약 30초): 작업 폴더 `WhyMath-cal`을 이 브랜치에 맞추고 점검한다(`STAGE=run`).
   - 블록 S(약 10~60초): 시연용 Postgres(`whymath-demo-db` · 55432)를 켠다.
   - 블록 R(**약 30~50분**): 새 데이터베이스 생성 → 표 생성 → 실행 전 출발점 기록(숫자 4줄) → 120세션 실행. 튜터는 OpenRouter, 학생은 로컬 Ollama `qwen2.5:7b`다. PC가 잠들지 않게 한다.
   - 블록 X(약 20초): 섀도 표에서 이번 실행 행만 뽑는다 → 추출기가 20건을 고르고 궤적을 검산한다 → 통과하면 클립보드에 넣는다.
4. **성공 기준**
   - 블록 A: `READY=True`, `STAGE=run`.
   - 블록 S: `DB_READY=True`.
   - 블록 R: `RUN COMPLETE=True`(`SIM_DONE_LINES=1` · `JSONL_LINES`+`SKIPPED`=120 · `SIM_EXIT` 0 또는 1). `SIM_EXIT=1`은 차단 메트릭 위반 측정일 수 있어 정상 종료로 친다.
   - 블록 X: `S33_CHECK ok=True picked=20 traj=20 chain_mismatch=0`과 `CLIPBOARD=True`. 그다음 이 세션 대화창에 **Ctrl+V로 붙여넣어 보낸다**(설명 없이 붙여넣기만 해도 된다).
   - 실패 시 대처: 각 블록의 `…=False` 줄이 무엇이 틀렸는지 말한다. 그 줄만 세션에 보낸다. 블록 X가 `ok=False`면 `S33_CHECK`·`S33_NUM` 두 줄만 보낸다.
5. **실행 환경**: Phaiakes9(이 PC) · Windows PowerShell.
   - 공유 작업 사본 `C:\Users\kiki\Desktop\__AI\WhyMath`: 읽기만 한다. `.venv`·시드·compose 파일을 빌려 쓴다.
   - 작업 폴더 `C:\Users\kiki\Desktop\__AI\WhyMath-cal`: S20·S23·S28 때 만든 것을 재사용한다.
   - 결과 폴더 `C:\Users\kiki\Desktop\__AI\sim-s33`.
   - 선행 조건: Docker Desktop 가동 · Ollama 앱 가동 · `WHYMATH_OPENROUTER_API_KEY` 사용자 환경변수(S28과 같은 것) · S16 시드 파일.
6. **창 구분**: **새 PowerShell 창 하나(창 A)**에서 블록 A → S → R → X를 차례로 붙여넣는다.
   - A·S·R은 앞 블록의 변수를 쓰므로 같은 창이어야 한다. 블록 X는 혼자서도 돈다(새 창도 된다).
   - 블록 R이 도는 30~50분 동안 **이 창은 건드리지 않는다**(Ctrl+C는 복사가 아니라 중단이다). 다른 작업은 다른 창에서 한다.
   - 각 블록의 판정 줄을 눈으로 본 다음에 다음 블록을 붙여넣는다. 쓰기 블록(R)은 앞 조건이 틀리면 스스로 거부한다.

## 블록 R — 새 데이터베이스 + 120세션 (창 A · 약 30~50분 · 이 창은 건드리지 않는다)

```powershell

$Date = Get-Date -Format "yyyy-MM-dd"
$OutDir = "$S33Dir\out"
$SimLog = "$S33Dir\sim.txt"
$Complete = $false
$RunOk = $Ready -and $DbReady -and ($Stage -eq "run")
if ($RunOk) {
New-Item -ItemType Directory -Force -Path $OutDir | Out-Null
$DbName = "whymath_s33_" + (Get-Date).ToUniversalTime().ToString("yyyyMMddHHmm")
docker exec whymath-demo-db createdb -U whymath $DbName
$DbCreated = ($LASTEXITCODE -eq 0)
Set-Content -Path "$S33Dir\db_name.txt" -Value $DbName -Encoding ASCII
$env:WHYMATH_DATABASE_URL = "postgresql+asyncpg://whymath@127.0.0.1:55432/" + $DbName + "?ssl=disable"
Remove-Item Env:GOLDEN_FAKE_LLM, Env:GOLDEN_T1_RUBRIC, Env:GOLDEN_T2_MISCONCEPTION, Env:GOLDEN_MASTERY_ENGINE, Env:SIM_FULL -ErrorAction SilentlyContinue

$PreLines = 0

ollama run $Model "hi" 2>&1 | Out-Null

} else { Write-Host "RUN_REFUSED=True — READY=$Ready DB_READY=$DbReady STAGE=$Stage (블록 A·S 판정 줄 확인 · STAGE=extract면 블록 X로)" }
```

- 클립보드 글(`%TEMP%\s33_20.txt`)에는 세 가지가 들어 있다: 고른 20건의 학생·튜터 발화, 숫자 줄(`S33_NUM` · M1~M5), 궤적 줄(`TRAJ_START`·`TRAJ` — 페르소나·문항·판정·simple·bkt). 붙여넣은 뒤 그 파일은 지워도 된다(`Remove-Item $env:TEMP\s33_20.txt`).
- 시드를 베낀 학생 발화는 S24·S29 추출기와 같은 검사로 `[시드 일치 — 가림]`으로 바꾸고 건수(`masked=`)를 낸다(공통 규칙 7).
- **궤적 검산**: 페르소나마다 1회차 30문항의 판정 순서대로 두 엔진을 다시 계산해 섀도 값과 맞춘다. 실행 때 api가 쓴 규칙과 같다(simple +0.10/−0.05 잘라내기·반올림 · `golden.mastery.bkt.update`).
  - 출발점은 블록 R이 기록한 `pre.csv`다. 새 데이터베이스라 simple 0.00 · bkt 0.2(P(L0))여야 한다.
  - 한 칸이라도 다르면 `chain_mismatch`가 0보다 커지고 거부된다.
- 새 데이터베이스 `whymath_s33_…`는 시연용 컨테이너 안에 남는다. 지우지 않는다. 시연용 컨테이너를 내리면 함께 사라진다(원래 일회용).
- 한 번이 정본이다. 블록 A는 `sim-s33\out\run_meta.json`이 이미 있으면 `STAGE=extract`로 실행을 건너뛴다(같은 설정을 다시 돌려 숫자를 고르지 않는다). 블록 X는 몇 번 다시 돌려도 된다(읽기 전용).
- 블록 R이 중간에 멈췄으면(`COMPLETE=False`) `sim-s33\out\run_meta.json`이 없을 때만 블록 A부터 다시 할 수 있다. 다시 하면 새 데이터베이스를 하나 더 만든다(앞 것은 지우지 않는다). `run_meta.json`이 생긴 뒤에 멈췄으면 그 줄을 세션에 알린다.
