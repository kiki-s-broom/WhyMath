## 사전 브리핑 (6항목)

1. **과제 명칭**: S23 1부 — 튜터 프롬프트 개정 **전** 720세션(30문항 × 페르소나 8 × 3회)을 실제 LLM으로 돌리고, T1 평가기 집계를 낸다.
2. **목적**: 개정 전 숫자가 기준선이다. 세션은 이 집계의 상위 실패 유형 3개를 보고 프롬프트를 **한 문장** 고친다. 개정 후 같은 720세션을 다시 돌려 M1(답 유출)·M3(판정 오류)가 나빠지지 않았는지, M2(턴 수)가 어떻게 바뀌었는지 숫자로 본다(지시서 S23).
3. **구체적 절차**
   - 블록 A(약 30초): 작업 폴더 `WhyMath-cal`을 S23 브랜치에 맞추고 점검한다. 프롬프트가 개정 전 그대로인지(`STAGE=before`) 확인한다.
   - 블록 S(약 10~60초): 시연용 Postgres(`whymath-demo-db` · 55432)를 켠다.
   - 블록 R(**약 3~5시간** · 120세션에 30~50분 걸렸으므로 그 6배): 실제 LLM으로 720세션. 튜터 OpenRouter · 학생 로컬 Ollama `qwen2.5:7b` · T1 평가기 켬(`GOLDEN_T1_RUBRIC=1`). PC가 잠들지 않게 한다(전원 설정 → 절전 안 함).
   - 블록 M(약 1분): T1 집계를 내고 숫자 파일 3개를 `golden/reports_phase1/S23/before/`에 복사해 커밋·푸시한다.
4. **성공 기준**
   - 블록 A: `READY=True`, `STAGE=before`.
   - 블록 S: `DB_READY=True`.
   - 블록 R: `RUN_COMPLETE=True`(= `SIM_DONE_LINES=1`·`JSONL_LINES=720`·`SIM_EXIT` 0 또는 1). `SIM_EXIT=1`은 차단 메트릭 위반 측정일 수 있어 정상 종료로 친다 — 숫자는 세션이 읽는다. `RUN_COMPLETE=False`면 블록이 로그 끝 5줄을 찍으니 그대로 세션에 알린다.
   - 블록 M: `T1_SUMMARY run=before … sessions=720 …` 한 줄 · `SUM_EXIT=0` · `PUSH_EXIT=0`.
5. **실행 환경**: Phaiakes9(이 PC) · Windows PowerShell · 공유 작업 사본 `C:\Users\kiki\Desktop\__AI\WhyMath`(읽기만 — `.venv`·시드·compose 파일을 빌려 쓴다) · 작업 폴더 `C:\Users\kiki\Desktop\__AI\WhyMath-cal`(S20 때 만든 것 재사용) · 결과 `C:\Users\kiki\Desktop\__AI\sim-s23`. 선행 조건: Docker Desktop 가동 · Ollama 앱 가동 · `WHYMATH_OPENROUTER_API_KEY` 사용자 환경변수(S19·S20과 같은 것) · S16 시드 파일.
6. **창 구분**: **새 PowerShell 창 하나(창 A)**에서 블록 A → S → R → M을 차례로 붙여넣는다. 앞 블록의 변수를 뒤 블록이 쓰므로 같은 창이어야 한다. 블록 R이 도는 3~5시간 동안 **이 창은 건드리지 않는다**(Ctrl+C는 복사가 아니라 중단이다). 다른 작업은 다른 창에서 한다. 각 블록의 판정 줄을 눈으로 본 다음에 다음 블록을 붙여넣는다 — 쓰기 블록(R·M)은 앞 조건이 틀리면 스스로 거부한다.

## 블록 R — 개정 전 720세션 (창 A · 약 3~5시간 · 이 창은 건드리지 않는다)

```powershell
# [창 A · 블록 R — S23 개정 전 720세션] Windows PowerShell — READY·DB_READY가 True이고 STAGE=before일 때만 30문항 × 8 페르소나 × 3회를 실제 LLM으로 1회 실행(T1 평가기 켬 · 출력은 cmd로 파일에 바로 씀)
$Date = Get-Date -Format "yyyy-MM-dd"
```

## 블록 M — T1 집계 + 숫자 파일 3개 커밋·푸시 (창 A · 약 1분)

```powershell

$SumLog = "$S23Dir\$Stage.summary.txt"

if ($RunComplete -and ($Stage -eq "before")) { Set-Location "$Wt\src\backend"; cmd /c "$Py -m golden.sim.t1_summary summarize --run-dir $OutDir --out $OutDir\t1_summary.json > $SumLog 2>&1"; $SumExit = $LASTEXITCODE; Get-Content -Path $SumLog -Encoding UTF8 } else { Write-Host "WRITE_REFUSED=True — RUN_COMPLETE=$RunComplete STAGE=$Stage (블록 R 판정 줄 확인)" }
Write-Host "SUM_EXIT=$SumExit  (0 = 집계 완료 · 2 = 바로 위 T1_SUMMARY_REFUSED가 이유)"
if ($SumExit -eq 0) { New-Item -ItemType Directory -Force -Path $Dest | Out-Null; Copy-Item -Path "$OutDir\sim_report.json", "$OutDir\run_meta.json", "$OutDir\t1_summary.json" -Destination $Dest -Force; git -C $Wt add "golden/reports_phase1/S23/$Stage"; git -C $Wt commit -q -m "S23: Kiki machine 720 $Stage (F-01)"; if ($LASTEXITCODE -eq 0) { git -C $Wt push origin "HEAD:$Branch"; $PushExit = $LASTEXITCODE } else { Write-Host "COMMIT_FAILED=True — git 사용자 이름·메일이 없거나 바뀐 파일이 없다(세션에 알리기)" } } else { Write-Host "PUSH_SKIPPED — SUM_EXIT=$SumExit" }
Write-Host "PUSH_EXIT=$PushExit  (0이면 성공 — 세션에 '푸시했다'고만 알리면 세션이 숫자를 읽고 프롬프트를 개정한다)"
git -C $Wt log -1 --oneline
Set-Location $Root
```

## 끝난 뒤

- 세션에는 "블록 M까지 `PUSH_EXIT=0`"이라고만 알린다. 숫자는 세션이 브랜치에서 직접 읽는다. 학생·튜터 문장은 채팅에 붙이지 않는다.
- 세션이 개정 1문장을 커밋하고 이 런북에 **2부(개정 후 실행)**를 덧붙인다. 2부는 같은 창 구성으로 블록 A2 → S → R2 → M2이고, 마지막에 전후 표를 만든다.
- 개정 전 실행은 한 번이 정본이다. 블록 A는 `before/t1_summary.json`이 이미 있으면 `STAGE=none`으로 거부한다(같은 설정을 다시 돌려 숫자를 고르지 않는다).
