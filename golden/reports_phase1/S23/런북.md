## 끝난 뒤

- 세션에는 "블록 M까지 `PUSH_EXIT=0`"이라고만 알린다. 숫자는 세션이 브랜치에서 직접 읽는다. 학생·튜터 문장은 채팅에 붙이지 않는다.
- 세션이 개정 1문장을 커밋하고 이 런북에 **2부(개정 후 실행)**를 덧붙인다. 2부는 같은 창 구성으로 블록 A2 → S → R2 → M2이고, 마지막에 전후 표를 만든다.
- **`PUSH_EXIT`가 0이 아니면 블록 A를 다시 돌리지 않는다.** 블록 A는 작업 폴더를 원격 커밋으로 되돌리므로 방금 만든 로컬 커밋이 가리키는 곳 없이 남고, 개정 전 실행이 끝났다는 표시도 사라진다. 그 줄을 세션에 알리면 세션이 푸시만 다시 하는 블록을 준다. 숫자 파일은 `C:\Users\kiki\Desktop\__AI\sim-s23\out\before\`에 그대로 있다.
- 개정 전 실행은 한 번이 정본이다. 블록 A는 `before/t1_summary.json`이 이미 있으면 `STAGE=none`으로 거부한다(같은 설정을 다시 돌려 숫자를 고르지 않는다).

   - 블록 M2: `T1_SUMMARY run=after …` 한 줄 · `SUM_EXIT=0` · 전후 표와 `T1_COMPARE m1_m3_kept=…` 한 줄 · `CMP_EXIT=0` · `PUSH_EXIT=0`. `m1_m3_kept=False`도 정상 결과다(개정을 되돌릴지는 세션이 정한다).
   - 실패 시 대처: `READY=False`면 그 줄의 항목 이름을 세션에 알린다. `CMP_EXIT=2`면 바로 위 `T1_SUMMARY_REFUSED` 줄을 알린다.
5. **실행 환경**: 1부와 같다 — Phaiakes9 · Windows PowerShell · 공유 작업 사본 `C:\Users\kiki\Desktop\__AI\WhyMath`(읽기만) · 작업 폴더 `C:\Users\kiki\Desktop\__AI\WhyMath-cal` · 결과 `C:\Users\kiki\Desktop\__AI\sim-s23`. 선행 조건: Docker Desktop · Ollama 앱 · OpenRouter 키 · S16 시드.
6. **창 구분**: **새 PowerShell 창 하나(창 B)**에서 블록 A2 → S → R2 → M2를 차례로 붙여넣는다(1부 창 A는 닫아도 된다 — 2부는 1부 변수를 쓰지 않는다). 블록 R2가 도는 동안 **이 창은 건드리지 않는다**(Ctrl+C는 중단이다). 각 블록의 판정 줄을 본 다음에 다음 블록을 붙여넣는다 — 쓰기 블록(R2·M2)은 앞 조건이 틀리면 스스로 거부한다.

## 2부 끝난 뒤

- 세션에는 "블록 M2까지 `PUSH_EXIT=0`"과 `ERR run=…` 줄들(크래시 M4의 페르소나·회차·문항·오류 종류 이름 — 문장 없음)을 알린다. 전후 표는 세션이 브랜치에서 읽는다. 학생·튜터 문장과 `errors.jsonl`의 `detail`은 채팅에 붙이지 않는다.
- `m1_m3_kept=False`면 세션이 개정 커밋을 되돌리는 커밋을 올린다(Kiki 머신에서 할 일 없음). 두 번째 개정은 하지 않는다.
- **`PUSH_EXIT`가 0이 아니면 블록 A2를 다시 돌리지 않는다**(1부와 같은 이유 — 로컬 커밋이 가리키는 곳 없이 남는다). 그 줄을 세션에 알리면 푸시만 다시 하는 블록을 준다. 숫자 파일은 `C:\Users\kiki\Desktop\__AI\sim-s23\out\after\`에 그대로 있다.
- 개정 후 실행도 한 번이 정본이다. 블록 A2는 `after/t1_summary.json`이 이미 있으면 `STAGE=none`으로 거부한다.
