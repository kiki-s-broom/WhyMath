# WhyMath 4단계 「파일럿」 — 작업 지시서 (AI 실행용 · 8주)

작업 번호를 받은 AI는 이 문서의 공통 규칙·용어·공유 계약과 해당 번호의 지시만 읽고 작업한다. 지시에 없는 값은 추정하지 않고 "미확인"으로 보고한다. 원본 계획서는 `plan_phase4_pilot_8weeks.docx`(Kiki 보관 원본 · 저장소 미포함 — office·PDF 문서는 `.gitignore`와 `scripts/ops/check_source_document_binaries.py`가 커밋을 막는다 · 저장소 안 정본은 이 지시서)(2026-11-15 · Kiki)이고, 골든 패스(S1~S15) → 1단계(S16~S35) → 2단계(S36~S55) → 3단계(S56~S75)의 후속이다. 세션 번호는 S76부터 S105까지 30회. **시작 조건: 3단계 S75 게이트 첫 줄(네 번째 단원 추가 코드 0줄)이 "예"**다. 아니면 이 묶음을 열지 않는다. 2027-03-08(월)~04-30(금) 8주 — 준비 2주(S76~S85 매일) · 운영 5주(S86~S100 월·수·금) · 마감 1주(S101~S105 매일).

이 단계가 답하는 질문은 둘이다. **(1) 학생이 시키지 않아도 계속 쓰는가 — 4주 리텐션 40%. (2) 쓴 만큼 실력이 오르는가 — 사전·사후 상승이 보이고 더 쓴 학생이 더 오른다.** 앞선 네 단계가 "만들 수 있나"를 물었다면 이 단계는 처음으로 "쓸 만한가"를 학생 20~30명에게 묻는다. 서버는 처음으로 Kiki가 잠든 시간에도 돌아야 하고, 학생은 처음으로 Kiki가 옆에 없는 곳에서 앱을 켠다.

**2026-11-17 Kiki 결정으로 이 단계는 실제 학생 없이 AI 코호트로 진행한다.** 위 두 질문은 "미실시"가 되고, 이 단계는 "실제 학생을 받을 준비가 됐는가"를 답하는 **운영 리허설**이 된다. 읽는 법은 공유 계약 「실학생 대체 결정」 블록이 정하며, 그 블록이 아래의 "학생"·"보호자" 문구보다 우선한다.

### S103. 상승 분석 — 사전·사후 쌍체 검정 · d · CI · 사용량–상승 상관 · 단원별

- **읽는 법(실학생 대체 결정):** AI 학생은 실력이 오르지 않는다. 이 세션은 `uplift.py`가 실제 모양의 데이터에서 끝까지 도는지 보는 **파이프라인 검증**이다. `out/uplift.json` 첫 필드에 `"source": "ai_cohort"`와 `"interpretation": "파이프라인 검증 — 상승 측정 아님"`을 넣고, p·d·ρ가 무엇으로 나오든 보고에 "상승했다"·"상관이 있다"·"효과가 없다"고 쓰지 않는다. 추가 검증 1개: 사전·사후 점수를 손으로 만든 픽스처(알려진 차이·알려진 상관)에 `uplift.py`를 돌려 기대값이 나오는지 테스트로 고정한다 — 개방 시점에 이 코드를 믿고 쓸 근거다.
- **선행 산출물:** S101. S102와 동시.
- **할 일:** ①`pyproject.toml`에 `pilot-analysis` extra(`scipy`) — `golden/` 밖 변경 이유 명시 ②`analysis/uplift.py`: 사전·사후 쌍(사후 미응시 제외 · n 명시) → 정규성(Shapiro) → 쌍체 t 또는 윌콕슨 → Cohen's d + 95% CI(부트스트랩 제안값) ③스피어만 ρ(세션 수 또는 문항 수 vs 차이) ④단원별 차이 표 ⑤의심 세션 제외 전후 ⑥`out/uplift.json`. n이 작으면 "이 n으로는 모른다"를 결과 파일에도 적는다.
- **완료 기준:** out/uplift.json(검정명·p·d·CI·ρ·n) · 단원별 표 · 민감도 분석 · 손 계산 0.
- **하지 말 것:** 유의하지 않은 결과를 "거의 유의"로 쓰지 않는다. 대조군이 없다는 한계를 숫자 옆에 적는다.
