# S7 에뮬레이터 확인 런북 (Kiki 머신 · 1회 · 약 15분)

S7 세션(클라우드)에는 안드로이드 에뮬레이터가 없다. 그래서 같은 Dart 코드를 **Flutter 웹 빌드와 헤드리스 크롬(휴대폰 크기)** 으로 실제 서버에 붙여 확인했다. 이 폴더의 캡처 5장이 그 결과다. 지시서 할 일 6의 "실기기/에뮬레이터에서 결과 화면 캡처"만 이 런북으로 Kiki 머신에서 한 번 한다. S6 때 성공한 방식을 그대로 쓴다: 에뮬레이터 `Pixel_7_Pro` + 서버 주소 `10.0.2.2:8000`.

## 6항목 브리핑

1. **과제 명칭**: 골든 앱 S7 화면(결과·다음 문제) 에뮬레이터 1회 확인
2. **목적**: 안드로이드 에뮬레이터에서 아래 세 가지를 본다. 결과는 S7 보고의 결과를 "일부 완료"에서 "완료"로 바꾸는 근거가 된다.
   - 정답·오답 판정 뒤 결과 화면에 맞음/틀림·숙련도·바뀐 양이 보이는가
   - "다음 문제"가 다른 문제를 띄우는가
   - 앱을 다시 켠 뒤 같은 닉네임으로 들어가면 숙련도가 유지되는가
3. **구체적 절차**
   - 창 A: 골든 서버를 띄운다. 가짜 LLM 모드라 키가 필요 없고, 튜터는 고정 문장과 힌트를 돌려준다. 1~2분 걸린다.
   - 창 B: 에뮬레이터를 켜고 골든 앱을 실행한다. 첫 빌드는 3~6분 걸린다.
   - 앱 조작은 아래 순서로 한다.
     1. 닉네임 `self-s7-check`를 입력하고 시작한다.
     2. 첫 문제에 정답을 보낸다. 같은 닉네임을 처음 쓰면 LF-01이 나오고 정답은 `-12`다.
     3. 결과 화면이 나오면 **캡처 1**을 한다.
     4. "다음 문제"를 누른다. 다른 문제가 보이고 대화가 비어 있는지 본다.
     5. 아무 오답이나 4번 보낸다(예: `0`, `0`, `0`, `0`). 튜터가 3번 되묻고 4번째에 판정이 나온다.
     6. 결과 화면이 나오면 **캡처 2**를 한다.
     7. 창 B에서 `q`를 눌러 앱을 끈다. 맨 아래 "재시작" 블록으로 앱을 다시 실행한다.
     8. 같은 닉네임 `self-s7-check`로 시작해 위쪽 숙련도를 본다. **캡처 3**을 한다.
4. **성공 기준**
   - 캡처 1: 초록 체크 아이콘, "맞음", "숙련도 0.xx" 아래 "(+0.10)"이 보인다.
   - 캡처 2: 주황 전구 아이콘, "틀림", "(−0.05)", "튜터와 주고받은 횟수: 3번"이 보인다.
   - 4단계: 문제 화면 위쪽 작은 줄이 "LF-02 · 2/30"처럼 바뀌어 있다.
   - 캡처 3: 위쪽 숙련도가 캡처 2의 숙련도와 같다.
   - 화면 맨 위에 빨간 띠("서버에 연결할 수 없어요…")가 **없다**. 빨간 띠가 보이면 실패다. 먼저 창 A의 서버가 살아 있는지 본다.
5. **실행 환경**
   - Phaiakes9(이 PC)의 Windows PowerShell 창 2개를 쓴다.
   - 작업 디렉터리는 `C:\Users\kiki\Desktop\__AI\WhyMath`다.
   - 선행 조건: S7 PR이 main에 머지돼 있다. Docker Desktop이 실행 중이다(`whymath-pg` 5433). 안드로이드 AVD `Pixel_7_Pro`가 있다(S6 때 쓴 것).
6. **창 구분**
   - 창 A = **새 창, 서버 전용**이다. 마지막 명령을 실행한 뒤에는 이 창을 건드리지 않는다. Ctrl+C는 복사가 아니라 서버 중단이다.
   - 창 B = 새 창이며, 에뮬레이터와 앱 실행에 쓴다.

여러 세션이 함께 쓰는 공유 작업 사본을 건드리지 않도록 **별도 워크트리**에서 실행한다. 확인이 끝나면 맨 아래 정리 블록으로 지운다.

## 창 A — 서버 전용 (새 창)

```powershell
# [창 A · 서버 전용] Windows PowerShell — 이 블록 실행 후 이 창은 조작 금지(Ctrl+C = 서버 중단)
cd C:\Users\kiki\Desktop\__AI\WhyMath
git fetch origin main
git worktree add --detach C:\Users\kiki\Desktop\__AI\WhyMath-s7check origin/main
cd C:\Users\kiki\Desktop\__AI\WhyMath-s7check
$S7Ready = (Test-Path src\mobile\lib\golden\result_screen.dart) -and (Test-Path src\backend\golden\api.py)
Write-Host ("S7_FILES_PRESENT=" + $S7Ready)
docker start whymath-pg
$env:WHYMATH_DATABASE_URL = "postgresql+asyncpg://whymath@127.0.0.1:5433/whymath"
$env:GOLDEN_FAKE_LLM = "1"
cd src\backend
if ($S7Ready) { C:\Users\kiki\Desktop\__AI\WhyMath\src\backend\.venv\Scripts\python.exe -m uvicorn golden.api:app --host 0.0.0.0 --port 8000 } else { Write-Host "RUN_REFUSED=True — S7 PR이 아직 main에 없다. 머지 뒤 다시 실행" }
```

자가검증
- 성공: `S7_FILES_PRESENT=True`가 보이고, 마지막에 `Uvicorn running on http://0.0.0.0:8000`이 보인다.
- `RUN_REFUSED=True`가 보이면 S7 PR이 아직 main에 머지되지 않은 것이다. 서버는 뜨지 않는다.

## 창 B — 에뮬레이터 + 앱 실행 (새 창)

```powershell
# [창 B · 앱] Windows PowerShell — 에뮬레이터를 켜고 기기가 잡힐 때까지 기다린 뒤 앱을 실행한다
cd C:\Users\kiki\Desktop\__AI\WhyMath-s7check\src\mobile
$Health = try { (Invoke-WebRequest -UseBasicParsing -Method Post -ContentType 'application/json' -Body '{"nickname":"self-s7-ping"}' "http://127.0.0.1:8000/golden/session").StatusCode } catch { "FAIL" }
Write-Host ("SERVER_REACHABLE=" + $Health)
flutter emulators --launch Pixel_7_Pro
$Emu = $null; foreach ($i in 1..24) { $Emu = (flutter devices) | Select-String "emulator-"; if ($Emu) { break }; Start-Sleep -Seconds 5 }
Write-Host ("EMULATOR_READY=" + [bool]$Emu)
if (($Health -eq 200) -and $Emu) { flutter pub get --enforce-lockfile; dart run build_runner build --delete-conflicting-outputs; flutter run -t lib/main_golden.dart --dart-define=API_URL=http://10.0.2.2:8000 } else { Write-Host "RUN_REFUSED=True — SERVER_REACHABLE이 200이 아니면 창 A를, EMULATOR_READY가 False면 Android Studio의 Device Manager에서 Pixel_7_Pro를 직접 켠 뒤 이 블록을 다시 붙여넣기" }
```

자가검증
- `SERVER_REACHABLE=200`과 `EMULATOR_READY=True`가 보인 뒤 빌드가 시작된다.
- `RUN_REFUSED=True`면 앱은 실행되지 않는다. 출력된 이유를 먼저 해결한다.
- 서버 주소 `10.0.2.2`는 에뮬레이터 안에서 이 PC를 가리키는 고정 주소다.
