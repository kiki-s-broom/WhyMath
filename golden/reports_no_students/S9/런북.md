# S9 본인 학생 역할 런북 (Kiki 머신 · 1회 · 약 40분)

Kiki가 닉네임 `self-1`로 **학생 역할 규칙 4개**를 지키며 문제 5개(LF-01~LF-05)를 풀고, 관찰 기록과 서버 대화 기록(`self1_turns.csv`)을 남기는 절차다. 끝나면 두 파일 내용을 S9 AI 세션에 붙여 넣는다. 세션은 그것을 읽고 `golden/reports_no_students/S9/보고.md`를 쓴다.

S8 런북의 방식을 그대로 잇는다. 별도 워크트리를 쓰고, 창 A(서버)와 창 B(앱)를 나누며, 자가검증이 통과한 뒤에만 실행한다. S8과 다른 점은 다섯 가지다.
- **실제 LLM이 필수**다. S9의 핵심 측정값이 되묻기 품질(GP-4)이라서, 가짜 튜터면 서버를 띄우지 않는다.
- **풀이식=답 채점 동작을 앱 실행 전에 검사**한다. Kiki 결정(2026-11-10)은 "`-3+4=1`을 정답으로 채점"이고 S8 세션(GOLD-08)이 구현 중이다. 창 B가 떠 있는 서버에 실제로 답을 보내 보고, 반영되지 않았으면 앱을 띄우지 않는다.
- 닉네임 `self-1`이 DB에 이미 있으면 앱을 띄우지 않는다. 기록이 섞이는 것을 막기 위해서다.
- 기록 파일은 워크트리가 아니라 **공유 작업 사본의 `golden\logs\`**에 둔다. 워크트리는 정리할 때 지워지기 때문이다.
- **CSV를 뽑기 전에는 정리 블록이 DB를 지우지 않는다.** 시연 DB는 볼륨이 없어 `down`하면 기록이 사라진다.

## 6항목 브리핑

1. **과제 명칭**: 골든 앱 S9 본인 학생 역할 — `self-1`로 모르는 척 5문제
2. **목적**: 첫 실사용 로그를 만든다. 답을 아는 사람이 풀면 끊김이 안 보이므로, 역할 규칙으로 일부러 서툴게 푼다. 그래야 튜터 되묻기(GP-4)가 실제로 몇 번 돌고 그 품질을 1~5점으로 매길 수 있다. 결과는 S9 보고(문제별 표·끊긴 지점 후보 3개·본인 피험자 한계)가 되고, S10이 S11(AI 시뮬레이션 학생)의 로그와 함께 고친다.
3. **구체적 절차**(총 약 40분)
   - 창 A(서버 전용 · 3~5분): 워크트리 만들기 → 자가검증 5개 → 시연 DB → 골든 서버(실제 LLM). 이 창은 그 뒤 건드리지 않는다.
   - 창 B 준비(1분): "0. 기록 파일 준비" 블록이 `golden\logs\<오늘 날짜>_self1.md`를 만들고 메모장으로 연다.
   - 창 B 앱(첫 빌드 3~6분): 안드로이드 폰(포코 X3 NFC) · 패드 · 에뮬레이터 중 하나에 골든 앱을 실행한다. 폰은 USB 역방향 연결(`adb reverse`)로 서버에 붙는다.
   - 학생 역할 풀이(약 20분): 아래 "역할 규칙 4개"와 "문제별 계획표"대로 LF-01~LF-05를 푼다. 한 문제가 끝날 때마다 메모장에 그 줄을 채운다(점수 포함).

## 역할 규칙 4개 (지시서 그대로 · 풀이 내내 지킨다)

1. **첫 입력은 항상 질문이나 오답이다.** 예: "x가 뭐예요?", 부호를 틀린 답.
2. **튜터 되묻기에는 중2가 쓸 법한 짧은 문장(10자 안팎)으로만 답한다.** 예: "5 넣어요?", "곱하기요?", "-15요". 긴 설명은 쓰지 않는다.
3. **5문제 중 2문제(LF-03·LF-05)는 끝까지 틀린다.** 오답 4번을 보내 튜터 턴 3회를 다 쓰면 결과 화면이 나온다. 지시서의 "3문제 중 1문제"를 5문제에 맞춘 비율이다.
4. **맞는 답은 2번째 또는 3번째 입력에만 낸다.** 첫 입력에 정답을 내면 그 문제의 GP-4 기록이 0건이 된다. 지시서 '하지 말 것'이다.

매 문제가 끝나면 메모장의 그 줄에 **되묻기 점수(1~5)**를 적는다. 질문은 "튜터 되묻기가 실제로 나를 다음 생각으로 이끌었는가"이고, 기준은 기록 파일 표 아래에 있다. **막힌 척한 지점**도 적는다(예: "x에 값 넣기", "음수 곱셈").

하지 말 것: 세션 중 코드를 고치지 않는다. 앱이 이상해도 고치지 말고 시각과 함께 메모한다.

막히면: **앱이 5분 이상 멈추면 세션을 끝내고** 그 지점을 기록 파일 "가장 먼저 끊긴 지점"에 1순위로 적는다. 그다음 바로 "기록 꺼내기"로 간다.

## 문제별 계획표 (계획대로면 숙련도 0.00 → 0.20 · 서버 기록 16행)

정답은 괄호 안에 적었다. 앱에는 보이지 않는다. 예시 입력은 그대로 써도 되고 비슷한 말로 바꿔도 된다. 다만 **정답 칸의 입력 순서(몇 번째에 맞히는지)는 지킨다.**

| 문제 | 문제 본문 | 1번째 입력(규칙 ①) | 2번째 | 3번째 | 4번째 | 보여야 하는 결과 화면 |
| --- | --- | --- | --- | --- | --- | --- |
| LF-01 | f(x) = −3x + 3, f(5) (정답 −12) | `x가 뭐예요?` | 튜터 말에 짧게(예: `5 넣어요?`) | `-12` ← 정답 | — | 맞음 · 숙련도 0.10 (+0.10) · 2번 |
| LF-02 | f(x) = x + 4, f(−3) (정답 1) | `7` (부호 실수 3+4) | `1` ← 정답 | — | — | 맞음 · 숙련도 0.20 (+0.10) · 1번 |
| LF-03 | f(x) = 6x − 8, f(2) (정답 4) | `20` (12+8 부호 실수) | 짧게, 틀리게(예: `12요?`) | 짧게, 틀리게(예: `-4?`) | `-4` | 틀림 · 답은 4 · 숙련도 0.15 (−0.05) · 3번 |
| LF-04 | f(x) = −x − 5, f(3) (정답 −8) | `f가 뭐예요?` | 짧게(예: `3 넣어요?`) | `-3-5=-8` ← 풀이식=답(정답) | — | **맞음** · 숙련도 0.25 (+0.10) · 2번 |
| LF-05 | f(x) = 4x + 8, f(0) (정답 8) | `12` (0 대입을 건너뜀) | 짧게, 틀리게(예: `4요?`) | 짧게, 틀리게(예: `0이요?`) | `0` | 틀림 · 답은 8 · 숙련도 0.20 (−0.05) · 3번 |

주의
- LF-03·LF-05의 2~4번째 입력에 **실수로 정답(4·8)을 치지 않는다.** 그러면 바로 "맞음"이 나와 규칙 ③이 깨진다. 깨졌으면 메모하고 계속한다.
- LF-04의 3번째 입력이 "맞음"이 아니라 튜터 말풍선으로 나오면 풀이식=답 채점이 반영되지 않은 것이다. 창 B의 `EQ_FORM_GRADED` 검사가 막았어야 하므로 이상 신호다. 시각과 화면을 메모하고, 이어서 `-8`만 보내 맞힌 뒤 계속한다.
- 튜터 말풍선이 "어느 부분이 막히는지 한 가지만 말해 줄래? …"로 시작하면 LLM이 제한 시간(20초)을 넘겨 대체 문장이 나온 것이다. 그 턴의 점수는 1로 하고, 메모에 횟수를 센다.
- 한 문제가 끝날 때마다(결과 화면에서 "다음 문제"를 누르기 전에) 메모장 그 줄을 채운다. 튜터 말풍선 원문도 옮겨 적는다.

## 창 B — 1. 앱 실행 (포코 X3 NFC · USB 연결)

폰은 **USB 역방향 연결**(`adb reverse`)로 서버에 붙는다. 폰 안의 `127.0.0.1:8000`이 USB 케이블을 타고 PC의 8000번 서버로 이어진다. 그래서 같은 Wi-Fi·LAN IP·Windows 방화벽(`/demo-doctor` D행)이 필요 없다. 앱 디버그 빌드는 `http://` 통신을 허용한다(`src/mobile/android/app/src/debug/AndroidManifest.xml`의 `usesCleartextTraffic="true"`). 앱 최소 안드로이드는 6.0(API 23)이고, 포코 X3 NFC는 안드로이드 10으로 나와 12까지 업데이트된 기기라 그 위에서 돈다(설정 → 휴대폰 정보의 "Android 버전"으로 확인).

### 폰 준비 (처음 한 번 · 폰에서)

1. **개발자 옵션 켜기** — 설정 → 휴대폰 정보 → "MIUI 버전"을 7번 연달아 누른다("개발자가 되었습니다").
2. **USB 디버깅 3종** — 설정 → 추가 설정 → 개발자 옵션에서 켠다.
   - "USB 디버깅"
   - "USB를 통해 설치" — 샤오미는 이것이 꺼져 있으면 앱 설치가 실패한다(`/demo-doctor` C행 실측). Mi 계정 로그인을 요구할 수 있다.
   - "USB 디버깅(보안 설정)" — 같은 C행이 함께 켜라고 적었다.
3. **USB로 PC에 연결** — 폰에 "USB 디버깅을 허용하시겠습니까?"가 뜨면 "이 컴퓨터에서 항상 허용"에 체크하고 허용한다.
4. **한국어 키보드 확인** — 아무 입력창에서 한글이 쳐지는지 본다. 안 되면 설정 → 추가 설정 → 언어 및 입력 → 키보드 관리 → Gboard(또는 기본 키보드) → 언어 → 한국어를 추가한다.
5. **화면 꺼짐 늘리기(권장)** — 설정 → 디스플레이(또는 잠금 화면) → 화면 꺼짐 → 10분. 문제를 생각하는 동안 화면이 꺼지면 다시 켜야 해서 흐름이 끊긴다.

`flutter run`이 앱을 설치할 때 폰에 "USB로 설치하시겠습니까?" 확인 창이 잠깐 뜰 수 있다. **설치**를 누른다. 시간 안에 누르지 않으면 설치가 실패하는데, 그때는 이 블록을 다시 붙여넣는다(MIUI에서 흔히 알려진 동작 · 이 저장소 실측 아님).

### 앱 실행 블록


자가검증
- 다음 줄이 보인 뒤 빌드가 시작된다. 폰에 "닉네임" 화면이 뜨면 성공이다.
  - `SERVER_REACHABLE=200`
  - `EQ_FORM_GRADED=True  (… 응답 kind=graded)`, `WRONG_EQ_REJECTED=True  (… 응답 kind=tutor_turn)`
  - `SELF1_FRESH=True  (self-1 행 수=0 · 기대 0)`
  - `ADB=C:\…\platform-tools\adb.exe`, `PHONE=…  (id=…)` — 이름이 "POCO X3 NFC"가 아니라 `M2007J20CG` 같은 모델 번호로 보일 수 있다(지역판마다 번호가 다르다 · 추정). 이름이 아니라 id가 비어 있지 않은지가 판정 기준이다, `ADB_REVERSE_OK=True`
- `EQ_FORM_GRADED`·`WRONG_EQ_REJECTED`·`SELF1_FRESH`는 아래 패드 블록과 같은 검사다(설명은 그 블록의 자가검증).
- 블록은 USB로 연결된 실제 안드로이드 기기(에뮬레이터 제외) 하나를 골라 그 기기에만 설치한다. 다른 기기가 함께 잡혀 있어도 묻지 않는다.
- 앱이 뜨면 닉네임에 `self-1`을 넣고 시작한다. 위쪽에 "LF-01 · 1/30 · 숙련도 0.00"이 보이면 "문제별 계획표"대로 푼다.
- **풀이 도중 USB 케이블을 뽑지 않는다.** 역방향 연결이 끊겨 앱 위쪽에 빨간 띠("서버에 연결할 수 없어요…")가 뜬다. 뽑혔으면 다시 꽂고 아래 "USB 다시 잇기" 블록을 붙여넣은 뒤, 앱에서 같은 답을 다시 보낸다. 끊긴 시각과 문제를 메모한다.

### USB 다시 잇기 (풀이 도중 케이블이 빠졌을 때만 · 새 창 C)

창 B는 `flutter run`이 쓰고 있으니 새 PowerShell 창을 열어 붙여넣는다.

```powershell
# [창 C · USB 다시 잇기] Windows PowerShell — 역방향 연결만 다시 건다(앱·서버는 그대로)
$Adb = @((Get-Command adb -ErrorAction SilentlyContinue).Source, "$env:ANDROID_HOME\platform-tools\adb.exe", "$env:ANDROID_SDK_ROOT\platform-tools\adb.exe", "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe") | Where-Object { $_ -and (Test-Path $_) } | Select-Object -First 1
Write-Host ("ADB=" + $Adb)
if ($Adb) { & $Adb reverse tcp:8000 tcp:8000 | Out-Null; Write-Host ("ADB_REVERSE_OK=" + [bool]((& $Adb reverse --list) -match "tcp:8000")) } else { Write-Host "RUN_REFUSED=True — adb를 찾지 못함" }
```

자가검증: `ADB_REVERSE_OK=True`가 보이면 앱에서 다시 보내기를 누른다. 기기가 둘 이상 잡혀 있으면 adb가 `more than one device`로 거부한다. 그때는 다른 기기(에뮬레이터 등)를 끄고 다시 붙여넣는다.

## 세션 AI가 미리 확인한 것 (클라우드 리눅스 · 2026-11-10)

- 풀이식=답 채점 검사(창 B의 `EQ_FORM_GRADED`·`WRONG_EQ_REJECTED`와 같은 요청을 curl로 보냄)
  - 지금 main(`9a06dbe6` · 풀이식=답 수정 전) 서버에서는 LF-01에 `-3*5+3=-12` → `kind=tutor_turn`이 나온다. `EQ_FORM_GRADED=False`가 되므로 창 B가 거부한다.
  - 임시 워크트리에 `normalize` 끝 `rsplit("=", 1)[-1]` 한 줄을 넣어 수정을 흉내 낸 서버(8001번)에서는 `kind=graded`·`correct=true`가 나온다. `EQ_FORM_GRADED=True`다.
  - 틀린 풀이식 `-3*5+3=-11`은 두 서버 모두 `kind=tutor_turn`이다. 그래서 `WRONG_EQ_REJECTED=True`이고, "`=`가 있으면 무조건 정답" 같은 과잉 수정도 걸러진다.
  - 검사는 GOLD-08이 어떤 방식으로 구현하든 동작만 본다. 처음에는 파이썬 검사 파일로 만들었으나, 모든 `.py`가 CI 린트 대상이어야 한다는 계약(`tests/infra/test_lint_coverage.py`)에 걸려 HTTP 검사로 바꿨다. 실제로 학생이 쓸 서버를 직접 검사하므로 실행 코드 출처 확인도 따로 필요 없다.
- `export_self1_turns.sql`
  - PostgreSQL 16 + 골든 서버(가짜 LLM)에 `self-1` 3턴과 다른 닉네임 2개를 만든 뒤, `psql -f`로 돌렸다.
  - 결과는 `COPY 3`, `ROWS=3`, exit 0이었다.
  - 파일 머리는 `id,problem_id,turn_no,kind,correct,student_text,tutor_text,created_at`이고, 닉네임·session_id 열이 없다. 다른 닉네임 행도 빠졌고, 한글은 그대로 남았다.
- 폰 블록이 읽는 `flutter devices --machine` 필드는 CI와 같은 Flutter 3.41.9 소스(`packages/flutter_tools/lib/src/device.dart`의 `toJson`)에서 확인했다. 필드는 `name`·`id`·`isSupported`·`targetPlatform`·`emulator`·`sdk`·`capabilities`이다. `targetPlatform`은 안드로이드면 `android-arm`·`android-arm64`·`android-x64`(`build_info.dart`의 `getNameForTargetPlatform`)이고, `emulator`는 로컬 에뮬레이터 여부(참/거짓)다. 그래서 `-like "android*"`와 `-not emulator` 조건은 에뮬레이터·Windows·Chrome 대상을 빼고 실기기만 고른다. 포코 X3 NFC 실기기·`adb reverse`·MIUI 설치 확인 창은 실측하지 못했다(미확인).
- PowerShell 블록 자체는 이 환경에 PowerShell이 없어 돌려 보지 못했다(미확인).
  - 구조는 S8 런북에서 Kiki 머신으로 두 번 성공한 블록(창 A·창 B·에뮬레이터 대안)을 그대로 이었다.
  - 새로 넣은 것은 다음과 같다: 컨테이너 이름으로 다루는 DB 기동(`docker ps -a --filter` → `docker start` 또는 `compose up`)·정리(`docker rm -f`) · `docker exec … psql -At -c` 한 줄 · `docker cp` · `Import-Csv -Encoding UTF8` · `Set-Clipboard`. 시연 DB를 컨테이너 이름으로 다루는 이유는, S8 워크트리에서 만든 컨테이너가 남아 있으면 폴더 이름이 다른 이 워크트리의 `compose up`이 이름 충돌로 실패하기 때문이다.
  - 최상위 제어 흐름은 한 줄짜리 `if (…) { … } else { … }`뿐이다. 거부 가지는 이유를 출력한다.
