## §2. 접근 가능성 3분류 — 이게 우선순위의 진짜 기준

지금까지 확립한 패턴(Tier1 SymPy 수치 검산 기반 결정론 스켈레톤 생성기)이 **어디까지 통하고 어디서 끊기는지**를 먼저 나눈다. 이 분류가 "무엇부터 할까"보다 먼저 와야 한다 — C급을 A급처럼 다루면 검증 없는 콘텐츠를 만들게 된다.

### A급 — Tier1 수치 검산 직결 (지금 패턴 그대로 적용 가능)

"계산해서 값 하나를 구하시오" 유형. 지금까지 만든 5개가 전부 이 등급이다.

| 영역 예시 | 왜 A급인가 |
|---|---|
| 고등 방정식과 부등식(잔여 15) | 이미 이차방정식 생성기 있음 — 유사 구조(삼차·연립·부등식 영역) |
| 고등 도형의 방정식(10) | 좌표·거리·직선의 방정식 — 전부 대수 계산 |
| 고등 함수와 그래프(5)·지수함수와 로그함수(4) | 함숫값·교점 좌표 — 중등 함숫값 생성기와 동형 확장 |
| 고등 수열(3)·미분(6)·적분(6)·미분법(9)·적분법(7) | 일반항·극한값·정적분값 — 전부 SymPy 닫힌형 계산 |
| 고등 벡터(4)·삼각함수(2)·행렬(3, 잔여) | 성분 연산·특수각 값 — 이번 행렬 생성기와 동형 |
| 초등 수와 연산(39)·중등 수와 연산(5) | 사칙연산 확장(분수·소수·비와 비율) |
| 대학 CALC1(31, 잔여)·LINA1(17)·ODE 계산부 | 닫힌형 계산이 있는 파트(적분표·행렬 연산 등) |

**추정 소요**: 코드 1개당 생성기 1개가 원칙이나, **같은 생성기가 여러 형제 코드를 커버**할 수 있다(예: 이차방정식 생성기 확장으로 "이차부등식"까지, 함숫값 생성기의 `a·x+b` → `a·x²+b·x+c`로 교체하면 이차함수까지). 실측 기준 생성기 1개(스파이크 테스트 → 구현 → 위생 게이트 디버깅 → 테스트 → 배치 → 커버리지 확인)는 **세션 내 30분~1시간** 규모다.

### B급 — 수치 검증 우회 설계가 필요 (가능하나 A급보다 손이 감)

| 영역 | 필요한 설계 |
|---|---|
| 고등 통계 잔여(6) | 이번 기댓값 패턴을 표준편차·이항분포·정규분포로 확장(분산 계산은 기댓값의 자연스러운 후속) |

| 고등 자료의 분석·수집과 정리(8) | 평균·중앙값·최빈값·산포도 — 순수 산술이라 실은 A급에 가까움(재분류 여지) |

### C급 — 현 파이프라인 밖 (이 세션에서 착수 금지)

| 영역 | 왜 안 되는가 |
|---|---|

## §3. 실행 순서 제안

```
Phase 1 (즉시 착수 가능·이 세션 계속)
  └─ A급 소진 — 우선순위: ①이미 존재하는 형제 생성기 확장(가장 쌈) ②고등 계산형 잔여
                          ③초등 도형·연산 확장(최대 gap) ④대학 CALC1/LINA1 계산부

Phase 2 (A급 소진 후)
  └─ B급 — 통계 확장(표준편차)·경우의 수(전수열거 패턴)·초등/대학 계산-분류 재판정

Phase 3 (별도 계획 필요 — 이 문서 범위 밖)
  └─ C급 — Tier3 형식 검증 설계 착수 여부는 Kiki 결정 사항(신규 인프라 투자 판단)
  └─ AI 검수 게이트 승격 — Kiki 머신에서 실 LLM 배치 실행(기존 v0 코퍼스 6종 전체 대상)
```

**Phase 1 안에서의 세부 순서 원칙** — 매 슬라이스는 "가장 싼 것부터":
1. **기존 생성기의 형제 코드 확장**이 신규 생성기보다 싸다(스켈레톤 인프라·게이트 통합·테스트 템플릿 재사용률이 더 높음). 예: 이차방정식 생성기 → 이차부등식 variant 추가.
2. 그다음 **이번 5개 생성기와 동형 구조**(단일 계산·단일 대입)를 가진 새 코드.
3. 마지막으로 **새로운 수학적 조작이 필요한** 코드(예: 벡터 내적은 행렬 성분곱과 유사하지만 신규 스켈레톤 필요).

## §4. 반복 가능한 생성기 제작 SOP (5회 실측에서 도출)

이 표가 사실상 "방대한 남은 부분"에 대한 가장 실질적인 답이다 — 사람이 매번 새로 설계하는 게 아니라, 아래 체크리스트를 그대로 따르면 된다.

| 단계 | 내용 | 실측 근거 |
|---|---|---|
| ① 타깃 선정 | 커버리지 리포트의 0커버 코드 중 A급 판정 | `problem_bank_coverage.py` |
| ② 개념그래프 조회 | `concept_graph_v1/graph.json`에서 `standard_codes`로 역검색 → `source_id` 확보. **없으면 정직하게 `concept_tags=()`**(대학 축 선례) | S4-24 발견 |
| ③ 스파이크 테스트 | Tier1(`verify_answer`)에 목표 조건 형태를 직접 넣어 pass/fail 실측 확인. 미분이면 `.doit()` 필수, 대입이면 `.subs()`만으로 충분 | S4-22·S4-24·S4-25 |
| ④ 생성기 작성 | `_Skeleton`(dataclass)·`_build_pool()`(고정 시드)·`generate()`·`_assemble()`. **다변형이면 `operation` 필터를 처음부터 넣는다**(안 넣으면 밴드 중복 방출 버그 — S4-22 실측 사고) | S4-22 버그·S4-23 재사용 |
| ⑤ 표기·문법 | 계수 1 생략·이중부호 금지(`_term` 헬퍼)·조사는 항상 `josa.eul_reul`/`wa_gwa`(하드코딩 금지 — **해설 문구에서도** 재발 확인, 매번 점검) | S4-22·S4-24·S4-25 반복 발견 |
| ⑥ 해설 문구 | **등호를 쓰지 않는 서술형**("값은 N이다")으로 작성 — 위생 게이트(SymPy 산술/방정식 시드 검증기)가 "(숫자)...=숫자" 패턴을 오탐 | S4-24 실측 사고 2건 |
| ⑦ 배치 오케스트레이션 | `run_batch`가 아니라 `run_equivalent_generation(..., signature_index=None)` 직접 반복 — 구조 dedup이 답값 기반이라 오탐(S4-22 실측) | 전 생성기 공통 처방 |

| ⑩ 코퍼스 생성·검증 | 배치 실행 → `problem_id` 전건 고유 확인 → 커버리지 리포트 재실행 → 실제 이동 확인 | 전 생성기 공통 |
| ⑪ 전체 스위트 호출 | `cd src/backend && python -m pytest -q`(**bare invocation만** — testpaths는 `pyproject.toml`이 이미 지정). **명시 경로 인자**(`pytest ../../tests/backend`·특정 파일·`-k` 등)로 부르면 `asyncio_mode`가 적용되지 않아 async 테스트(`test_coach.py` 등) 수백 건이 "async def functions are not natively supported"로 무더기 거짓 실패한다(`pyproject.toml` ARCH-22 결정 로그에 이미 기지 — bare invocation만 실 CI와 동일하게 green 확인됨) | S4-40 실측 사고(616건 거짓 실패 → 원인 격리 → bare 재실행으로 9087 passed 0 failed 확인) |

## §5. 명시적으로 하지 않는 것 (이 계획의 범위 밖)

- ❌ **C급 전체를 이 경로로 풀려는 시도** — 명제 논리·증명형·융합 서술형은 Tier1 수치 검산으로 검증 불가능한 걸 검증 가능한 척 만드는 것이 더 위험하다(CLAUDE.md "AI 응답을 검증 없이 제공 금지"와 직결).
- ❌ **AI 검수(Wilson 게이트) 승격을 이 환경에서 시도** — 실 LLM 필요, 구조적으로 불가능(API 키 없음). 6개 v0 코퍼스(elementary·matrix·university·middle·discrete-ev + 기존)가 전부 이 게이트를 기다리는 중 — **Kiki 머신에서의 실행이 이 계획 전체의 실질적 병목**이라는 걸 명시한다.
- ❌ **"완성" 목표 설정** — 761개 코드를 다 채우는 건 이 계획의 목표가 아니다. 목표는 "A급을 최대한 소진하고, B급 설계를 확립하고, C급의 경계를 명확히 그어 두는 것"이다.
- ❌ **질문형식 다양화(서술형·논술형 등)** — 이번 5개 생성기 전부 단답형이다. 편중 문제(W1에서 지적)가 축적되고 있음을 인지하되, 이 계획에서 새로 다루지 않는다(별도 후속).
