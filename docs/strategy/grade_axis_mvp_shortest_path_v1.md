## §0. 요약 — "백본은 이미 4축이다"

세 문장으로 줄이면 이렇다.

1. **막고 있는 것은 지식 백본이 아니다.** 원자 그래프는 이미 초등 464 · 중학 225 · 고등 925 · **대학 1,069** = 2,683 노드로 4축 전체를 덮고 있다. 개념·선수관계는 다 있다.
2. **막고 있는 것은 콘텐츠 커버리지와 4개의 끊긴 seam이다.** 성취기준 커버율 16.6%(초등 4.1% · 대학 0%), 그리고 학년축이 관통하지 않은 배선 4곳. 둘 다 기계 자동화 구간이다.
3. **따라서 최단경로는 순서를 바꾸는 것이다.** 고3 파일럿(사람 병목)이 도는 동안 4축 관통을 기계로 완성한다. MVP 완성선은 "성취기준 100%"가 아니라 **"4축 각각에서 1루프가 실제로 돈다"**(수직 관통)로 잡는다.

**현행 계획 대비 무엇이 달라지는가**:

| | 현행 (`business_plan_master_v1.md` 제3부) | 본 제안 |
|---|---|---|
| 순서 | M1 고3 → M2 고교 → M3 중등 → M4 초등 → M5 대학 (직렬) | 고3 파일럿 ∥ 4축 확장 (병렬) |
| 학년 확장의 선행조건 | `S3-01-pilot-cohort` (owner: kiki) | 없음 — W1 관측 리포트만 |

| 임계경로 | 사람 병목(파일럿 모집·운영) | 기계 구간(콘텐츠 공장 W2) |

## §2. 아키텍처 — 학년축이 어디로 흐르는가

### 2.1 제1원칙: 학년축 = 오버레이 파라미터, 구조 분기 아님

CLAUDE.md 8대 구조 원칙 ⑤ **Curriculum은 Overlay**(개념은 영속, 매핑만 교체)와 `status_roadmap_2026-07.md` §5 S4 질문 4("학년 축이 프롬프트 파라미터인가 구조 분기인가")의 답을 **코드로 못 박는다**.

실측상 이 원칙은 이미 대체로 지켜지고 있다:
- `subject == "math"` 류 과목 분기 — **0건**
- `school_level`은 DB **필터 컬럼**(`db/models/atom_node.py:96`, 보조 인덱스 `ix_atom_node_school_level`)이지 제어 흐름이 아니다
- `grade`는 이미 L4 프롬프트 **인자**로 thread되어 있다 (`l4/pedagogy/prompt_assembler.py:85,122` — `grade: int | None`)
- 발화 프로파일은 이미 **4밴드**다 (`l4/speech/profiles.py` — 초등·중등·고등·대학)

### 2.2 구조도 — 학년축의 흐름

- **U2**: 대학 원자 1,069의 `standard_codes` 잔여 **557건**을 소단원↔성취기준 1:1 맵으로 채움. 입력은 `data/corpus/standards_university_v1/concept_standard_links.json`(409건·1:1·멀티값 0).
- **U3**: `l1/standards/standard_loader.py`로 `achievement_standard` + `concept_standard_link` 멱등 적재.
- **검수 게이트 (우회 금지)**: 대학 성취기준 본문은 **AI 추정 초안**이다(`standards_university_v1.md` §4 — "노출 전 검수 게이팅 대상"). S2에서 확립된 **AI 검수 + Wilson 표본 게이트**를 적용하고, 통과 전 `is_published=false`를 유지한다. 검수 없는 AI 초안 노출은 5중 해자 중 **④신뢰**를 직접 훼손한다.
- 라이선스: 대학 본문은 **자체작성**이라 NCIC redaction 불요(K-12와 취급 분리) — 이것이 대학 축을 싸게 만드는 두 번째 이유다.

### W4. 진단 4축 — CAT가 초등·대학에서도 성립

- `l1/atom_probe/` 프로젝션에 초·중·대학 프로브 공급.
  - ⚠️ **중복 착수 금지** — `REC-02-misconception-probe-supply`(오개념 표적 프로브 공급 · "select_probe 후보 0" 해소)가 **다른 세션 claim 중**이다. 그 산출물을 **소비만** 한다.
- **L2는 변경 0** — BKT·IRT는 학년 무관(문항 파라미터만 본다). 검증은 "초등 문항만으로 θ 추정이 수렴하는가" 테스트로만.
- **대학 오개념 0건**: MVP에서는 미보유를 **정직하게 표시**하고, reactive retrieval이 빈 결과에 graceful하도록만 보장한다. 신규 카탈로그 저작은 범위 밖(§5).

### W5. L5 / L6 — 학년 선택과 모드 라우팅

- **온보딩(S-4 해소)**: 학년·트랙 입력 추가 → `PATCH /v1/users/me`(`api/users.py:103` 화이트리스트 재사용) → `UserTrackHistory` 쓰기 좌석 배선.
- **L6 라우팅 (모드 신설 금지)**:
  - 초등·중등 → 학교진도 · 메타인지 · 사고력 모드
  - 고등 → 수능 모드 (현행)
  - **대학 → 학교진도 모드의 오버레이로 흡수** — `l6/school_progress/gating.py`의 depth 앵커만 확장한다. L6는 순수 결정 로직(부수효과 0·L1만 의존)이므로 모드를 늘릴 이유가 없다.

### W6. 4축 E2E 게이트 — **MVP 완성의 정의**

- 축별 E2E 시나리오 **4본** (초·중·고·대학 각 1루프):
  `온보딩 → CAT 진단 → 문제 제시 → 풀이 입력 → WH-1 코칭 → 3-tier 검증 응답`
- **mock-우선 · hermetic** — 라이브 키 불요. `s1_e2e_vertical_slice_design.md` §2가 전 구간 hermetic 구동 가능함을 이미 실증했다(coach 결정론 · verify SymPy · L2 순수수치 · judge Fake).
- **성능 게이트**: 원자 2,683 전량 활성 상태에서 traversal 예산(visited set · timeout · token budget, **depth ≤ 2 / nodes ≤ 12~20 / tokens ≤ 3000**) 실부하 통과 — `S4-01` acceptance 그대로.

## §4. 순서와 병렬성

```
W0 학년축 배선 ──┬── W1 4축 관측 ──┬── W2 콘텐츠 공장 4축 ───────────┐ ◀ 임계경로
  (선행 필수)     │                 ├── W3 대학 자산 U2·U3 ──────────┤
                  │                 └── W4 진단 프로브 4축 ──────────┤
                  └── W5 온보딩 학년 입력 + L6 라우팅 ───────────────┤
                                                                     └─▶ W6 4축 E2E = 완성 판정

 [병렬·독립] 고3 파일럿 S3-01 (owner: kiki) ─── 결과는 W2 재실행으로 4축에 일괄 반영
```

**소요를 결정하는 것은 W2 하나다.** W0·W1·W5는 배선이라 짧고, W3·W4는 W2와 동시 진행할 수 있다.

**기간을 약속하지 않는 이유**: 프로젝트 규약이 "게이트가 기간에 우선한다"(`ROADMAP.md`)이며, 신뢰할 수 있는 견적은 **W1 리포트가 나온 뒤에만** 가능하다 — 입력이 `0커버 코드 수 × 코드당 생성 시도 × 게이트 통과율`이고, 이 중 초등·대학의 게이트 통과율은 **아직 한 번도 측정된 적이 없다**(현 통과율 실측은 고등 대수·미적 계열에서만 나왔다). 추정치를 여기에 적으면 §1의 실측과 같은 무게로 읽히므로 적지 않는다.
