# Phase 3 — Math EOS 과목 완성 (2026.10.26~11.22) — 회차별 지시문 목차

- **무엇인가**: 「Phase 3 — Math EOS 과목 완성 실행계획」을 회차 단위로 집행하기 위한 지시문 모음이다.
- **목표 한 문장**: 대표 교육과정 1개를 대상으로 학습 데이터·콘텐츠·AI·운영도구를 모두 연결해 실제 서비스 가능한 **Subject Package v1**을 완성한다.
- **왜 쪼갰나**: 원 문서의 "콘텐츠 + UX + 품질 + 관리자 운영"은 4주 동안 범위가 퍼지기 쉽다. 그래서 **착수 단위 15개 + 판정 회차 5개**로 나눴다. 기준은 기능 개수가 아니라 `Coverage × 연결밀도 × 품질 × 운영가능성`이다.
- **전제**: Phase 2 Gate 2(10/25)가 PASS여야 한다.

## 쓰는 법 (3단계)

1. 아래 표의 **번호 순서대로** 파일을 연다.
2. 파일 안의 `text` 블록 **전체**를 복사해 새 세션 첫 메시지로 붙인다(마스터 프리앰블이 이미 앞에 합쳐져 있다).
3. 세션이 끝나면 파일 하단 체크리스트로 완료 판정을 확인하고, **충족됐을 때만** 다음 번호로 넘어간다.

> ✅ 표시된 판정 회차는 반드시 **새 세션**에서 단독으로 쓴다.
> `상시/` 폴더는 순서와 무관하게 필요할 때 진행 중인 세션에 끼워 넣는다.
> 전체를 한 번에 훑어보려면 `Phase3_Math_EOS_과목완성_통합본.md`를 연다.

## 주의

1. **한 세션 = 한 항목.** 두 파일을 한 세션에 붙이지 않는다.
2. **P3-01의 대표 과정 선택은 Kiki가 한다.** 세션이 옵션을 내면 하나를 골라 답해 준다. AI가 임의 확정하면 이후 모든 Coverage 분모가 흔들린다.

```text
2. **mastery_update_allowed는 LLM이 true로 만들 수 없다.** LLM 출력값과 무관하게 서버가 false로 덮어쓰거나,
   true면 거부하라. LLM은 상태를 결정하지 않는다(Phase 2 경계 유지).
3. concept_id·misconception_id는 **실제 존재하는 ID인지** DB로 확인하라. 존재하지 않는 ID(환각)는 거부하고 fallback한다.
4. 스키마 위반(잘못된 JSON, 필드 누락, 범위 밖 hint_level)은 학생에게 노출하지 않고 fallback 경로로 보낸다.
   실패는 예외 타입명을 로그에 남긴다(침묵 실패 금지).
5. 검증: ①mastery_update_allowed=true 주입 ②존재하지 않는 concept_id 주입 ③깨진 JSON 주입 — 3종 모두 학생 응답에
   도달하지 않는지 RED로 확인하라.
6. 산출: 스키마 + 검증기 + fallback 연결 + PR.
```

```text
- 대표 과정 범위(P3-01에서 동결) 밖의 콘텐츠를 채우지 않는다. "김에 같이" 다른 학년·단원을 넣지 않는다.

[아키텍처 규율 — Phase 2에서 동결된 것]
- LLM은 학습 상태를 직접 결정하지 않는다. LearnerState의 최종 변경은 Assessment/Mastery/Policy Engine만 한다.
- EOS Core 안에 `if subject == "math"`류 분기를 만들지 않는다. 수학 특화 로직은 Math Adapter로 보낸다.
- 모든 LLM 호출은 라우터(l3/router.py) 경유 + Langfuse 추적. 수학 동치 판정은 기존 SymPy 단일 권위 경로만 쓴다.
- 오개념은 LLM 초기 context에 preload하지 않는다(reactive retrieval만). 그래프 조회는 depth ≤ 2, max_nodes ≤ 12~20.
- 표현이 아니라 구조로 저장한다(화면 문자열 금지 — CLAUDE.md L1-L4 규칙).

[콘텐츠 규율]
- 콘텐츠는 코드가 아니라 데이터다. 개념·문제·풀이·오개념을 소스 코드에 하드코딩하지 않는다.
- 정답·풀이의 수학적 정확성은 SymPy 경로로 기계 검증한다. LLM이 만든 콘텐츠는 검증 전까지 Draft다.
- ID 체계는 기존 것(Concept ID·오개념 kebab↔M-id 크로스워크 등)을 경유한다. 새 ID 체계를 만들지 않는다.
- 지표(Coverage 등)는 사람이 세지 않는다. CLI가 계산하고 exit code로 판정한다.

[착수 규율 — CLAUDE.md]
- 첫 행위는 `python3 scripts/harness/backlog.py start <태스크ID>`다. 대상 파일을 열어보는 것부터가 착수다.
  claim 없이 코드를 읽거나 쓰지 않는다. 해당 태스크가 없으면 backlog.py add로 먼저 등재하고 claim한다.
- 부재를 단정하기 전에 ①역할 기반으로 재검색 ②소비자(호출측) 역추적 ③그래도 0건이면
  "내가 찾은 방법으로는 0건"이라고 범위를 밝혀 적는다. `git log --all --grep=<ID>`로 미머지 브랜치도 본다.
- 판정 근거는 trunk 실측이다. 보고 상단에 `판정 기준: main <커밋해시>`를 박는다. 미머지 브랜치를 근거로 조건을 닫지 않는다.

[검증 규율 — CLAUDE.md]
- 새로 만든 가드·테스트·게이트·계측기는 **막으려는 상태를 실제로 주입해 RED를 확인**한 뒤에만 "보호된다"고 말한다.
  정상 입력에서 초록인 것은 증거가 아니다. 주입이 실제 적용됐는지(mutated != original)도 단언한다.
- 판정은 exit code로 한다. `-q`·`| tail`로 출력을 자르고 눈에 보이는 문자열로 통과를 선언하지 않는다.
- 로컬 검증은 CI 잡의 **스텝 목록 전체**에 맞춘다(pytest만이 아니라 mypy --strict·lint-imports·게이트 CLI 포함).
- 백엔드 소스·테스트를 건드렸으면 전체 스위트를 돌린다. 못 돌렸으면 "전체는 확인하지 못했다"를 명시한다.
- 측정 실패를 0건 통과로 위장하지 않는다. 외부 관측(Langfuse 등)이 죽었으면 "측정 실패"로 보고한다.

[산출 규율]
- PR은 Vertical Slice 또는 콘텐츠 묶음(단원 단위) 단위로 연다. 제목은 흐름·범위로 쓴다.
- 커밋이 있고 (조사전용/미완/CI red/Kiki 보류) 4종 예외가 아니면 PR 생성이 기본값이다.
- 세션 끝에 다음 4줄을 보고한다: ①이번 항목의 완료 판정 결과(충족/미충족, 근거 커밋) ②연 PR 링크
  ③원 문서 대비 미이행으로 남긴 것과 이유 ④다음 항목에 넘기는 선행 조건.

[이번 세션 항목]
```

### P3-02. Coverage 계측기 (Content·Curriculum·Completeness·Graph Connectivity) (W1 (10/26~11/1) · Week 1 · 측정 지표)

```text
[항목 P3-02] 대표 과정의 연결 상태를 숫자로 재는 계측기를 만든다. 측정 없는 목표는 목표가 아니다.

1. 아래 4개 지표를 하나의 CLI로 산출하라. 분모는 P3-01 동결 명세다.
   - Content Coverage Rate = 완전 연결 Concept / 출시 대상 Concept (핵심 Concept 기준 목표 ≥ 95%)
   - Curriculum Coverage = Curriculum → Concept → Skill → Problem 경로가 있는 Curriculum 항목 비율 (목표 ≥ 98%)
   - Concept Completeness = 핵심 Concept 중 Prerequisite·Misconception·Solution·Hint·Pedagogy가 모두 연결된 비율 (목표 ≥ 95%)
   - Graph Connectivity Coverage = 핵심 Concept 중 Concept → Skill → Problem → Misconception → Pedagogy 경로가 완전히 존재하는 비율
2. "완전 연결"의 정의를 코드 한 곳에 두고 문서화하라. 정의가 여러 곳에 흩어지면 지표가 조작 가능해진다.
3. 결과는 지표값 + **미충족 Concept 목록(무엇이 빠졌는지 포함)**을 함께 낸다. 숫자만으로는 채울 수 없다.
4. 목표 미달이면 non-zero exit. 대상이 0건이면(분모 0) 통과가 아니라 실패로 처리하라.
5. 검증: ①특정 Concept의 Problem 연결을 끊는 주입 ②Pedagogy 연결 제거 주입 ③분모 0 주입 — 각각 수치가 떨어지거나 실패하는지 확인하라.
6. 산출: 계측 CLI + 현재 실측값(기준선) + 주입 결과 + PR.
```

**완료 판정**: 지표 4종이 CLI로 산출되고, 각각 연결을 끊는 주입에 수치가 떨어짐

### P3-03. Coverage 채우기 (최소 구조 + 핵심 개념 5종 연결) (W1 (10/26~11/1) · Week 1 완료 기준)

```text

1. 모든 Curriculum 항목에 최소 구조 Curriculum → Concept → Skill → Problem을 연결하라.
2. 핵심 Concept에는 추가로 Prerequisite / Misconception / Solution / Hint / Pedagogy를 연결하라.
3. Prerequisite 추가는 DAG를 깨지 않아야 한다(P-01 reachability 테스트가 초록이어야 한다).
4. LLM으로 초안을 만들어도 되지만 상태는 Draft로 둔다. 정답·풀이는 SymPy 경로로 검증된 것만 연결 완료로 센다.
```

## 4. 주의

1. **한 세션 = 한 항목.** 두 파일을 한 세션에 붙이지 않는다.
2. **P3-01의 대표 과정 선택은 Kiki가 한다.** 세션이 옵션을 내면 하나를 골라 답해 준다. AI가 임의 확정하면 이후 모든 Coverage 분모가 흔들린다.
3. **지시문을 "~해줘"로 줄이지 않는다.** 마지막 검증 항목(주입·RED 확인)이 핵심이다.
4. **판정 회차(✅)는 구현 세션과 분리한다.** 새 세션에서 단독으로 붙인다.
5. 목표 수치(95%·98%·99%)는 원 문서의 "목표 예시"다. P3-02·P3-10에서 실측 기준선을 본 뒤 Kiki가 확정한다.
