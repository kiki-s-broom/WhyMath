## §2. 평가

### 2.1 강점 (지키고 있는 것)

1. **L1–L4 독립 수학 코어의 두께와 순도** — 표현≠의미, Concept Purity, 노드 본문 redaction까지 플레이북 2대 철칙이 문서가 아닌 **CI 게이트로 강제**되고 있다. "구조 붕괴는 반드시 온다"는 전제를 코드로 방어 중인 프로젝트는 드물다.
2. **테스트가 소스보다 많은 문화** — 346개 테스트 파일/92.7k줄. 거버넌스 테스트(embedding namespace·edge relation·node purity·five-node connectivity)가 설계 결정을 동결하는 패턴이 정착됨.
3. **법적 안전조합 완결성** — 저작권 가이드 v2.0 기준 위험 소스 0건, 자체 동등문제 대체 전략 + redaction 삼중 방어. 나중에 못 고치는 유형의 리스크가 선제 차단됨.
4. **하네스 설계 수준** — WH-1(보상 신호 부재를 상태 외부화·가설 상한·확증편향 방지로 우회)·WH-S(기계 검증 가능성을 객관 보상으로 활용)는 학계 최신(STaR/rStar-Math)과 정합하는 설계. "측정 없는 도입 없음" 자기 절제도 유지 중.
5. **결정 로그 규율** — MEMORY.md가 진실 원천으로 실제 작동. 모든 반전(SkillNode 승격, Part 8 3분류 정정)이 근거와 함께 기록됨.

### 2.2 약점 (직시할 것)

1. **E2E 학습 루프가 한 번도 돈 적 없다** — 온보딩→진단→문제→풀이입력→코칭→검증응답의 수직 슬라이스가 미연결. 90일 체크리스트의 온보딩 흐름·자동 커리큘럼 정렬·베타·시범 사용자 5~10명 전부 미완. **부품은 고급인데 자동차가 조립된 적이 없다.**
2. **이중 truth source 활성** — 구 437 개념그래프와 신 1,837 원자 백본이 공존(마이그레이션 Phase 4·5 미완). 플레이북 7대 붕괴 연쇄 중 "유지보수 지옥"의 정확한 입구. concept→skill 매핑(#419)도 구 437 기준으로 저작되어 갭이 더 벌어지는 중.
3. **라이브 검증 정체** — L3 클라우드 튜닝(실측 비용·프롬프트 캐싱·guard_cloud 임계값), OCR Qwen3-VL 실모델, 토큰 실비용 회계가 전부 Phaiakes9 라이브 키/실머신 대기. **코드로 못 푸는 병목이 코드 뒤에 숨어 있다.**
4. **설계 정본화 국면의 장기화 징후** — 최근 한 달 커밋 대부분이 코드 0. 정본화 자체는 옳았으나(리치 Part 2 채택 등 실질 성과), 수확 체감 구간에 들어서고 있다. Part 검토는 12까지 완주했다 — **이제 검토할 Part가 없다.**
5. **사람 병목 2건 미해결** — 수학 교육 도메인 파트너(M1.3 게이트) 트랙 미정, 시범 사용자 채널 부재. AI가 대신 못 하는 항목.

### 2.3 종합 판정

> **"코어는 과잉 성숙, 제품 루프는 미성숙."**
>
> L1–L4와 품질 인프라는 Phase 1 MVP 요구를 이미 초과하는 수준이다. 반면 학생이 실제로 겪는 경험(L5 루프·L6 수능 모드)은 골격이다. 지금 가장 큰 리스크는 기술 부채가 아니라 **검증 부채** — 이 코어가 실제 고3의 30번 문제 앞에서 작동한다는 증거가 0건이다.
>
> **권고: 무게중심을 "설계 정본화"에서 "수직 슬라이스 실증"으로 이동할 시점이다.** 단, 그 전에 이중 truth source를 청산해야 한다(S0). 정본화 국면에서 얻은 규율(거버넌스 테스트·결정 로그)은 그대로 유지하되, 신규 설계 검토는 실증에서 발견된 문제에 의해서만 착수한다.

### S1. E2E 수직 슬라이스

1. **[붕괴]** "온보딩→CAT→문제제시→풀이입력→WH-1 코칭→검증응답 루프에서 각 단계 간 계약(스키마·상태 전이)을 나열하고, 통합 시 처음 깨질 가능성이 높은 계약 3개를 근거와 함께 지목하라." *(체크포인트 단계8 검문)*
2. **[경계]** "Minimal Reasoning Subgraph 상한(depth ≤ 2·nodes ≤ 12~20·tokens ≤ 3000)이 context builder 코드 어디에 배선되어야 하는가? 상한 초과 시 fail-open인가 fail-closed인가 — 각각의 교육적 결과는?" *(Part 8 해제 트리거 계약 준수 확인)*
3. **[붕괴]** "학생 응답이 PRM/도구 검증을 우회해 도달할 수 있는 코드 경로가 존재하는가? verify_step의 3상태(correct/incorrect/unverifiable) 중 unverifiable일 때 WH-1이 정답을 흘리지 않는다는 보장은 어디에 있는가?"
4. **[붕괴]** "WH-1 도구 루프가 무한 반복하거나 end_turn 없이 종료되는 경로를 찾아라. 루프 가드·timeout·토큰 예산이 각각 어느 계층에서 강제되는가?"
5. **[분리]** "이 루프에서 오개념이 초기 context에 preload되는 지점이 없는지 검사하라. 웜 스타트의 '단원 고빈도 오개념 프리로드'와 reactive retrieval 원칙의 경계는 무엇인가?"
6. **[존재 이유]** "OCR과 MathLive 중 S1 시연에 필수인 것은 무엇인가? 둘 다 넣을 때와 MathLive만 넣을 때 검증 범위 손실을 비교하라."
7. **[경계]** "Langfuse 트레이스와 토큰 실비용 회계에서, 어떤 데이터가 미성년자 개인정보에 해당해 암호화/최소화 대상인가?"
8. **[붕괴]** "루프의 어느 단계에 `subject == 'math'` 류 과목 하드코딩이 스며들었는지 grep 기준(패턴 목록)을 만들어 검사하라."

### S2. 콘텐츠 볼륨·품질 게이트

1. **[붕괴]** "동등문제 생성→SymPy 게이트→PRM→검수 파이프라인에서 각 게이트의 예상 통과율을 가정하고, 100문 확보에 필요한 생성 시도 횟수와 비용을 추정하라. 어느 게이트가 첫 병목이 되는가?"
2. **[경계]** "생성된 동등문제가 평가원 원문과 '동등하되 복제 아님'을 판정하는 기준은 무엇인가? 유사도 검사의 임계값과 그 법적 근거(저작권 가이드 v2.0)를 명시하라." *(체크포인트 단계10 검문)*
3. **[붕괴]** "WH-S 솔버가 '검증 통과했지만 교육적으로 나쁜 풀이'(비직관적 요행수·교육과정 밖 도구 사용)를 저장소에 축적하는 시나리오를 만들어라. 어떤 필터가 필요한가?"
4. **[존재 이유]** "다중 풀이 N개 중 학생에게 노출할 가치가 있는 '본질적으로 다른' 풀이의 판정 기준은 무엇인가? 표면 표현 차이와 인지 행동 차이를 어떻게 구분하는가?"
5. **[분리]** "SymPy 검증기가 파이프라인 본체에 새어 들어간 지점이 있는가? 물리의 단위·차원 검증기로 교체 가능한 인터페이스인지 검사하라."
6. **[붕괴]** "오개념 839건 기반 distractor 설계가 오히려 오개념을 '가르치는' 역효과 시나리오를 분석하라. distractor 노출 규칙에 어떤 안전장치가 필요한가?"
