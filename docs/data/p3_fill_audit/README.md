## 한계 (명시)

- **반복 감사의 한계**: 회차를 거듭해 첫 통과에서 멈추면, 각 회차의 95% 보증과 별개로 '우연한 통과'의 여지가 회차 수만큼
  커진다. 그래서 1·2회차를 지우지 않고 남기며, **이 승인은 3회차 감사의 통과다**(1·2회차 불합격 · 회차마다 다른 은행).
- **n = 204는 k = 0만 통과하는 경계다**: 보증이 P3-03(n = 504, k ≤ 3 통과)보다 *엄격한* 대신 표본이 작아 여유가 없다.
  3회차의 '결함 0건'은 판정자 8명이 모두 같은 지침으로 본 결과이며, 판정자 간 일치는 결함이 나온 1·2회차에서
  오히려 낮았다(1회차 A·B 겹침 7/19 · 2회차 0/2) — 감사가 놓칠 수 있는 결함이 있다는 뜻이고, 판정 규칙 밖의 결함은
  검출률 보정(L = 0.96898)이 흡수한다고 가정한다.
- **사전 등록 커밋 없음**: P3-03 5회차는 은행 sha256·묶음 sha256을 판정자 라벨을 받기 전에 별도 커밋했다. 이 감사의
  매니페스트(`manifest.json`)는 판정자 투입 전에 만들었으나 *판정 전에 커밋하지는 않았다* — 바이트 동결 증거는 매니페스트의
  sha256과 이 폴더의 `audited_bank.jsonl`이 같다는 것뿐이다.
- **판정자는 같은 모델 계열의 LLM이다**: 독립 구현의 서로 다른 모델이 아니므로 공통 사각이 있을 수 있다. 자격 측정이 같은
  프로토콜의 검출률을 측정해 보정에 반영했다(120/120).
- **S2 퍼징·S3 기계 검증자 K ≥ 3은 이 감사의 범위 밖**이다(P3-03 README와 같은 한계).
