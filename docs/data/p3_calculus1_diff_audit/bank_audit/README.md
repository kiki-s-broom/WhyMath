# P3-03 미분 은행 감사(S5) — 자격 통과 프로토콜로 504건 판정

> 태스크 `P3-03-coverage-fill` · 2026-10-08 · 근거 `docs/standards/superhuman_verification_standard.md` §3 ·
> 자격 측정 `../qualification/README.md`(프로토콜 합격: 검출 120/120 · 오경보 6/120)

## 무엇을 하는가

자격 측정을 통과한 감사 프로토콜(기계 게이트 ∪ LLM 판정자 A ∪ B)로 은행 `problem_bank_p3_calculus1_diff_v0`
504건을 판정하고, 관측 결함 판정 수 k를 검출률로 보정해 은행 결함률 상한을 낸다(CLI `s5`).

## 사전 등록 (판정자 라벨을 받기 전에 커밋)

- **은행**: sha256 `cc7e953974185ac4aa4c1291d3e27e08fc999a76bc5f82b5471d7a31900af16f`(`manifest.json`의 `bank_sha256`).
  이 감사는 이 바이트의 은행에 대한 것이다. 은행을 고치면 이 감사 결과는 그 은행에 옮겨 가지 않는다.
- **지침**: `../qualification/rater_protocol.md` 그대로(지문 `rater_protocol_sha256`). 자격 측정과 같은 지침이어야
  측정한 검출률이 은행 감사로 옮겨 간다.
- **묶음**: CLI `bank-sheets`가 은행을 `problem_id` 순으로 정렬한 뒤 문자열 시드 `20261008:bank-audit-order`로 섞어
  63건씩 8묶음으로 나눈다(자격 측정 묶음 60건에 가장 가까운 등분). 필드는 시험지와 같고 `item_id` 자리에
  `problem_id`가 들어간다. 묶음 파일은 판정자 격리를 위해 저장소 밖에 두고, 묶음별 sha256만 `manifest.json`에 둔다
  (`bank-sheets --check`로 재생성 대조).
- **판정자**: 묶음마다 서로 다른 판정자 2명이 따로 판정한다. 판정자 A 라벨 = 8묶음의 첫째 판정자 라벨을 합친 것,
  판정자 B = 둘째. 자격 측정과 같은 지시문(입력 폴더 경로·묶음 크기만 다르다).
- **판정 규칙**: 하나라도 `defect`면 결함(합집합). S5 = Wilson 단측 97.5% 상한(k, 504) ÷ 검출률 단측 97.5% 하한
  ≤ 0.02. 실측 자격 결과(120/120)에서 **k ≤ 3이면 통과**다.
- **as-found**: 결함 판정을 받은 문항을 교정한 뒤 같은 504건을 다시 채점해 불합격을 합격으로 바꾸지 않는다.
  교정본은 새 은행(새 지문)이고 새 감사를 받는다. 결함 판정 문항을 걸러 내고 나머지만 승인하는 것도 하지 않는다 —
  계약 `docs/standards/review_status_stamping_contract.md` §5.3(걸러 낸 집합의 결함률은 선택 편향)이 금지한다.

## 예상(판정 전 기록)

자격 측정의 오경보율 점추정은 6/120 = 5%다. 은행이 실제로 무결해도 504건에서 오경보만으로 k ≈ 25가 기대되므로
**이 감사는 불합격할 가능성이 높다.** 그래도 돌리는 이유: 결함 판정 목록이 은행 교정의 입력이고, 자격 측정의 오경보
6건이 전부 "미분 없이 풀림"이었다는 점이 그 부류가 실제 잔여 결함인지(교정 대상) 판정자 성향인지(오경보)를 가르는
재료가 된다. 교정 후 재감사는 새 측정이다.
