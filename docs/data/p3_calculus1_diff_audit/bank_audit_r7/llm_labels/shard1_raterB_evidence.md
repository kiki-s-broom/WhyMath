# 판정 근거 — calc_shard1_B (shard1.jsonl, 63건)

결함 판정 0건. 모든 문항을 `defect`로 표시하지 않았으므로 결함별 근거 항목이 없다.

## 판정 방법 (기록용)
- 63건 전부 발문만 보고 직접 다시 풀었다(손계산 + SymPy `check.py`, `check2.py`, 이 폴더). 직접 푼 값이 모두 `answer`와 일치했다.
  - 극값 문항(1, 12, 38, 51, 53번째 등): f'(x)=0의 근마다 좌우 부호 변화를 확인해 극대/극소/극값 아님을 판정.
  - 실근·교점 개수 문항: real_roots로 개수 확인(2, 14, 18, 48번째 문항 등).
  - 평균값 정리 문항: 평균변화율과 열린구간 안의 c를 직접 계산(6, 15, 20, 33, 42, 47, 55, 58, 60번째 등).
  - 미정계수 문항: 연립해 a, b, k를 구하고 극대·극소 종류까지 확인(3, 13, 27, 29, 34, 44번째 등).
- 객관식 오답 선지–오개념 연결: choice_index를 0부터 세는 방식으로 일관되며, 연결된 선지는 모두 설명된 잘못된 절차로 실제로 나온다
  (예: x=2t^4-6t에서 지수 내리기 누락 → 2t^3-6 → 48, 지수 줄이기 누락 → 8t^4-6t → 630; 롤의 정리 혼동 → f'(c)=0의 근 2/3, 1/3;
  극값·극점 혼동 → 0개; 곱의 미분 f'g' → -12). 정답 선지에 연결된 오개념 없음.
- 해설의 도함수·중간값·인수분해를 검산했고 오류를 찾지 못했다. 학생 대면 텍스트에서 조사·코드 표기·부호 표기 결함을 찾지 못했다.
- verify는 일부가 변형된 꼴(예: 5·57번째의 c·m, c+m 인코딩, 8·35·43·46번째의 평행이동 다항식, 22번째의 기울기 m에 대한 삼차방정식)이지만
  모두 발문과 같은 함수·같은 대상을 가리키며 같은 값을 준다(SymPy로 확인). 발문–검산 불일치로 보지 않았다.
