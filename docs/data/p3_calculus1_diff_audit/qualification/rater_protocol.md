# P3-03 미분 문항 LLM 판정자 지침 (사전 등록)

> **지위**: 자격 측정(`blind_240.jsonl`)과 은행 감사(`problem_bank_p3_calculus1_diff_v0`)에 **같은 지침을 그대로** 쓴다.
> 지침이 다르면 자격 측정에서 잰 검출률이 은행 감사로 옮겨 가지 않는다. 이 파일은 판정을 시작하기 전에
> 커밋한다. 판정을 받은 뒤 지침을 고치면 그 측정은 무효이고 새 시험지로 다시 잰다.
>
> **등록**: 2026-10-08 · 태스크 `P3-03-coverage-fill` · 근거 `docs/standards/superhuman_verification_standard.md` §3

## 판정자에게 주는 것

- 문항 JSONL 한 묶음(판정자가 볼 수 있는 유일한 자료). 필드: `item_id`(또는 은행 감사에서는 `problem_id`),
  성취기준 코드, 슬롯 태그, 문항 형식, 답 형식, 발문, 선지, 정답, 해설, 오답 선지–오개념 연결(오개념 설명 포함),
  기계 검산 재료(`verify`: 조건식·정답 맵·풀이 단계).
- 이 지침 본문(아래 "판정 기준"과 "산출 형식").

## 판정자가 하지 않는 것

- 저장소의 다른 파일(은행·생성기·판정기·테스트·감사 기록·README·정답지)을 읽지 않는다. 다른 판정자의 결과를 보지 않는다.
- 묶음에 결함 문항이 몇 건 들어 있는지 짐작해 판정을 맞추지 않는다. 문항마다 따로 판단한다.

## 판정 기준 — 하나라도 해당하면 `defect`

정답은 **발문만 보고 직접 새로 푼다**(SymPy 또는 손계산). `verify`를 다시 돌려 통과를 확인하는 것은 판정이 아니다.

1. **정답 오류** — 직접 푼 값이 `answer`와 다르다. 객관식이면 정답 선지가 직접 푼 값과 다르다.
2. **정답이 하나로 정해지지 않음** — 발문의 조건만으로는 해가 둘 이상이다(양수·구간·대소 같은 유일성 조건이 빠짐),
   또는 조건이 서로 모순이다, 또는 답 형식(자연수·정수·분수·실수)과 정답 값이 맞지 않는다.
3. **미분 없이 풀림** — 그 성취기준의 인지 행동(도함수·미분계수·평균값 정리·증감 판정 등)을 쓰지 않고도 현실적인
   경로로 정답에 닿는다. 예: 발문이 답을 정하는 핵심 값(극값의 위치, 평균변화율, 최솟값의 위치 등)을 이미 알려 줌,
   대입·인수분해·판별식·꼭짓점 공식만으로 끝남, 어떤 오답 경로로 풀어도 같은 값이 나와 변별이 없음.
4. **문장·표기 결함** — 수·변수·프라임 뒤 조사 오류, 조사 중복, 맞춤법 오류, 정의 없이 쓰인 기호, 한 기호를 두 대상에
   씀, 부호·계수 표기 깨짐(`+ -`, `- -`, `1x`, `1*`), 학생 대면 텍스트의 코드 표기(`<=`, `>=`, `*`, `sqrt(`),
   수학적으로 틀린 서술, 용어 오용.
5. **해설 결함** — 해설의 계산·식이 틀렸다(중간 값 포함), 결론만 말하고 핵심 중간 단계(도함수 식·세운 방정식·부호
   판단)가 없다, 발문에 없는 기호를 소개 없이 쓴다, 발문이 묻는 것과 다른 대상을 다룬다.
6. **오답 선지–오개념 연결 오류** — 객관식에서 오개념이 연결된 선지가 그 오개념의 절차(설명에 적힌 잘못된 방법)로
   실제로 나오지 않는 값이다, 또는 정답 선지에 오개념이 연결돼 있다. 연결이 없는 오답 선지는 결함이 아니다.
7. **발문–검산 불일치** — 발문에 적힌 함수·수치·묻는 대상과 `verify`(조건식·정답 맵)가 서로 다른 문제를 가리킨다.

확신이 낮은 의심도 `defect`로 표시하고 근거에 "불확실"이라고 적는다. 판정은 `verdict`만 채점에 쓰이며,
`defect_class`와 근거는 기록용이다.

## 산출 형식

- 라벨 파일: 줄마다 `{"item_id": "…", "verdict": "ok" | "defect", "defect_class": "…"}`(은행 감사에서는
  `item_id` 자리에 은행 `problem_id`). 받은 문항 전부, 중복 없이. `defect_class`는 위 1~7의 이름(정답 오류 ·
  해 불명확 · 미분 없이 풀림 · 문장 표기 · 해설 · 오개념 연결 · 발문 검산 불일치) 중 하나, `ok`면 빈 문자열.
- 근거 파일(기록용): 결함마다 문항 id · 분류 · 확신도(확실/중간/불확실) · 근거(발문 인용 + 직접 푼 값과 문항 값).
  빈 근거·자리표시자는 금지.

## 묶음 구성 (사전 등록)

- 자격 측정: 시험지 240건을 시험지 순서대로 60건씩 4묶음으로 나누고, 묶음마다 서로 다른 판정자 2명이 따로 판정한다.
  판정자 A 라벨 = 4묶음의 첫째 판정자 라벨을 합친 것, 판정자 B = 둘째 판정자 라벨을 합친 것(문항마다 독립 판정자 2명).
- 은행 감사: 같은 방식으로 504건을 묶음으로 나눠 묶음마다 판정자 2명.
- 프로토콜 판정: 기계 게이트 ∪ 판정자 A ∪ 판정자 B — 하나라도 `defect`면 결함.

## 채점 규칙 (사전 등록 — 판정을 받은 뒤 바꾸지 않는다)

- 합격 기준은 `qualification/README.md`의 표(Kiki 결정 2026-10-08)와 코드 상수 `criteria()`가 정본이다.
- 정상 문항(정답지상 결함 없음)을 결함으로 본 판정은 **예외 없이 오경보**로 센다. 채점 뒤 그 문항이 은행의 실제 잔여
  결함으로 보여도 라벨을 고치지 않는다(사후 재라벨 = 재채점 금지). 그런 문항은 기록해 은행 교정에 넘기고, 필요하면 새
  시험지로 다시 잰다.
- **S5 보정의 신뢰도**: 은행 S5 판정에 쓰는 두 경계(은행 결함 판정 수의 Wilson 상한, 프로토콜 검출률의 Wilson
  하한)는 **각각 단측 97.5%**로 계산한다. Bonferroni로 합성 신뢰도 ≥ 95%가 되어 초인간 검증 S5의 "95% 상한"과
  맞는다. 자격 측정의 합격 판정(검출률 95% 하한 ≥ 0.90 등)은 그대로 둔다.
