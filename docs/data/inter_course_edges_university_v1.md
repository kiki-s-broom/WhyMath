## 1. 왜 필요한가 (착수 시점 실측)

| 항목 | 값 |
|---|---|
| 대학 노드 | 1,069 (그중 세부개념 512 · 32개 과목) |
| 과목 *안* 엣지 | 479 |
| 과목 *간* 엣지 | **2** (수치해석↔미적분학 I) |
| 대학 과목의 연결 성분 | 31개 (32과목이 사실상 고립 사슬) |

해석학 I → 해석학 II, 현대대수학 I → II 같은 명백한 계열조차 이어져 있지 않았다.
슬라이스 1(고등→대학 24건)만으로는 6개 과목의 입구만 열리고, 그 안쪽 사슬이 서로 이어지지
않으면 K-12에서 출발한 학습 경로가 대학 축 대부분에 닿지 못한다.

## 2. 설계 원칙

- **희소 연결**: 과목 쌍은 992개(32×31)인데 제안은 **66쌍**에만 걸고, 쌍당 **최대 4건**이다.
  상한은 문서 약속이 아니라 검증기 규칙 `pair_density_cap`(error)이 집행한다.
- **신규 relation 타입 0건**: 전부 `prerequisite`. `relation_subtype`은 `과목간(추정)` — 기존
  과목간 엣지 2건의 표기(`소단원간`)와 구분되도록 새 표기를 썼다(메타일 뿐 새 관계 타입이 아니다).
- **노드 추가·수정 0건**: 양끝은 모두 정본의 대학 세부개념 원자다.
- **출처 구분**: `evidence = "S4-01 대학 과목간 저작 v1"`.
- **근거 동반 의무**: 레코드마다 `rationale`이 있고 비면 검증기가 error를 낸다.
- **채택 기준**: "같은 개념의 직접 계승" 또는 "이 개념 없이는 저 개념의 정의·증명이 서지 않는" 의존만.
  단순 연상·주제 유사는 채택하지 않았다.

## 3. 측정 — 4축 활성을 노드 존재가 아니라 도달 가능성으로

고등 세부개념에서 선수 방향으로 도달 가능한 대학 세부개념 수다
(`university_reachability`, 결정론·읽기 전용).

| 가정한 병합 범위 | 도달 대학 세부개념 | 도달 과목 | 과목 연결 성분 |
|---|---|---|---|
| 정본만 | 0 / 512 (0.0%) | 0 / 32 | 31 |
| 슬라이스 1(고→대 24건)만 | 198 / 512 (38.7%) | 7 / 32 | 31 |
| **이번 제안(137건)만** | 0 / 512 | 0 / 32 | **2** |
| **슬라이스 1 + 이번 제안** | **466 / 512 (91.0%)** | **31 / 32** | 2 |

세 번째 줄이 중요하다 — 과목 사이를 잇기만 해서는 K-12에서 한 걸음도 갈 수 없다(진입로가 없다).
두 제안은 **함께일 때만** 의미가 있고, 한쪽만 병합하면 반쪽 효과다. 이 비율은 테스트가 동결한다.

### 도달하지 못하는 46개 (정직 고지)

대부분 각 과목의 **첫 진입 개념**이다(예: `CALC1-C01` 함수는 입력 하나에 출력 하나,
`SETLOG-C01` 조건문은 전건이 거짓이면 참). 이를 잇는 K-12 엣지는 슬라이스 1 범위(남은 범위 ⒠)이며
이번 슬라이스가 닫지 않는다. 졸업세미나(`CAPST-P01~04`)는 내용상 선수가 없어 의도적으로 제외했다.
유입 엣지가 없는 과목: 미적분학 I · 선형대수학 I · 집합과 논리(= K-12가 직접 들어올 입구) · 졸업세미나.

## 4. 저작 중 기계가 거부한 것

`CALC1-C26 → NUMER-C01`(테일러 근사 → 절단오차)을 처음 저작했으나 **순환**이 되어 거부됐다.
정본에 `NUMER-P01 → CALC1-C16`이 이미 있어, 수치해석 사슬(`NUMER-C01→…→NUMER-P01`)이 미적분학 I
사슬(`CALC1-C16→…→CALC1-C26`)로 되돌아오기 때문이다. 이 엣지는 제안 단독으로는 순환이 보이지 않고
정본과 합칠 때만 보인다(`acyclic_when_merged`가 정본 엣지를 포함해 판정하는 이유 — 테스트
`test_m7b`가 동결). 교육적으로도 절단오차의 직접 선수는 해석학 II의 "테일러는 나머지항이 핵심"
(`ANAL2-C02`)이 더 정확해서 그 엣지로 교체했다.

## 5. 정본 병합 조건 (아직 병합하지 않는 이유)

기계 검증은 **구조**만 판정한다 — "이 개념이 저 개념의 선수인가"는 기계 증명 대상이 아니다.

1. **사람 검수 승인** — 게이트 `G-s401-inter-course-edge-review`. 부분 승인이 정상이며, 반려분은
   생성 스크립트의 저작 목록에서 제거한 뒤 재생성한다(손편집 금지 · `--check`가 바이트 동일 보증).
   과목 쌍(§6 표의 묶음) 단위로 승인·반려하면 검수 부담이 줄어든다.
2. **스키마 처리** — `AtomEdge`는 `extra="forbid"`라 `rationale`을 받지 못한다. 슬라이스 1 문서 §5와
   같은 세 안(evidence 합성 / 모델 필드 추가 / 제안 파일을 근거 원장으로 유지) 중 하나를 병합 세션이
   명시적으로 결정한다. **슬라이스 1과 같은 결정을 쓰도록 한 번에 병합하는 것을 권장한다.**
3. 병합 시 `_meta.source_graph_sha256`이 당시 `graph.json`과 다르면 재검증부터 한다.

## 6. 기계 검증

```bash
cd src/data-pipeline
python -m data_pipeline.atom_graph.inter_course_edges \
    --proposal ../../data/corpus/atom_graph_v1/inter_course_edges_university_v1.json \
    --graph ../../data/corpus/atom_graph_v1/graph.json \
    --also-proposal ../../data/corpus/atom_graph_v1/cross_band_edges_university_v1.json
```

exit 0 = error 0건. 읽기 전용. **현재 판정: error 0 · warning 0 (137건 전건 통과).**

| 규칙 | 심각도 | 무엇을 막는가 |
|---|---|---|
| `endpoint_exists` | error | 정본에 없는 code로 유령 엣지를 만드는 것 |
| `direction_inter_course` | error | 학교급을 넘는 엣지·같은 과목 안 엣지가 섞이는 것 |
| `level_detail_concept` | error | 단원·소단원 컨테이너에 선수관계를 거는 것 |
| `no_duplicate` | error | 제안 내부 중복, 정본에 이미 있는 엣지 재등재 |
| `relation_prerequisite_only` | error | prerequisite 외 관계 타입 유입 |
| `rationale_present` | error | 교육적 근거 없는 엣지 |
| `pair_density_cap` | error | 과목 쌍당 4건 초과(관계 폭발) |
| `acyclic_when_merged` | error | 정본과 합쳤을 때 순환 선수관계 |
| `subject_coherence` | warning | 허용 과목 쌍 표에 없는 쌍 — 검수자 확인 신호 |

변별력: 검증기 **절 단위 뮤테이션 20종 전건 RED·생존 0**(절 무력화·경계값 `>`→`>=`·정본 엣지 무시·
warning→error 승격·도달성 판정/출발점/성분 병합 무력화·CLI 항상 성공 등), 정상 대조군 GREEN.
도달성 측정도 제안 단독 → 0이라는 대조군으로 값을 지어내지 않음을 증명한다.
