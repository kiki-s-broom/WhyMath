## 1. 왜 필요한가 (착수 시점 실측)

| 항목 | 값 |
|---|---|
| 개념 노드 | 2,683 |
| 선수 엣지 | 2,210 (전량 `prerequisite`) |
| 학교급 경계 통과 엣지 | 20건 (0.90%) |
| **고등→대학 엣지** | **0건** |
| 대학 노드 | 1,069 (그중 세부개념 512) |

고등→대학 엣지가 0건이므로 대학 1,069노드는 **K-12 쪽에서 도달 불가능한 섬**이다.
학습 경로 탐색(traversal)이 고등 개념에서 출발하면 대학 축으로 한 걸음도 갈 수 없다.
이 슬라이스는 그 경계에 24개의 다리를 놓는 *제안*이다.

## 2. 설계 원칙

- **희소 연결**: 전수 연결이 아니다. 기존 중→고 경계 관례(중학 원자 225건에 경계 엣지 11건)와
  같은 밀도의 희소 설계 — 경계는 "모든 개념이 이어지는 면"이 아니라 "몇 개의 관문"이다.
  (구축 플레이북 "관계 폭발 금지" — 엣지는 N²로 늘 수 있고 그 순간 traversal과 AI 추론이 무너진다.)
- **신규 relation 타입 0건**: 전부 `prerequisite`. `학교급간(추정)`은 `relation_subtype`
  메타일 뿐 새 관계 타입이 아니다(기존 경계 엣지 8건과 같은 표기).
- **노드 추가·수정 0건**: 양끝은 모두 정본에 이미 있는 세부개념 원자다.
- **출처 구분**: `evidence = "S4-01 고→대 경계 저작 v1"` — 기존 백본 엣지(`"원자 백본 v1"`)와
  구분돼야 사후에 "이 엣지는 누가 왜 놓았나"를 추적할 수 있다.
- **근거 동반 의무**: 레코드마다 `rationale`(교육적 근거 산문)이 있고, 비면 검증기가 error를 낸다.

## 5. 정본 병합 조건 (아직 병합하지 않는 이유)

기계 검증(§6)은 **구조**만 판정한다 — "이 엣지가 교육적으로 옳은가"는 기계 증명 대상이 아니다.
따라서 다음 두 조건이 모두 충족돼야 정본에 병합한다.

1. **사람 검수 승인** — 게이트 `G-s401-uni-boundary-edge-review`. 부분 승인(일부 엣지 반려)이
   정상 결과이며, 반려분은 제안 파일에서 제거한 뒤 재생성한다(저작 목록은 스크립트 상수가 정본).
2. **병합 시 스키마 처리** — `AtomEdge` 모델은 `extra="forbid"`라 `rationale` 필드를 그대로
   받지 못한다. 병합 세션은 ⒜ `rationale`을 `evidence`에 합성해 넣거나 ⒝ 모델에 필드를
   추가하거나 ⒞ 제안 파일을 근거 원장으로 남기고 정본에는 스키마 호환 필드만 넣는 셋 중
   하나를 **명시적으로 결정**해야 한다. 이 슬라이스는 그 결정을 하지 않는다.

병합은 **별도 세션 소관**이다. 그때 `_meta.source_graph_sha256`이 당시 `graph.json`과 다르면
정본이 그 사이 바뀐 것이므로 재검증부터 한다.

## 6. 기계 검증

```
cd src/data-pipeline
python -m data_pipeline.atom_graph.cross_band_edges \
    --proposal ../../data/corpus/atom_graph_v1/cross_band_edges_university_v1.json \
    --graph ../../data/corpus/atom_graph_v1/graph.json
```

exit 0 = error 0건(성공), exit 1 = error 1건 이상. 검증기는 **읽기 전용**이다(어떤 파일도 쓰지 않는다).

| 규칙 | 심각도 | 무엇을 막는가 |
|---|---|---|
| `endpoint_exists` | error | 정본에 없는 code(오타·구 코드)로 유령 엣지를 만드는 것 |
| `direction_high_to_university` | error | 역방향(대학→고등)·동급(대학→대학) 엣지가 경계 엣지로 섞이는 것 |
| `level_detail_concept` | error | 단원·소단원 같은 **컨테이너** 노드에 선수관계를 거는 것 |
| `no_duplicate` | error | 제안 내부 중복, 그리고 정본에 이미 있는 엣지의 재등재 |
| `acyclic_when_merged` | error | 병합 시 순환 선수관계 발생(= 학습 경로 구성 불능) |
| `relation_prerequisite_only` | error | `prerequisite` 외 관계 타입 유입(관계 타입 폭발) |
| `rationale_present` | error | 교육적 근거 없는 엣지 |
| `subject_coherence` | **warning** | 계열이 낯선 과목 쌍 — 차단이 아니라 검수자 확인 신호 |

**현재 판정: error 0건 · warning 0건 (제안 24건 전건 통과).**

검증기 자체의 변별력은 테스트가 증명한다 — 뮤테이션 9종(존재하지 않는 code · 방향 역전 ·
대학→대학 · 컨테이너 code · 제안 내부 중복 · 정본 중복 · 병합 사이클 · 빈 근거 · 외래 relation)
전건 RED + **정상 대조군 GREEN**. 대조군이 없으면 "모든 입력을 error로 뱉는 과잉 검증기"도
뮤테이션 전건 RED로 위장할 수 있다.

또한 *검증기 자신*의 검사 절 12종(검사 8종 + 중복 규칙의 두 축 + CLI 종료코드 판정 + CLI 파일부재
가드)을 하나씩 무력화하는 절 단위 뮤테이션에서 **12종 전건 RED·생존 0**을 확인했다 — 각 테스트가
정말 그 절을 밟는다는 뜻이다(픽스처가 절에 닿지 않아 뮤테이션이 살아남는 사고 선례 대비).

## 7. 이 슬라이스가 닫지 않는 것

- 대학 과목 **간** 엣지(현재 2건뿐 — 32개 고립 사슬 상태)는 그대로다.
- 24건이 진입하는 대학 과목은 6개뿐이다. 나머지 26개 대학 과목의 경계 진입은 미착수.
- 대학 코드를 참조하는 문항은 여전히 0건(문제은행 축은 별건).
- traversal 성능 예산 실부하 측정은 미실행.
