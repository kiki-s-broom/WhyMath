# 시스템 우월성 유지 표준 (SSM · System Superiority Maintenance)

> **작성일**: 2026-07-09 | **버전**: 1.0 | **범위**: 프로세스 표준(문서 전용) · **적용**: 전 계층(L1~L7)·전 스택
>
> **한 줄**: "무너지는 것을 감지하는 상시 방어"를 넘어, **새 기술·데이터 트렌드를 주기적으로 능동 스캔하고 도입을 게이트로 관리해 시스템의 상대적 우월성을 유지**하는 규율.

---

## 1. 목적·배경 (왜 필요한가)

WhyMath에는 시스템 건강을 지키는 장치가 이미 있으나, **전부 사후·수동(reactive)이거나 애드혹**이다:

1. **상시·수동 방어(reactive)** — `s1_structure_audit_2026-07.md`·`math_ai_failure_checklist.md`·CLAUDE.md "7대 붕괴 연쇄"·"성능 병목"·token budget guard. *이미 무너지는 것*을 감지·상환한다.
2. **애드혹 스택 변경 기록** — CLAUDE.md 기술 스택 표 규칙 "변경하려면 MEMORY.md에 결정 로그 필수". 사람이 필요를 느낄 때만 발동 → *능동·주기 스캔 아님*.
3. **주기 검토는 있으나 기술 트렌드용 아님** — ROADMAP "1주 회고·월간 검토"(사업 지표), `docs/legal/copyright_guide_v2.md` §10 "모니터링·갱신 체계"(저작권 한정).

**갭**: "새 LLM·OCR·벡터DB·교수학 기법·경쟁 서비스가 등장했는가? 우리 스택은 여전히 우월한가?"를 *주기적으로 능동적으로* 묻고 도입 여부를 시스템적으로 관리하는 규율이 없다. 기술·데이터는 양적·질적으로 빠르게 변하므로, 이 부재는 **조용한 상대적 열위(silent obsolescence)** 리스크다. 본 표준이 그 규율을 신설한다.

**본 표준이 하지 않는 것(경계)**: SSM은 *새 방어 인프라를 만들지 않는다*. 붕괴·부하 감지는 기존 reactive 장치가 계속 담당하고, SSM은 그 위에 **능동 스캔·도입 게이트 층**만 얹는다.

## 2. 2층 구분 (핵심 프레임)

| | **L-방어 (Reactive · 기존)** | **L-우월 (Proactive · 본 표준 신설)** |
|---|---|---|
| 질문 | "지금 무너지고 있는가?" | "더 나은 것이 등장했는가? 우리는 여전히 우월한가?" |
| 트리거 | 붕괴·부하·오류 신호 발생 시 | 주기(분기) + 임계 초과·외부 신제품 |
| 담당 | 붕괴 감사·성능 가드·failure checklist | 지평 스캔(Horizon Scan) → 도입 게이트 |
| 산출 | 상환 목록·핫픽스 | 도입/파일럿/보류/기각 판정 → MEMORY 로그 |
| 실패 시 | 시스템 다운·품질 붕괴 | 조용한 상대적 열위·기술 부채 누적 |

> 두 층은 **상보**다. L-방어가 없으면 SSM이 좇는 신기술이 시스템을 무너뜨리고, L-우월이 없으면 방어만 하다 서서히 뒤처진다.

## 4. 주기·트리거 (언제 스캔하나)

### 4-1. 분기별 심층 지평 스캔 (Horizon Scan · 3개월)
- 4대 축을 순회하며 "지난 분기 대비 무엇이 바뀌었나 / 우리보다 나은 후보가 등장했나"를 조사.
- 산출: 축별 후보 목록 + 각 후보의 도입 게이트(§5) 1차 판정 → 분기 스캔 리포트(§8).
- **1인 capacity 가드**: 심층 스캔은 분기 1회로 제한. 매주·매월 상시 조사는 금지(과부하·컨텍스트 오염).

### 4-2. 즉시 트리거 (분기 대기 없이 발동)
아래 임계 초과·이벤트 시 해당 후보만 즉시 게이트에 올린다. 임계값은 **기존 하네스 대리 지표**(ROADMAP "WH-1 0단계 대리 지표 7종·Langfuse")를 재사용하고, 초기값은 ROADMAP "게이트 미달 시그널"과 정합한다.

| 트리거 | 임계·이벤트 예시 |
|---|---|
| 비용 드리프트 | 학생당 월 LLM 비용이 목표(예: 2,000원) 접근·초과 |
| 지연 드리프트 | 핵심 경로 p50/p95가 SLA 대비 회귀 |
| 정확도 드리프트 | PRM 통과율·검증 커버리지가 베이스라인 대비 하락 |
| 외부 신제품 | 수학·한국어 SOTA 신모델, 경쟁 신제품 출시 |
| 법·규제 변화 | 저작권·개인정보·미성년 규제 개정(→ 법무 우선) |

## 5. 도입 게이트 (5단계: 포착 → 평가 → 판정 → 기록 → 회귀)

새 기술·데이터 후보는 아래 게이트를 통과해야 도입된다. **게이트는 "더 나은가?"가 아니라 "우리 우선순위 안에서 더 나은가?"를 묻는다.**

**① 포착** — 스캔/트리거로 후보 식별. 무엇이 왜 우월해 보이는지 1~2줄.

**② 평가** — 아래 세 관문을 *모두* 통과해야 한다:
- **(a) 가치 우선순위 종속** — CLAUDE.md 의사결정 우선순위(`1.학생 안전·웰빙 → 2.법적·윤리 → 3.교수학 정확성 → 4.학습 효과 → 5.UX → 6.비용·효율 → 7.개발 속도`)에 **종속**. 우월성(주로 5~7)이 상위(1~4)를 **역전하면 자동 기각**. *"이 순서는 협상 불가"*.
- **(b) 측정 없는 도입 없음** — ROADMAP 하네스 단계화 원칙. 베이스라인 대비 개선을 **대리 지표로 실측**할 계획이 없으면 도입 불가(파일럿까지만).
- **(c) 구조 붕괴 방어** — CLAUDE.md 8대 구조 원칙·작업 전/후 하드 게이트 통과. 새 기술이 노드/관계 폭발·Concept Purity·context slimming·단일 진실 원천을 깨지 않는지. (특히 새 저장소·새 관계 타입·새 LLM 컨텍스트 주입 방식은 붕괴 연쇄 재검토.)

**③ 판정** — 4택 1:
- **도입** — (a)(b)(c) 전부 통과 + 실측 개선 확인.
- **파일럿** — 유망하나 측정 필요. 측정 지표·기간·재판정 시점 명시.
- **보류** — 지금은 아님. **재검토 시점을 반드시 기록**(예: "Phase 2 진입 시").
- **기각** — 부적합. **사유 기록**(우선순위 역전·붕괴 위험·법적·비용).

**④ 기록** — 판정은 **MEMORY.md 결정 로그로 배출**(단일 진실 원천). 스택이 실제 바뀌면 **CLAUDE.md 기술 스택 표 + 결정 로그 링크**를 갱신(기존 규칙 재사용). 선례: `pgvector`(슬98)·`PaddleOCR+Qwen3-VL`(2026-05-28)·Flutter 단일 클라(슬89).

**⑤ 회귀** — 도입 후 대리 지표로 개선을 재확인. 열화 시 롤백 또는 재판정. 파일럿은 재판정 시점에 자동 재진입.

## 6. 우월성 KPI (무엇을 "우월"로 재나)

우월성은 단일 숫자가 아니라 **의사결정 우선순위와 정렬된 다축**이다. 상위 축의 열위는 하위 축의 우위로 상쇄 불가:

1. **교수학 효과** — 장기 숙달·메타인지·답 미루기 정합 (최상위, 대체 불가)
2. **정확성·신뢰** — PRM 통과율·검증 커버리지·환각률
3. **법적·안전** — 라이선스 안전·미성년 개인정보·정서 안전
4. **비용·지연** — 학생당 LLM 비용·p50/p95·로컬화 비율
5. **운영 단순성** — 1인 유지가능성·스택 복잡도

> 예: "정확도 +2%, 비용 −30%지만 라이선스 회색지대"인 후보 → **3축 위반으로 기각**. 5·6번(비용) 때문에 1~3번을 양보하지 않는다.

## 7. 기존 시스템과의 연계

SSM은 독립 사일로가 아니라 기존 규율에 **물려 돌아간다**:

| 연계 대상 | 관계 |
|---|---|
| 붕괴 감사·성능 가드 (reactive) | SSM 게이트 ②(c)가 이들의 8원칙·하드 게이트를 재사용. SSM은 방어 장치를 대체하지 않고 그 통과를 도입 조건으로 요구 |
| MEMORY.md 결정 로그 | SSM 판정의 **배출구**(단일 진실 원천). 애드혹 스택 변경 규칙을 능동 스캔으로 승격 |
| CLAUDE.md 의사결정 우선순위 | SSM 평가의 **상위 헌법**. 우월성은 이 순서에 종속 |
| ROADMAP 검토 주기 | 분기 스캔이 ROADMAP 월간/게이트 검토와 동기. 즉시 트리거 임계는 "게이트 미달 시그널"과 정합 |
| 하네스 대리 지표(Langfuse) | 트리거 임계·도입 측정의 **계측 원천**("측정 없는 도입 없음") |

## 8. 산출물·기록 규약

- **분기 스캔 리포트**: `docs/standards/ssm_scan_YYYY-Qn.md` (예: `ssm_scan_2026-Q3.md`). 없으면 MEMORY.md 결정 로그 항목으로 대체 가능.
- **개별 도입 판정**: MEMORY.md 핵심 결정 로그(시간 역순 최상단)에 축·후보·판정·근거·범위 기록.
- **스택 실변경**: CLAUDE.md 기술 스택 표 갱신 + 결정 로그 링크(기존 규칙).

### 분기 리마인더 스케줄 (Routine 스펙)

> 분기 스캔이 "잊혀서 안 도는" 실패를 막기 위한 표준 스케줄. **라이브 Routine 생성은 대화형 세션(승인 게이트 통과 가능한 환경)에서 아래 스펙 그대로 만든다** — 비대화형/자동 세션에서는 스케줄링 도구가 승인 게이트에 막힐 수 있어, 본 스펙 문서가 진실 원천(대화 휘발 방지)이다. 생성 전까지는 수동 발동(분기 1일 캘린더 알림)으로 대체.

- **이름**: `SSM 분기 지평 스캔 (자동)`
- **cron**: `0 0 1 1,4,7,10 *` — 1/4/7/10월 1일 00:00 UTC(=09:00 KST). 분기 주기(§4-1)와 정합. 다음 발동 앵커 = **2026-10-01(Q4)**.
- **모드**: 발동 시 **새 세션 생성**(fresh-session-per-fire) — 세션 컨테이너는 휘발성이라 특정 세션 바인딩 대신 매 분기 클린 세션이 스캔을 수행. 완료 시 **푸시 알림**.
- **정책**: 스캔·리포트 산출까지 자동, **PR은 draft로 열고 auto-merge 금지** — 판정에 사람 판단이 필요하므로 Kiki 검수·머지. 즉시 트리거(§4-2)는 별개(수동/조기 발동).
- **발동 프롬프트(독립 지시문 요지)**: 본 표준(§3~§9)·최신 `ssm_scan_*.md`·`CLAUDE.md` 스택표·`MEMORY.md` 로그 숙지 → 4축 능동 조사(SEO 단일출처는 `[불확실]`·1차 출처 교차검증) → §5 게이트 판정(라이브 계측선 미가동이면 "도입" 금지·파일럿/보류) → `ssm_scan_YYYY-Qn.md`(§8 템플릿·직전 대비 델타) 작성 → MEMORY 로그 1건 → 최신 `origin/main`에서 `claude/ssm-scan-YYYY-Qn` 브랜치·draft PR(auto-merge 미설정). 레포=`kiki-s-broom/WhyMath`.

## 9. 안티패턴·금기 (NEVER)

- ❌ **Hype 추종** — 신제품이라서·SOTA라서 도입 금지. 게이트(§5) 통과 없이는 후보일 뿐.
- ❌ **우선순위 역전** — 비용·성능·속도(5~7)로 학생 안전·법·교수학(1~3)을 양보 금지. "협상 불가".
- ❌ **측정 없는 도입** — 대리 지표 실측 계획 없는 채 프로덕션 투입 금지.
- ❌ **신기술로 구조 붕괴** — 새 저장소·관계 타입·컨텍스트 주입 방식이 8원칙·붕괴 연쇄를 깨면 도입 금지.
- ❌ **스캔 과부하** — 심층 스캔을 분기 1회 초과로 상시화 금지(1인 capacity·컨텍스트 오염).
- ❌ **경쟁 데이터 침해** — 경쟁 서비스 약관·데이터 추출·본문 복제로 트렌드 조사 금지. 공개 정보만.
- ❌ **LLM에 전체 그래프 투입** — 트렌드 조사를 AI로 할 때도 Minimal Reasoning Subgraph 원칙 준수(전체 그래프 통째 금지).
