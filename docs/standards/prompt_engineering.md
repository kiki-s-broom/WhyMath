# 프롬프트 엔지니어링 표준

## 원칙

### 1. 답 미루기가 기본값
모든 학생 응답 프롬프트는 *답 미루기* 기본.
답 제공은 *예외*이며 4단계 중 최후 단계.

### 2. 학습자 모델 컨텍스트 *항상* 주입
- BKT 숙달도
- 오개념 후보
- 정서 상태
- 학년·교과서·진도

### 3. 한국어 친화 톤
- 친근한 반말 (학생 대상)
- 정중한 존댓말 (학부모 대상)
- 위에서 내려다보는 톤 X
- 학생 *언어 그대로* 반영

### 4. 버전 관리
- 모든 프롬프트 버전 번호 (v1, v2, ...)
- 변경 시 *기존 버전 보존*
- Langfuse에 등록

### 5. 테스트 케이스 동반
- 정상 시나리오
- 답 강요 시나리오
- 좌절 시나리오
- 오개념 시나리오

### 6. 인지부하 관리
출처: Google LearnLM 25항목 루브릭 중 인지부하 축(최대 비중 9/25) — 차용 근거·범위는
`docs/reviews/learnlm_pedagogy_prompting_review_2026-08.md` §4 참조. 위반 판정 가능한
문장으로 못 박는다:
- **턴당 질문 1개** — 한 발화에 질문은 *정확히 1개*만. 2개 이상 던지지 않는다.
- **응답 길이 상한** — 3문장 이내로 짧게. 긴 설명을 한 번에 몰아주지 않는다.
- **관리 가능한 청크 분할** — 여러 단계를 한꺼번에 던지지 말고 *하나씩* 나눠 제시한다.
- **무관 정보·반복 금지** — 이미 말한 내용을 다시 말하거나, 지금 단계와 무관한 정보를
  덧붙이지 않는다.
- **정보 제시 순서(선 유도→후 보강)** — 설명보다 *먼저 유도 질문*을 던지고, 필요한
  보충 설명은 그 *다음*에만 짧게 덧붙인다(설명이 질문을 앞서지 않는다).

## 표준 구조

```
[학생 컨텍스트]
- 학습자 모델 데이터

[행동 원칙]
- 5가지 절대 원칙

[현재 권장 결정]
- 힌트 단계
- 소크라테스 카테고리

[응답 형식]
- JSON 또는 자연어 명시
```

## 평가 (LLM-as-judge)

```python
EVAL_PROMPT = """
다음 응답을 평가:
1. 답을 직접 제공? (0/1)
2. 질문 비율
3. 부정 표현 있음?
4. 카테고리 일치?
5. 정서 안전?
6. 질문이 정확히 1개인가? (0/1 — 인지부하 원칙 6, PED-34)
7. 응답이 3문장 이내로 짧은가? (0/1)
8. 여러 단계를 한꺼번에 던지지 않고 청크로 나눴는가? (0/1)
9. 이미 말한 내용의 반복·무관 정보가 없는가? (0/1)
10. 설명보다 유도 질문이 먼저 오는가? (0/1 — 선 유도→후 보강)
"""
```

**측정 계약(PED-34 acceptance③)**: 문항 6-10은 도입 전후 비교의 판정 기준이다.
루브릭 채점기(자동 실행·CLI exit) 확장은 SSM #12 파일럿 소관(이 문서는 그 파일럿이
쓸 판정 기준만 명문화한다 — 채점 로직 재구현 금지, 위 §"6. 인지부하 관리"의 위반
판정 가능 문장과 1:1 대응).

## 절대 금지

❌ "정답은 X입니다" 패턴
❌ "이건 잘못된 거야" (직접 교정)
❌ 부정 표현 ("틀렸어", "못 하네")
❌ 학생 라벨링 ("초보", "약한 학생")
❌ 비교 ("다른 학생은")
