# 단일 에이전트 + 업무 매뉴얼 방법론 (정본)

> 태스크: HARN-316 · 작성 2026-10-26 · 검사기 `scripts/manuals/manual.py` · 테스트 `tests/harness/test_manual_lint.py`

## 0. 한 줄 요약

에이전트를 여러 개 두거나 매번 채팅으로 고치는 대신, **업무마다 매뉴얼 1개**를 두고 한 에이전트가 그 매뉴얼대로 일한다. 매뉴얼에는 ① 절차 ② 쓸 도구(툴박스) ③ "완료"의 정의(완료 조건)가 들어 있고, 오류가 나면 **매뉴얼을 고친다**.

| 단계 | 하는 일 | 쓰는 것 | 기계가 막는 것 |
|---|---|---|---|
| 1. 매뉴얼 생성 | 에이전트가 사용자를 인터뷰해 매뉴얼을 채운다 | `/manual-interview <id>` · `manuals/_template/MANUAL.md` | 미해결 질문이 남았는데 ready 로 표시 |
| 2. 툴박스 세팅 | 승인된 스크립트·템플릿·파일을 머리말 `toolbox` 에 등록 | 머리말 `toolbox:` | 등록된 경로가 저장소에 없음 |
| 3. 완료 조건 검증 | 결과를 내기 전 완료 조건을 스스로 검사 | `/manual-run <id>` · `manual.py verify` | 확인 방법 없는 완료 조건 · ready 인데 기계 검사 0건 |
| 4. 피드백 루프 | 오류가 나면 해당 매뉴얼을 고치고 버전을 올린다 | `/manual-fix <id>` | 수정 위치 없는 실수 기록 · 변경 이력 없는 버전 |

## 1. 매뉴얼 한 개의 모양

위치: `manuals/<id>/MANUAL.md` (id = 폴더명 = 머리말 `id`). 두 부분으로 나뉜다.

- **머리말(YAML)** — 기계가 읽는 부분. `id · title · version · updated · readiness(draft|ready) · owner · open_questions · toolbox · verify`
- **본문 9절(고정 순서)** — 사람과 에이전트가 읽는 부분.
  1. 목적과 범위 · 2. 시작 전 입력 · 3. 절차 · 4. 판단 분기 · 5. 금지 · 6. 툴박스 사용 규칙 · 7. 완료 조건 자체 검사 · 8. 실수 카탈로그 · 9. 변경 이력

왜 이렇게 나눴나: 완료 조건과 툴박스는 **기계가 실행·확인**해야 하므로 구조화하고, 절차·판단은 사람이 읽고 고치기 쉬워야 하므로 산문으로 둔다.

## 2. 1단계 — 인터뷰로 매뉴얼 만들기

목표는 "사람이 없어도 일할 수 있는 수준"이다. 그 기준을 감(感)이 아니라 **멈춤 조건**으로 정한다.

**질문 8축** (`/manual-interview` 가 이 순서로 묻는다)

| 축 | 질문 예 | 채워지는 곳 |
|---|---|---|
| 목적 | 결과물은 누가 어디에 쓰나? | §1 |
| 범위 | 이 업무가 *아닌* 것은? | §1 |
| 입력 | 시작하려면 무엇이 있어야 하나? 없으면? | §2 |
| 절차 | 실제로 지난번에 어떤 순서로 했나? | §3 |
| 분기 | 애매할 때 보통 어떻게 정하나? 언제 사람에게 물어야 하나? | §4 |
| 금지 | 하면 안 되는 것·사고 났던 것은? | §5 · §8 |
| 도구 | 어떤 파일·스크립트·양식을 쓰나? | 머리말 toolbox |
| 완료 | "끝났다"는 걸 무엇을 보고 아나? 그걸 명령으로 확인할 수 있나? | 머리말 verify |

**멈춤 조건 (ready 로 올리는 기준)** — 전부 참이어야 한다:
- `open_questions` 0건 (답 못 받은 질문이 없다)
- §4 모든 분기에 기본 행동이 있다
- toolbox 1건 이상, 경로 전부 실재
- verify 중 `how: cmd` 1건 이상
- `manual.py lint` exit 0

인터뷰 규칙: 한 번에 3문항 이하로 묻는다 · 사용자가 모르면 그 질문을 `open_questions` 에 남기고 draft 로 둔다 · 저장소에서 알 수 있는 것(파일 위치·기존 스크립트)은 묻지 않고 직접 찾는다.

## 3. 2단계 — 툴박스

툴박스 = 에이전트가 이 업무에서 쓸 수 있는 **승인된 것의 목록**. 실물은 저장소의 원래 위치에 두고 매뉴얼은 경로만 가리킨다(복사하면 원본과 어긋난다).

- 등록 형식: `- path: <저장소 상대 경로>` + `role: <이 업무에서 무엇에 쓰나>`
- 규칙: 목록에 없는 스크립트를 즉석에서 만들어 쓰지 않는다. 필요하면 `/manual-fix` 로 먼저 등록한다.
- 기계 검사: 경로가 없으면 lint 실패 → 스크립트가 옮겨지거나 지워지면 매뉴얼이 곧바로 빨갛게 된다.

## 4. 3단계 — 완료 조건 (Verification List)

항목마다 **무엇이 참이어야 하는가(check)** 와 **어떻게 확인하나(how)** 를 둔다.

| how | 의미 | 필수 필드 | 판정 |
|---|---|---|---|
| `cmd` | 명령 실행 | `cmd` (`{name}` 자리는 `--arg name=값`) | exit 0 = 통과 |
| `read` | 산출물을 다시 읽고 대조 | `evidence` | 에이전트가 증거를 보고서에 적음 |
| `human` | 사람만 판정 가능 | `evidence` | 사람 확인 대기 |

실행: `python3 scripts/manuals/manual.py verify <id> --arg k=v` — cmd 항목은 실제 실행(타임아웃 300초), read·human 은 "증거 필요" 목록으로 출력. **❌ 가 하나라도 있으면 완료 보고 금지**, ⏳ 는 증거를 적은 뒤에만 완료.

좋은 완료 조건 만드는 요령: 가능한 한 `cmd` 로 바꾼다 → 실패 상태에서 실제로 실패하는지 한 번 확인한다(성공·실패 양쪽에서 같은 값을 내면 검사가 아니다).

## 5. 4단계 — 피드백 루프 (매뉴얼을 고친다)

오류가 났을 때 채팅에서 "다음엔 이렇게 해"라고만 하면 다음 세션은 모른다. 대신 `/manual-fix <id>` 로 매뉴얼을 고친다.

1. **분류** — 왜 틀렸나 (5종)
   - 절차 누락 → §3 · 분기 기본값 부재 → §4 · 금지 누락 → §5 · 도구 부재·오용 → 툴박스 · **완료 조건이 못 잡음 → verify 항목 추가 (필수)**
2. **수정** — 해당 위치를 고친다
3. **기록** — §8 실수 카탈로그에 행 추가 (수정 위치 칸은 §N·VN·툴박스 중 하나 필수)
4. **버전** — `version` +1, `updated` 갱신, §9 에 같은 버전 행
5. **검사** — `manual.py lint` → `manual.py verify` 재실행
6. **재발 확인** — 같은 실수가 2회째면 매뉴얼 문장만 고치지 말고 `cmd` 완료 조건(또는 코드 가드)으로 막는다

원칙: "고친 매뉴얼에서 다시 돌리면 이번 오류가 ❌ 로 잡히는가?" 가 예이면 루프 1회 완료.

## 6. 기존 장치와의 관계

- **사고 대장**(`backlog.py incident`, build_harness.md §2c): 시스템 실수·반복 실수의 등재 의무는 그대로다. 매뉴얼 카탈로그는 *업무 단위*의 기록이고, 사고 대장은 *저장소 전체*의 기록이다. 반복 실수면 둘 다 쓴다.
- **CLAUDE.md**: 매뉴얼은 CLAUDE.md 아래에 있다. 매뉴얼이 CLAUDE.md·코딩 헌법과 충돌하면 매뉴얼을 고친다. 새 규칙을 CLAUDE.md 에 산문으로 추가하지 않는다(2026-09-20 동결) — 업무별 규칙은 매뉴얼에 둔다.
- **카탈로그형 명령**(`/demo-doctor`·`/llm-perf-doctor`): "카탈로그에 행을 추가한다"는 같은 발상의 선례다. 이 방법론은 그것을 모든 업무에 공통 형식 + 기계 검사로 일반화한다.
- **런북**(`docs/ops/*_runbook.md`): Kiki가 실행하는 절차서다. 매뉴얼은 에이전트가 실행하는 절차서다.

## 7. 한계 (명시)

- 검사기는 매뉴얼의 **형식과 도구 실재**만 본다. 절차가 옳은지는 실행 결과(완료 조건)와 피드백 루프로만 드러난다.
- `read`·`human` 완료 조건은 에이전트의 정직한 보고에 기댄다. 그래서 반복 실수는 `cmd` 로 승격한다(§5-6).
