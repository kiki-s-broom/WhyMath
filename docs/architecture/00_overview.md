## 계층별 한 줄 정의

| 계층 | 역할 | 핵심 자산 | 서브에이전트 |
|---|---|---|---|
| **L1** | 진실 원천 데이터 보유 | 성취기준·교과서·기출·OER + 개념 그래프·다국 커리큘럼 매트릭스·교과서 매핑·`StudentProfile` (PRD 흡수) | data-engineer |
| **L2** | 학생의 *장기 상태* 추적 | BKT/IRT 모델 + 오개념 매핑 | ml-engineer |
| **L3** | LLM 응답 *생성·검증* | 라우터 + PRM + 도구 | llm-architect |
| **L4** | *교수학적 결정* | Polya·소크라테스·답 미루기 | pedagogy-designer |
| **L5** | *학생과의 인터페이스* | Flutter 앱 + FastAPI 서버 | flutter/backend-engineer |
| **L6** | *시장별 진입 모드* | 7개 모드 콘텐츠 큐레이션 | content-curator |
| **L7** | *사회적 학습* | 갤러리·Live Problems·보고서 | content-curator |

## 의존성 방향

**상위 → 하위 방향만 허용** (역방향 의존 금지):
```
L7 → L6 → L5 → L4 → L3 → L2 → L1
                ↑      ↑
               (이 둘은 자주 같이 호출됨)
```

> **L1-L4 = 독립 수학 코어(UI-agnostic)** · L5 = 클라이언트. 구조(AST/JSON)는 코어, 렌더는 클라(Flutter·웹·PDF·AI) — *표현≠의미* (슬라이스 89).

### 경계 침범 예시

❌ **나쁜 예**: L3가 BKT 업데이트 직접 호출하여 학습자 상태 변경  
✅ **좋은 예**: L3가 응답 생성 → L4가 후처리 → L5(orchestrator)가 L2에 업데이트 요청

❌ **나쁜 예**: L4가 PostgreSQL 쿼리 직접 작성  
✅ **좋은 예**: L4가 L1의 매핑 서비스 *함수 호출*

## 횡단 관심사 (Cross-Cutting Concerns)

다음은 모든 계층을 가로지름 — 별도 인프라:

- **로깅 (structlog)**
- **추적 (OpenTelemetry + Langfuse)**
- **메트릭 (Prometheus)**
- **에러 처리 (Sentry)**
- **보안 (인증·암호화·PII 보호)**
- **개인정보 (동의·삭제)**
- **국제화 (한국어 우선, 영문 Phase 5+)**

### 하네스 (Harness) — LLM 호출 방식 횡단 인프라

7계층은 *무엇을* 어디서 하는지의 축이고, **하네스는 L3(생성)·L4(결정)의 LLM 호출 *방식*을 바꾸는 횡단 인프라**다(새 계층이 아님·경계 원칙 유지). 프롬프트 스터핑 → 상태 외부화 + 도구 루프(agent loop)로 전환한다. 두 하네스:

- **WH-1 (튜터링 하네스)** — 학생 세션 런타임. 상태(오개념 가설·증거 그래프)를 DB로 외부화하고 LLM은 매 턴 "다음 교수학적 행동"만 판단. L4 교수학(Polya·소크라테스·LTHC·오개념)·L2·L1을 *소비*하는 온라인 런타임. 상세: `04a_wh1_tutoring_harness.md`
- **WH-S (솔버 하네스)** — 시스템 자체 풀이력 자기진화. MCTS 탐색 + 3-Tier 검증(수치·SymPy·Lean) + STaR/rStar-Math 루프. 학생 세션에 직접 개입하지 않는 **L3/L1 업스트림**(검증 풀이·PRM을 WH-1에 공급). 오프라인 배치. 상세: `03b_wh_s_solver_harness.md`

## 데이터 흐름 — 학생 메시지 1건

```
[학생] 채팅 입력 "이 문제 잘 모르겠어요"
   ↓
[L5 Mobile] 텍스트 전송 → FastAPI /chat
   ↓
[L5 Backend] 인증·세션 로드
   ↓
[L2] 학습자 상태 조회 (BKT·오개념·정서)
   ↓
[L1] 학생 컨텍스트 조회 (학년·교과서·진도·성취기준)
   ↓
[L4] 교수학 결정 (Polya 단계? 힌트 단계? 소크라테스 카테고리?)
   ↓
[L3] LLM 라우팅 → 호출 → PRM 검증 → 다중 풀이 옵션
   ↓
[L4] 정서 안전 필터 (금기 표현 제거)
   ↓
[L2] BKT 업데이트
   ↓
[L5 Backend] 응답 반환
   ↓
[L5 Mobile] 채팅 UI 표시 (Polya 단계 인디케이터 갱신)
   ↓

```

## 배포 토폴로지 — PRD 5블록 (7계층과 직교하는 두 번째 축)

> MathScope PRD v1.1을 정본으로 흡수하며 들여온 관점. 자세한 채택 근거는 `MEMORY.md` 2026-05-14 결정 로그 참조.

### 두 축은 충돌하지 않고 보완한다

WhyMath 아키텍처는 *서로 직교하는 두 축*으로 본다:

- **7계층 = 책임 레이어** — *누가 무엇을 책임지는가*. 서브에이전트 위임 단위(`.claude/agents/` 7개)와 직결.
- **5블록 = 배포 토폴로지** — *무엇이 어디서 실행되는가*. 프로세스·인프라·런타임 경계.

하나의 7계층 컴포넌트는 여러 배포 블록에 흩어져 살 수 있고(예: L1 데이터 서비스는 Backend 블록에서 실행되지만 그 자산은 DB 블록에 저장), 하나의 배포 블록은 여러 계층의 코드를 담을 수 있다(예: Backend 블록 안에 L3·L4·L5 코드가 공존). 따라서 *둘 중 하나를 고르는 문제가 아니라 두 좌표로 같은 시스템을 읽는 문제*다.

### 5블록 정의

| 배포 블록 | 실행 주체 | 담는 7계층 코드 | 핵심 스택 |
|---|---|---|---|
| **Client** | Flutter 단일 학생앱(패드 중심·모드 분기) + 별도 웹(교사·SEO·Phase3+) | L5 일부, L6/L7 UI | 앱: Flutter 3.x+Riverpod·MathLive/three.js WebView · 별도 웹: React/Next |
| **Backend** | FastAPI + uvicorn | L1 서비스·L2·L3·L4·L5 오케스트레이터·L6 모드 로직 | Python 3.12 + FastAPI |
| **DB** | 다중 저장소 | L1·L2 자산의 영속 계층 | **현재 운영:** PostgreSQL 16 + pgvector, Redis 7 · **조건부 확장:** TimescaleDB, ClickHouse, S3/MinIO (Neo4j는 2026-08-03 정정 — 런타임 미도입, 개념 그래프는 PG 단일 평면) |
| **ML** | 추론·검증 런타임 | L3 모델 호출, L3 도구 검증 | Claude Sonnet/Opus(⏸ 2026-09-24~12-31 Anthropic API 사용 중단 · ARCH-66), Qwen3-Math(Phaiakes9 로컬), SymPy, 임베딩 bge-m3(기본·로컬 — 클라우드 옵션 te-3-large, 정본 = CLAUDE.md 스택 표) |
| **Content Pipeline** | 배치·ETL | L1 수집·정형화·검증 | Prefect/Airflow, httpx + playwright, PaddleOCR+Qwen3-VL(로컬 OCR — 2026-05-28 Mathpix 대체), pdfplumber |

### 블록별 보충 메모

- **Client — Flutter 단일 학생앱 + 별도 웹**: PRD의 3개 앱(학생·학부모·교사) 동시 개발은 Phase 1 부담(MEMORY.md PRD 허점 ③). Phase 1은 *Flutter 학생앱 1개*(패드 중심·학생+학부모 모드 분기 L6)에 집중하고, **교사 대시보드는 별도 웹(React/Next)으로 Phase 3+** (슬라이스 89). 수학 로직은 클라에 두지 않고 독립 코어(L1-L4) API로 소비.
- **DB — 벡터 저장소 = pgvector(확정·슬98)**: 기존 Postgres 16에 pgvector 확장으로 통합 — 메타데이터(subject·exam_year·difficulty)가 이미 PG 컬럼이라 하이브리드 검색이 단일 SQL·6번째 store 회피·미성년 PII 통제 DB 유지. 대규모/고QPS 시 Qdrant 이관(지연 트리거). ChromaDB는 개발용(SQLite)이라 프로덕션 비채택.
- **DB — 신규 저장소**: ~~Neo4j(개념 연결 그래프)~~(2026-08-03 정정 — 개념 그래프는 PG 단일
  평면으로 확정, Neo4j 런타임 도입 안 함), ClickHouse(학습 행동 로그), S3/MinIO(영상·이미지)는
  PRD 채택으로 추가. 상세 용도는 `01_data_foundation.md` 및 각 계층 문서 참조.
- **ML — 로컬 우선**: 클라우드 LLM 호출 전 항상 Phaiakes9 로컬(Qwen3-Math) 가능성 검토(CLAUDE.md 절대 원칙). AWS Seoul ↔ Phaiakes9 하이브리드의 동기화 비용은 PRD가 누락한 항목(MEMORY.md PRD 허점 ⑦) — 기존 하이브리드 인식 유지.
- **Content Pipeline ↔ L1**: 이 블록은 거의 전적으로 L1(data-engineer)의 코드를 실행한다. PRD 신규 자산(개념 그래프·다국 매트릭스·교과서 매핑 12단계)의 수집·정형화가 모두 여기서 돈다.

### 횡단 관심사는 두 축 모두를 가로지른다

위에서 정의한 횡단 관심사(로깅·추적·메트릭·에러·보안·개인정보·국제화)는 7계층뿐 아니라 5블록 전체에도 걸친다. 특히 PIPA 데이터 권한 매트릭스는 Client·Backend·DB 세 블록에 동시 적용된다(상세는 `docs/legal/` 및 횡단 인프라 문서).
