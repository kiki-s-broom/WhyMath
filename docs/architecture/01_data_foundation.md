### 9. 개념 연결 그래프 (Concept Graph)

수학 개념을 노드로, 개념 간 관계를 엣지로 표현하는 그래프. *왜 이 개념을 배우는가*를 구조로 답하기 위한 자산.

- **저장소**: ~~Neo4j~~ **2026-08-03 정정: PG 단일 평면**(`l1/concept_graph/retrieval.py:16`·
  `node_projection.py:14` — "backend↔Neo4j 런타임 연결 안 함(확정 설계 결정)". Neo4j는 배포
  토폴로지 DB 블록에도 실재하지 않는다 — `00_overview.md` §정정 참조)
- **목표 규모**: 500노드 · 2,000엣지 — 실측(2026-08-03): 개념 축 437노드·581엣지, 원자 백본
  2,683노드·2,210엣지(runtime truth source, `knowledge_module_gap_review.md`)
- **Phase 1 범위**: 고1 미적분 영역 ~100개념 (첫 진입 = 고1 내신 트랙에 정렬) — 실측은 전 학년·
  전 영역으로 이미 확장됨(위 실측 규모 참조)

**`Concept` 노드 필드**:
| 필드 | 설명 |
|---|---|
| concept_id (canonical) | `math.<area>.<slug>` — 교육과정·언어·렌더러 무관 의미론 PK (2026-07-02 P2d·Part 9). 옛 `{TRACK}-{AREA}-{NNN}`·UC는 `aliases` 보존 |
| 표기 (한·영·일) | **노드 비내장** — locale 계층(`locales/{lang}.json`·canonical 키)이 3개 언어 명칭 단일 진실 (P2d·Concept Purity). Phase 1은 `ko`만 충전 |
| 선수개념 참조 | 이 개념을 이해하기 위해 선행돼야 하는 개념들 |
| 오개념 참조 | 이 개념에서 전형적으로 발생하는 오개념(기존 7번 카탈로그 연결) |
| 시각화 카드 참조 | L5 시각화 자산 키 (L1은 *참조만* 보유, 렌더링은 L5) |

**`Edge` — 7가지 관계 유형** (`notation_variant` 포함 — pipeline `Relation` 정본, backend 투영은 `docs/data/concept_graph.md` §2.2b crosswalk):
| 관계 | 의미 |
|---|---|
| `prerequisite` | 선수 — A를 알아야 B를 배움 |
| `generalization` | 일반화 — B는 A의 더 일반적 형태 |
| `specialization` | 특수화 — B는 A의 특수 사례 |
| `contrast` | 대조 — A와 B는 헷갈리기 쉬워 구분 학습 필요 |
| `application` | 응용 — A를 B 상황에 적용 |
| `composition` | 합성 — B는 여러 개념(A 포함)의 결합 |
| `notation_variant` | 표기 변형 — 같은 개념의 다른 표기 |

각 엣지는 **강도(strength)** 와 **증거(evidence)** 를 함께 가진다 — 관계가 얼마나 강한지, 그 판단의 근거가 무엇인지.

### 10. 다국 커리큘럼 매트릭스 (Multi-Curriculum Matrix)

같은 수학 개념이 나라마다 *몇 학년에·어떤 깊이로* 다뤄지는지를 교차표로 정리한 자산.

- **구조**: 3차원 — `개념 × 9~12개국 × CurriculumEntry(30필드)`
- **목표 규모**: 5,000~6,000셀
- **Phase 1 범위**: 한국 + 참고용 미국·IMO만. **9~12개국 풀스케일은 Phase 3** (PRD 본문 §1.6 vs §15.1 불일치 — Phase 1 과욕으로 판단해 재배치, `MEMORY.md` PRD 허점 ② 참조)
- **한국 열 = NCIC 성취기준**: 기존 1번 NCIC 성취기준이 *이 매트릭스의 한국 열*이다. 즉 매트릭스는 NCIC를 버리는 게 아니라 NCIC를 국제 비교 축에 끼워 넣는 구조.

`CurriculumEntry`(30필드)는 한 (개념, 국가) 쌍에 대해 도입 학년·도입 맥락·요구 깊이·평가 방식·표준 코드 등을 담는다. 상세 필드 정의는 `schemas/v1.1/` 엔티티 명세 참조.

### 11. 교과서 매핑 파이프라인 (Textbook Mapping)

검정 교과서의 *구조*를 다국 커리큘럼 매트릭스의 개념에 연결하는 파이프라인.

- **대상 규모**: 한국 9종 × 8과목
- **엔티티**: `TextbookMapping` — 교과서 메타데이터 · 단원 트리 · 페이지 범위 · 교육과정 코드 · (매트릭스 개념과의 다대다 매핑) · 교과서 톤 프로필
- **파이프라인**: 12단계 (요약은 부록 H 참조 — 수집 → 단원 트리 추출 → 페이지 범위 정합 → 교육과정 코드 매핑 → 매트릭스 개념 매핑 → 톤 프로필 추출 등)

**저작권 안전선 (절대 준수)**:
- ✅ 사용: **구조 메타데이터만** — 목차·단원명·페이지 범위·교육과정 코드
- ❌ 미사용: 본문·문제·그림 — 일절 복제하지 않음
- 교과서 문제가 필요한 경우 *자체 코퍼스의 동등 문제*로 대체한다 (교과서 문제 자체를 담지 않음)
- 교과서 *학습목표 텍스트* 인용은 **변호사 검토를 전제로만** 진행 — PRD가 "페어유즈"로 단정한 부분이나 단정 위험이 있어 보류(`MEMORY.md` PRD 허점 ⑥). CLAUDE.md 절대 금기 "검정 교과서 본문·예제 복제 금지"와 이 안전선은 동일 선상.

### 12. 자동 커리큘럼 정렬 입력 (`StudentProfile`)

학생 개개인을 그가 속한 교육 맥락에 맞춰 콘텐츠를 정렬하기 위한 입력 데이터.

- **엔티티**: `StudentProfile` — 국가 · 학년 · 학교 · 사용 교과서 · 진도 · 학습 목표 · 학습 선호
- **계층 경계**: **L1이 보유**하고 **L6 응용 모드가 소비**한다. 자동 커리큘럼 정렬 *엔진*의 로직은 L6 소관 — L1은 정렬에 필요한 *입력 자산*만 책임진다 (`00_overview.md` 컴포넌트 매트릭스에서 "자동 커리큘럼 정렬 엔진"을 L1+L6로 표기한 이유).
- 기존 3번 학교별 채택 정보(학교알리미)는 `StudentProfile`의 "학교 → 교과서" 자동 채움을 떠받친다.

### 자산 간 연결 — 한눈에

```
NCIC 성취기준(1) ──┬─→ 다국 매트릭스(10)의 "한국 열"
                  └─→ 교과서 매핑(11)의 매칭 타겟
개념 그래프(9) ←──── 오개념 카탈로그(7) 참조 / 시각화 카드(L5) 참조
교과서 매핑(11) ──→ 매트릭스 개념과 다대다 연결
StudentProfile(12) ←── 학교알리미(3)로 "학교→교과서" 자동 채움
                   └─→ L6 자동 커리큘럼 정렬 엔진이 소비
```

**기존 크롤러가 출발점**: 이미 구현된 NCIC 크롤러(`src/data-pipeline/data_pipeline/ncic/`)가 위 그림 전체의 시작점이다. 그것이 산출하는 성취기준이 다국 매트릭스의 한국 열을 채우고, 동시에 교과서 매핑이 단원을 연결할 매칭 타겟이 된다. PRD 신규 자산 4가지는 *새 크롤러*가 아니라 이 출발점 위에 얹는 구조화 레이어다.
