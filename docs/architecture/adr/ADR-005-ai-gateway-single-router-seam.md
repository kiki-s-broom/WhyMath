## 결정

### D1. 모든 LLM 호출은 L3 라우터를 경유한다 — 프로바이더 직접 호출 금지

출처: `CLAUDE.md` §"✅ 절대 원칙 → LLM 사용" 1항 ("LLM 호출은 항상 라우터 경유 — 직접 호출 금지").

라우터는 *어디서 생성할지*만 정한다. 라우터가 환각 방어를 대체하지 않는다(03a §요약).

### D2. 라우팅은 3축의 합성이다 — `mid`를 단독으로 쓰지 않는다

출처: `03a_l3_router_design.md` §0 (2026-05-19·2026-05-20 Phaiakes9 실측 근거).

| 축 | enum | 값 |
|---|---|---|
| 축1 비용·위치 | `CostTier` | `LOCAL` / `CLOUD_MID` / `CLOUD_HIGH` |
| 축2 로컬 크기 | `LocalModelTier` | `FAST` / `MID` / `QUALITY` |
| 축3 모델 패밀리 | `ModelFamily` | `MATH` / `GENERAL` / `VISION` |

실제 로컬 모델 = **(축3 패밀리 × 축2 크기)** 매트릭스 해석(`LOCAL_MODEL_MATRIX`). 축3이 필요한
이유는 취향이 아니라 실측이다 — NLP 호출지점을 수학 특화 모델로 돌리면 **7b조차 정확도 0%**였고,
일반 모델로 바꾸자 match 3b=100%·translate 7b=75%였다(2026-05-20).

`CLOUD_MID`(축1)와 `LOCAL/MID`(축2)가 같은 단어를 쓰므로, **축 접두사 없는 맨 `mid` 표기를
금지**한다(03a §0.1).

### D3. 로컬 우선 — 목표 분포 80 / 18 / 2, 승급은 단방향

출처: `03a` §0 표·§E.3, `router.py` `ESCALATION_CHAIN`.

`LOCAL/FAST → LOCAL/MID → LOCAL/QUALITY → CLOUD_MID → CLOUD_HIGH`. 로컬 3단계를 먼저 올리고
로컬 천장에서도 미달일 때만 클라우드로 넘어가며, 클라우드 승급은 항상 `guard_cloud()`를 통과한다
(무료 요금제는 클라우드 금지, 잔여 예산 부족 시 `LOCAL` 강등, `basic`은 `CLOUD_HIGH` 불가 →
`CLOUD_MID` 제한).

### D4. 프로바이더 포트폴리오는 고정 집합이 아니라 *측정 기반 개방 목록*이다

출처: `MEMORY.md` 2026-08-16 결정 로그(Kiki 지시), `CLAUDE.md` §"✅ 절대 원칙 → LLM 사용" 5항.

신규 프로바이더(OpenRouter 등)·신규 모델을 전제로 배제하지 않는다. **채택 조건 3건**:

1. 라우터(`l3/router.py`) 경유 배선 — D1은 프로바이더가 바뀌어도 불변
2. 실측 근거 (2026-05-20 태스크 인지 실측 선례 형식)
3. MEMORY 결정 로그 기재

현행 핀(실측): 클라우드는 `config.py`의 `anthropic_model_mid`·`anthropic_model_high` **2건뿐**이며
GPT-5·Gemini 2.5는 스택 표에 적혀 있으나 **라우터 미배선**이다(CLAUDE.md 스택 표 단서와 일치).

### D5. 프로바이더가 바뀌어도 불변인 계약 4종

출처: `CLAUDE.md` 2026-08-16 결정 로그 단서 문장 ("모델이 바뀌어도 검증 계약은 불변").

1. **검증 권위** — SymPy 단일 권위, 학생 제공 전 PRM/도구 검증 통과
2. **관측** — 모든 LLM 호출은 Langfuse 추적
3. **미성년자 데이터 정책**
4. **저작권 레일**

게이트웨이는 *어느 모델이 답했는가*를 바꿀 수 있어도 *무엇이 학생에게 나가는가*의 조건은 바꾸지
못한다.

### D1 집행의 근거 (ARCH-46 — 판정 기준: main `2e1220b4` + 본 PR)

**초판(main `4b33d243`)은 이 자리에 "미집행 — 사람 규율"과 "위반 13건 이상"을 적었다.** ARCH-46이
그 13건의 정오 판정을 수행했고, 결과는 아래와 같다 — **위반 0건**이다.

#### ① 전수 실측 (절단 없음)

`l3/providers/*`를 `providers/` 밖에서 직접 임포트하는 지점은 **70건**(테스트 포함), 파일 단위로는
프로덕션 소스에서 **좌석 18건**이다. 초판의 "13건 이상"은 절단된 수치였다.

```bash
# 재현 — 임포트 지점 전건(테스트 포함)
grep -rn "from whymath_backend\.l3\.providers" --include="*.py" src/ scripts/ tests/ \
  | grep -vc "^src/backend/whymath_backend/l3/providers/"      # 70

# 재현 — 프로덕션 좌석 수와 분류
python3 scripts/ops/check_provider_seat_contract.py            # 좌석 18 / 직접 호출 4(유예) / 위반 0
```

#### ② 3분류 판정

| 분류 | 건수 | 근거 |
|---|---|---|
| **(a) 정상 경유** | 14 | `.route(...)`로 결정을 받거나 `l3.pipeline.generate`를 경유한다. 조립 전용(FACTORY)도 여기 넣는다 — 누가 *부르는가*가 D1의 관심사이고 조립은 아니다(`app.py`·`pregenerate/__main__.py`·`residue_gate_demotion_battle.py`) |
| **(b) 위반** | **0** | 라우터 증거 없이 프로바이더를 부르면서 유예에 없는 좌석은 없다 |
| **(c) 의도적 예외** | 4 | 측정·강등전 전용. 공통 사유 하나: *라우터가 모델을 고르면 측정이 성립하지 않는다*(dense↔MoE 정확도 비교·결함 주입 검출률·결정론 재생성). 만료일 2026-12-31 동반 |

초판이 판정을 유보했던 `l4/misconception/judge_seam.py`는 **(a) 정상**이다 — 라우터를 직접
임포트하지 않지만 `l3.pipeline.generate`를 경유하고, 파이프라인이 내부에서 `Router().route()`를
돈다. 초판의 "읽어서 그렇게 보인다"는 유보가 옳았다: 임포트만 보면 위반처럼 보이고, 경유를 보면
정상이다.

#### ③ 왜 import-linter가 아니라 AST 스캐너인가

열린 질문 ①이 후보로 든 import-linter `forbidden` 계약은 **채택하지 않았다**. 두 가지 이유다.

1. forbidden은 "source가 target을 임포트 금지" 형태라 *허용 좌석만 열거*하려면 저장소의 모든
   모듈을 `source_modules`에 적어야 한다(유지보수 불가).
2. 더 근본적으로 **임포트 여부만 보고 경유 여부는 못 본다.** 여기서 필요한 판정은 "임포트했는가"가
   아니라 "임포트해서 *라우터 없이 불렀는가*"다. baseline 동결도 불필요해졌다 — 위반이 0건이므로
   동결할 baseline이 없고, 예외 4건은 만료일을 가진 유예로 관리한다.

#### ④ 이 게이트가 자매 게이트 둘과 겹치지 않는 지점

`check_routing_data_grade.py`(EOS-59)와 `check_routing_decision_bypass.py`(EOS-77)는 *라우팅
자료구조가 등장할 때* 작동한다. 새 프로바이더를 붙이며 라우터를 통하지 않고 직접 부르는 경로는
`RoutingDecision`을 **아예 만들지 않을 수 있고**, 그러면 자매 둘은 조용히 통과한다. 이 게이트가
그 사각을 맡는다 — D4(프로바이더 포트폴리오 개방)를 실제로 행사할 때 필요한 안전장치다.

#### ⑤ 변별력의 근거 (측정, 인상 아님)

가드의 절마다 뮤테이션을 주입해 **11종 전건 RED**(생존 0)를 확인했다. 초판 스위트에서는 2종이
생존했고, 그것이 두 가지를 드러냈다: ⓐ `.route()` Attribute 인정 절을 밟는 픽스처가 없었다
(패키지 속성·상대 임포트 반례를 추가) ⓑ `Router()` *생성*을 증거로 인정하던 절은 **과잉**이었다
(만들어 놓고 안 쓰는 코드를 통과시킨다) — 픽스처를 억지로 만들지 않고 절을 제거했다.

> **범위의 한계(밝혀 적는다)**: 11종은 *내가 목록에 올린 절*만이다. 전건 RED는 가드가 그 11개
> 자리에서 센 정도를 말할 뿐 **무엇을 안 봤는지는 말하지 않는다**(CLAUDE.md「뮤테이션 전건 RED는
> 커버리지의 증거가 아니다」). 알려진 공백 둘은 스캐너 docstring이 적고 있다: 파일 간 데이터 흐름
> 미추적, 동적 `getattr` 프로바이더 취득(2026-09-16 실측 프로덕션 0건).

## 결과·트레이드오프

- **얻는 것**: 게이트웨이 계약이 한 문서에서 읽힌다. 프로바이더 교체 시 무엇이 협상 가능하고
  (모델·가격·지연) 무엇이 불변인지(D5) 구분된다.
- **치르는 것**: 라우터가 단일 병목이다. 라우터 변경은 전 호출지점에 영향을 준다 — 그래서 3축을
  타입으로 분리해 두었다(D2).
- **의도적 미채택**: 별도 게이트웨이 *서비스*(프록시 프로세스)를 만들지 않는다. 현행 경계는
  **인프로세스 모듈 경계**이며, 이는 CLAUDE.md의 "6번째 store 회피"와 같은 결에서 과공학을
  피한 것이다.

## 계획서 번호와의 관계

이 문서의 파일명 번호 **005**는 저장소 계열의 다음 빈 번호이고(`adr_number_check.py` 판정),

연결한다.
