## 0. Context (왜 이 문서인가)

WhyMath는 "답이 아닌, 이유를 묻는 수학"을 정체성으로 하는 메타인지 중심 학습 앱이다.
그 심장은 수학적 의미를 **화면 문자열이 아니라 구조(AST/JSON)로 다루는 MATH DSL**
계층이다(슬라이스 89: *표현 ≠ 의미*).

지금까지의 개발은 개별 슬라이스(Visualization·LearningScene·verify_step·오개념
진단 등)를 하나씩 견고하게 쌓아 올렸다. 이제 필요한 것은 **"이 조각들이 통합적으로
어떤 시스템이 되어야 하는가"**라는 방향 판단이다. 방향이 없으면 각 슬라이스가
국소 최적화되면서 전체는 응집을 잃는다(컨텍스트 오염의 아키텍처판).

이 문서는 9개 후보 진화 방향을 놓고, **현 구조에 무엇이 이미 있고(자산)·무엇이
없고(부족)·무엇을 절대 만들면 안 되는가(금기)**를 판정하여 하나의 진화축을
제시한다. 추상 이론이 아니라 실재하는 파일·스키마에 대한 판정이다.

## 1. 현재 MATH DSL 구조 요약 (판정의 근거)

핵심 인식: **WhyMath에는 "하나의 MATH DSL"이 없다.** L1~L5에 걸친 선언적 명세들의
계층 조합이 있고, 그것이 모두 "표현 ≠ 의미" 위에 선다.

| 구성요소 | 위치 | 성숙도 | 핵심 성질 |
|---|---|---|---|
| SymPy 동치 권위 `identity_status` | `l3/symbolic_equivalence.py` | 🟢 완전 | 4상태(identity/not_identity/undecidable/parse_error), **명시 AST 없음** |
| verify_step / verify_answer | `l3/verify_step.py`·`verify_answer.py` | 🟢 완전 | 3상태 정직성(correct/incorrect/unverifiable), Tier1 수치 + Tier2 기호 |
| Visualization DSL | `schema/visualization.py` | 🟢 완전 | 4종 typed spec, 클라 렌더만 |
| LearningScene DSL | `l4/learning_scene.py` | 🟢 완전 | 6종 요소·검증 게이트(답미루기·낙인·참조 불변식) |
| SolutionPath | `schemas/v1.1/solution_path.schema.yaml` | 🟡 구조 확정 | concept_sequence·steps·embedding, 동치성 = 휴리스틱 + 사람검수 |
| L1 개념 그래프 | Neo4j | 🟡 v0 완성 | 503노드·541선수엣지·6관계유형(2026-07-01 작성 기준) |
| 오개념 카탈로그·진단 | `l4/misconception/` | 🟡 30종 | 3중 표현 부채(kebab / M-id / JSONB) |
| WH-S 솔버 / WH-1 튜터 하네스 | `whs/`·docs | 🔄 진행중 | MCTS + 3Tier / 상태 외부화·가설 추적 |
| L3 라우터(3축) | `l3/router` | 🟢 설계+구현 | CostTier × LocalModelTier × ModelFamily |

**진화 판정을 지배하는 결정적 설계 사실 4가지**:

1. **명시적 수식 AST가 없다** — SymPy를 직접 동치 권위로 쓴다. `FormulaNode`는 **canonical 참조
   노드로 도입됐으나(P5a)** *재작성 규칙 트리·자체 CAS는 여전히 미도입*(Q3·Q8 경계). 노드는 canonical
   수식의 정체성·참조만 담고 동치 계산은 l3 SymPy 단일 권위가 한다(노드 모듈 sympy 미import).
   (과설계 회피 = 이미 내려진 아키텍처 결정)
2. **의미와 렌더가 분리** — 코어는 구조(JSON)만 산출, 클라(Flutter·웹·PDF·AI)는
   렌더만. 같은 spec이 여러 표면에서 각자 그려진다.
3. **안전성이 스키마 불변식으로 박혀 있다** — 답 미루기·낙인 금지·저작권이 프롬프트
   지침이 아니라 `parse_learning_scene` 게이트로 강제된다.
4. **검증이 정직하다** — 판정 불가는 `undecidable`/`unverifiable`로 노출, pass 위장
   금지. 이것이 신뢰의 구조적 근거다.

## 2. 9개 진화 방향 판정 (각 8차원)

각 방향을 8차원으로 판정한다: ① 현재 구조와의 적합성 ② 구조적 부족점 ③ 미래 병목
④ 반드시 추가해야 하는 abstraction ⑤ 절대 추가하면 안 되는 abstraction
⑥ AI integration 적합성 ⑦ 유지보수 가능성 ⑧ 실제 서비스 생존 가능성.

범례: 적합성/생존 = ◎매우높음 ○높음 △중간 ✕낮음

### 2.1 Symbolic Math Engine (기호 수학 엔진)

- **① 현재 적합성 ✕**: 이미 SymPy를 권위로 *소비* 중. DSL 자체를 기호엔진으로 만드는
  것은 SymPy 재구현이며, 명시 AST를 의도적으로 피한 현 설계(§1 사실 1)와 정면충돌.
- **② 구조적 부족점**: 없음 — 부족한 게 아니라 **불필요**. CAS(computer algebra
  system)는 수십 년 상용 최적화 영역이다.
- **③ 미래 병목**: 자체 기호엔진은 SymPy 대비 정확도·커버리지에서 영구 열위 →
  검증 신뢰 붕괴(NEVER: "LLM 응답을 검증 없이 학생에게 제공 금지" 위반 위험).
- **④ 필수 abstraction**: (이 방향 채택 시) 항·재작성규칙·정규형 엔진 — 이는 곧
  **추가 금지 대상**이다.
- **⑤ 금지 abstraction**: 자체 CAS·**재작성 규칙 트리**(risk_register Q3·Q8) — *여전히 금지*.
  단 `FormulaNode` **canonical 참조 노드는 허용**(P5a·2026-07-08): 노드는 canonical 수식의 정체성·
  참조만 담고 CAS/재작성 로직을 내장하지 않는다(동치는 l3 SymPy 단일 권위). "자체 기호엔진 구축"과
  "canonical 참조 노드"는 다르다 — 전자만 anti-goal.
- **⑥ AI 적합성 △**: LLM은 기호엔진을 *호출*하면 되지 그것이 *될* 필요가 없다.
- **⑦ 유지보수 ✕**: CAS 정확도 유지비용은 사실상 무한. 4~5명 팀에 불가능.
- **⑧ 생존 ✕**: Wolfram·SymPy와의 경쟁 = 즉사. 교육적 차별화 0.
- **판정: 자체 기호엔진(CAS) 구축은 반대(anti-goal).** SymPy는 *검증 커널*로만 유지하되 DSL의 정체성
  으로 삼지 않는다. **FormulaNode canonical 참조 노드는 이 판정과 무관하게 허용**(CAS를 만들지 않으므로).

### 2.2 Educational Reasoning Engine (교육 추론 엔진)

- **① 적합성 ◎**: 현 구조가 이미 이것이다. verify_step(정직성)·SolutionPath(개념
  시퀀스 = 풀이 골격)·LearningScene(교수학 합성)·오개념 가설 추적이 모두 "왜"를
  구조화하는 추론 계층. CLAUDE.md 정체성("답이 아닌 이유")과 완전 정렬.
- **② 구조적 부족점**: 풀이의 *추론 스텝*이 아직 자연어+LaTeX 문자열
  (`SolutionStep.content`). "왜 이 변형이 정당한가"의 **정당화(justification) 구조**가
  1급 시민이 아니다. 오개념→개입의 인과 연결이 데이터로만 존재.
- **③ 미래 병목**: 동치성 휴리스틱·사람 검수가 병목. 추론 스텝이 불투명 문자열이라
  기계가 "이 단계가 어떤 추론 유형(연역/치환/사례/역방향)인가"를 읽지 못한다.
- **④ 필수 abstraction**: `ReasoningStep`/`Justification` — 스텝에 **추론 유형 태그**
  (deduction/substitution/case/induction/heuristic 등 *폐쇄 enum*)와 **정당화 근거
  참조**(정리·개념 노드·이전 스텝)를 얇게 추가. `SolutionPath.steps`의 상위호환.
- **⑤ 금지 abstraction**: 완전 형식논리 증명 트리(Tier3에 위임). 자체 정리증명기.
  추론 유형을 무한 세분화하는 온톨로지(6~8종 폐쇄집합 유지).
- **⑥ AI 적합성 ◎**: LLM이 스텝별 추론 유형을 태깅하고 SymPy/PRM이 검증하는 구조 —
  현 WH-S/WH-1 하네스가 그대로 재료.
- **⑦ 유지보수 ○**: 기존 스키마의 얇은 확장. 폐쇄 enum이면 폭발 없음.
- **⑧ 생존 ◎**: 콴다·EBS가 못 하는 유일 차별화. "이유를 묻는 수학"의 엔진 본체.
- **판정: 핵심 진화축(권장 1순위).**

### 2.3 AI Tutoring Operating System (AI 튜터링 OS)

- **① 적합성 ○**: WH-1 하네스(상태 외부화·도구 8종·전략 3종)가 이미 "OS 커널" 형태.
  LearningScene DSL이 "앱이 그리는 화면 명세", L3 라우터가 "스케줄러".
- **② 구조적 부족점**: OS를 자처하려면 *제3자 확장*(도구/모드/렌더러 플러그인) 경계가
  명세로 고정돼야 하는데 현재는 내부 레지스트리 수준. 세션 생애주기·권한·격리가
  튜터링 특화라 "범용 OS"는 과대포장.
- **③ 미래 병목**: "OS" 야심이 조기에 오면 범위 폭발(PRD의 3앱 분리를 거절한 것과
  같은 실수). 관측성·버전 계약이 없으면 확장 지옥.
- **④ 필수 abstraction**: `TutoringSession`(생애주기·상태 스냅샷·이벤트 로그)을 1급
  엔티티로. WH-1 도구 8종의 안정 인터페이스 계약(ABI).
- **⑤ 금지 abstraction**: 범용 플러그인 마켓·임의 서드파티 수학 로직 주입(슬라이스
  89 "수학 로직을 클라/외부에 넣지 않는다" 위반). 튜링완전 규칙엔진.
- **⑥ AI 적합성 ◎**: LLM-as-planner + 외부화 상태 = 정확히 현 WH-1 철학.
- **⑦ 유지보수 △**: OS 프레이밍은 표면적이 넓어 유지비 큼. 도구 계약을 좁게 유지해야.
- **⑧ 생존 ○**: 장기 제품 서사로는 강력("학습 OS"). 단 **정체성**이 아니라 **제품
  표면**으로만. 엔진(§2.2)이 먼저 서야 OS가 의미를 가진다.
- **판정: 제품화 표면(권장 3순위, §2.2 위에 얹음). 조기 정체성화 금물.**

### 2.4 Visualization Runtime (시각화 런타임)

- **① 적합성 ○**: Visualization DSL(4종) + SceneRenderer 레지스트리가 이미 런타임.
  "표현 ≠ 의미"로 명세/렌더 분리 완성.
- **② 구조적 부족점**: 시각화가 *설명의 부속*이지 추론의 주체가 아님. 상호작용
  이벤트(학생이 슬라이더 조작 → 무엇을 깨달았나)가 학습자 모델(L2)로 환류되는 루프가
  얇다. (`시각화조작` EventType 배선은 있으나 인지 신호화는 초기)
- **③ 미래 병목**: 렌더 기술(Desmos/three.js/Manim) 다변화 시 spec 계약 drift.
  `notation_contract`처럼 시각화에도 golden test가 필요.
- **④ 필수 abstraction**: `InteractionEvent`(조작 → 관찰 신호) 스키마로 L2 환류.
  spec↔렌더 golden test(현 notation_contract의 시각화판).
- **⑤ 금지 abstraction**: 렌더 엔진별 분기 로직을 코어에 넣기(클라 책임 유지).
  범용 애니메이션 타임라인 DSL(과설계).
- **⑥ AI 적합성 ○**: LLM이 spec 생성, 검증 게이트 통과 후 렌더 — 현 흐름.
- **⑦ 유지보수 ○**: 폐쇄 4타입 유지 시 견고. 타입 증식 억제가 관건.
- **⑧ 생존 △**: 단독 정체성으론 Desmos/GeoGebra와 경쟁 = 약함. **엔진의 출력 표면**
  으로서 가치.
- **판정: 하위 역량(§2.2의 출력 채널). 정체성 아님.**

### 2.5 Curriculum Compiler (커리큘럼 컴파일러)

- **① 적합성 ○**: L6 자동 커리큘럼 정렬(7차원) + L1 다국 매트릭스 + overlay가
  "컴파일러" 은유에 잘 맞는다(개념그래프 + 학생프로필 → 정렬된 학습경로).
- **② 구조적 부족점**: 현재는 "정렬(alignment)"이지 "컴파일(경로 생성·최적화)"까진
  아님. 선수관계 그래프에서 학습 순서를 *유도*하는 스케줄러가 얇다(위상정렬 기초만).
  7차원 중 깊이축만 1차 구현.
- **③ 미래 병목**: 9~12국 확장(Phase3) 시 규칙 폭발. 그래프 순환 위생 부재
  (risk_register: reachability/SCC 게이트 없음)가 컴파일 정확성을 직격.
- **④ 필수 abstraction**: `LearningPathPlan`(선수 위상정렬 + 숙달상태 + 목표 제약의
  산출물). 그래프 위생 게이트(acyclic 보장·SCC 검출) = **컴파일러의 전제조건**.
- **⑤ 금지 abstraction**: 튜링완전 커리큘럼 규칙 언어. 국가별 하드코딩 분기(overlay
  단일 진실 원칙 유지). 교과서 본문 기반 컴파일(저작권 절대금기).
- **⑥ AI 적합성 △**: 경로 계획은 결정론 그래프 알고리즘이 주력, LLM은 보조.
- **⑦ 유지보수 △**: 다국 규칙 스케일 시 비용 큼. overlay 계층으로 격리 필수.
- **⑧ 생존 ○**: "교과서/진도 자동 정렬"은 강한 한국시장 차별화(PRD 핵심 자산). 단
  엔진의 *입력 정렬기*이지 전체 정체성은 아님.
- **판정: 강력한 하위 시스템(L6). 그래프 위생 선결. 정체성 아님.**

### 2.6 Misconception Diagnosis System (오개념 진단 시스템)

- **① 적합성 ○**: 오개념 카탈로그(30) + WH-1 가설 추적(감쇠·ε탐색·반박증거 우선) +
  wrong_form_match(SymPy Wild)이 이미 진단 엔진의 심장. CLAUDE.md "모든 오답 = 오개념
  후보" 원칙과 정렬.
- **② 구조적 부족점**: **오개념 3중 표현(kebab / M-id / JSONB) = 최대 부채**(risk 🔴).
  단일 canonical ID로 수렴하기 전엔 진단 신뢰성이 흔들린다. 진단 → 개입 효과 측정
  (대리지표)이 0단계.
- **③ 미래 병목**: 카탈로그 30 → 300 확장 시 ID 정체성·중복·오탐. 확증편향(가설
  고착)은 감쇠/ε-탐색으로 방어 중이나 실측 검증 필요.
- **④ 필수 abstraction**: `MisconceptionId`(단일 canonical, crosswalk 흡수) — 이미
  진행 중인 remediation의 완주. `EvidenceGraph`(오답 → 오개념 → 커리큘럼) 1급화.
- **⑤ 금지 abstraction**: 학생별 "낙인" 상태(스키마가 이미 정답/수정 필드 차단 —
  유지). 오개념을 확정 라벨로 굳히는 구조(항상 confidence 있는 가설로).
- **⑥ AI 적합성 ◎**: LLM 매칭 + SymPy 거짓등식 검증 + pgvector 검색 = 현 구조.
- **⑦ 유지보수 △→○**: 3중 표현 해소하면 ○. 지금은 부채로 △.
- **⑧ 생존 ○**: 진단 정밀도는 강한 차별화지만 단독 제품은 아님. 엔진의 *진단 서브
  시스템*.
- **판정: 핵심 서브시스템. canonical ID 수렴이 최우선 부채상환. §2.2에 흡수.**

### 2.7 Adaptive Learning Graph (적응형 학습 그래프)

- **① 적합성 ○**: L1 개념그래프 + L2 MasteryState(BKT) + 선수엣지가 적응의 기반.
  숙달상태로 활성 개념 게이팅 = 적응 루프의 뼈대.
- **② 구조적 부족점**: L2가 아직 BKT 스텁 수준. 적응이 "게이팅"이지 개인화 경로
  *재계획*까진 약함. 그래프 순환 위생 부재.
- **③ 미래 병목**: DKT/협업필터링(Phase3)은 데이터량 의존 — 콜드스타트. 임베딩
  namespace 분리 미해결이 그래프 검색 오염 위험.
- **④ 필수 abstraction**: `MasteryState`의 완성(BKT → IRT theta + 신뢰구간 + 망각곡선).
  그래프 위생 게이트. §2.5의 `LearningPathPlan`과 공유.
- **⑤ 금지 abstraction**: 무자비 게임화 적응(스트릭/랭킹 — CLAUDE.md 절대금기). 약한
  relation 폭발(ANALOGOUS_TO 등 정책적 미적재 유지).
- **⑥ AI 적합성 △**: 통계모델(BKT/IRT/DKT) 주력, LLM 보조.
- **⑦ 유지보수 △**: 그래프 + 통계모델 결합 유지비 중간. namespace/위생 선결.
- **⑧ 생존 ○**: 적응은 필수 기대치이나 그 자체가 브랜드는 아님. 엔진의 *상태 기층*.
- **판정: 필수 기층(L1+L2). 그래프 위생·MasteryState 완성 선결. §2.2·§2.8과 융합.**

### 2.8 Math Cognition Graph (수학 인지 그래프)

- **① 적합성 ◎**: 개념그래프(의미) + 오개념(오인지) + MasteryState(개인 인지상태) +
  개념 점화 지도(활성화) + 증거그래프(인지 궤적)를 하나로 보면 이미 "인지 그래프".
  §2.6·§2.7이 여기로 수렴. CLAUDE.md 메타인지 정체성과 최상 정렬.
- **② 구조적 부족점**: 이 4~5개 그래프가 아직 *따로* 산다(개념/오개념/숙달/증거/점화).
  통합 인지 뷰가 개념적으로만 존재. 오개념 3중표현이 통합을 막는다.
- **③ 미래 병목**: 그래프 순환·relation 폭발·임베딩 namespace가 모두 여기서 폭발.
  다섯 그래프 조인 성능(Neo4j + pgvector + PG JSONB 하이브리드).
- **④ 필수 abstraction**: `CognitiveState`(학생 × 개념 × 시점 → 숙달 + 활성오개념 +
  점화강도의 통합 *읽기 투영*). 그래프 위생 불변식(acyclic·SCC·relation 화이트리스트).
- **⑤ 금지 abstraction**: 만능 지식그래프 온톨로지(관계유형 무한증식 — 6종 폐쇄 유지).
  학생 인지의 외부공유형 프로파일(미성년 PII 절대금기).
- **⑥ AI 적합성 ○**: LLM이 그래프를 읽어 교수학 결정(§2.2), 그래프는 결정론.
- **⑦ 유지보수 △**: 다중 그래프 통합은 야심적. 위생 게이트가 생명선.
- **⑧ 생존 ◎**: "학생이 무엇을 어떻게 아는가의 지도" = 메타인지 앱의 궁극 해자.
  장기 데이터 자산(방어 가능).
- **판정: 장기 기층 정체성(권장 2순위). §2.6·§2.7을 흡수하는 상위 그릇.**

### 2.9 Interactive Theorem Environment (대화형 정리증명 환경)

- **① 적합성 △**: WH-S Tier3(Lean)가 설계상 존재하나 **자동형식화 난제로 Phase1
  제외**. 증명/기하는 초기 scope 밖.
- **② 구조적 부족점**: 자동형식화(자연어 → Lean)가 미해결 연구난제(R-S5). 한국
  중고생 대상(고3 MVP)에 정리증명 환경은 페르소나 불일치.
- **③ 미래 병목**: Lean 검증 커버리지·형식화 비용. 학생이 Lean을 배우는 게 아니다.
- **④ 필수 abstraction**: (장기) `ProofObligation`/`FormalStep` — **Tier3 도구로서만**,
  DSL 정체성 아님.
- **⑤ 금지 abstraction**: 학생 대면 정리증명 UI를 코어 정체성으로. 전면 형식화 강제.
- **⑥ AI 적합성 △**: 자동형식화는 최전선 연구 — 현 팀 규모 부적합.
- **⑦ 유지보수 ✕**: Lean 형식화 유지비 매우 큼. 초기 부담 금지.
- **⑧ 생존 △**: 영재/KMO(Phase3+·객단가 높음)엔 미래가치. MVP 생존과 무관.
- **판정: 경계된 Tier3 도구로만 장기 보류. 정체성화 절대 금지.**

## 3. 종합 판정: 권장 진화 경로

**한 줄 결론**: MATH DSL은 **"수학 인지 그래프(기층) 위에 얹힌 교육 추론 엔진(핵심)"**
으로 진화하고, 그 위에 **AI 튜터링 OS(제품 표면)**를 얹는다. SymPy는 영구히 *검증
커널*로만 두고(재구현 금지), Lean/정리증명은 *경계된 Tier3 도구*로만 보류한다.

```
        ┌─────────────────────────────────────────────┐
 제품표면 │  AI Tutoring OS (§2.3)  — WH-1 세션·도구 계약     │  ← 장기, 얇게
        ├─────────────────────────────────────────────┤
 핵심엔진 │  Educational Reasoning Engine (§2.2)           │  ← 정체성 본체
        │   · ReasoningStep / Justification (추론 1급화)    │
        │   · 출력채널: Visualization Runtime (§2.4)        │
        │   · 입력정렬: Curriculum Compiler (§2.5)          │
        ├─────────────────────────────────────────────┤
 인지기층 │  Math Cognition Graph (§2.8)                   │  ← 장기 해자
        │   = 개념그래프 + 오개념진단(§2.6) + 적응그래프(§2.7) │
        │   · CognitiveState 통합 투영                      │
        │   · 그래프 위생 불변식 (선결 부채)                  │
        ├─────────────────────────────────────────────┤
 검증커널 │  SymPy (§2.1은 커널로만, 엔진 아님)               │  ← 불변
        │  Lean / Theorem (§2.9는 Tier3 도구로만 보류)       │
        └─────────────────────────────────────────────┘
```

### 3.1 우선순위 결론

1. **교육 추론 엔진(§2.2)** = 정체성 본체. 추론 스텝을 1급 시민으로 승격.
2. **수학 인지 그래프(§2.8)** = 장기 해자. §2.6·§2.7을 흡수하는 그릇.
3. **AI 튜터링 OS(§2.3)** = 제품 표면. 엔진이 선 *후에* 얇게.
4. §2.4·§2.5 = 엔진의 출력/입력 하위역량(정체성 아님).
5. §2.1·§2.9 = 커널/도구로 *경계*(정체성화 절대 금지).

### 3.2 반드시 추가해야 하는 abstraction (종합)

| abstraction | 위치/방향 | 목적 |
|---|---|---|
| `ReasoningStep` / `Justification` | §2.2 | 추론 유형(폐쇄 enum) + 근거 참조로 스텝을 기계가독화 |
| `CognitiveState` | §2.8 | 학생 × 개념 × 시점 통합 *읽기 투영*(신규 저장소 아님) |

### 3.4 선결 부채 (진화의 전제조건)

진화축은 부채 위에 세울 수 없다. 아래 순서로 상환한다.

1. 🔴 **오개념 canonical ID 수렴**(3중 표현 → 단일) — `math_dsl_remediation_design.md`
   진행분의 완주. 인지 그래프 통합의 최우선 전제.
2. 🟡 **그래프 순환/위생 게이트**(reachability·SCC) — 인지그래프·컴파일러 공통 전제.
   (현재 적재 시점 cycle DFS 게이트는 있으나 증분 edge-add·SCC 크론은 미도입 —
   소비처 생길 때 도입, premature 금지)
3. 🟡 **동치성 구조화**(휴리스틱 → 추론 유형 태깅으로 기계가독) — §2.2 `ReasoningStep`.
4. 🟡 **임베딩 namespace 분리** — 인지그래프 검색 오염 방지.
5. 🟡 **MasteryState 완성**(BKT → IRT + 신뢰구간 + 망각) — 적응 기층.

### 3.5 Phase 매핑 (risk_register 교차참조)

- **Phase 1 (현재)**: 부채 #1(canonical ID) 완주 + `ReasoningStep` 얇은 도입 설계.
  엔진 정체성 확립. Lean·OS는 손대지 않는다.
- **Phase 2**: `CognitiveState` 통합 투영 + MasteryState 완성 + 그래프 위생 게이트.
  인지 기층 응집.
- **Phase 3+**: `TutoringSession` 1급화 + 다국 컴파일러 확장 + (영재 트랙 한정)
  Tier3 Lean 도구 실험. OS 표면 서서히.

## 4. 핵심 원칙 (진화 내내 불변)

이 진화는 다음을 절대 배신하지 않는다.

1. **표현 ≠ 의미** — 코어는 구조를, 클라는 렌더를. 새 방향도 이 분리를 지킨다.
2. **SymPy는 커널, DSL은 엔진** — 검증은 위임, 교육적 추론은 우리 것.
3. **안전은 스키마 불변식으로** — 답 미루기·낙인 금지·저작권은 프롬프트가 아니라
   게이트로. 새 abstraction도 불변식으로 안전을 박는다.
4. **정직한 검증** — undecidable/unverifiable을 숨기지 않는다.
5. **premature abstraction 금지** — 소비처 없는 추상은 도입하지 않는다(risk_register
   Q10의 정신). 방향은 크게, 도입은 소비처가 생길 때.

> **요약**: WhyMath의 MATH DSL은 *기호엔진*도 *정리증명기*도 되어서는 안 된다.
> 그것은 **수학 인지 그래프 위에서 "왜"를 구조화하는 교육 추론 엔진**이 되어야 하며,
> SymPy와 Lean은 그 엔진이 *호출하는 도구*로 남는다. 이것이 "답이 아닌 이유를 묻는
> 수학"을 아키텍처로 번역한 결론이다.
