# 용어집 (Glossary)

> WhyMath 시스템에서 고유하게 지정된 **용어·과정·상황**을 영역별로 모은 참조 문서입니다.
> 각 항목은 *요약*이며, **정본은 해당 아키텍처·전략 문서**입니다(하단 §11 정본 인덱스 참조).
> 표기 축이 세 가지(계층 L·코딩 완성 단계 S·사업 페이즈 Phase)로 병존하므로 혼동하지 마세요 —
> **L = 책임 레이어**(무엇을 책임지나), **S = 코딩 완성 순서**(무엇을 먼저 만드나), **Phase = 시장/사업 단계**(무엇을 언제 출시하나).
>
> 각 영역의 *"왜·어디까지·무엇이 위험한가"* 심화 서술은 짝 문서 [`system_deep_dive.md`](system_deep_dive.md) 참조.

---

## §1. 계층 (Layer) — 책임 레이어, 상위→하위 단방향 의존

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **L1** | 데이터 기반 | 성취기준·교과서 매핑·원자/개념 그래프·오개념 카탈로그 — 진실 원천 |
| **L2** | 학습자 모델 | 학생의 장기 상태 추적 (BKT·IRT·정서 신호) |
| **L3** | 콘텐츠 생성·검증 | **모든 LLM 호출 집약** — 라우팅·도구·검증·캐싱·비용 추적 |
| **L4** | 교수학 엔진 | 교수학적 *결정* (Polya·소크라테스·오개념 진단) — 핵심 차별화 |
| **L5** | 상호작용 | 학생과의 유일한 접점 (Flutter 앱·서버·OCR·시각화) |
| **L6** | 응용 모드 | 같은 코어 위 시장별 진입점 (수능·영재·메타인지 등 모드 분기) |
| **L7** | 커뮤니티·소셜 | 다중 풀이 갤러리·학부모/교사 대시보드 (Phase 3+) |

> **경계 원칙**: L1–L4 = UI와 무관한 독립 수학 코어, L5 = 클라이언트. "표현 ≠ 의미"(구조는 AST/JSON로 코어에, 렌더는 클라).

## §2. 코딩 완성 단계 (Stage) — 실제 작업 과정, 게이트가 기간에 우선

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **S0** | 정합성 회복 ✅ | 이중 truth source 청산 — 원자 백본 단일화 (완료) |
| **S1** | E2E 수직 슬라이스 🔄 | "고3 1명이 1문제 끝까지" 1루프 실동작 **증거** |
| **S2** | 콘텐츠 공장 🔄 | 검증 통과 동등문제 100문+ 생성 파이프라인 |
| **S3** | 파일럿 | 진짜 학생 5~10명 측정·KPI 베이스라인 |
| **S4** | 수학 K-12 완성 | 미적분에서 전 학년으로 커버리지 수평 확장 |
| **S5** | 타과목 확장 게이트 | 물리 진입 **가부 판정** (기능이 아니라 판정) |

> 각 단계는 **진입 게이트 → 완료 정의(DoD) → 탈출 게이트** 구조. 미달 시 연장, 다음 단계 강행 금지. 정본: `../strategy/status_roadmap_2026-07.md`.

## §3. 사업 페이즈 (Phase) — S단계가 채우는 시장 그릇

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **Phase 0** | 청사진 | 아키텍처·하네스·파트너 확보 |
| **Phase 1** | MVP (현재) | 공유 메타인지 코어 + 고3 수능 우선 노출 |
| **Phase 2** | 풀 K-12 | 학교진도 + 검정고시·학종 + 결제 출시 |
| **Phase 3** | 영재·대시보드 | 영재 트랙·부모/교사 대시보드·다국 매트릭스 |
| **Phase 4** | B2B | 학교·교육청 시범 |
| **Phase 5** | 글로벌 | 영문화·베트남·인도 |
| **M1.1~M1.6** | Phase 1 마일스톤 | 월별 게이트 (M1.3 = 도메인 파트너 검수 게이트) |

> 매핑: S1~S3가 Phase 1(MVP)을 실제로 완성, S4가 Phase 2 콘텐츠 본체, S5가 다과목 확장 진입 판정. 정본: `../../ROADMAP.md`.

## §4. 하네스 (Harness) — LLM 호출 *방식*을 바꾸는 횡단 인프라 (새 계층 아님)

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **WH-1** | 튜터링 하네스 (온라인) | 오개념 가설·증거를 프롬프트가 아닌 **DB로 외부화**, 매 턴 "다음 교수학적 행동"만 판단 |
| **WH-S** | 솔버 하네스 (오프라인) | MCTS 탐색 + 3-Tier 검증으로 자체 풀이력 자기진화, 검증 풀이만 업스트림 공급 |
| **0단계 평가 하네스** | 측정 인프라 | "측정 없는 도입 없음" — 대리 지표 7종·Langfuse 베이스라인 |

> 정본: `04a_wh1_tutoring_harness.md`(WH-1) · `03b_wh_s_solver_harness.md`(WH-S).

## §5. 교수학 용어

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **Polya 4단계** | 문제해결 골격 | 이해→계획→실행→검토, 모든 학습 경로가 매핑됨 |
| **소크라테스 코칭** | 질문 우선 | 6카테고리(명료화·가정·근거·관점·함의·메타인지) |
| **답 미루기** | Productive Struggle | 방향→의사코드→부분풀이→전체풀이, 가장 빠른 단계에서 멈춤 (막혀도 바로 정답 금지) |
| **LTHC** | Low Threshold High Ceiling | 진입 문턱은 낮고 도달 천장은 높은 문항 설계 |
| **오개념 진단** | Misconception | 지목·낙인 대신 질문 종류만 바꿈 (reactive 매칭) |
| **정서 안전 톤 필터** | 감정 보호 | "틀렸·못 해" 금지, "흥미로운 시도네" 권장 |
| **개념 점화 지도** | Concept Priming | 어떤 개념이 켜졌나 (L4 판정 / L5 시각화) |

## §6. 학습자 모델 용어

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **BKT** | Bayesian Knowledge Tracing | 성취기준별 숙달 확률 (콜드스타트용, Phase 1) |
| **DKT** | Deep Knowledge Tracing | 신경망 숙달 추적 (데이터 많을 때, Phase 3+) |
| **IRT** | Item Response Theory | 문항 난이도 + 학생 능력 동시 추정 (theta) |
| **정서 신호** | Affective State | 입력 7종 → FLOW/FRUSTRATED/BORED/OVERWHELMED/AT_RISK 5분류 |
| **MasteryState** | 숙달 상태 | 학생×개념노드 숙달 (BKT+IRT+망각곡선+선호 풀이 스타일) |

## §7. 데이터·구조 원칙 용어 (구조 붕괴 방어)

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **truth source** | 진실 원천 | 개념/원자/스킬 각각 정확히 1개만 — 이중화 금지 |
| **legacy_snapshot** | 격하된 구 자산 | 구 437 개념그래프 (readonly·audit_only, 런타임 차단) |
| **원자 백본** | Atom Backbone | 현 런타임 진실 원천 (원자 <!-- fact:atom_graph.atoms -->1,823<!-- /fact -->·선수엣지 <!-- fact:atom_graph.prerequisite_total -->3,251<!-- /fact -->) |
| **Concept Purity** | 개념 순수성 | 노드에 renderer·UI·prompt·오개념·임베딩 혼입 금지 |
| **Minimal Reasoning Subgraph** | 최소 추론 부분그래프 | LLM엔 전체 그래프 금지 — depth≤2·nodes≤12~20·tokens≤3000 |
| **7대 붕괴 연쇄** | 실패 시나리오 | 노드폭발→관계폭발→순환참조→유지보수지옥→성능병목→AI추론실패→교육일관성붕괴 |
| **Curriculum Overlay** | 교육과정 오버레이 | 개념은 영속, 교육과정 매핑만 교체 (2022개정→차기 전환) |
| **자동 커리큘럼 정렬** | 7차원 조정 | 학생 교과서·진도에 표기·깊이·풀이 스타일 자동 맞춤 |
| **확장 대비 불변식** | 과목 중립 원칙 | `if subject == "math"` 금지 — 물리 확장 시 부채 폭발 방지 |
| **동등문제** | 자체 생성 문항 | 평가원·EBS 본문 복제 대신 동등하되 복제 아닌 자체 문항 |

## §8. 검증·품질 용어

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **PRM** | Process Reward Model | 풀이 *단계별* 검증기 (환각 방어 핵심) |
| **3-Tier 검증** | 검증기 스택 | Tier1 수치 → Tier2 SymPy 기호 → Tier3 Lean4 형식(보류) |
| **verify_step** | 단계 검증 도구 | correct/incorrect/**unverifiable** 3상태 (unverifiable 시 정답 미유출) |
| **SymPy 게이트** | 동치성 검사 | 생성 동등문제의 수학적 동치성 자동 판정 |
| **guard_cloud** | 클라우드 임계값 | 로컬 우선, 임계 초과 시에만 클라우드 라우팅 (목표 로컬 80%) |
| **게이트 / DoD** | 통과 조건 | 진입 게이트→완료 정의(DoD)→탈출 게이트, 미달 시 다음 단계 강행 금지 |

## §9. 기술 스택·도구

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **Phaiakes9** | 로컬 LLM 개발 서버 | 로컬 모델(Qwen3-Math/VL) 구동 인프라 (라이브 키가 S1 병목) |
| **pgvector** | 벡터 검색 | PostgreSQL 확장 (ChromaDB 대체 확정) — 단일 SQL 하이브리드 |
| **MathLive** | 수식 입력 | 학생 수식 입력 표준 (WebView 국소 임베드) |
| **Manim / Desmos** | 시각화 | 서버 렌더 / 그래프 임베드 (선언적 JSON 명세) |
| **SymPy / Lean4** | 수학 검증 | 기호 계산 / 형식 증명 (계산은 LLM에 안 시킴) |
| **MCTS** | 몬테카를로 트리 탐색 | WH-S 솔버의 풀이 탐색 알고리즘 |
| **Langfuse** | LLM 추적 | 모든 LLM 호출 추적·비용 회계 표준 |
