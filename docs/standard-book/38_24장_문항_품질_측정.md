# 24장. 문항 품질 측정

한 줄 요약: **문항 난이도와 변별력은 '감'이 아니라 응답 데이터로 측정하고, 결함 신호가 나온 문항은 자동으로 격리해 사람에게 돌려보낸다.**

#### ① 증상

- 난이도를 AI 추정이나 감으로 매겼는데, 실제 정답률과 동떨어짐
- 아무도 고르지 않는 오답 선지 — 사실상 4지선다
- 상위권 학생이 오히려 더 많이 틀리는 문항 (문항 결함의 강한 신호)
- 적응형 문항 선택(CAT)이 엉뚱한 난이도의 문항을 계속 제시

#### ② 근본 결함

문항 품질이 **측정되지 않고**, 측정값이 운영에 **되먹임(feedback)되지 않습니다.** 게시 이후 문항은 검사 없이 영원히 살아남습니다.

#### ③ 업계 표준

| 지표·이론 | 의미와 경험적 기준 |
|---|---|
| 난이도 p (고전검사이론, CTT) | 정답률. 0.3~0.8 범위가 흔한 목표 구간 |
| 변별도 (점이연 상관, point-biserial) | 이 문항 정답 여부와 나머지 총점의 상관. 0.3 이상 양호, 0.2 미만 검토, **음수면 결함 의심** |
| 선지 분석 (distractor analysis) | 선택률 5% 미만인 오답 선지는 '기능하지 않는 선지'로 봄 (Haladyna 등) |
| 문항반응이론 (IRT) | 1모수(Rasch)·2모수·3모수 모형. 모수 추정에 필요한 응답 수는 문헌마다 다르나 대략 1모수 100명 이상, 2모수 수백 명 수준이 흔히 권장됨 |
| 차등 문항 기능 (DIF) | 같은 능력인데 집단(성별·지역 등)에 따라 정답률이 다른 문항 — 공정성 검사 (Mantel–Haenszel 방법) |
| 문항 모수 이동 (drift) | 시간이 지나며 난이도가 변함 (문항 유출, 교육과정 변화) |

#### ④ 원전

- Thomas M. Haladyna, 『Developing and Validating Multiple-Choice Test Items』(3판, 2004)
- R. P. Chalmers, "mirt: A Multidimensional Item Response Theory Package for R", Journal of Statistical Software (2012)

#### ⑤ WhyMath 적용 — op-code가 제 역할을 하는지 측정

WhyMath의 오답 선지는 오개념 유형(OP_01~OP_08)에 맞춰 설계되었습니다. 선지 분석은 곧 **오개념 진단 설계의 검증**입니다. 특정 op-code의 선지가 문항 전반에서 거의 선택되지 않는다면, 그 오개념이 실제로 드물거나 선지 설계가 그 오개념을 잘 담지 못한다는 뜻입니다.

**문항 통계 (Python)**

```python
# scripts/analytics/item_stats.py — 문항 통계와 자동 격리 (pip install pandas scipy)
import pandas as pd
from scipy.stats import pointbiserialr

MIN_N = 30             # 판단에 필요한 최소 응답 수 (R24-02)
DEAD_OPTION = 0.05     # 기능하지 않는 선지 기준
QUARANTINE_R = -0.1    # 격리 기준: 0이 아니라 -0.1 (n=30이면 우연한 흔들림만으로도 0 근처 음수가 나옴)

def item_stats(df: pd.DataFrame) -> pd.DataFrame:
    """df 열: learner_id, item_id, item_revision, chosen, correct, op_code(선택한 선지의 op_code)"""
    df = df.copy()
    df["key"] = df["item_id"] + "@r" + df["item_revision"].astype(str)   # revision별 분리 (21장)
    total = df.groupby("learner_id")["correct"].sum()
    rows = []
    for key, g in df.groupby("key"):
        n = len(g)
        if n < MIN_N:
            rows.append({"key": key, "n": n, "status": "데이터 부족"})
            continue
        rest = g["learner_id"].map(total) - g["correct"]        # 이 문항을 뺀 총점 (보정 총점)
        r, _ = pointbiserialr(g["correct"].astype(int), rest)
        wrong = g[~g["correct"]]
        option_rates = (wrong["chosen"].value_counts() / n).to_dict()
        dead = sorted(o for o, rate in option_rates.items() if rate < DEAD_OPTION)
        if pd.isna(r):                                          # 모두 정답/오답이면 상관 계산 불가
            status = "계산 불가"
        else:
            status = "격리" if r < QUARANTINE_R else ("검토" if r < 0.2 else "양호")
        rows.append({"key": key, "n": n, "p": round(g["correct"].mean(), 3),
                     "discrimination": None if pd.isna(r) else round(r, 3),
                     "dead_options": dead, "status": status})
    return pd.DataFrame(rows)

# 격리 = 7장 상태 기계의 published → quarantined 전이 (사람 재검토로 돌아감)
# 아무도 고르지 않은 선지는 value_counts에 나타나지 않으므로, 실제 운영에서는
# 문항 파일의 선지 목록과 대조해 선택률 0%인 선지도 dead_options에 포함시킬 것
```

격리 기준을 0이 아니라 -0.1로 둔 이유는 **표본 오차** 때문입니다. 응답 30건일 때 상관계수의 표준오차는 대략 1/√30 ≈ 0.18이어서, 실제로는 정상인 문항도 우연히 -0.01 같은 값이 나올 수 있습니다. 이 코드를 모의 데이터로 돌려 보았을 때 정상 문항 하나가 -0.007로 격리되는 것을 확인하고 기준을 조정했습니다. 격리는 삭제가 아니라 사람 재검토로 돌려보내는 것이므로, 기준은 운영하며 판례로 조정합니다.

공개 전(콜드 스타트)에는 응답이 없으므로 난이도는 AI 추정값을 **출처와 함께** 쓰고(`source: ai_estimate`, R24-03), 응답이 MIN_N을 넘으면 실측값(`empirical`)으로 교체합니다. 출처 표기가 있어야 CAT가 불확실한 추정값에 과도하게 의존하지 않게 설계할 수 있습니다.
