# 2장. 게이트는 노드다

한 줄 요약: **승인·검사·검토는 흐름 밖에 붙이는 절차가 아니라, 입력을 가지고 하류가 기다리는 그래프 안의 노드다.**

#### ① 증상

- "검토는 나중에 따로 하자" → 바쁠 때 건너뛰어짐
- 검토가 끝나기 전의 결과물이 이미 다음 단계(게시·배포)에서 사용됨
- 누가, 언제, 무엇을 근거로 통과시켰는지 기록이 없음
- 한 게이트를 통과했다는 이유로 **다른 게이트를 생략**함 — 예: 중복 검사에 걸린 문항이라 품질 판정을 보류(s)로 넘김
- 급할 때 "이번만" 우회하고, 우회했다는 사실도 남지 않음

#### ② 근본 결함

게이트가 **그래프 밖의 섬**입니다. 하류 작업이 게이트의 통과 여부를 **입력으로 요구하지 않기** 때문에, 게이트를 거치지 않아도 하류가 실행될 수 있습니다. 게이트가 사람의 성실성(L1~L3)에만 기대고 있는 상태입니다.

#### ③ 업계 표준

게이트를 일반 노드와 똑같이 다룹니다. 게이트는 앞 단계를 `needs`로 가지고, 뒤 단계는 게이트를 `needs`로 가집니다. 그러면 **게이트를 통과하지 않은 결과물은 구조적으로 하류에 도달할 수 없습니다.**

| 사례 | 게이트가 노드로 표현되는 방식 |
|---|---|
| GitHub Actions 환경 승인 | 배포 잡에 `environment: production`을 걸고 그 환경에 필수 승인자를 지정하면, 잡이 승인 대기 상태로 멈춤. 이 잡 자체가 `needs:`로 테스트 잡에 연결됨 |
| Continuous Delivery의 배포 파이프라인 | 모든 변경은 같은 파이프라인의 모든 단계를 통과해야 하며 **우회 경로가 없음**이 원칙 |
| 단계-게이트 모델(Stage-Gate, Robert Cooper, 1990) | 제품 개발의 각 단계 사이에 판정 기준이 명시된 관문을 둠 |
| 데이터베이스 제약 | 승인 레코드가 없으면 게시 테이블에 행을 넣을 수 없도록 DB가 거부 |

좋은 게이트는 네 가지 요건을 갖춥니다.

1. **입력이 명시됨** — 무엇을 검사하는지 (어떤 파일·어떤 문항 묶음)
1. **통과 기준이 명시됨** — 무엇을 보면 통과인지 (예: F1~F8 중 해당 없음)
1. **결과가 기록됨** — 누가·언제·무엇을 근거로 (감사 추적, audit trail)
1. **우회가 불가능하거나, 우회도 기록됨** — 비상 우회(break-glass: 유리 깨고 비상벨 누르기)는 허용하되 반드시 흔적이 남음

#### ⑤ WhyMath 적용

### (1) 두 게이트는 서로 대체하지 않는다

N7 중복 게이트와 N8 사람 품질 검토는 **서로 다른 질문에 답하는 독립된 노드**입니다. 중복 게이트는 "이미 있는 문항과 겹치는가"를, 품질 검토는 "이 문항 자체가 교육적으로 올바른가"를 묻습니다. 중복으로 표시된 문항도 품질 판정은 받아야 합니다(중복 판정이 잘못됐을 수 있고, 나중에 원본 문항이 폐기되면 이 문항이 살아나야 하기 때문). 이 원리는 13장(검증 계층의 독립)에서 더 깊이 다룹니다.

### (2) 게시는 두 게이트 기록을 입력으로 요구한다

**게시 조회 (PostgreSQL)**

```sql
-- 게시 후보 조회: 중복 게이트와 사람 품질 게이트를 '모두' 통과한 문항만
SELECT i.item_id
FROM items AS i
JOIN gate_results AS d                       -- 중복 게이트 기록
  ON d.item_id = i.item_id AND d.gate = 'dedup'         AND d.verdict = 'pass'
JOIN gate_results AS q                       -- 사람 품질 검토 기록
  ON q.item_id = i.item_id AND q.gate = 'human_quality' AND q.verdict = 'accept'
JOIN gate_results AS c                       -- 저작권 판정 기록 (섬 노드를 그래프 안으로)
  ON c.item_id = i.item_id AND c.gate = 'copyright'     AND c.verdict IN ('tier1','tier2')
WHERE i.status = 'candidate';
```

여기서 저작권 등급 조건 `('tier1','tier2')`는 예시입니다. 실제 허용 등급은 「MathScope 저작권 종합가이드 v2.0」의 4-Tier 기준을 원본으로 삼아야 합니다(4장 단일 진실 원천).

### (3) 게이트 기록 테이블

**게이트 기록 스키마**

```text
-- 게이트 통과 기록: 누가·언제·무엇을 근거로 (감사 추적)
CREATE TABLE gate_results (
    item_id     TEXT        NOT NULL REFERENCES items(item_id),
    gate        TEXT        NOT NULL,          -- 'dedup' | 'human_quality' | 'copyright' ...
    verdict     TEXT        NOT NULL,          -- 판정 결과
    reason_code TEXT,                          -- 예: 'F7' (연령 부적합 어휘)
    reviewer    TEXT        NOT NULL,          -- 'kiki' 또는 'bot:dedup-v2' 처럼 기계도 이름을 가짐
    decided_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    evidence    JSONB,                         -- 판단 근거 (유사도 점수, 검토 소요 초 등)
    bypass      BOOLEAN     NOT NULL DEFAULT false,  -- 비상 우회였는가 (우회도 기록)
    PRIMARY KEY (item_id, gate)
);
```

### (4) 배포 쪽 게이트 — GitHub Actions

**배포 워크플로 예시**

```text
# .github/workflows/deploy.yml — 승인 게이트를 '잡'으로 표현
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pytest -q                     # 테스트 실패 시 이후 잡은 실행되지 않음

  deploy:
    needs: [test]                          # 선행 노드: 테스트 통과
    environment: production                # 이 환경에 필수 승인자를 지정하면 여기서 멈추고 승인 대기
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: ./scripts/deploy.sh
```

> **1인 개발자 주의**
>
> **비공개 저장소에서의 환경 보호 규칙(필수 승인자 등)은 GitHub 요금제에 따라 제공 범위가 다릅니다.** kiki-s-broom/WhyMath가 비공개라면 현재 요금제에서 가능한지 GitHub 공식 문서의 요금제 표를 먼저 확인하세요. 불가하면 `workflow_dispatch`(사람이 버튼을 눌러야 시작)로 배포 잡을 분리하는 것이 차선책입니다.
>
> 혼자 개발하므로 승인자도 본인입니다. 그래도 가치가 있는 이유는 **강제로 한 번 멈추게 하고, 멈춘 기록이 남기 때문**입니다. 단 "자기 검토 금지(Prevent self-review)" 옵션은 꺼 두어야 본인이 승인할 수 있습니다.

#### ⑥ 자동 검사와 목표 강도

| 장치 | 강도 |
|---|---|
| 게시 스크립트가 위 SQL로만 대상을 뽑음 (직접 INSERT 금지) | L5 |
| DB 트리거: `published_items`에 넣을 때 세 게이트 기록이 없으면 거부 | L5 (스크립트를 우회해도 막힘) |
| `bypass = true` 행이 생기면 주간 보고에 자동 표시 | L4 |
| 검토 소요 시간 중앙값·반려율을 게이트 기록에서 자동 집계 (19장) | L4 (도장 찍기 조기 경보) |
