# 11장. 점진적 개선 — 래칫

한 줄 요약: **지금 수준을 기준선으로 고정해 더 나빠지지만 않게 잠그고, 좋아질 때마다 기준선을 끌어올린다.**

#### ① 증상

- 린트 규칙을 켰더니 경고 2,000개 → 결국 다시 끔
- "대청소 브랜치"가 몇 주째 병합되지 못하고, 그 사이 main이 계속 바뀌어 충돌 폭발
- "나중에 한 번에 정리하자"는 날이 오지 않음
- 예외 목록(`per-file-ignores`)에 올린 파일에 **새 위반이 추가돼도** 검사가 잡지 못함

#### ② 근본 결함

개선을 **한 번의 큰 사건**으로 설계합니다. 그리고 현재 수준을 고정하는 장치가 없어서, 고치는 속도보다 새로 생기는 속도가 빠르면 영원히 따라잡지 못합니다.

#### ③ 업계 표준

| 표준 | 핵심 |
|---|---|
| 래칫 (ratchet) | 톱니바퀴처럼 한 방향으로만 도는 장치. 위반 수를 기준선에 기록 → 늘면 실패, 줄면 기준선 자동 하향 |
| 기준선 도구 | Betterer(JS), mypy 기준선 방식, ESLint `--max-warnings`, ruff `--add-noqa`(기존 위반에 예외 주석을 자동 삽입해 '새 위반만' 잡음) |
| 교살자 무화과 패턴 (Strangler Fig) | Martin Fowler, 2004. 새 구조가 옛 구조를 조금씩 감싸며 대체 — 한 번에 갈아엎지 않음 |
| 보이스카우트 규칙 | "캠프장을 처음보다 깨끗하게" — 건드린 파일은 조금이라도 개선 |
| 특성 테스트 (characterization test) | Michael Feathers. 레거시 코드를 고치기 전에 **현재 동작**을 테스트로 고정 |

#### ④ 원전

- Michael Feathers, 『레거시 코드 활용 전략』(Working Effectively with Legacy Code, 2004)
- Martin Fowler, "StranglerFigApplication" (martinfowler.com, 2004)

#### ⑤ WhyMath 적용 — 파일 단위 예외에서 개수 래칫으로

과거 ruff 정리 때 남은 187개 파일을 `per-file-ignores`(파일 단위 예외)로 묶은 방식에는 **누수 면**이 있습니다. 예외 파일 안에서는 해당 규칙 위반이 **새로 생겨도** 보이지 않습니다. 개선책은 파일마다 **위반 개수**를 기준선으로 기록해, 어떤 파일이든 개수가 늘면 실패시키는 것입니다.

**개수 래칫 (Python)**

```python
# scripts/constitution/ratchet.py — 린트 위반 개수 래칫 (R11-01, R11-02)
# 최초:   python ratchet.py --init          → 기준선 파일이 없을 때 한 번만 현재 상태로 생성 (사람이 실행)
# 검사:   python ratchet.py                 → 어떤 파일이든 기준선보다 늘면 실패
# 갱신:   python ratchet.py --update        → 줄어든 파일만 기준선을 낮춤 (늘리기 불가)
import json
import subprocess
import sys
from collections import Counter
from pathlib import Path

BASELINE = Path("constitution/lint_baseline.json")   # 기준선도 헌법 폴더에 (AI 수정 불가)

def current_counts() -> Counter:
    res = subprocess.run(["ruff", "check", ".", "--output-format", "json", "--exit-zero"],
                         capture_output=True, text=True, encoding="utf-8")
    if res.returncode != 0:
        sys.exit(f"⛔ ruff 실행 실패: {res.stderr.strip()}")
    root = Path.cwd().resolve()
    counts = Counter()
    for v in json.loads(res.stdout or "[]"):
        rel = Path(v["filename"]).resolve().relative_to(root).as_posix()
        counts[f"{rel}::{v['code']}"] += 1              # 파일×규칙 단위로 셈
    return counts

def main() -> int:
    base = Counter(json.loads(BASELINE.read_text(encoding="utf-8"))) if BASELINE.exists() else Counter()
    now = current_counts()
    if "--init" in sys.argv:
        if BASELINE.exists():
            print("⛔ 기준선이 이미 있음 — 초기화는 처음 한 번만 (완화는 헌법 개정 절차로)")
            return 1
        BASELINE.parent.mkdir(parents=True, exist_ok=True)
        BASELINE.write_text(json.dumps(dict(now), ensure_ascii=False, indent=1, sort_keys=True), encoding="utf-8")
        print(f"✅ 기준선 생성: 위반 {sum(now.values())}개")
        return 0
    worse = {k: (base.get(k, 0), n) for k, n in now.items() if n > base.get(k, 0)}
    if "--update" in sys.argv:
        if worse:
            print("⛔ 늘어난 항목이 있어 기준선을 갱신할 수 없음 (먼저 고치세요)")
        else:
            lowered = {k: n for k, n in now.items() if n > 0}   # 0이 된 항목은 목록에서 삭제
            BASELINE.write_text(json.dumps(lowered, ensure_ascii=False, indent=1, sort_keys=True), encoding="utf-8")
            print(f"✅ 기준선 갱신: 위반 {sum(base.values())} → {sum(now.values())}")
            return 0
    for k, (b, n) in sorted(worse.items()):
        print(f"⛔ 래칫 위반 {k}: 기준선 {b} → 현재 {n}")
    print(f"현재 위반 합계 {sum(now.values())} (기준선 {sum(base.values())})")
    return 1 if worse else 0

if __name__ == "__main__":
    sys.exit(main())
```

기준선 파일을 `constitution/` 아래에 두는 이유가 있습니다. 헌법 제9조에 따라 AI가 수정할 수 없으므로, **AI가 기준선을 늘려서 검사를 통과시키는 우회**가 구조적으로 막힙니다. 기준선을 처음 만드는 `--init`과 낮추는 갱신(`--update`)도 사람이 실행해 커밋합니다. (`--init`은 이 코드를 실제로 돌려 보다가 ‘기준선이 없으면 처음부터 모든 항목이 늘어난 것으로 보여 영원히 만들 수 없다’는 결함을 발견해 추가한 옵션입니다.) `--verify-monotonic` 옵션(R11-02)은 git 이력에서 기준선 합계가 늘어난 커밋을 찾아 개정 기록이 함께 있는지 확인하도록 확장합니다.
