# 파트 II 정리 — 점검표 겸 헌법 이식 규칙

이 파트의 ⑥칸을 헌법의 법률(rules.yaml)로 옮긴 목록입니다. 규칙 11개 중 10개가 L5(자동 차단)입니다. 각 행을 "이 규칙이 지금 지켜지고 있는가?"라는 점검 질문으로 읽으면 그대로 점검표가 됩니다. '단계'는 헌법 이식 단계(constitution/STAGE)이며, 그 단계에 도달하기 전까지 위헌 심사에서 "예정"으로 표시됩니다.

| ID | 규칙 (점검 질문) | 강도 | 단계 | 근거 조문 |
|---|---|---|---|---|
| R5-01 | 모듈 의존 방향은 api → infra → subject_* → eos_core 이며 역방향 import를 금지한다 | L5 | 3 | 제7조의2 |
| R5-02 | eos_core는 DB 드라이버·AI SDK를 직접 import하지 않는다 | L5 | 3 | 제7조의2 |
| R6-01 | AI 출력과 외부 입력은 경계에서 스키마로 파싱하며, 실패하면 재시도 후 격리한다 | L5 | 3 | 제7조의2 |
| R6-02 | 스키마 변경은 과거 실제 데이터 표본으로 호환성 테스트를 통과해야 한다 | L5 | 3 | 제7조의2 |
| R6-03 | 경계를 넘는 모든 데이터 스키마에는 schema_version 필드가 있다 | L5 | 3 | 제7조의2 |
| R7-01 | 문항 상태는 status 한 컬럼으로만 표현하며 상태를 뜻하는 불리언 플래그 컬럼을 두지 않는다 | L5 | 5 | 제7조의2 |
| R7-02 | 상태 전이는 전이표(item_transitions)에 있는 것만 DB가 허용한다 | L5 | 5 | 제7조의2 |
| R8-01 | 비밀값(API 키·비밀번호·암호화 키)은 저장소에 커밋될 수 없다 | L5 | 3 | 제7조의2 |
| R8-02 | 앱 빌드 산출물에 서버용 비밀 키 패턴이 없어야 한다 | L5 | 4 | 제8조 |
| R8-03 | 서버는 필수 설정이 빠지면 시작하지 않고 즉시 종료한다 | L5 | 3 | 제7조의2 |
| R8-04 | 백업 암호화 비밀키는 백업과 다른 곳 2곳 이상에 보관하고 위치를 기록한다 | L2 | 1 | 제7조의5 |

> **rules.yaml에 넣는 방법**
>
> 이 표의 규칙은 별도 파일 `rules_additions_v1.1.yaml`에 집행 장치 경로·실행 명령까지 포함해 정리되어 있습니다. 헌법 제11조에 따라 **사람이** 개정 기록(A0002)과 함께 rules.yaml에 반영합니다.
>
> 근거 조문 중 `제7조의2~5`, `제8조의2`는 현행 헌법에 없는 새 조문입니다. 개정안 초안(A0002)에 들어 있습니다.

다음 파트 III은 변경의 구조(9장 커밋 규율, 10장 DB 마이그레이션, 11장 점진적 개선)입니다.
