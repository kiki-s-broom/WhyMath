# 14장. 정적 분석 게이트

한 줄 요약: **검사 도구의 버전·설정·범위를 고정하고, 특히 "검사가 보지 않는 파일"이 없는지를 따로 검사한다.**

#### ① 증상

- 일부 폴더가 린트 검사 범위 밖에 있어서, 규칙 위반이 몇 달간 쌓여도 몰랐음
- 내 PC에서는 통과, CI에서는 실패 — 도구 버전이 다름
- 경고가 수백 개라 새 경고가 생겨도 눈에 안 띔
- 타입 오류가 실행 중에야 발견됨 (`None`에 속성 접근)

#### ② 근본 결함

검사 도구 자체가 **검사받지 않습니다.** 어느 버전이, 어떤 설정으로, **어느 범위**를 검사하는지가 고정·확인되지 않습니다. "검사 통과"는 "검사한 범위 안에서 통과"라는 뜻인데, 범위를 모르면 통과의 의미도 모릅니다.

#### ③ 업계 표준

| 표준·도구 | 핵심 |
|---|---|
| pre-commit 프레임워크 | pre-commit.com. 커밋 직전 여러 검사를 순서대로 실행, 훅 버전을 설정 파일에 고정 |
| CI 필수 검사 | 로컬 훅은 우회 가능(`--no-verify`)하므로 같은 검사를 CI에서 다시 실행 |
| 도구 버전 고정 | 잠금 파일(uv, pip-tools의 `requirements.lock`)로 ruff·mypy·pytest 버전 고정 |
| ruff (Astral, 2022~) | Rust로 만든 Python 린터·포매터. `--show-files`로 검사 대상 파일 목록 출력 가능 |
| 타입 검사 | Python: mypy·pyright. Dart: `flutter analyze --fatal-infos` (info 수준도 실패 처리) |
| 경고 0 정책 또는 래칫 | 경고는 0개로 유지하거나, 11장 래칫으로 늘지 않게 |

#### ⑤ WhyMath 적용 — 검사 범위 감시

과거 ruff 정리 과정에서 **검사 범위 밖 파일**이 있었던 경험이 이 장의 핵심 사례입니다. 해법은 "git이 관리하는 모든 .py 파일"과 "ruff가 실제로 검사하는 파일"을 비교하는 것입니다.

**검사 범위 감시 (Python)**

```python
# scripts/constitution/lint_scope.py — 검사 범위 밖 파일 탐지 (R14-01)
import subprocess
import sys
from pathlib import Path

ALLOWED_OUTSIDE = {"migrations/env.py"}   # 의도적으로 제외한 파일은 여기에 명시 (사유를 주석으로)

def run(cmd: list[str]) -> str:
    res = subprocess.run(cmd, capture_output=True, text=True, encoding="utf-8")
    if res.returncode not in (0, 1):      # ruff는 위반이 있으면 1을 돌려줄 수 있음
        sys.exit(f"⛔ 실행 실패: {' '.join(cmd)}\n{res.stderr}")
    return res.stdout

def main() -> int:
    root = Path.cwd().resolve()
    tracked = {p for p in run(["git", "ls-files", "*.py"]).splitlines() if p}
    checked = set()
    for line in run(["ruff", "check", ".", "--show-files"]).splitlines():
        path = Path(line.strip())
        if path.suffix == ".py":
            checked.add(path.resolve().relative_to(root).as_posix())
    outside = sorted(tracked - checked - ALLOWED_OUTSIDE)
    for f in outside:
        print(f"⛔ 검사 범위 밖: {f}")
    print(f"추적 {len(tracked)}개 중 검사 {len(tracked & checked)}개, 범위 밖 {len(outside)}개")
    return 1 if outside else 0

if __name__ == "__main__":
    sys.exit(main())
```

**통합 pre-commit 설정 예시**

```yaml
# .pre-commit-config.yaml — 모든 게이트를 한 곳에 (도구는 잠금 파일로 설치된 것을 system으로 호출)
repos:
  - repo: local
    hooks:
      - { id: ruff,        name: ruff 린트,        entry: python scripts/constitution/ratchet.py, language: system, pass_filenames: false }
      - { id: lint-scope,  name: 검사 범위 감시,    entry: python scripts/constitution/lint_scope.py, language: system, pass_filenames: false }
      - { id: imports,     name: 의존 방향(5장),    entry: lint-imports, language: system, pass_filenames: false }
      - { id: pipeline,    name: 파이프라인(1장),   entry: python scripts/constitution/pipeline_check.py, language: system, pass_filenames: false }
      - { id: migrations,  name: 마이그레이션(10장), entry: python scripts/constitution/check_migrations.py, language: system, pass_filenames: false }
      - { id: unit-tests,  name: 단위 테스트(12장), entry: pytest -q -m unit --disable-socket, language: system, pass_filenames: false }
      - { id: commit-msg,  name: 커밋 메시지(9장),  entry: python scripts/constitution/check_commit_msg.py, language: system, stages: [commit-msg] }
  - repo: https://github.com/gitleaks/gitleaks
    rev: vX.Y.Z   # 설치 시점 최신 태그로 고정 (8장)
    hooks:
      - id: gitleaks
```

`language: system`은 "이미 설치된 도구를 그대로 쓴다"는 뜻입니다. 도구 버전은 `requirements-dev.lock`이 고정하므로(R14-02), 로컬과 CI가 같은 버전을 씁니다. 설치는 `pre-commit install` 과 `pre-commit install --hook-type commit-msg` 두 번 실행합니다.
