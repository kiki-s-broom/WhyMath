# 29장. 교실·기기 현실

한 줄 요약: **개발 환경이 아니라 교실 환경 — 학급 전원의 동시 접속, 흔들리는 와이파이, 보급형 기기, 다양한 학습자 — 을 요구사항으로 명시하고 측정한다.**

#### ① 증상

- 수업 시작과 함께 학급 전원이 동시에 접속하자 서버가 멈춤
- 학교에 보급된 저사양 태블릿에서 수식 렌더링이 느려 화면이 버벅임
- 와이파이가 잠깐 끊겼다 돌아오자 입력하던 답이 사라짐
- 화면 낭독기(스크린 리더)를 쓰는 학생에게 수식이 "이미지" 또는 기호 나열로 읽힘
- 학교 방화벽이 앱이 쓰는 도메인 일부를 차단

#### ② 근본 결함

설계와 테스트가 **개발자의 환경**(고성능 PC, 안정적인 네트워크, 혼자 쓰는 상황)을 기준으로 이루어집니다. 교실 조건이 **측정 가능한 요구사항**으로 적혀 있지 않습니다.

#### ③ 업계 표준

| 표준 | 핵심 |
|---|---|
| 오프라인 우선 (offline-first) | 기기에 먼저 저장하고 연결되면 동기화. Ink & Switch, "Local-first software"(2019) |
| 응답 시간 한계 | Jakob Nielsen(1993): 0.1초(즉각적으로 느낌), 1초(흐름 유지), 10초(주의 유지 한계) |
| 성능 예산 (performance budget) | 첫 화면 시간·번들 크기 등의 상한을 정해 CI에서 측정 |
| 부하 시험 | Locust(Python), k6 등으로 '수업 시작 순간의 동시 접속'을 재현 |
| 접근성 | WCAG 2.2(W3C, 2023), 한국형 웹 콘텐츠 접근성 지침 2.2. 수식은 읽기 텍스트(대체 텍스트)나 MathML로 낭독 가능하게 |

#### ④ 원전

- Martin Kleppmann 외, "Local-first software" (Ink & Switch, 2019)
- Jakob Nielsen, 『Usability Engineering』(1993), 5장 응답 시간 · W3C WCAG 2.2

**기준 기기**를 하나 정해 두는 것이 핵심입니다. 학교 보급형 수준의 태블릿 실기기 한 대를 기준으로 지정하고, 성능 목표는 이 기기에서 측정합니다. 개발용 PC에서의 측정값은 교실 성능을 말해 주지 않습니다.

**교실 부하 시험 (Locust)**

```python
# loadtest/classroom.py — 수업 시작 순간 재현 (pip install locust)
# 실행: locust -f loadtest/classroom.py --headless --users 35 --spawn-rate 35 --run-time 10m --host https://staging.example
from locust import HttpUser, between, task

class Student(HttpUser):
    wait_time = between(5, 20)          # 문제를 읽고 푸는 시간 (초)

    def on_start(self):
        # 수업 코드로 입장 (테스트용 학급·계정만 사용 — 실제 학생 데이터 금지)
        self.client.post("/api/session", json={"class_code": "LOADTEST-01"})

    @task(3)
    def next_item(self):
        self.client.get("/api/items/next", name="다음 문항")

    @task(1)
    def submit(self):
        self.client.post("/api/answers", json={"item_id": "QE-03-0001", "choice": "③"}, name="답안 제출")
```

**답안 임시 저장 (Dart)**

```dart
// app/lib/answer_draft.dart — 답안을 입력할 때마다 기기에 먼저 저장 (오프라인 우선, R29-02)
import 'package:shared_preferences/shared_preferences.dart';

class AnswerDraft {
  static String _key(String itemId) => 'draft_$itemId';

  /// 입력이 바뀔 때마다 호출: 네트워크와 무관하게 기기에 저장
  static Future<void> save(String itemId, String answer) async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.setString(_key(itemId), answer);
  }

  /// 화면을 다시 열거나 앱이 재시작돼도 복원
  static Future<String?> load(String itemId) async {
    final prefs = await SharedPreferences.getInstance();
    return prefs.getString(_key(itemId));
  }

  /// 서버 전송이 '성공한 뒤에만' 삭제 (실패하면 남겨 두고 재연결 시 재전송)
  static Future<void> clearAfterSent(String itemId) async {
    final prefs = await SharedPreferences.getInstance();
    await prefs.remove(_key(itemId));
  }
}
```

수식 낭독은 21장 문항 파일의 `stem_speech` 필드로 해결합니다. 앱은 수식 위젯을 Flutter의 `Semantics(label: …)`로 감싸 이 텍스트를 화면 낭독기에 제공합니다. 읽기 텍스트는 AI로 초안을 만들 수 있지만, 수식 읽기에는 관례(예: "x 제곱")가 있으므로 사람 검토 게이트의 확인 항목에 포함합니다.
