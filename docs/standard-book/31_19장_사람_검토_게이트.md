# 19장. 사람 검토 게이트

한 줄 요약: **사람 게이트는 AI 결과의 '확인 버튼'이 아니다. AI 판정을 숨기고 먼저 판정하게 하며, 정답을 아는 보정 문항으로 검토 품질 자체를 측정한다.**

#### ① 증상

- 검토 시간 중앙값 3초, 반려 0건 — 판례 P0001
- AI가 만든 판정표를 터미널에 옮겨 적는 것이 검토가 됨
- 피곤한 밤에 수십 개를 일괄 승인
- 같은 유형의 결함을 어떤 날은 반려하고 어떤 날은 통과

#### ② 근본 결함

사람 게이트가 **AI 출력의 확인 버튼**으로 설계되어 있습니다. 사람은 기계의 판정을 보면 그것을 과신하는 경향이 있습니다. 이를 **자동화 편향**(automation bias)이라 하며, 항공·의료에서 오래 연구된 현상입니다. 판정을 먼저 보여주면 사람 층은 기계 층의 복사본이 됩니다(13장 공통 원인 고장). 또 검토 품질을 **측정하는 장치**가 없어 도장 찍기를 알아챌 방법이 없습니다.

#### ③ 업계 표준

| 표준 | 핵심 |
|---|---|
| 블라인드 우선 판정 | 기계 판정을 가린 채 사람이 먼저 판정 → 제출 후 대조. 불일치만 재검토 |
| 평가 기준표 (rubric) | 판정 코드(F1~F8)마다 정의와 **예시 문항**을 고정. 날마다 기준이 흔들리는 것을 막음 |
| 보정 문항 (gold item) | 정답(올바른 판정)을 이미 아는 문항을 몰래 섞음. 크라우드소싱 품질관리의 표준 기법 |
| 평가자 일치도 | 같은 문항을 시간 간격을 두고 다시 판정 → 코헨의 카파(Cohen's kappa, 1960)로 일관성 측정 |
| 세션 길이 제한 | 코드 리뷰 연구(SmartBear): 한 번에 60분 이내가 효과적. 피로는 판정 품질을 떨어뜨림 |

#### ④ 원전

- Raja Parasuraman·Dietrich Manzey, "Complacency and Bias in Human Use of Automation", Human Factors 52(3) (2010)
- Jacob Cohen, "A coefficient of agreement for nominal scales", Educational and Psychological Measurement (1960)

#### ⑤ WhyMath 적용 — 검토 터미널 재설계

| 현재 (a/e/r/s/q 키, F1~F8) | 재설계 | 규칙 |
|---|---|---|
| AI 참고 판정이 먼저 보임 | 사람이 키를 누른 **뒤에** AI 판정 공개 → 불일치 시 사유 한 줄 입력 | R19-01 (L5) |
| 모든 문항이 실제 후보 | 보정 문항 10% 이상 무작위 삽입 (예: F7 어휘 결함이 알려진 문항) | R19-02 (L5) |
| 세션 제한 없음 | 40문항 또는 50분마다 종료·휴식 | 도구 설정 |
| 품질 측정 없음 | 세션 끝에 건강도 보고: 시간 중앙값·반려율·보정 정답률 | R2-04, R19-03 (L4) |

**검토 건강도 (Python)**

```python
# scripts/constitution/review_health.py — 검토 세션 건강도 (R2-04, R19-03)
# 입력: 검토 로그 JSONL 한 줄 = {"item_id", "verdict", "f_code", "seconds", "is_gold", "gold_expected"}
#       (필드 이름은 실제 review_session 로그에 맞게 조정)
import json
import statistics
import sys
from pathlib import Path

LOG = Path("logs/review_sessions/latest.jsonl")
MIN_MEDIAN_SEC = 10     # 이보다 빠르면 도장 찍기 의심
MIN_GOLD_ACC = 0.80     # 보정 문항 정답률 하한

def main() -> int:
    try:
        rows = [json.loads(l) for l in LOG.read_text(encoding="utf-8").splitlines() if l.strip()]
    except (OSError, json.JSONDecodeError) as e:
        print(f"⚠️ 검토 로그를 읽을 수 없음: {e}")
        return 0                                   # L4 규칙: 경고만, 실패로 만들지 않음
    real = [r for r in rows if not r.get("is_gold")]
    gold = [r for r in rows if r.get("is_gold")]
    warnings = []
    if real:
        median = statistics.median(r["seconds"] for r in real)
        reject_rate = sum(r["verdict"] == "r" for r in real) / len(real)
        if median < MIN_MEDIAN_SEC:
            warnings.append(f"검토 시간 중앙값 {median:.1f}초 < {MIN_MEDIAN_SEC}초")
        if reject_rate == 0 and len(real) >= 10:
            warnings.append("반려율 0% (10문항 이상) — 독립 검토 여부 확인")
    if "--gold" in sys.argv:
        if not gold:
            warnings.append("보정 문항 없음 (R19-02 위반 가능성)")
        else:
            acc = sum(r.get("f_code") == r.get("gold_expected") for r in gold) / len(gold)
            if acc < MIN_GOLD_ACC:
                warnings.append(f"보정 문항 정답률 {acc:.0%} < {MIN_GOLD_ACC:.0%} → 이 세션 판정 재검토 표시")
    for w in warnings:
        print(f"⚠️ {w}")
    print(f"검토 {len(real)}건 · 보정 {len(gold)}건 · 경고 {len(warnings)}건")
    return 1 if warnings else 0                   # 위헌 심사에서 L4는 '경고'로만 집계됨

if __name__ == "__main__":
    sys.exit(main())
```

> **AI가 할 일과 하지 말 일 (헌법 제9조 ③)**
>
> AI는 검토자가 **대조할 참고 자료**(재도출 결과, 유사 문항, 어휘 등급 검사 결과)를 준비합니다. 판정표를 완성된 형태로 만들어 옮겨 적게 하지 않습니다.
>
> AI의 참고 판정은 사람이 판정을 제출한 뒤에 공개됩니다. 사람과 AI가 다르게 판정한 문항이 가장 가치 있는 데이터입니다. 이 불일치 사례는 22장 정답 검증기와 25장 평가셋의 개선 재료가 됩니다.
