# 12장. 테스트 구조

한 줄 요약: **빠르고 안정적인 단위 테스트를 많이, 느린 통합 테스트는 적게 두고, 버그 하나마다 재현 테스트 하나를 먼저 쓴다.**

#### ① 증상

- 테스트가 느려서(몇 분) 아무도 자주 돌리지 않음
- 테스트가 실제 AI API를 호출 → 가끔 실패(flaky: 같은 코드인데 결과가 들쭉날쭉), 돌릴 때마다 비용 발생
- 코드 구조를 조금 바꿨는데 테스트 20개가 깨짐 — 동작이 아니라 구현 세부를 검사하고 있었음
- 고친 버그가 두 달 뒤 다시 나타남

#### ② 근본 결함

두 가지가 겹쳐 있습니다. 첫째, 코드가 **테스트하기 어려운 구조**입니다. DB·AI 호출이 로직 안에 박혀 있으면 가짜로 바꿔 끼울 수 없습니다(5장의 포트가 해법). 둘째, **테스트 종류별 역할**이 정해져 있지 않아 모든 테스트가 느리고 불안정한 통합 테스트가 됩니다.

#### ③ 업계 표준

| 표준 | 핵심 |
|---|---|
| 테스트 피라미드 | Mike Cohn, 『Succeeding with Agile』(2009). 단위(많이·빠르게) > 통합(적당히) > 종단 간 E2E(조금) |
| 테스트 대역 (test double) | Gerard Meszaros, 『xUnit Test Patterns』(2007). 가짜(fake: 간이 구현), 스텁(stub: 정해진 답), 목(mock: 호출 검증) 등으로 외부 의존을 대체 |
| 회귀 테스트 규칙 | 버그를 고치기 전에 **그 버그를 재현하는 실패 테스트**를 먼저 쓰고, 고친 뒤 통과를 확인 |
| 속성 기반 테스트 | QuickCheck(Haskell, 1999) → Python은 Hypothesis. 예시 몇 개 대신 "모든 입력에서 성립해야 할 성질"을 적고 도구가 수백 개 입력을 자동 생성 |
| 녹화·재생 | vcrpy / pytest-recording. 외부 API 응답을 한 번 녹화해 두고 이후엔 재생 → 빠르고 무료, 결과 고정 |
| 네트워크 차단 | pytest-socket. 단위 테스트 중 네트워크 접속 시도 자체를 실패로 만듦 |

#### ⑤ WhyMath 적용

| 층 | 대상 예시 | 외부 의존 | 목표 개수·시간 |
|---|---|---|---|
| 단위 | BKT 갱신 계산, 계약 파싱(6장), 전이표(7장), 정답 동치 판정(22장) | 없음 (가짜로 대체, 네트워크 차단) | 수백 개, 전체 60초 이내 |
| 통합 | PostgreSQL 저장소 어댑터, 적재 스크립트, 마이그레이션 | 테스트용 DB 컨테이너 | 수십 개, 수 분 |
| AI 계약 | 생성 프롬프트 → 파싱 가능한 JSON이 나오는가 | 녹화 재생 (주 1회만 실제 호출로 재녹화) | 수십 개 |
| E2E | 학생 가입 → 문항 풀이 → 숙달 판정 | 스테이징 전체 | 핵심 흐름 5~10개 |

수학 앱은 속성 기반 테스트와 궁합이 특히 좋습니다. 수학 성질은 "모든 입력에서 성립"하는 형태로 적을 수 있기 때문입니다. 예를 들어 이차방정식 문항 생성기에는 "근을 먼저 정하고 식을 만들면, 재도출한 근이 원래 근과 같아야 한다"는 성질이 있습니다.

**Hypothesis 예시**

```python
# tests/unit/test_quadratic_props.py — 속성 기반 테스트 (pip install hypothesis sympy)
from hypothesis import given, strategies as st
import sympy as sp

from subject_math.generators import make_quadratic   # 근 r1, r2와 계수 a로 식을 만드는 함수
from subject_math.verify import derive_roots          # 식만 보고 근을 다시 구하는 함수 (22장)

nonzero = st.integers(min_value=-9, max_value=9).filter(lambda v: v != 0)
small = st.integers(min_value=-12, max_value=12)

@given(a=nonzero, r1=small, r2=small)
def test_roots_survive_round_trip(a, r1, r2):
    """성질: 근으로 만든 식에서 다시 구한 근은 원래 근과 같다 (중근 포함)."""
    expr = make_quadratic(a=a, r1=r1, r2=r2)           # 예: 2x² - 2x - 12
    assert set(derive_roots(expr)) == {sp.Integer(r1), sp.Integer(r2)}

@given(a=nonzero, r1=small, r2=small)
def test_generated_text_has_no_float_noise(a, r1, r2):
    """성질: 정수 근 문항의 식에는 0.30000000000000004 같은 부동소수 잡음이 없다."""
    assert "." not in str(make_quadratic(a=a, r1=r1, r2=r2))
```

**네트워크 차단 설정**

```python
# tests/conftest.py 일부 — 단위 테스트는 네트워크 차단 (pip install pytest-socket)
import pytest

def pytest_collection_modifyitems(items):
    for item in items:
        if "tests/unit/" in str(item.fspath).replace("\\", "/"):
            item.add_marker(pytest.mark.unit)          # 폴더로 자동 분류

# 실행: pytest -m unit --disable-socket   → 단위 테스트가 외부 접속을 시도하면 즉시 실패
```
