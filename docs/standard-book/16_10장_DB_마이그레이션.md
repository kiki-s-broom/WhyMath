# 10장. DB 마이그레이션

한 줄 요약: **스키마 변경은 번호 붙은 파일로만 하고, 파괴적 변경은 확장→이전→수축의 여러 단계로 쪼개 매 단계가 이전 버전과 공존하게 한다.**

#### ① 증상

- 컬럼 이름을 바꾸자마자 아직 옛 코드를 쓰는 배치 스크립트와 설치된 앱이 동시에 깨짐
- 운영 DB에 직접 `ALTER TABLE`을 쳐서, 개발 DB·테스트 DB와 스키마가 달라짐
- "컬럼 하나 지우는 건데" 했다가 학습자 응답 기록 일부가 사라짐
- 잘못된 마이그레이션을 되돌릴 방법이 없음

#### ② 근본 결함

스키마 변경이 **코드처럼 버전 관리되지 않거나**, 여러 버전의 코드가 동시에 도는 현실을 무시하고 **한 번에 파괴적 변경**을 합니다. 배포는 순간이 아니라 기간입니다. 서버를 업데이트해도 사용자 기기의 앱은 며칠~몇 주간 옛 버전으로 남습니다.

#### ③ 업계 표준

| 표준·도구 | 핵심 |
|---|---|
| 마이그레이션 도구 | Alembic(SQLAlchemy 사용 시), Flyway, Liquibase, sqitch, dbmate. 공통점: 번호 붙은 변경 파일 + 적용 기록 테이블 |
| 확장–수축 (Expand–Contract, 병렬 변경) | ① 확장: 새 구조 추가(옛것 유지) ② 이전: 양쪽에 쓰고 과거 데이터 채우기(backfill) ③ 전환: 읽기를 새 구조로 ④ 수축: 옛 구조 제거. 각 단계를 **별도 배포** |
| 적용된 마이그레이션 불변 | 한 번 적용된 파일은 고치지 않음. 수정은 새 번호 파일로 |
| 변경 전 백업 | 마이그레이션 직전 자동 백업 + 백업 확인 후에만 적용 |
| PostgreSQL의 강점 | 대부분의 DDL이 트랜잭션 안에서 실행됨 → 중간 실패 시 전부 취소. 단 `CREATE INDEX CONCURRENTLY` 등 예외 있음. 11 버전부터 고정 기본값을 가진 컬럼 추가는 테이블 전체 재작성 없이 빠르게 끝남 |

#### ⑤ WhyMath 적용

학습자 응답과 숙달 상태는 **DB가 원본**(4장)이므로 스키마 변경의 위험이 가장 큽니다. 예: `items.body`(JSON 텍스트)를 `items.content`(JSONB)로 바꾸는 경우를 확장–수축으로 나누면 다음과 같습니다.

| 단계 | 마이그레이션 파일 | 코드 변경 | 되돌리기 |
|---|---|---|---|
| ① 확장 | `0042_expand_items_content.sql`: content JSONB 컬럼 추가 (NULL 허용) | 없음 | 컬럼 삭제로 즉시 |
| ② 이전 | `0043_backfill_items_content.sql`: body → content 복사 | 쓰기를 **양쪽**에 | 코드만 되돌림 |
| ③ 전환 | 없음 | 읽기를 content로 | 코드만 되돌림 |
| ④ 수축 | `0044_contract_drop_items_body.sql`: body 삭제 (`-- contract-of: 0042` 표식) | body 참조 제거 | 백업에서 복원 (그래서 ④는 충분히 기다린 뒤) |

**마이그레이션 검사 (Python)**

```python
# scripts/constitution/check_migrations.py — 마이그레이션 규칙 검사 (R10-01, R10-02)
import hashlib
import json
import re
import sys
from pathlib import Path

MIG_DIR = Path("migrations")
LOCK = MIG_DIR / "applied.lock.json"      # 적용된 파일의 해시 기록 (적용 스크립트가 갱신)
DESTRUCTIVE = re.compile(r"\b(DROP\s+(TABLE|COLUMN)|RENAME\s+(COLUMN|TO)|ALTER\s+COLUMN\s+\w+\s+TYPE)\b", re.I)
CONTRACT_MARK = re.compile(r"--\s*contract-of:\s*(\d{4})")

def sha(path: Path) -> str:
    return hashlib.sha256(path.read_bytes()).hexdigest()

def main() -> int:
    errors = []
    try:
        applied = json.loads(LOCK.read_text(encoding="utf-8")) if LOCK.exists() else {}
    except json.JSONDecodeError as e:
        print(f"⛔ {LOCK} 형식 오류: {e}")
        return 1
    files = sorted(MIG_DIR.glob("[0-9][0-9][0-9][0-9]_*.sql"))
    numbers = {f.name[:4] for f in files}
    for f in files:
        # 1) 적용된 파일은 수정 금지 (해시 비교)
        if f.name in applied and applied[f.name] != sha(f):
            errors.append(f"[수정 금지] {f.name} 은(는) 이미 적용됨 → 새 번호 파일로 고치세요")
        # 2) 파괴적 변경은 contract 표식 + 선행 expand 번호 필수
        sql = f.read_text(encoding="utf-8")
        if DESTRUCTIVE.search(sql):
            m = CONTRACT_MARK.search(sql)
            if not m:
                errors.append(f"[파괴적 변경] {f.name}: '-- contract-of: NNNN' 표식 없음")
            elif m.group(1) not in numbers or m.group(1) >= f.name[:4]:
                errors.append(f"[파괴적 변경] {f.name}: 선행 expand {m.group(1)} 이(가) 없거나 순서가 틀림")
    for e in errors:
        print(e)
    if not errors:
        print(f"✅ 마이그레이션 {len(files)}개 규칙 준수")
    return 1 if errors else 0

if __name__ == "__main__":
    sys.exit(main())
```
