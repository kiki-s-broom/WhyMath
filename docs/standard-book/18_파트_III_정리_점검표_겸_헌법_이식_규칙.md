# 파트 III 정리 — 점검표 겸 헌법 이식 규칙

이 파트의 ⑥칸을 헌법의 법률(rules.yaml)로 옮긴 목록입니다. 규칙 8개 중 6개가 L5(자동 차단)입니다. 각 행을 "이 규칙이 지금 지켜지고 있는가?"라는 점검 질문으로 읽으면 그대로 점검표가 됩니다. '단계'는 헌법 이식 단계(constitution/STAGE)이며, 그 단계에 도달하기 전까지 위헌 심사에서 "예정"으로 표시됩니다.

| ID | 규칙 (점검 질문) | 강도 | 단계 | 근거 조문 |
|---|---|---|---|---|
| R9-01 | 커밋 메시지는 Conventional Commits 형식(content 타입 포함)을 따른다 | L5 | 3 | 제7조의3 |
| R9-02 | 한 커밋의 변경 파일이 25개를 넘으면 경고한다 | L4 | 3 | 제7조의3 |
| R9-03 | 코드 변경과 콘텐츠 변경을 한 커밋에 섞으면 경고한다 | L4 | 3 | 제7조의3 |
| R10-01 | DB 스키마는 migrations/ 파일로만 바꾸며, 적용된 마이그레이션 파일은 수정하지 않는다 | L5 | 3 | 제7조의3 |
| R10-02 | DROP·RENAME이 든 마이그레이션은 contract 표식과 선행 expand 번호가 있어야 한다 | L5 | 3 | 제7조의3 |
| R10-03 | 마이그레이션은 자동 백업을 만들고 확인한 뒤에만 적용된다 | L5 | 5 | 제7조의5 |
| R11-01 | 린트 위반 수는 파일별 기준선보다 늘어날 수 없다 (래칫) | L5 | 3 | 제7조의3 |
| R11-02 | 기준선은 줄어드는 방향으로만 갱신되며, 늘리려면 개정 기록이 필요하다 | L5 | 3 | 제11조 |

> **rules.yaml에 넣는 방법**
>
> 이 표의 규칙은 별도 파일 `rules_additions_v1.1.yaml`에 집행 장치 경로·실행 명령까지 포함해 정리되어 있습니다. 헌법 제11조에 따라 **사람이** 개정 기록(A0002)과 함께 rules.yaml에 반영합니다.
>
> 근거 조문 중 `제7조의2~5`, `제8조의2`는 현행 헌법에 없는 새 조문입니다. 개정안 초안(A0002)에 들어 있습니다.

다음 파트 IV는 검증의 구조(12장 테스트 구조, 13장 검증 계층의 독립, 14장 정적 분석 게이트)입니다.
