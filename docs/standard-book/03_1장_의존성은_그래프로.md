# 1장. 의존성은 그래프로

한 줄 요약: **모든 작업과 산출물을 "입력을 가진 노드"로 선언하면, 순서·누락·영향 범위를 기계가 계산한다.**

#### ① 증상

- "아, 이걸 먼저 돌렸어야 했는데" — 실행 순서를 사람이 기억해야 함
- 개념 그래프의 노드 하나를 고쳤는데, **무엇을 다시 돌려야 하는지** 모름. 결국 전부 다시 돌리거나, 아무것도 안 돌려서 옛 문항이 옛 노드를 계속 가리킴
- README에 "순서: 1) 추출 2) 적재 3) 생성"이라고 적혀 있지만, 새 단계가 추가될 때 README는 갱신되지 않음
- 어떤 산출물이 어디서 쓰이는지 몰라서 지우지 못하는 파일·테이블이 쌓임

#### ② 근본 결함

의존 관계(무엇이 무엇을 필요로 하는가)가 **사람의 머릿속이나 자연어 문장에만 존재**합니다. 기계가 모르니 세 가지를 할 수 없습니다. 순서를 자동으로 정하지 못하고, 고리(A가 B를 필요로 하고 B가 다시 A를 필요로 하는 순환)를 찾지 못하며, 하나가 바뀌었을 때 영향받는 범위를 계산하지 못합니다.

#### ③ 업계 표준

모든 작업·산출물을 **노드**로, "필요로 한다"를 **화살표**로 선언해 **DAG**(Directed Acyclic Graph: 방향이 있고 고리가 없는 그래프)를 만듭니다. 그러면 기계가 **위상 정렬**(topological sort: 선행 노드가 반드시 먼저 오도록 한 줄로 세우는 계산)로 실행 순서를 정하고, 바뀐 노드의 **하류**(downstream: 그 노드를 직접·간접으로 필요로 하는 모든 노드)만 다시 실행합니다.

| 도구·기법 | 등장 | 노드가 되는 것 | 핵심 아이디어 |
|---|---|---|---|
| Make | 1976, Bell Labs (Stuart Feldman) | 파일 | 대상 파일보다 입력 파일이 새것이면 다시 만듦 |
| Bazel | 2015 공개 (Google 사내 Blaze) | 빌드 대상 | 입력의 **내용 해시**로 판단 → 같은 입력이면 결과 재사용 |
| Apache Airflow | 2014, Airbnb | 데이터 작업(task) | 작업 간 의존을 파이썬 코드로 선언, 스케줄러가 순서 실행 |
| dbt | 2016~ | SQL 모델 | `ref('다른모델')` 한 줄이 곧 화살표 선언 |
| Dagster | 2019~ | 데이터 자산(asset) | 작업이 아니라 **산출물**을 노드로 봄 — 콘텐츠 파이프라인에 잘 맞음 |
| CPM 임계 경로 기법 | 1957, DuPont (Kelley·Walker) | 작업·마일스톤 | 가장 긴 선행 사슬이 전체 일정을 결정 |

그래프가 생기면 공짜로 얻는 능력이 세 가지입니다.

- **순서 자동 결정** — 사람이 README를 갱신하지 않아도 됨
- **순환 검출** — 고리가 생기는 순간 오류로 알 수 있음
- **영향 범위 계산** — "이걸 바꾸면 무엇을 다시 돌려야 하나?"에 즉답. 업계에서는 이를 blast radius(폭발 반경)라고도 부름

#### ④ 원전

- Martin Kleppmann, 『데이터 중심 애플리케이션 설계』(2017), 10장 일괄 처리 — 작업 흐름을 DAG로 다루는 이유
- Jez Humble·David Farley, 『Continuous Delivery』(2010), 5장 배포 파이프라인
- Python 공식 문서 `graphlib` 모듈 (Python 3.9부터 표준 라이브러리, 별도 설치 불필요)

> 혼자 개발할 때 가장 흔한 섬은 **N9 저작권 판정**, **백업**, **교육과정 정합성 재검토**입니다. "중요하니까 따로 챙긴다"고 생각한 것일수록 흐름 밖에 떨어져 있다가 바쁠 때 건너뛰어집니다. 중요한 것일수록 그래프 **안**에 넣어서 게시(N10)의 선행 조건으로 묶어야 합니다.

**설정 파일 예시**

```text
# pipeline.yaml — 콘텐츠 파이프라인의 노드와 선행 관계 (이 파일이 순서의 유일한 원본)
nodes:
  standards:     { source: true }               # 원천 노드: 입력 없음을 명시
  concept_graph: { needs: [standards] }
  misconceptions: { needs: [concept_graph] }
  csat_patterns: { needs: [concept_graph] }
  generate:      { needs: [concept_graph, misconceptions, csat_patterns] }
  derive_verify: { needs: [generate] }
  dedup_gate:    { needs: [generate] }
  human_review:  { needs: [derive_verify, dedup_gate] }
  copyright:     { needs: [generate] }
  publish:       { needs: [human_review, copyright] }
```

**검사기 예시 (Python)**

```python
# pipeline_check.py — 파이프라인 그래프 검사기 (누락·순환·섬 노드 검출 + 영향 범위 계산)
import sys
from graphlib import TopologicalSorter, CycleError  # 파이썬 3.9+ 표준 라이브러리
import yaml  # 설치: pip install pyyaml

def load(path: str) -> dict:
    """YAML에서 노드 정의를 읽는다. 파일이 없거나 형식이 틀리면 즉시 알린다."""
    try:
        with open(path, encoding="utf-8") as f:
            return yaml.safe_load(f)["nodes"]      # safe_load: 임의 코드 실행 방지
    except (OSError, KeyError, yaml.YAMLError) as e:
        sys.exit(f"[설정 오류] {path}: {e}")

def check(nodes: dict) -> list[str]:
    errors = []
    # 1) 존재하지 않는 선행 노드를 참조하는가 (오타·삭제된 노드)
    for name, spec in nodes.items():
        for dep in spec.get("needs", []):
            if dep not in nodes:
                errors.append(f"[누락] '{name}' 이(가) 없는 노드 '{dep}' 를 참조")
    # 2) 순환이 있는가 (A→B→A 같은 고리)
    graph = {n: set(s.get("needs", [])) for n, s in nodes.items()}
    try:
        list(TopologicalSorter(graph).static_order())
    except CycleError as e:
        errors.append(f"[순환] {' → '.join(e.args[1])}")
    # 3) 섬 노드: 원천도 아니고, 입력도 없고, 아무도 쓰지 않는 노드
    used = {d for s in nodes.values() for d in s.get("needs", [])}
    for name, spec in nodes.items():
        if not spec.get("source") and not spec.get("needs") and name not in used:
            errors.append(f"[섬] '{name}' 은(는) 그래프와 연결되지 않음")
    return errors

def downstream(nodes: dict, changed: str) -> set[str]:
    """changed 노드가 바뀌면 다시 실행해야 할 모든 하류 노드를 구한다."""
    children: dict[str, list[str]] = {n: [] for n in nodes}
    for n, s in nodes.items():
        for d in s.get("needs", []):
            children.setdefault(d, []).append(n)
    result, stack = set(), [changed]
    while stack:                                   # 깊이 우선 탐색
        for c in children.get(stack.pop(), []):
            if c not in result:
                result.add(c)
                stack.append(c)
    return result

if __name__ == "__main__":
    nodes = load("pipeline.yaml")
    errs = check(nodes)
    for e in errs:
        print(e)
    sys.exit(1 if errs else 0)                     # 오류가 하나라도 있으면 실패 코드
```

예를 들어 `downstream(nodes, "misconceptions")`는 `{generate, derive_verify, dedup_gate, human_review, copyright, publish}`를 돌려줍니다. 오개념 DB를 고치면 이 여섯 단계를 다시 거쳐야 한다는 뜻이고, `csat_patterns`는 영향이 없으므로 다시 돌릴 필요가 없습니다.

#### ⑥ 자동 검사와 목표 강도

| 장치 | 언제 실행 | 강도 |
|---|---|---|
| `pipeline_check.py`를 pre-commit 훅에 등록 | 커밋할 때마다 | L5 (오류면 커밋 불가) |
| 같은 검사를 GitHub Actions CI에도 등록 | 푸시할 때마다 | L5 (다른 PC·AI 에이전트가 커밋해도 잡힘) |
| 실행 스크립트가 `pipeline.yaml` 순서대로만 동작 | 파이프라인 실행 시 | L5 (사람이 순서를 고를 여지 제거) |
