# 16장. 백업과 복구

한 줄 요약: **백업의 목적은 복원이다. 복원해 보지 않은 백업은 백업이 아니다.**

#### ① 증상

- 백업 스크립트는 매일 "성공"인데, 한 번도 복원해 본 적 없음
- 백업 파일이 0바이트거나 중간에 잘렸는데 아무도 모름
- 암호화 키를 잃어버려 백업이 있어도 열 수 없음
- 모든 사본이 같은 계정(같은 클라우드)에 있어 계정 사고 한 번에 전부 위험
- 데이터 손상을 40일 뒤에 발견했는데 백업은 30일치만 보관

#### ② 근본 결함

**"백업 성공 = 스크립트 종료 코드 0"**으로 착각합니다. 백업의 성공 기준은 "정해진 시간 안에, 정해진 시점의 데이터로 **복원되는 것**"입니다. 이 기준을 정기적으로 검증하는 장치가 없습니다.

#### ③ 업계 표준

| 표준 | 핵심 |
|---|---|
| 3-2-1 규칙 | 사본 3개, 서로 다른 매체 2종, 그중 1개는 다른 장소(오프사이트). 확장판 3-2-1-1-0: 1개는 오프라인·변경 불가, 복원 검증 오류 0 |
| RPO / RTO | RPO(복구 시점 목표): 최대 얼마 전 데이터까지 잃어도 되나. RTO(복구 시간 목표): 복구에 최대 얼마나 걸려도 되나 |
| 정기 복원 훈련 (restore drill) | 실제로 복원해 보고 데이터 개수·무결성을 확인. 기록을 남김 |
| GFS 보관 (할아버지-아버지-아들) | 일간·주간·월간 백업을 다른 기간 보관 → 늦게 발견한 손상에도 대응 |
| PostgreSQL 백업 | `pg_dump`(논리 백업, 전체 스냅숏) + 필요 시 WAL 보관·시점 복구(PITR: pgBackRest, WAL-G)로 RPO를 분 단위로 |

실제 사례로, 2017년 1월 GitLab.com은 운영 DB 데이터를 실수로 삭제한 뒤, 준비해 둔 여러 백업·복제 수단이 **대부분 제대로 동작하지 않았다**는 사실을 사고 중에 발견했습니다. 결국 약 6시간 분량의 데이터를 잃었습니다. 백업을 여러 겹 두는 것만으로는 부족하고 **복원 검증**이 핵심이라는 교훈으로 업계에 널리 인용됩니다.

**복원 훈련 (Python)**

```python
# scripts/backup/restore_drill.py — 월 1회 자동 복원 훈련 (R16-02)
# 전제: 백업은 'pg_dump -Fc'(사용자 정의 형식)로 만들고 age로 암호화한 *.dump.age 파일
#       age·docker가 설치되어 있고, 비밀키 경로는 환경 변수 WHYMATH_AGE_KEY 로 지정
import datetime as dt
import json
import os
import subprocess
import sys
import time
from pathlib import Path

BACKUP_DIR = Path(os.environ.get("WHYMATH_BACKUP_DIR", "backups"))
PG_IMAGE = "postgres:16"               # ← 운영 DB와 같은 주 버전으로 맞출 것
CONTAINER = "whymath-restore-drill"
MIN_ROWS = {"concept_nodes": 500, "misconceptions": 350}   # 복원 후 최소 행 수 (현실 값으로 조정)
LOG = Path("constitution/drills.jsonl")  # 훈련 기록 (위헌 심사 R16-02가 읽음)

def sh(*cmd: str, check: bool = True) -> str:
    return subprocess.run(cmd, check=check, capture_output=True, text=True, encoding="utf-8").stdout

def main() -> int:
    key = os.environ.get("WHYMATH_AGE_KEY")
    latest = max(BACKUP_DIR.glob("*.dump.age"), key=lambda p: p.stat().st_mtime, default=None)
    if not key or latest is None:
        print("⛔ 비밀키 경로(WHYMATH_AGE_KEY) 또는 백업 파일이 없음")
        return 1
    plain = Path("drill.dump")
    result = {"at": dt.datetime.now().isoformat(timespec="seconds"), "backup": latest.name, "ok": False}
    started = time.monotonic()
    try:
        sh("age", "--decrypt", "-i", key, "-o", str(plain), str(latest))       # 1) 복호화
        sh("docker", "run", "-d", "--rm", "--name", CONTAINER,
           "-e", "POSTGRES_PASSWORD=drill", PG_IMAGE)                           # 2) 빈 DB 컨테이너
        for _ in range(30):                                                     # 3) 준비될 때까지 대기
            if subprocess.run(["docker", "exec", CONTAINER, "pg_isready", "-U", "postgres"],
                              capture_output=True).returncode == 0:
                break
            time.sleep(2)
        sh("docker", "cp", str(plain), f"{CONTAINER}:/tmp/db.dump")
        sh("docker", "exec", CONTAINER, "pg_restore", "-U", "postgres", "-d", "postgres",
           "--no-owner", "/tmp/db.dump")                                        # 4) 복원
        counts = {}
        for table, minimum in MIN_ROWS.items():                                 # 5) 내용 검증
            n = int(sh("docker", "exec", CONTAINER, "psql", "-U", "postgres", "-tAc",
                       f"SELECT count(*) FROM {table}").strip())
            counts[table] = n
            if n < minimum:
                raise RuntimeError(f"{table} 행 수 {n} < 최소 {minimum}")
        result.update(ok=True, counts=counts)
    except (subprocess.CalledProcessError, RuntimeError, ValueError) as e:
        result["error"] = str(getattr(e, "stderr", "") or e)[-500:]
    finally:
        result["seconds"] = round(time.monotonic() - started)                   # 실측 RTO
        subprocess.run(["docker", "rm", "-f", CONTAINER], capture_output=True)   # 정리
        plain.unlink(missing_ok=True)                                           # 복호화본 즉시 삭제
        with LOG.open("a", encoding="utf-8") as f:
            f.write(json.dumps(result, ensure_ascii=False) + "\n")
    print(("✅ 복원 성공" if result["ok"] else "⛔ 복원 실패"), json.dumps(result, ensure_ascii=False))
    return 0 if result["ok"] else 1

if __name__ == "__main__":
    sys.exit(main())
```

이 훈련은 두 가지를 동시에 측정합니다. **복원이 되는가**(무결성)와 **얼마나 걸리는가**(실측 RTO)입니다. `drills.jsonl`에 기록이 쌓이면 위헌 심사가 마지막 성공 훈련 날짜를 읽어 35일이 지나면 경고합니다(R16-02). 윈도우 작업 스케줄러에 월 1회 등록하면 됩니다.

매일 백업 직후에는 가벼운 검사(R16-01)를 돌립니다. age 암호화 파일은 첫 줄이 `age-encryption.org/v1`로 시작하므로, 이 헤더와 최소 파일 크기(예: 직전 백업의 50% 이상)만 확인해도 "0바이트 백업"과 "암호화 안 된 백업"을 잡을 수 있습니다.
