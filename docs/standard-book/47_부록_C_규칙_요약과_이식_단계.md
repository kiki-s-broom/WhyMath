# 부록 C. 규칙 요약과 이식 단계

파트 II~VII이 제안한 규칙은 모두 81개입니다. 강도별로 L5(자동 차단) 62개, L4(자동 경고) 18개, L2(문서) 1개입니다. 규칙의 원본은 `rules_additions_v1.1.yaml`이며, 각 파트 끝의 표는 이 원본에서 생성했습니다.

| 이식 단계 | 내용 | 추가 규칙 수 | 근거 |
|---|---|---|---|
| 1 | 헌법 문서 + 원본 등록부 + 위헌 심사 스크립트 | 1 | 현재 (A0001) |
| 2 | Claude Code 훅 연결 (헌법 보호, Stop 훅 위헌 심사) | 0 | A0001 |
| 3 | pre-commit·CI 연결 — 파트 II~VII 규칙 대부분이 여기서 집행 | 45 | A0002 이후 |
| 4 | AI 작업 단위·검토 도구·운영 감시 (훅, 백업 검사, 튜터 가드) | 18 | A0002 이후 |
| 5 | DB 제약 (전이 트리거, 추가 전용, 게시 게이트, E2E) | 13 | A0002 이후 |
| 6 | 실사용 데이터 기반 규칙 (일치율, 재생 비교, 문항 통계) | 4 | 공개 이후 |

> **단계를 올리는 기준**
>
> 한 단계의 규칙이 **모두 '준수'**가 된 뒤 다음 단계로 올립니다. 위헌 심사에서 "예정"이던 규칙이 단계를 올리는 순간 "위반"으로 바뀌므로, 한 번에 여러 단계를 올리면 위반이 폭증해 래칫 없이 규칙을 끄고 싶어지는 11장의 증상이 재현됩니다.
>
> 3단계의 44개 규칙은 한꺼번에 켜지 말고 **파트 단위로** 켭니다: 파트 II(경계) → III(변경) → IV(검증) → VII 콘텐츠 검사 순이 권장 순서입니다. 파트마다 집행 장치 스크립트를 만들고, 위헌 심사가 해당 파트 규칙을 모두 '준수'로 보고하면 다음 파트로 넘어갑니다.
