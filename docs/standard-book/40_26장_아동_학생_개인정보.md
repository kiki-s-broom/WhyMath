# 26장. 아동·학생 개인정보

한 줄 요약: **필요한 개인정보만 수집하고, 모든 개인정보 필드와 그 흐름을 목록(인벤토리)으로 관리하며, 목록 밖의 수집·전송은 기계로 막는다.**

> **이 장의 성격**
>
> 이 장은 법률 자문이 아니라 **구조 설계** 관점의 정리입니다. 적용 법령과 요건은 서비스 형태(개인 대상 판매, 학교 계약, 해외 서비스 여부)에 따라 달라지므로, 공개 전에 개인정보·교육 분야 법률 전문가의 검토를 받으시길 권합니다.

#### ① 증상

- 가입 화면에서 실명·생년월일·전화번호를 "혹시 필요할까 봐" 수집
- 만 14세 미만 가입자에 대한 법정대리인 동의 절차가 없음
- 학생이 올린 풀이 사진(OCR용)에 얼굴·이름표·학교명이 찍혀 있음
- 분석 SDK가 광고 식별자를 수집 → 앱 심사 반려
- 튜터 대화에 학생이 적은 전화번호가 외부 AI API로 그대로 전송

#### ② 근본 결함

개인정보의 수집·저장·전송이 **기능 개발의 부산물**로 늘어나고, "어떤 개인정보가 어디에서 어디로 흐르는가"를 담은 **지도(인벤토리)**가 없습니다. 지도가 없으면 무엇을 지켜야 하는지도 기계가 검사할 수 없습니다.

#### ③ 업계 표준과 법규

| 기준 | 핵심 (요지) |
|---|---|
| 개인정보 보호법 제22조의2 (아동의 개인정보 보호) | 만 14세 미만 아동의 개인정보 처리에 동의가 필요하면 **법정대리인의 동의**를 받고 확인해야 함. 동의를 받기 위한 최소 정보는 아동에게서 직접 수집 가능. 아동에게 알릴 때는 이해하기 쉬운 표현 사용 |
| 개인정보 보호법 — 최소 수집·국외 이전 | 목적에 필요한 최소한만 수집. 해외 AI API 등으로 개인정보를 보내면 **국외 이전** 요건 검토 필요 |
| 미국 COPPA | 13세 미만 아동 대상 온라인 서비스 규정 (FTC). 2025년 규칙 개정. 해외 사용자를 받을 경우 검토 |
| Apple 앱 심사 지침 1.3·5.1.4 | 키즈 카테고리 앱은 제3자 분석·광고 사용이 원칙적으로 금지되고, 아동 개인정보의 제3자 전송이 엄격히 제한됨 |
| Google Play 가족 정책 | 아동 대상 앱의 SDK·광고·데이터 수집 요건 |
| 프라이버시 중심 설계 (Privacy by Design) | Ann Cavoukian의 7원칙. 기본값이 보호, 수집 최소화, 처음부터 설계에 포함 |

### (1) 개인정보 인벤토리 — 이 파일이 원본

**개인정보 인벤토리 (YAML)**

```yaml
# privacy/inventory.yaml — 개인정보 필드와 흐름의 단일 원본 (R26-01)
fields:
  - name: learner.nickname
    purpose: 화면 표시
    required: true
    retention: 탈퇴 시 파기
  - name: learner.birth_year          # 생년월일 전체가 아니라 '연도'만 → 만 14세 판정에 필요한 최소
    purpose: 연령 확인 (만 14세 미만 동의 절차 분기)
    required: true
    retention: 탈퇴 시 파기
  - name: guardian.contact
    purpose: 법정대리인 동의 확인
    required: 만 14세 미만만
    retention: 동의 확인 후 법정 기간 보관 뒤 파기   # 기간은 법률 검토로 확정
  - name: upload.solution_image
    purpose: 풀이 OCR
    required: false
    retention: 텍스트 추출 직후 원본 이미지 삭제
flows:
  - to: 외부 AI API (문항 생성·튜터)
    allowed_fields: []                # 개인정보 전송 없음 — 문제·풀이 텍스트만
  - to: 로컬 LLM (Phaiakes9, Ollama)
    allowed_fields: [upload.solution_image]   # OCR·민감 텍스트 처리는 국외 이전 없는 로컬에서
```

로컬 LLM 인프라를 선호하는 운영 방침이 여기서 구조적 강점이 됩니다. 학생 풀이 이미지처럼 개인정보가 섞일 수 있는 입력은 **로컬에서만 처리**하고, 외부 API로는 개인정보가 제거된 텍스트만 보내면 국외 이전 문제가 크게 줄어듭니다.

### (2) 외부 AI 호출 차단기

**개인정보 차단기 (Python)**

```python
# infra/pii_guard.py — 외부 AI API로 가는 요청의 개인정보 차단 (R26-02)
import re

PII_PATTERNS = {
    "휴대전화": re.compile(r"01[016789][-\s.]?\d{3,4}[-\s.]?\d{4}"),
    "이메일": re.compile(r"[\w.+-]+@[\w-]+\.[\w.-]+"),
    "주민등록번호": re.compile(r"\b\d{6}[-\s]?[1-8]\d{6}\b"),
}

class PIIBlocked(Exception):
    """개인정보가 감지되어 외부 전송을 막음. 호출부는 로컬 처리로 돌리거나 가림 처리 후 재시도."""

def assert_no_pii(payload: str) -> None:
    found = [name for name, pat in PII_PATTERNS.items() if pat.search(payload)]
    if found:
        raise PIIBlocked(f"외부 전송 차단: {', '.join(found)} 패턴 감지")   # 값 자체는 로그에 남기지 않음

# 모든 외부 AI 어댑터(5장)의 전송 직전 한 곳에서 호출 → 어댑터를 새로 만들어도 빠질 수 없게
# 오탐(수학 숫자가 패턴에 걸림)은 막고 나서 확인하는 쪽이 안전 — 막힌 사례는 테스트에 추가
```
