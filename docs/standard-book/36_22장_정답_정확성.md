# 22장. 정답 정확성

한 줄 요약: **정답은 생성 AI의 말이 아니라 기계로 검증된 사실이어야 한다. 계산으로 검증할 수 있는 모든 것은 계산으로 검증한다.**

#### ① 증상

- 정답 표기 오류 (실제 정답은 ②인데 ③으로 저장)
- 선지 두 개가 모두 참 (복수 정답) 또는 참인 선지가 없음
- AI 풀이 중간에 계산 실수가 있는데 최종 답만 맞음 → 풀이를 보여주는 튜터가 틀린 과정을 가르침
- 주관식에서 `1/2`, `0.5`, `2/4`가 서로 다른 답으로 채점됨
- 수식 렌더링이 학생 기기에서 깨짐

#### ② 근본 결함

정답을 **단일 출처(생성 AI)**에 의존하고, 정답을 **기계로 검증 가능한 형태**로 저장하지 않습니다. 수학은 드물게 정답을 기계로 확인할 수 있는 영역인데, 그 장점을 쓰지 않고 있습니다.

#### ③ 업계 표준

| 표준·도구 | 핵심 |
|---|---|
| 컴퓨터 대수 시스템 (CAS) | SymPy(Python), Maxima 등. 기호 계산으로 방정식을 풀고 식을 정리 |
| 기호 동치 + 수치 동치 | `simplify(a - b) == 0`은 참이면 확실하지만, 거짓이 '다르다'를 보장하지는 않음 → 무작위 값 대입 비교를 병행 (다항식 동치 판정의 Schwartz–Zippel 보조정리, 1979~80이 이론적 근거) |
| 선지 유일성 검사 | 모든 선지를 검사해 참인 것이 **정확히 1개**인지 확인 |
| CAS 기반 채점 | Moodle의 STACK(Chris Sangwin, Maxima 기반)이 대표 사례. 학생 답을 기호적으로 동치 판정 |
| 수식 표준 | LaTeX 입력 → KaTeX(웹) / flutter_math_fork(Flutter) 렌더. 파싱 오류는 게시 전에 기계로 검출 |

#### ④ 원전

- SymPy 공식 문서 (docs.sympy.org) — solve, simplify, parse_expr
- C. J. Sangwin, 『Computer Aided Assessment of Mathematics』(Oxford University Press, 2013)

#### ⑤ WhyMath 적용

**정답 검증 (Python)**

```python
# subject_math/verify.py — 동치 판정·선지 유일성·안전한 파싱 (pip install sympy)
import random
import re
import sympy as sp
from sympy.parsing.sympy_parser import parse_expr, standard_transformations, implicit_multiplication_application

X = sp.Symbol("x")
SAFE_INPUT = re.compile(r"^[0-9x+\-*/^().\s]{1,60}$")   # 학생 입력 허용 문자 (R22-03)
TRANSFORMS = standard_transformations + (implicit_multiplication_application,)  # '2x' → 2*x

MAX_EXP = 100                                            # 거듭제곱 지수 상한

def _reject_huge_powers(expr: sp.Expr, text: str) -> None:
    """서버를 멈추게 할 수 있는 거대 거듭제곱을 거부한다."""
    for node in sp.preorder_traversal(expr):
        if isinstance(node, sp.Pow) and (
            node.exp.has(sp.Pow)                                  # 지수 안의 거듭제곱: 9^(9^9) (보수적: x^(1/2)도 거부)
            or (node.exp.is_number and abs(node.exp) > MAX_EXP)   # 너무 큰 지수: 2^1000
            or (node.is_number and node.base.has(sp.Pow))):       # 숫자 거듭제곱 탑: (9^99)^99
            raise ValueError(f"지수가 너무 크거나 중첩됨: {text!r}")

def safe_parse(text: str) -> sp.Expr:
    """학생 입력을 파싱. SymPy 파서는 내부적으로 eval을 쓰므로 허용 문자 검사를 반드시 먼저 한다."""
    if not SAFE_INPUT.match(text):
        raise ValueError(f"허용되지 않은 문자 또는 길이: {text!r}")
    src = text.replace("^", "**")
    # 1차: 계산하지 않고 구조만 파싱 → '9^9^9' 같은 거대 거듭제곱(서버 멈춤 공격)을 먼저 거른다
    _reject_huge_powers(parse_expr(src, local_dict={"x": X}, transformations=TRANSFORMS, evaluate=False), text)
    expr = parse_expr(src, local_dict={"x": X}, transformations=TRANSFORMS)   # 2차: 안전 확인 후 계산
    _reject_huge_powers(expr, text)          # (x^99)^99 → x^9801 처럼 계산 후 커지는 기호 거듭제곱도 거른다
    return expr

def equivalent(a: sp.Expr, b: sp.Expr, trials: int = 12) -> bool:
    """기호 동치 → 실패 시 무작위 유리수 대입으로 확인 (정의되지 않는 점은 건너뜀).
    a, b: safe_parse 결과이거나 코드 안의 숫자 (신뢰할 수 없는 문자열은 받지 않음)."""
    a, b = sp.S(a), sp.S(b)                        # 파이썬 숫자도 SymPy 객체로 (subs 사용 위해)
    try:
        if sp.simplify(a - b) == 0:
            return True
    except (TypeError, ValueError):
        pass
    tested = 0
    for _ in range(trials * 3):
        v = sp.Rational(random.randint(-50, 50), random.randint(1, 7))
        try:
            da, db = a.subs(X, v), b.subs(X, v)
            if not (da.is_finite and db.is_finite):
                continue
            if sp.simplify(da - db) != 0:
                return False
            tested += 1
        except (ZeroDivisionError, TypeError):
            continue
        if tested >= trials:
            return True
    return False                                   # 충분히 검증하지 못하면 '동치 아님'으로 보수적 판정

def single_correct(choices: dict[str, sp.Expr], truth: sp.Expr) -> list[str]:
    """참인 선지 목록. 길이가 1이 아니면 문항 결함 (R22-01)."""
    return [label for label, expr in choices.items() if equivalent(expr, truth)]

# 예: x²-5x+6=0 의 두 근의 합
# roots = sp.solve(X**2 - 5*X + 6, X)          → [2, 3]
# single_correct({"①": -5, "②": -6, "③": 5, "④": 6, "⑤": 1}, sum(roots))  → ["③"]
```

> **보안 주의: 학생 입력과 eval**
>
> SymPy의 `sympify`와 `parse_expr`는 내부적으로 파이썬 `eval`을 사용합니다. 학생이 입력한 문자열을 그대로 넘기면 서버에서 임의 코드가 실행될 수 있습니다. 반드시 **허용 문자 검사(화이트리스트)를 먼저** 통과시키고, 길이도 제한합니다(R22-03). 허용 문자만으로도 공격이 가능하다는 점도 주의하세요. 이 코드를 실제로 실행해 확인하던 중, 다섯 글자짜리 입력 `9^9^9`가 약 3억 7천만 자리 수를 계산하느라 서버를 멈추게 하는 것을 발견했습니다(서비스 거부 공격). 그래서 먼저 **계산하지 않고 구조만 파싱**(`evaluate=False`)해 중첩되거나 너무 큰 지수를 거른 뒤에 계산하고, 계산 결과도 한 번 더 검사합니다(`(x^99)^99`는 계산하면 `x^9801`이 되기 때문). 이 규칙은 L5여야 합니다. 학생 대상 서비스에서 서버 탈취는 곧 개인정보 유출(26장)이기 때문입니다.

**KaTeX 파싱 검사 (Node.js)**

```javascript
// scripts/constitution/katex_check.js — 모든 수식이 KaTeX로 파싱되는지 (npm install katex js-yaml)
const fs = require("fs");
const path = require("path");
const katex = require("katex");
const yaml = require("js-yaml");

// $...$ 안의 수식을 모두 뽑는다 (문항 파일의 모든 문자열 값 대상)
const MATH = /\$([^$]+)\$/g;
let errors = 0;

function walk(dir) {
  for (const name of fs.readdirSync(dir)) {
    const p = path.join(dir, name);
    if (fs.statSync(p).isDirectory()) walk(p);
    else if (p.endsWith(".yaml")) checkFile(p);
  }
}

function checkFile(file) {
  const text = JSON.stringify(yaml.load(fs.readFileSync(file, "utf8")));  // 모든 문자열 값을 한 번에
  for (const m of text.matchAll(MATH)) {
    const tex = JSON.parse('"' + m[1] + '"');     // JSON 이스케이프(\\ 등)를 원래 문자로 복원
    try {
      katex.renderToString(tex, { throwOnError: true });   // 파싱 오류면 예외
    } catch (e) {
      errors++;
      console.log(`⛔ ${file}: $${tex}$ → ${e.message}`);
    }
  }
}

walk(process.argv[2] || "content");
console.log(`KaTeX 검사 완료: 오류 ${errors}건`);
process.exit(errors ? 1 : 0);
```

KaTeX 검사는 수식이 **파싱되는지**만 봅니다. YAML 큰따옴표 때문에 `\theta`가 탭+"heta"로 바뀐 경우처럼 **파싱은 되지만 뜻이 바뀐** 손상은 통과하므로, 21장의 제어 문자 검사(R21-04)와 함께 써야 합니다.

Flutter 앱에서 쓰는 렌더러(예: flutter_math_fork)는 KaTeX와 지원 문법이 완전히 같지 않을 수 있습니다. 앱에서만 깨지는 수식이 발견되면 그 문법을 콘텐츠 린트의 금지 목록에 추가하는 방식으로 좁혀 갑니다(판례로 기록).
