# 28장. 교과 확장 구조

한 줄 요약: **코어는 과목을 모르고, 과목은 코어가 소유한 계약 테스트를 통과해야 등록된다. 가짜 과목 하나로 코어의 과목 독립성을 상시 증명한다.**

#### ① 증상

- 수학 전용 코드(LaTeX 처리, SymPy)가 EOS 코어에 섞여 있음
- 화학을 붙이려니 코어 곳곳을 고쳐야 함
- 과목마다 게시 게이트를 따로 구현하다 한 과목에서 저작권 게이트가 빠짐
- 과목 어댑터가 코어의 기대를 조용히 어겨 특정 조건에서만 오류

#### ② 근본 결함

코어와 과목 사이의 **계약이 코드로 명시·검증되지 않고**, 확장 지점(extension point)이 설계되지 않았습니다. 과목이 하나(수학)뿐인 동안에는 코어가 수학에 기대고 있어도 드러나지 않습니다.

#### ③ 업계 표준

| 표준 | 핵심 |
|---|---|
| 마이크로커널(플러그인) 아키텍처 | Mark Richards, 『Software Architecture Patterns』(O'Reilly, 2015). 작은 코어 + 등록된 플러그인 |
| 개방–폐쇄 원칙 (OCP) | Bertrand Meyer(1988). 확장에는 열려 있고 수정에는 닫혀 있어야 함 — 과목 추가가 코어 수정 없이 |
| 호환성 키트 (TCK) | Java 표준의 Technology Compatibility Kit 개념. 표준을 소유한 쪽이 테스트 모음을 제공하고, 모든 구현이 통과해야 '호환' |
| 플러그인 등록 | Python 패키지 entry points (`importlib.metadata.entry_points`)로 설치된 과목을 자동 발견 |
| 세 번째 사례 규칙 | Don Roberts(Fowler 『리팩터링』 인용). 추상화는 세 번째 사례 때. 두 번째 과목 전에 과한 추상화를 경계 |

#### ④ 원전

- Mark Richards, 『Software Architecture Patterns』(O'Reilly, 2015) · import-linter의 independence 계약

#### ⑤ WhyMath 적용 — Subject Contract와 허수아비 과목

Math EOS v1.0 단계에서는 실제 과목이 수학 하나뿐이므로, 세 번째 사례 규칙과 충돌하지 않으면서 코어 독립성을 확인하는 방법이 필요합니다. 해법은 **허수아비 과목**(dummy subject)입니다. 개념 3개, 문항 5개, 항상 정답을 확인하는 검증기만 가진 가짜 과목 어댑터를 테스트 전용으로 두고, 코어 전체 흐름(생성 → 검증 → 게이트 → 게시 → 숙달 판정)이 이 가짜 과목으로도 돌아가는지 CI에서 계속 확인합니다. 코어에 수학 의존이 스며들면 이 테스트가 먼저 깨집니다.

**Subject Contract (Python)**

```python
# eos_core/subject_contract.py — 코어가 과목에게 요구하는 계약 (포트, 5장)
from typing import Protocol
from dataclasses import dataclass

CORE_REQUIRED_GATES = ("dedup", "human_quality", "copyright")   # 과목이 제거할 수 없는 게이트 (R28-04)
CONTRACT_VERSION = "1.0"

@dataclass
class VerifyResult:
    ok: bool
    reason: str

class SubjectAdapter(Protocol):
    subject_id: str                    # "math", "chem", "dummy"
    contract_version: str              # 코어의 CONTRACT_VERSION과 주 버전이 같아야 함
    def concept_graph(self) -> dict: ...              # 20장 불변식을 통과하는 그래프
    def item_payload_schema(self) -> dict: ...        # 과목 고유 필드의 JSON Schema (6장)
    def verify_answer(self, item: dict) -> VerifyResult: ...   # 22장 (수학은 CAS)
    def extra_gates(self) -> tuple[str, ...]: ...     # 과목 추가 게이트 (코어 게이트에 '추가'만 가능)
```

**계약 테스트 (pytest)**

```python
# tests/contract/test_subject_contract.py — 코어가 소유하는 호환성 키트 (모든 과목이 통과해야 등록)
import pytest
from importlib.metadata import entry_points
from eos_core.subject_contract import CONTRACT_VERSION, CORE_REQUIRED_GATES
from eos_core.graph_invariants import check_graph          # 20장 검사기를 코어로 옮긴 것

def discover():
    """설치된 과목 플러그인 + 테스트 전용 허수아비 과목"""
    adapters = [ep.load()() for ep in entry_points(group="eos.subjects")]
    from tests.contract.dummy_subject import DummySubject
    return adapters + [DummySubject()]

ADAPTERS = discover()
IDS = [a.subject_id for a in ADAPTERS]

@pytest.mark.parametrize("adapter", ADAPTERS, ids=IDS)
def test_contract_version(adapter):
    assert adapter.contract_version.split(".")[0] == CONTRACT_VERSION.split(".")[0]

@pytest.mark.parametrize("adapter", ADAPTERS, ids=IDS)
def test_graph_invariants(adapter):
    assert check_graph(adapter.concept_graph()) == []

@pytest.mark.parametrize("adapter", ADAPTERS, ids=IDS)
def test_core_gates(adapter):
    gates = set(CORE_REQUIRED_GATES) | set(adapter.extra_gates())
    assert set(CORE_REQUIRED_GATES) <= gates          # 코어 게이트는 항상 포함 (제거 불가)

def test_dummy_present():
    assert "dummy" in IDS                              # 허수아비가 빠지면 독립성 증명도 빠짐 (R28-03)
```

**import-linter independence 계약**

```ini
# .importlinter 추가분 — 과목끼리는 서로 모른다 (R28-01)
[importlinter:contract:subjects-independent]
name = 과목 패키지 상호 독립
type = independence
modules =
    subject_math
    subject_dummy
```
