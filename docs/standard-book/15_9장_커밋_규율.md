# 9장. 커밋 규율

한 줄 요약: **커밋 하나 = 논리적 변경 하나 = 그 자체로 동작하는 상태. 그래야 되돌리기와 원인 추적이 한 명령으로 끝난다.**

#### ① 증상

- 버그 하나를 되돌리려 했더니 같은 커밋에 섞인 다른 기능까지 사라짐
- 커밋 메시지가 "수정", "wip", "ㅇㅇ" — 석 달 뒤 무엇을 왜 바꿨는지 모름
- AI 에이전트가 한 번에 40개 파일을 바꾼 커밋 하나 → 검토 불가
- 언제부터 오답 판정이 틀리기 시작했는지 찾으려는데, 중간 커밋들이 실행조차 안 됨
- 개념 그래프(콘텐츠) 수정과 코드 수정이 한 커밋에 섞여, 콘텐츠만 되돌릴 수 없음

#### ② 근본 결함

**변경의 단위가 정의되어 있지 않습니다.** 커밋이 "저장 버튼"처럼 쓰이면, 되돌리기·검토·원인 추적의 단위가 사라집니다. git의 강력한 기능(되돌리기 `revert`, 이분 탐색 `bisect`, 부분 선택 `cherry-pick`)은 모두 **커밋이 의미 있는 단위일 때만** 작동합니다.

#### ③ 업계 표준

| 표준 | 핵심 |
|---|---|
| 원자적 커밋 (atomic commit) | 하나의 논리적 변경만 담고, 그 커밋 시점에서 빌드·테스트가 통과 |
| Conventional Commits 1.0.0 | `타입(범위): 설명` 형식. feat(기능)·fix(버그)·refactor(구조 개선)·docs·test·chore 등. `!` 또는 `BREAKING CHANGE:`로 호환성 깨짐 표시 |
| 시맨틱 버저닝 2.0.0 | 주.부.수 버전. 호환 깨짐→주, 기능 추가→부, 버그 수정→수. 커밋 타입에서 자동 계산 가능 |
| 트렁크 기반 개발 | 짧게 사는 브랜치(하루~며칠)를 자주 main에 병합. 오래 사는 브랜치는 병합 지옥의 원인 |
| git bisect | "여기선 정상, 여기선 버그" 두 지점 사이를 이분 탐색해 원인 커밋을 찾음. 1,000개 커밋도 약 10번 만에 찾음 (2¹⁰ = 1,024) |

#### ④ 원전

- conventionalcommits.org (v1.0.0) · semver.org (v2.0.0) · trunkbaseddevelopment.com
- 『Pro Git』 2판 (Scott Chacon·Ben Straub, 2014, git-scm.com에서 무료) — 7.10절 git bisect

#### ⑤ WhyMath 적용

### (1) 커밋 타입에 content를 추가

WhyMath는 코드와 콘텐츠가 함께 사는 저장소이므로 표준 타입에 `content`를 추가합니다. Conventional Commits는 타입 추가를 허용합니다. 콘텐츠 변경은 코드 변경과 **다른 커밋**으로 분리합니다(R9-03). 그래야 "개념 그래프 수정만 되돌리기"가 가능합니다.

| 예시 메시지 | 의미 |
|---|---|
| `feat(generate): 오답 op-code별 생성 슬롯 추가` | 생성 기능 추가 |
| `fix(bkt): 연속 정답 시 숙달 확률 1.0 초과 버그` | 버그 수정 (재현 테스트 포함 필수, R12-02) |
| `content(concept-graph): 이차방정식 선수 노드 2개 보강` | 콘텐츠 변경 |
| `refactor(core)!: Item 스키마 v2 — answer를 answers 목록으로` | 호환 깨짐 (! 표시) |

### (2) AI 작업 1건 = 브랜치 1개, 논리 단위마다 커밋

Claude Code에 작업을 맡길 때는 `task/짧은-이름` 브랜치를 만들고, 작업 안에서도 논리 단위(예: 스키마 → 로직 → 테스트)마다 커밋하게 합니다. 이 커밋들이 **되돌리기 경계**(rollback boundary)가 됩니다. 18장에서 작업 명세(TASK.md)와 함께 다룹니다.

**커밋 메시지 검사 (Python)**

```python
# scripts/constitution/check_commit_msg.py — 커밋 메시지 형식 검사
# pre-commit의 commit-msg 단계:  python check_commit_msg.py .git/COMMIT_EDITMSG
# 위헌 심사용(최근 커밋 검사):    python check_commit_msg.py --last [--size] [--mixed]
import re
import subprocess
import sys

TYPES = "feat|fix|refactor|perf|docs|test|build|ci|chore|content|revert"
PATTERN = re.compile(rf"^({TYPES})(\([\w가-힣.\-]+\))?!?: .{{5,}}")   # 설명은 5자 이상
MAX_FILES = 25                                           # R9-02 경고 기준

def git(*args: str) -> str:
    return subprocess.run(["git", *args], capture_output=True, text=True,
                          encoding="utf-8", check=True).stdout

def check_message(msg: str) -> list[str]:
    first = msg.strip().splitlines()[0] if msg.strip() else ""
    if first.startswith(("Merge ", "Revert \"")):        # git이 자동 생성한 메시지는 통과
        return []
    return [] if PATTERN.match(first) else [f"형식 위반: '{first}' → 예: feat(generate): 설명"]

def main() -> int:
    args = sys.argv[1:]
    try:
        if "--last" in args:
            msg = git("log", "-1", "--pretty=%B")
            files = [f for f in git("show", "--name-only", "--pretty=", "HEAD").splitlines() if f]
        else:
            msg = open(args[0], encoding="utf-8").read()
            files = []
    except (subprocess.CalledProcessError, OSError, IndexError) as e:
        print(f"⛔ 커밋 정보를 읽을 수 없음: {e}")
        return 1
    errors = check_message(msg)
    if "--size" in args and len(files) > MAX_FILES:       # L4: 경고만
        print(f"⚠️ 변경 파일 {len(files)}개 > {MAX_FILES}개 — 커밋을 나눌 수 있는지 검토")
    if "--mixed" in args:
        kinds = {"content" if f.startswith("content/") else "code" for f in files}
        if len(kinds) > 1:
            print("⚠️ 코드와 콘텐츠가 한 커밋에 섞임 — 콘텐츠만 되돌릴 수 없게 됨")
    for e in errors:
        print(f"⛔ {e}")
    return 1 if errors else 0

if __name__ == "__main__":
    sys.exit(main())
```

**git bisect 자동 실행**

```bash
# 원인 커밋 찾기 — 어제는 정상, 오늘 오답 판정이 틀림
git bisect start
git bisect bad HEAD                 # 지금은 버그 있음
git bisect good v0.9.2              # 이 태그 때는 정상이었음
git bisect run pytest -q tests/test_grading.py   # 테스트로 자동 판정하며 이분 탐색
git bisect reset                    # 끝나면 원래 위치로
```

`git bisect run`은 **모든 커밋에서 테스트가 실행될 수 있을 때만** 작동합니다. 원자적 커밋 규율이 원인 추적 능력으로 바로 이어지는 이유입니다.

#### ⑥ 자동 검사와 목표 강도

| 장치 | 강도 |
|---|---|
| commit-msg 훅으로 형식 검사 (`pre-commit install --hook-type commit-msg`) | L5 |
| 커밋 변경 파일 25개 초과 경고 | L4 |
| 코드·콘텐츠 혼합 커밋 경고 | L4 |
