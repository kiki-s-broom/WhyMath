# 15장. 관측 가능성

한 줄 요약: **로그는 사람이 읽는 문장이 아니라 기계가 세고 거를 수 있는 기록(구조화 로그)으로 남기고, 핵심 숫자는 지표로 추적한다.**

#### ① 증상

- "어제 밤 배치에서 몇 개가 실패했지?"에 답하려면 로그 파일을 눈으로 훑어야 함
- 오류가 `print()`로만 찍혀서 서버 재시작과 함께 사라짐
- 학생이 "화면이 멈췄다"고 신고해도 그 요청을 찾아 재현할 수 없음
- AI API 비용이 급증한 것을 월말 청구서로 알게 됨

#### ② 근본 결함

시스템 **내부 상태를 밖에서 볼 창**이 없습니다. 로그가 자유 형식 문장이라 검색·집계가 안 되고, 요청들을 하나로 묶는 식별자가 없어 "한 학생의 한 번의 풀이"를 따라갈 수 없습니다.

#### ③ 업계 표준

| 표준 | 핵심 |
|---|---|
| 관측의 3기둥 | 로그(사건 기록), 지표(숫자의 시계열), 추적(trace: 요청 하나가 거쳐 간 경로) |
| OpenTelemetry | CNCF 표준(2019, OpenTracing과 OpenCensus 통합). 로그·지표·추적의 공통 형식과 SDK |
| 4대 골든 시그널 | Google SRE: 지연(latency), 트래픽, 오류, 포화(saturation). 무엇을 볼지 모를 때의 출발점 |
| 구조화 로그 | 한 줄 = JSON 한 개. `{"event":"item_created","run_id":…,"node":…}` → 기계로 세고 거를 수 있음 |
| 상관 ID (correlation id) | 요청·배치마다 고유 ID를 붙여 관련 로그를 한 줄로 꿰기 |
| 증상 기반 경보 | 원인(CPU 80%)이 아니라 사용자가 겪는 증상(응답 5초 초과)에 경보 |

#### ④ 원전

- OpenTelemetry 공식 문서 (opentelemetry.io) · structlog 문서

1인 운영에 맞는 구성은 가볍게 시작합니다. Phaiakes9의 Docker 위에 Grafana·Prometheus(지표)와 Loki(로그)를 올리거나, 오류 추적만 먼저 필요하면 Sentry 같은 호스팅 서비스의 무료 요금제로 시작할 수 있습니다(무료 한도는 서비스별로 확인). 어느 쪽이든 **로그를 구조화하는 것이 먼저**입니다. 구조화된 로그는 나중에 어떤 도구로든 옮길 수 있습니다.

**structlog 설정 (Python)**

```python
# infra/logging_setup.py — 구조화 로그 + 개인정보 마스킹 (pip install structlog)
import uuid
import structlog

SENSITIVE_KEYS = {"student_name", "email", "phone", "birth_date", "guardian_phone"}  # 26장 인벤토리와 동기화

def mask_pii(_logger, _method, event_dict):
    """로그에 개인정보 키가 들어오면 값을 가린다 (R15-03)."""
    for key in SENSITIVE_KEYS & event_dict.keys():
        event_dict[key] = "***"
    return event_dict

structlog.configure(processors=[
    structlog.contextvars.merge_contextvars,          # run_id 같은 공통 필드를 자동 포함
    structlog.processors.add_log_level,
    structlog.processors.TimeStamper(fmt="iso"),
    mask_pii,
    structlog.processors.JSONRenderer(ensure_ascii=False),   # 한글이 \uXXXX로 깨지지 않게
])
log = structlog.get_logger()

def start_run(batch: str) -> str:
    """배치 시작 시 호출: 이후 모든 로그에 같은 run_id가 붙는다."""
    run_id = uuid.uuid4().hex[:12]
    structlog.contextvars.bind_contextvars(run_id=run_id, batch=batch)
    return run_id

# 사용 예
# start_run("generate")
# log.info("item_created", node="QE-03", op_code="OP_02")
# log.info("batch_summary", created=168, skip=0, failed=2)   ← R15-02: 배치마다 요약 한 줄
```
