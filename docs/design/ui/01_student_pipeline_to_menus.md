# 01. 5단계 파이프라인 → 학생 UI 메뉴 구성

> **질문**: "교육목적 → 교수전략 → 콘텐츠구성 → DSL → 자동생성"의 5단계 파이프라인을 적용하면 학생 UI에는 메뉴가 어떻게 구성되나?
>
> **한 줄 답**: WhyMath는 이 파이프라인을 **학생 메뉴에 선형으로 투영하지 않는다**. 파이프라인은 *선언적 명세*(`LearningScene`/`Visualization`)를 산출하고, **학생 UI는 그 명세의 렌더러**다. 그래서 "메뉴"는 손으로 짠 콘텐츠 트리가 아니라 **3개 축(모드·교과서 좌표·행동 진입점)에서 파생되는 결과**다.

---

## §1. 왜 5단계를 학생 메뉴에 선형 투영하면 안 되는가

프로젝트는 이 파이프라인을 **명시적으로 인지하고, 의도적으로 변형**했다. `../architecture/04d_adaptive_pedagogy_engine.md`(§0, 14행)가 바로 이 순서를 인용하며 거부한다:

> "교육과정 → 교육목적 → **교수전략** → 콘텐츠 → DSL → 생성"처럼 교수전략을 DSL *이전*에 고정하면, 같은 교육목적이라도 학생마다·학습상황마다·오답패턴마다 달라져야 할 교수법이 **콘텐츠에 각인**되어 버린다.

같은 "일차방정식"이라도 계산 실수가 많은 학생에게는 `RETRIEVAL`(연습), 개념이 약한 학생에게는 `ANALOGY`(비유)가 필요하다. 교수전략을 DSL 생성 시점에 못 박으면 이 개인화가 불가능해진다.

### 해결: 교수법 2단계 분리 (불변식)

| 단계 | 시점 | 무엇을 결정 | 상태 |
|---|---|---|---|
| **① 설계용(Design Pedagogy)** | DSL *생성* 시(오프라인) | *무엇을* 담을지(개념·예시·오개념·평가) | 🟢 대부분 구현 — `PedagogyPack`(`schema/pedagogy_pack.py`)·소단원 DSL 컴파일러(`l1/pedagogy/unit_compiler.py`) |
| **② 실행용(Runtime Pedagogy)** | 학생 *학습* 시(온라인) | *어떻게* 보여줄지(설명/질문/문제/비유…) | 🔴 계획 — Runtime Pedagogy Selector(`PED-02`)·ConceptDSL+PedagogyAdapter(`REND-01`) |

**결론**: 사이 산출물(DSL)은 **교수법-중립**을 유지한다. 학생 화면의 "방식"은 저장된 것을 재생하는 게 아니라 **매 학습마다 런타임에 재선택·재렌더**된다. 따라서 학생 UI는 "5단계로 미리 짜둔 메뉴 트리"가 될 수 없고, **명세를 받아 그리는 렌더러**여야 한다.

## §2. 5단계 ↔ UI 산출물 매핑

각 단계가 학생 화면에서 *무엇으로* 나타나는지의 대응표. **핵심: 대부분의 단계는 "메뉴 항목"이 아니라 "화면 구성요소" 또는 "렌더 방식"으로 나타난다.**

| 파이프라인 단계 | 학생 UI 산출물 | 형태 | 정본 |
|---|---|---|---|
| **① 교육목적** (성취기준·학습목표) | 온보딩의 목표 수집 + 메인 화면의 **"내 교과서 좌표"** (예: `미래엔 수학II · p.156~162 · 도함수의 정의`) | 메뉴가 아니라 **좌표/맥락 표시** | `05:99-109` |
| **② 교수전략** | Runtime Pedagogy Selector가 학생 상태로 `SOCRATIC`/`ANALOGY`/`RETRIEVAL` 등 선택 → 코치 발화·장면의 **렌더 방식**에 반영 | 학생이 고르는 메뉴 **아님** (시스템이 선택) | `04d §2` |
| **③ 콘텐츠구성** | `LearningScene`의 `SceneElement` 7종이 **한 문제 화면 안의 위젯 구성**을 결정 | 화면 내부 레이아웃 | `05a` |
| **④ DSL** | ConceptDSL/LearningScene/Visualization JSON → `scene_renderer.dart` 레지스트리가 kind별 위젯 렌더 | UI가 소비하는 **입력 계약** | `05a`·`schema/visualization.py` |
| **⑤ 자동생성** | select-vs-generate: 캐시 히트=0원 렌더, 미스=라우터 생성 → 학생에겐 **투명**(로딩만 보임) | 화면 뒤 파이프라인 | `03c §3` |

### `SceneElement` 7종 = "한 화면의 구성요소"

콘텐츠구성(③)이 학생 화면에 나타나는 실체는 `LearningScene`의 요소 7종이다(`05a`):

- `visualization` — 그래프·곡면·시뮬레이션(`Visualization` 4종)
- `param_control` — 슬라이더·드래그(학생이 파라미터 조작 → 즉시 재렌더)
- `step_panel` — Polya 단계 풀이 패널
- `misconception_probe` — 오개념 반응형 프로브 (**정답·수정 필드 없음** — 스키마 불변식)
- `socratic_prompt` — 소크라테스 발화
- `annotation` — 주석·라벨
- `skill_focus` — 지금 다루는 스킬 하이라이트

→ 즉 **"문제 하나를 여는 것"이 곧 파이프라인 산출 장면 하나를 렌더하는 것**이다. 화면은 단원 목록에서 정적으로 고르는 게 아니라, 학생 상태 + 개념 노드 → 장면 명세로 조립된다.

## §3. 그렇다면 "메뉴"는 어디서 나오는가 — 실제 최상위 IA의 3축

학생이 손으로 탐색하는 "메뉴"는 콘텐츠 트리가 아니라 **아래 3축에서 파생**된다.

### (a) 모드 스위처 — L6 6모드 (진짜 최상위 메뉴)

같은 코어 위에서 *진입점*만 바꾸는 층(`06`). Phase별로 노출된다.

| 모드 | 타깃 | Phase | 상태 |
|---|---|---|---|
| 사고력·심화 | 전 학년 | 1(진입) | 🟢 게이팅 |
| 메타인지 코칭 | 전 학년 | 1(진입) | 🟢 게이팅 |
| 학교 진도 | 중1~고3 | 2 | 🟢 게이팅(깊이정렬 🟡) |
| 수능·내신 | 고2~고3·N수 | 2 | 🟢 게이팅 |
| 재수(N수) | 재수·검정고시 | 2 | 🟢 게이팅(retake) |
| 영재 트랙 | 영재원·KMO | 3 | 🟢 게이팅(데이터 대기) |

- 모드는 콘텐츠 *풀과 교수학 가중치*(`ModeConfig`의 `content_filter`·`polya_emphasis`·`gamification_level`·`primary_color`)를 정한다.
- **학생은 여러 모드를 동시 사용 가능**하고, 코어 상태(BKT·오개념)는 공유된다(`06:164-168`). 모드 전환은 "다른 앱"이 아니라 "같은 데이터의 다른 뷰".

### (b) 교과서 좌표 / 학습 경로 — 자동 커리큘럼 정렬 출력

콘텐츠 탐색의 축. **정적 단원 트리가 아니라** 정렬 엔진(L1+L6)이 학생 프로필로 만들어 내려주는 좌표·경로다(`05:99-109`·`06:53-103`).

- 메인 화면은 추상적 단원명이 아니라 *학생이 들고 다니는 그 교과서의 그 페이지*로 표시.
- 7차원 자동 조정(활성 개념 풀·표기·깊이·풀이 스타일 순서·용어·인접 개념 순서·평가 형식) 중 **깊이 축만 🟡 1차 구현**, 나머지 🔴.
- "다음에 뭘 풀까"는 학생이 트리에서 고르는 게 아니라 **진단·약점 기반 추천**(CAT)으로 흐른다(`diagnosis_controller.dart` → `GET /v1/me/next-problem`).

### (c) 행동(action) 진입점

학생이 *지금 할 수 있는 행동*. 현재 `chat_screen` 앱바·입력 영역에 이미 존재한다.

- 오늘의 문제 / 코치 대화 / **풀이 사진(OCR)** / **수식 입력(MathLive)** / **약점 개념 장면 보기** / (Phase3) 다중 풀이 갤러리·Live Problems.
- 입력 2모드: 대화 모드 ↔ 풀이 단계 모드(`_SolutionStepsEditor` — 번호 매김 단계 묶음 제출).

## §4. 하단 탭 제안 (현재 🔴 미구현 — `router.dart:9` "후속 슬라이스")

3축을 학생이 만나는 물리적 형태로 제안한다. **각 탭의 내용은 파이프라인 산출 명세로 채워지지, 탭 자체가 콘텐츠를 하드코딩하지 않는다.**

| 탭 | 담는 것 | 파이프라인 연결 |
|---|---|---|
| **홈** | 내 교과서 좌표 + 오늘의 문제 + 이어하기 | ① 교육목적(좌표) · ⑤ 자동생성(추천 문제) |
| **학습** | 코치 대화 + 풀이 단계 제출 + OCR/수식입력 (현 `chat_screen`) | ② 교수전략(렌더 방식) · ③ 콘텐츠구성(장면) |
| **탐구** | 사고력·시각화 장면 + 개념 점화 지도 + (Phase3) 갤러리 | ③·④ 선언적 장면 렌더 |
| **나** | 학습 경로 시각화 + 진단 결과 + 설정 (반게임화: 랭킹·스트릭 없음) | ① 목표 · L2 학습자 모델 뷰 |

- **모드 스위처**는 홈 상단 또는 "나" 탭에 둔다(Phase1은 사고력·메타인지 2모드만 노출 → 초기엔 스위처가 눈에 띄지 않아도 됨).
- 탭은 4개 이하 유지(패드·폰 공용·접근성 **48dp** 탭 영역 — 정본 단일값 `06_design_system.md` §7).

## §5. 학습 여정(Learning Journey) — 한 수업 *안*의 세로 흐름

> §3의 3축이 **수업 사이를 오가는 가로 IA**라면, 학습 여정은 **한 목표(수업) 안에서 학생이 밟는 세로 흐름**이다. Kiki의 ChatGPT 설계안(원본 [A]·[B]·[E])이 제안한 흐름을 WhyMath 코어에 매핑한다. 원본의 핵심 통찰 — *"학생은 DSL·교수법을 절대 보지 않고, 학습 경험만 본다"* — 은 본 도메인의 **표현≠의미** 불변식과 정확히 같은 말이다.

### 교과서형 UI vs 학습 여정

```
기존 교과서형 :  개념 → 예제 → 문제1 → 문제2 → 정답
WhyMath 여정 :  오늘 목표 → 왜 배울까 → 탐색 → 개념 → 예제 → 연습 → AI 피드백 → 오답 교정 → 형성평가 → 다음 목표
```
학생은 "문제를 푼다"가 아니라 **"목표를 달성한다"**는 경험을 한다.

### 여정 10단계 ↔ WhyMath 좌석 매핑

| 단계 | 학생 경험 | WhyMath 좌석 | Polya |
|---|---|---|---|
| ① 오늘의 목표 | 오늘 할 일·예상시간 체크리스트 | 성취기준/학습목표(`learning_objective`)·교과서 좌표 | — |
| ② 왜 배우는가 | 실생활 동기(택시요금·속력…) | AI 생성 동기(`generate` 라우터)·`annotation` | 이해 |
| ③ 탐색 | 슬라이더로 직접 움직여 봄 | `param_control` + `Visualization`(interactive_graph_2d) | 이해 |
| ④ 개념 | 처음으로 정식 정의 | `concept_content`(정식정의·직관) | 계획 |
| ⑤ 예제 | 단계별 풀이·"왜?"·다른 방법 | `step_panel`·`SolutionStep`·다중 풀이 | 계획 |
| ⑥ 연습 | 수준(쉬움/보통/도전) 자동 선택 | CAT 추천·난이도(`diagnosis_controller`) | 실행 |
| ⑦ AI 피드백 | "왜 -2가 되나요?" 질문 응답 | 코치 대화·`socratic_prompt`·L4 톤 필터 | 실행 |
| ⑧ 오답 교정 | "기울기를 거꾸로 계산했습니다" | `misconception_probe`·오개념 DB(반응형·**정답/수정 필드 없음**) | 반성 |
| ⑨ 형성평가 | 목표 달성 92%·추천 복습 | `skill_focus`·`verify-*`·L2 숙련도 | 반성 |
| ⑩ 다음 목표 | AI가 다음 개념으로 | 자동 커리큘럼 정렬(인접 개념 순서·차원6) | — |

- 각 단계는 별개 화면이 아니라 **`LearningScene` 요소의 조합**으로 렌더된다(§2). 여정 = 장면들의 시퀀스.
- **정합 주의(원본 대비 교정)**: 원본 [E]는 "Lesson을 매번 학생에게 생성한다"고 하나, WhyMath는 비용 때문에 **select-vs-generate**(`03c`)를 쓴다 — 여정 카드는 캐시 히트면 0원 렌더, 미스만 라우터 생성. "매번 생성"이 아니라 "매번 *선택·렌더*, 필요할 때만 생성".

### "메뉴가 사라지는 UI" — 목표 중심 카드 (가장 발전된 형태)

원본 [A]가 제시한 최종 형태. 학생은 고정 메뉴를 의식하지 않고 **AI가 생성한 다음 학습 카드를 하나씩 수행**한다.

```
[ 오늘 목표: 그래프에서 기울기를 읽는다  ■■■■□□□□ 40% ]
   → (완료) → 다음 카드 "식을 만들어 보세요"
   → (완료) → 다음 카드 "실생활 문제"
   → (완료) → AI 평가 → 목표 달성
```

이는 §3의 논지("메뉴는 파생 산출물")의 극단 실현이다 — 학생에게 메뉴 트리는 사라지고 **목표 진행률 + 다음 추천 카드**만 남는다. 내부에선 여전히 교육목적→교수전략→DSL→자동생성이 돌지만, 학생은 목표 달성 경험만 접한다.

### 3계층 구조 (원본 [A])

| 계층 | 내용 | WhyMath 대응 |
|---|---|---|
| **Level 1 앱** | 수학 | 앱 진입 |
| **Level 2 학습 지도** | 중2 → 함수 → 일차함수 | §3(b) 교과서 좌표(자동 커리큘럼 정렬) |
| **Level 3 AI 학습 카드** | ①목표 ②동기 ③탐색 … ⑩다음 | 위 여정 10단계(`LearningScene` 시퀀스) |

> **불변식 재확인**: 여정 어느 단계에도 "정답 보기"는 없다(⑧ 오답 교정에도 정답/수정 필드 부재·§6). 답 미루기·낙인 금지가 스키마로 강제되므로, 여정은 *정답 공개*가 아니라 *다음 사고 유도*로만 진행한다.

## §6. 데이터 흐름 (파이프라인 → 화면)

### 흐름 A — 설계-시점(오프라인, 🟢 대부분): 콘텐츠 자산 생성
```
성취기준(NCIC) + 학습목표  →  사람이 .unit.yaml 저작(UnitDSL)
   →  compile_unit(): k_type → PedagogyPack 조회 → slot_manifest → work_order
   →  콘텐츠 슬롯(DRAFT → PRESCREENED → APPROVED, fail-closed 검수)   [🔴 슬롯 자동생성 잔여]
```

### 흐름 B — 런타임(온라인, 🔴 계획): 개인화 렌더
```
학생 상태(L2: BKT·오개념·preferred_solution_style — ⚠️ 미구현 필드, 코드 0건)
   →  Runtime Pedagogy Selector.select() → PedagogyStrategy 1개   [PED-02]
   →  gate()(금지 모드·Polya 단계)  →  supply(): ConceptDSL 캐시 조회   [REND-01/CACHE-01]
   →  히트=adapter[strat].render()(0원) / 미스=라우터 생성 → DSL 승격
   →  학생 화면
```

### 흐름 C — 현행 실동작(🟢): 대화 1건 (`05:57-77`)
```
학생 입력 → POST /chat → auth+session → L2 상태 → L1 컨텍스트
   → L4 PedagogyDecision(Polya 단계·hint_level·socratic_category)
   → L3 LLM generate(라우터 경유·PRM/SymPy 검증) → L4 톤 필터 → L2 갱신
   → 클라: 표시 + Polya 업데이트
```
시각화 필요 시: 개념 → `generate_visualization_spec` → `Visualization` JSON → (합성) `generate_learning_scene` → `POST /v1/scenes/*` → `scene_renderer.dart`가 kind별 렌더(**수학 로직 0**).

> **현재는 흐름 C만 실동작**한다. 흐름 B(런타임 교수법 선택)는 `REND-01`/`PED-02` 구현 후 흐름 C의 L4 결정과 합류한다.

## §7. 불변식이 메뉴에 미치는 구조적 결과

- **"정답 보기" 메뉴가 구조적으로 불가능**: 문항 모델·힌트 스키마·`misconception_probe`에 **정답/수정 텍스트 필드가 없다**(`hint.schema.yaml`·`05a` 불변식). 학생 앱 `Problem` 모델도 `answer`를 담지 않는다. 메뉴에 "정답"을 넣으려 해도 실어 나를 데이터가 없다.
- **Polya 단계·답 미루기 상시 노출**: "지금 1단계 힌트 받음", "지금 어디에 있는지"를 화면에 항상 표시(`05:36-40`). 이건 장식이 아니라 메타인지 강화 장치.
- **반게임화**: 랭킹·스트릭·카운트다운·보상 연출은 어느 탭·어느 모드에도 없다(자유학기제 모드 예외·`gamification_level ≤ 3`).
