# HARN-209 판정 — 푸시·PR 생성 시점에 미러 결과 커밋이 푸시 대상 HEAD와 다르면 고지한다

> 판정 기준: main `05a3529bb` (2026-10-08). 이 문서가 서술하는 코드는 모두 그 시점 main 기준이며,
> 구현은 같은 PR(브랜치 `claude/gallant-euler-blngpj`)에 있다. 미머지 근거는 쓰지 않았다.

## 1. 풀려는 문제

`done`의 CI 미러 게이트(HARN-173, `ci_mirror_at_done: block`)는 **완료 선언** 시점에만 선다.
`/drive` 순서가 커밋 → PR(푸시) → `done`이라 게이트는 미검증 완료 선언을 막지만 **red 푸시 자체는
막지 못한다**. 2026-09-25 EOS-24 · PR #1316에서 PR CI가 red가 된 경로가 푸시였다. 같은 축의 미이행이
하나 더 있다 — PR 본문에 변경이 닿는 CI 잡 목록을 싣는 일은 지금 사람 몫이다.

## 2. 실측 (판정의 입력)

| 항목 | 값 | 출처 |
|---|---|---|
| 미러 필드가 기록된 `done` | **13건** (전부 PR 증적 경로) — 2026-09-29 ~ 2026-10-08, **9일분** | `backlog/events/*.ndjson`의 `action=done` 중 `mirror_scope` 존재 |
| 그 13건의 미러 상태 | pass 12 · unknown 1(`--no-mirror` 우회 1) | 같은 집계 |
| 도달 잡이 **상시 6잡뿐**인 PR | 13건 중 **6건** (46%) | 같은 집계의 `ci_reach_jobs` |
| 푸시 시점의 미러 상태 | **기록 자체가 없다** | 푸시는 대장 이벤트를 남기지 않는다 |

**데이터 부족을 그대로 적는다.** 요구 기준은 최소 2주분인데 게이트 착지(2026-09-29) 이후 9일분뿐이다.
그리고 이 표는 `done` 시점 상태라 **푸시 시점의 불일치 빈도는 한 번도 측정된 적이 없다** — `done`은
게이트가 막기 때문에 pass만 통과해 보인다(생존 편향). 그러므로 이번 판정은 "빈도가 높으니 건다"가 아니라
"빈도를 모르니 **측정 장치와 함께** 고지만 건다"이다 (§6 로그).

## 3. 후보 판정

| 후보 | 비용·결함 | 판정 |
|---|---|---|
| ⓐ 푸시 직전 `PreToolUse(Bash)`로 `git push` 포착 | 푸시 **직전**이라 고칠 수 있는 유일한 지점. 복합 명령(`commit && push`)은 훅이 커밋 전 HEAD를 본다 → §5 보정 | **채택(고지 전용)** |
| ⓑ PR 생성 직전 `PreToolUse(mcp__github__create_pull_request)` | 같은 대조 + 본문의 도달 잡 섹션 유무를 볼 수 있는 **유일한** 지점 | **채택(고지 전용)** |
| ⓒ 종료 시점 `Stop` 훅 | 이미 푸시된 뒤라 red 푸시를 못 막는다. 미푸시 커밋 경고는 기존 `check-stop`이 한다 | 미채택 |
| ⓓ 걸지 않는다 | EOS-24 경로가 그대로 열린다 | 미채택 |

**차단하지 않는다.** 이유: 오탐 비용(§4)이 0이 아니고, 측정 전 차단은 §2의 데이터 공백 위에 강제를 얹는
것이다. 고지가 소음이 돼 습관화되면 보호가 아니라 위장이므로(반복 관측되는 상시 경고) §6의 재평가 조건을
기준에 넣었다.

## 4. 오탐 비용과 그 처리 — "코드 없는 푸시를 어떻게 가려내는가"

**`ci_job_coverage scope`로는 가려낼 수 없다.** 상시 잡 6개(`changes`·`infra-contracts`·`infra-shell`·
`policy-guard`·`harness-integrity`·`declared-unwired-audit`)가 **모든 diff에 닿는다** — 변경 파일이
`backlog/events/x.ndjson` 한 줄이든 `docs/reviews/x.md` 한 장이든 같은 6잡이다(2026-10-08 실행:
`scope --stdin`). 게다가 원 사고(EOS-24)의 누락 스텝이 상시 잡 `harness-integrity`의
`ruff check scripts tests/harness`였다 — "path filter에 안 닿으면 안전"을 판별자로 쓰면 **원 사고
형태를 그대로 면제**한다. 그래서 도달 잡은 **고지 문구와 PR 본문**에만 쓰고, 고지 여부는 변경 **내용**으로
정한다.

| 푸시 형태 | 걸리는가 | 처리 |
|---|---|---|
| `done` 뒤 **대장 기록 커밋**(`backlog/events/`·`backlog/tasks/`만 바뀜) — 가장 흔할 것으로 **추정**(푸시 시점 기록이 없어 빈도 미측정) | 미러 커밋 ≠ HEAD라 걸린다 | **면제 A**: 트렁크 대비 기여가 전부 대장 기록이면 침묵 |
| 미러 통과 뒤 대장 기록만 더한 푸시 | 걸린다 | **면제 B**: 미러 커밋의 트렁크 대비 기여(대장 제외)와 HEAD의 것이 **blob까지 동일**하면 침묵 — 미러가 본 내용 그대로이기 때문 |
| 미러 뒤 `origin/main`을 병합만 한 푸시 | 걸린다 | 면제 B로 침묵(3점 diff는 병합 뒤 기준점이 옮겨가 브랜치 자체 기여만 남는다). main이 같은 파일을 건드려 blob이 달라지면 고지 — 올바른 동작 |
| 평가할 수 없는 형태(`git -C 다른경로`·`--dry-run`·태그만·삭제 푸시·HEAD 아닌 refspec) | — | 평가하지 않음(사유를 로그에 남긴다) |
| **문서만** 바뀐 푸시 | 걸린다 | **면제하지 않는다 — acceptance ③ 괄호 문면("대장·문서만")과 다르게 판정** |
| 클레임 푸시 | 걸리지 않는다 | `backlog.py start`가 서브프로세스로 내는 푸시라 Bash 도구 호출이 아니다 |

문서를 면제하지 않는 근거(문서가 비불활이라는 실측):
- 2026-10-07 같은 세션에서 `docs/ops/misc61_source_probe_runbook.md` **한 장**이 `check_ps_scripts`
  (런북 powershell 펜스 검사)에 걸려 `infra-contracts`·`infra-shell` 미러가 실패했다.
- `scripts/ops/check_ps_scripts.py`는 `docs/**/*.md` **전수**를 스캔한다(상시 잡 `infra-shell`).
- `tests/infra`·`tests/harness` 중 `docs/`를 참조하는 파일이 80개다.

따라서 acceptance ③의 "코드 없는 푸시" 대조군은 **대장 기록만 바뀐 푸시**로 구현하고, 문서만 바뀐 푸시는
**고지가 나는 쪽**으로 고정한다(반대 방향 대조군). 이 차이는 `backlog.py amend`로 acceptance에 정정 항목을
덧붙여 기록한다(append 전용 — 원문은 지우지 않는다).

## 5. 구현 선택과 그 한계

- **고지 채널**: 훅이 종료 코드 0과 함께 stdout JSON `hookSpecificOutput.additionalContext`를 낸다.
  공식 훅 문서에서 확인한 사실: 종료 코드 0일 때 **stdout·stderr는 PreToolUse에서 모델에게 전달되지
  않는다**(stderr는 디버그 로그 전용). 모델에게 닿는 경로는 `additionalContext`(system reminder로
  도구 결과 옆에 삽입)와 차단(exit 2)뿐이다. 이 확인은 문서 열람(서브에이전트 경유)이었고, **이 세션에서 실측으로도
  확인했다**(2026-10-08): 미러 결과를 치운 상태에서 무해한 푸시(`Everything up-to-date`)를 실행하자 하네스가
  `PreToolUse:Bash hook additional context: [CI 미러 고지 · 푸시 직전] …`를 도구 결과 옆에 주입했다. 설정 변경은
  실행 중 세션에 즉시 반영됐다(등록 직후부터 평가 로그가 쌓인다).
- **`updatedInput`으로 PR 본문을 자동 수정하지 않는다.** 문서상 `permissionDecision`과 짝지어 쓰며, `allow`를
  주면 사용자의 권한 확인을 건너뛰게 된다. 고지에 **붙여 넣을 섹션을 같이 실어** 모델이 직접 본문에 넣게
  한다.
- **복합 명령 보정**: `git commit … && git push`는 훅 시점에 커밋이 아직 없다. 같은 명령에 HEAD를 옮기는
  git 명령이 앞서 있으면 작업 트리의 미커밋 변경을 "곧 커밋될 내용"으로 겹쳐 본다(대장 기록만이면 면제,
  그 밖이면 새 커밋에는 미러 결과가 있을 수 없으므로 고지). `git pull`/`merge` 뒤 푸시는 병합 결과를
  **미리 알 수 없다** — 현재 HEAD로 판정한다.
- 훅은 평가 실패 시 푸시·PR을 막지 않는다(fail-open). 다만 예외 타입명을 로그에 남기고 상태를
  `unavailable`로 **따로** 센다 — 모른다는 통과가 아니다.
- 미러 상태 4종 중 `pass`·`not_executed`는 침묵한다(`done` 게이트와 같은 분류 — `not_executed`는
  HARN-181 전까지 조건 스텝 잡에서 항상 나온다). `fail`·`unknown`·`unavailable`은 고지한다.
- 같은 (트리거, HEAD, 사유)는 한 번만 고지한다(재시도 푸시 소음 방지). 로그에는 매번 남는다.

## 6. 습관화 감시와 재평가 조건

평가된 모든 푸시·PR 생성이 `.claude/logs/push_mirror_notices.jsonl`에 한 줄씩 남는다(고지 여부·사유 코드·
미러 상태·변경 건수). 이 파일이 §2의 공백을 메우는 **측정 장치**다.

재평가 조건(임시 기준 — 실측 뒤 재설정한다): 평가된 푸시 중 고지 비율이 **2주 연속 30% 초과**이면 고지가
상시 경고가 된 것이므로 원인(오탐 형태)을 규명해 면제를 늘리거나 고지를 끈다. 반대로 고지 없이 푸시된
커밋의 PR CI가 red인 사례가 나오면 면제 규칙(§4)을 재검토한다. 임계값 30%에는 근거 데이터가 없다 —
**관측 전 가정**이며 첫 2주분 로그로 대체한다.

## 7. 이 PR이 하지 않는 것

- 푸시 차단(`deny`/exit 2)은 하지 않는다. 승격은 §6 데이터 이후의 별건이다.
- `mcp__github__push_files`·`create_or_update_file`(GitHub API로 직접 커밋)은 보지 않는다 — 로컬 HEAD가
  아니라 원격에 커밋을 만드는 경로라 미러 대조가 성립하지 않는다.
- 훅이 `settings.json` 변경 즉시 이 세션에서 발화하는지는 확인하지 못했다(§5).

- 뮤테이션 **52종 전건 RED**(모듈 판정·계획 31 · 명령 분리 파싱 7 · 훅 11 · 등록·`/drive` 문서 3 … 적용 확인
  `count==1`·`mutated != original`, 원복 sha256 동일 단언). **첫 회차에 3종이 살아남았다** — M29(이름 변경의 원래
  경로 건너뛰기 제거): 제 픽스처의 `"docs/guide.md" not in paths`가 잘린 문자열(`s/guide.md`)을 못 봐 통과했다.
  M49(줄 잇기)·M52(괄호): 해당 절이 없어도 같은 결과가 나오는 입력만 있었다 — 각 절의 반례(`git push \\<줄바꿈> origin`
  → refspec이 비어야 함 · `(git push origin HEAD)`)를 픽스처에 넣어 RED를 확인했다.
- 훅의 "push 낱말만 든 명령" 로그 제외는 뮤테이션 이후에 넣은 변경이라 훅 뮤테이션 전건(M31~M45)을 다시 돌렸다.
- **실사용에서 드러난 결함(구현 뒤)**: 훅이 이 세션에서 발화하는 것은 확인됐으나(평가 로그에 이 세션 id), 실제 푸시 명령
  `ls … | head; git push -u origin …`이 `not_a_push`로 놓쳤다. 원인: `shlex.split`이 `head;`처럼 단어에 붙은 `;`를
  구분자로 쪼개지 않아 `git push`가 앞 명령의 인자가 됐다. 단위 픽스처는 공백이 있는 `&&`만 써서 못 봤다. 수정: 구분 기호
  토큰화(`punctuation_chars`)·따옴표 밖 줄바꿈 구분·히어독 본문 제거·리다이렉션 제거, 반례 13행과 훅 종단 회귀
  1건 추가.
- **검증하지 못한 것**: PR 생성 경로(`mcp__github__create_pull_request`)의 실발화 — 이 PR을 만들 때 처음 밟는다.
  푸시 경로의 `additionalContext` 도달은 위에서 실측했다.
