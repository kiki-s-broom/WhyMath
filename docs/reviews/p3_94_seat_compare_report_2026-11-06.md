## 결론

1. **로컬 모델 두 개는 LLM 문장을 한 건도 쓰지 않았다(초안 0/20 · 0/20).** 원인은 모델 크기가 아니라 **튜터 정책 프롬프트 계약**이다 —
   `wh1_llm_policy.py`의 도구 설명이 `end_turn`의 `utterance`를 "선택 — 비우면 하네스의 소크라테스 개입 발화가 대신 말합니다"로
   안내하고, 예시도 발화 없는 `end_turn`이다. 모델은 지시대로 행위만 고르고 말은 하네스에 넘겼다. 클라우드 모델도 응답 15건 중 11건에서
   발화를 비웠다. **현재 설계는 LLM이 말하지 않도록 되어 있으므로, D16의 판정 대상("LLM이 쓴 문장")은 좌석 교체만으로는 표본이 생기지 않는다.**
2. **`qwen2.5:7b`가 `qwen2.5:3b`보다 정책 좌석으로 낫다는 신호**: 출력 계약 위반 0/20(3b 3/20) · 턴 지연 중앙값 1.5초(3b 2.8초) ·
   턴당 호출 2.3회(3b 9.0회). 단 계약 위반 차이는 표본 20건이라 우연과 구별되지 않는다(Fisher 양측 p ≈ 0.23) — 경향으로 읽는다.
3. **클라우드(`deepseek-v4.1-flash`)는 현행 15초 턴 예산으로 서빙 불가**: 시간 초과 5/20(25%) · 중앙값 10.6초 · p95 15.0초. 대신
   실제로 문장을 쓴다(라이브 4건) — 문장 품질의 기준선으로는 쓸 수 있다.
4. 클라우드 초안 4건은 **정답 누설 0 · hallucination 0 · 설명 일관성·학생 수준 4/4**였고, 문장은 모두 소크라테스식 질문이었다.
   Hint 적절성은 0/3인데, 일부는 판정기 규칙의 글자 맞춤 사각이고 일부는 실제 부족이다(아래 §초안).

## 해석과 한계

- 표본 20건(초안 4건)은 판정용이 아니라 **방향 결정용**이다. 좌석 간 차이 중 통계적으로 확정된 것은 없다.
- 로컬 좌석의 초안 0건은 "모델이 발화를 못 쓴다"가 아니라 "쓰라고 요구받지 않았다"를 뜻한다 — 요구하면 쓰는지는 아직 재지 않았다.
- 클라우드 시간 초과 5건은 턴당 2회 호출에 호출당 5~8초가 걸린 결과다. 예산을 늘리면 통과할 수 있으나 그것은 서빙 SLO(p95 5초·PRD 3초)와 충돌한다.
- 트레이스 표기 한계: Langfuse의 `cost_tier`는 원래 결정(LOCAL)으로 남는다(교체가 파이프라인 바깥에서 일어남). 실제 모델은 관측 `served_model`로 확인했다.
- 클라우드 원가는 단가 계산을 하지 않았다 — 토큰(입력 45,428 · 출력 13,233)만 기록했다.

## 결정 대기 (Kiki)

D16 임계값 6개를 정하려면 "LLM이 쓴 문장" 표본이 필요한데, 현행 프롬프트 계약에서는 좌석과 무관하게 표본이 거의 생기지 않는다. 선택지:

1. **측정 전용 "발화 필수" 프롬프트 변형으로 재수집**(세션 권장): 서빙 프롬프트는 그대로 두고, 수집기 안에서만 `utterance`를 필수로
   요구하는 변형을 써서 "LLM이 말한다면 무엇을 쓰는가"를 잰다(D16 ⓐ의 측정 전용 원칙과 같은 축). 주 후보 `qwen2.5:7b` + 품질 기준선 클라우드.
   판정기-사람 일치율 측정(50~100건)을 함께 한다.
2. **D16 판정 대상 재검토**: LLM이 말하지 않는 현행 설계를 유지한다면, 판정 대상을 "학생이 실제로 받는 문장(경로 출력)"으로 되돌리고
   (P3-78·이번 회차 자료가 이미 있다), Hint 적절성 결함은 템플릿 힌트 쪽 과제로 넘긴다.
3. **서빙에서 LLM이 직접 말하도록 설계 변경**: 교수 안전·정답 억제 백스톱과 직결되는 제품 결정이라 별도 태스크로 다룬다.

정책 좌석 모델(3b → 7b) 교체 여부는 위 선택과 별개로 결정할 수 있다. 이번 자료는 7b 쪽 경향(계약 준수·지연·호출 수)을 보이지만,
CLAUDE.md 모델 채택 조건(실측 근거 · 라우터 배선 · MEMORY 결정 기록)을 채우려면 표본을 늘린 확인이 필요하다.
