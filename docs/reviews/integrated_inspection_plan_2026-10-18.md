## §5. 점검 포인트 전수 체크리스트 (놓치기 쉬운 것 중심)

Step 1 각 레인 체크리스트(§3)에 더해, **축을 가로지르는** 점검 포인트다. 각 항목은 "무엇을 보면 통과/실패인지"를 함께 적었다.

**검증 판정의 변별력**
- [ ] 모든 측정 CLI는 exit code로 판정(`echo EXIT=${PIPESTATUS[0]}` 병기) · `-q`·`tail` 금지 · CI가 쓰는 명령·대상 경로 그대로
- [ ] CI 잡 목록 20개를 먼저 열거하고, 로컬 재현이 어느 잡의 어느 스텝인지 적는다(2026-09-17 규칙) · 실패 잡의 skipped 스텝 수를 센다
- [ ] 보호 장치는 실패 주입 RED를 본 것만 "보호 있음"으로 친다 · 주입이 실제 적용됐는지(`mutated != original`) 단언
- [ ] "N passed"가 아니라 "무엇을 안 봤는가"를 적는다(뮤테이션 전건 RED는 커버리지의 증거가 아니다)

**판정 시점·근거**
- [ ] 판정 문서 상단에 기준 커밋 해시 · 미머지 근거는 열을 나눠 적는다(브랜치 ≠ 저장소)
- [ ] "없다" 판정 전에 역할 기반 검색 + 소비자 역추적 + `git log --all --grep` — 그래도 0이면 "내가 찾은 방법으로는 0건"
- [ ] 코드 착지 ≠ 대장 종결(QUAL-11 선례) — done 판정 시 acceptance 전수 재대조

**침묵 실패**
- [ ] green인 자동화의 **산출물 실재**를 본다(weekly-metrics 선례) — 성공 로그가 아니라 커밋·파일·행
