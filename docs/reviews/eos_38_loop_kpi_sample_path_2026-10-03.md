# EOS-38 — 루프 KPI ①②④ 판정 표본 산출 경로 판정 (2026-10-03)

> **판정 기준**: `main 5e9ce568`(작업 시작 시점) + 본 브랜치 변경. 아래 수치는 모두 이 브랜치에서 **실 PostgreSQL 16 + pgvector 위에서 직접 잰 것**이다(재현 명령 §8). 미머지 근거를 "충족"으로 적지 않았다 — 이 문서가 말하는 것은 *경로가 존재하고 변별한다*까지이며, Gate 2 재판정 자체는 이 태스크의 일이 아니다.

## §0. 결론 먼저

- **(나) 결정론 합성 부하를 전용 DB에 쌓고 그 위에서 판정 CLI를 돈다**를 채택했다. (가)·(다)는 기각했다(§2).
- 기본 부하(학습자 60명)에서 판정 CLI는 **5종 전부 PASS · exit 0**이다. 4회 공전하던 ①②④가 측정된다.
  - ① `60 / 60` · Wilson 하한 **0.9569** ≥ 0.95
  - ② `0 / 542` · Wilson 상한 **0.0050** ≤ 0.01
  - ④ `0 / 180` · 무관용 충족
- 위반 주입은 ①(끊긴 세션)·④(운영자 감사 행)를 FAIL로 바꾸고, ②는 **2건부터** FAIL로 바꾼다. **1건은 이 규모에서 ②를 뒤집지 못한다**(§5 — 설계 의도이며 결함이 아니다).
- **이 판정은 실사용 검증이 아니다.** 판정 CLI에 `--sample-basis synthetic` 표지를 두어 리포트·JSON에 그 사실이 각인된다(P3-13 ARCH-66 ⑥ 단서와 같은 취급).

## §1. 무엇이 막혔나

공식 실측의 ①②④는 분모 0으로 미측정이었다. 판정 하네스가 회차마다 학습자를 운영 삭제권(`DELETE /v1/me`)으로 스스로 지우기 때문이다. 학습자 1명을 남긴 보조 측정은 측정은 됐지만 표본 부족으로 FAIL이었다(① `1/1` → 하한 0.27 · ② `0/12` → 상한 0.18). 9/19·9/24·9/25·9/29 네 판정이 같은 모양이었다(EOS-141 판정문 §5).

통과에 필요한 최소 표본은 코드가 **계산**한다(`required_sample_sizes()` — 임계·신뢰수준에서 도출, 상수로 적지 않음).

| KPI | 통과 조건 | 최소 표본 |
|---|---|---|
| ① 완주율 | 전건 성공일 때 Wilson 하한 ≥ 0.95 | **52** 세션 |
| ② 상태 정합 | 위반 0건일 때 Wilson 상한 ≤ 0.01 | **268** 스캔 행 |
| ④ 수기 개입 | 무관용(분자 0) — Wilson 미적용 | 분모 ≥ 1 |

**발견 — ②의 분모는 학습자 행이 아니다.** `integrity_violations_gate`는 `concept_node`·`attempt_event` 등 *콘텐츠·이벤트 행*을 센다. 그래서 세션만 쌓아서는 ②의 표본이 늘지 않는다. 이 부하는 학습자 여정이 만드는 `attempt_event`(`문제시도` 3 + `시각화조작` 6 = 학습자당 9건)로 ②의 분모를 쌓는다. 60명 → `attempt_event` 540건 + 콘텐츠 2 = 스캔 542행.

## §5. 변별력 — 위반 주입이 각 KPI를 뒤집는가 (acceptance ③)

판정 CLI를 운영과 같은 방식(서브프로세스 · `--json`)으로 합성 부하 전용 DB 위에서 돌렸다. 매 주입 뒤 **원복해 PASS로 돌아오는 것**까지 확인했다(상태가 원래 FAIL이 아니라 주입이 원인임을 보인다).

| KPI | 주입 | 결과 |
|---|---|---|
| ① | 시도는 있는데 그 뒤 추천이 없는 세션 1개 | 분모만 +1(61), 분자 60 → 하한 0.9298 < 0.95 → **FAIL** · 원복 시 PASS |
| ② | 계약 위반 `attempt_event` **1건** | 분자 +1은 센다. 판정은 **PASS 유지** — 상한 0.0082 ≤ 0.01 |
| ② | 계약 위반 `attempt_event` **2건** | 상한 0.0110 > 0.01 → **FAIL** · 원복 시 PASS |
| ④ | 학생 본인 행위(`export_data`) | 세지 않는다 → PASS 유지 |
| ④ | 운영자 감사(`role_change`) 1건 | 무관용 → **FAIL** · 원복 시 PASS |
| 정상 대조군 | 합성 부하 그대로 | ①②④ **PASS** |

**②의 1건 비반전은 결함이 아니다.** ②의 계약은 "불일치 ≤ 1%"이고 1/543 = 0.18%는 그 안이다. 판정은 점추정이 아니라 Wilson 상한으로 하므로 표본이 클수록 1건에 관대하다. 이 사실을 테스트가 **양방향**(1건 PASS · 2건 FAIL)으로 고정해 둔다 — "위반 1건이면 FAIL이다"라고 기대하는 사람이 이 경로의 결과를 오독하지 않게 한다.

## §7. 한계 — 이 경로가 말해 주지 않는 것

1. **실사용 검증이 아니다.** 합성 학습자는 실제 학생이 아니다. 이 판정은 "충분한 표본이 있을 때 수집기·임계·판정 경로가 설계대로 동작한다"만 말한다. 실학생 세션 확인은 `G-student-work-after-internal-completion` 이후(ARCH-66 ⑥).
2. **① 여유가 얇다.** 60/60의 하한 0.9569는 기준 0.95를 0.0069 넘는다. 학습자 수를 줄이거나(최소 52) 한 세션이라도 끊기면 FAIL이다. 기본값 60은 최소 52에 여유 8을 둔 값이다.
3. **④의 사각은 그대로다.** 관측 범위는 `privacy_audit` 표면뿐이라 0은 "감사되는 표면에서는 개입이 없었다"이다. 합성 부하는 이 한계를 넓히지 않는다.
4. **② 분모는 attempt_event가 지배한다.** 학습자 수를 줄이면 ②의 분모가 최소 268 아래로 내려갈 수 있다(학습자당 9건 → 30명 미만). 기본값에서는 540이다.
5. **전용 DB 가드는 최후 방어선이 아니다.** 실DB와 **별도 인스턴스**에 두는 것이 안전하다. 같은 인스턴스에 둘 때는 이름 가드와 비합성 학습자 가드만 남는다.
6. **통합 테스트의 CI 실행은 이 환경에서 확인하지 못했다.** `backend-migrations` 잡(실 PG)이 `pytest -m integration`으로 돌리지만, 이 세션은 로컬 PG 16으로만 재현했다. 그 잡은 `timeout-minutes: 12`이고 이 모듈이 약 45초를 더한다.
