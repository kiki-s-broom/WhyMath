**변별력 장치 2종**(이게 없으면 8행은 아무것도 증명하지 않는다):

### 1.3 Persona C — 특정 오개념 (**핵심 판정**)

| # | 단계 | LearnerState |
|---|---|---|
| 1 | ①진단 | action=`diagnose` · reason=`unmeasured` |
| 2 | ②오답패턴→탐지 | 후보=`['distribution-over-power']` · confidence=**0.9** · 상태=`REMEDIATING` · next_action=`REMEDIATE_MISCONCEPTION` |
| 3 | ③패턴반복 | confidence=**0.98** (같은 거짓형 재관측 → 강화) |
| 4 | ④교정발화 | 개입=`distribution-over-power` · 활성가설수=1 · 단계검증=True |
| 5 | ⑤**targeted→감소** | 직전=**0.85** · 직후=**0.74** · **감소폭 0.11** |
| 6 | ⑥정답회차 | 직전=0.74 · 직후=**0.74** (무변화 — `EOS-123` 정직한 공백) |

**판정**: 완주. **confidence가 실제로 내려간다** — 원 지시문 2번 충족.

**구간을 왜 좁혔는가**: 감소를 *여정 전체의 차이*로 재면 무엇이 내렸는지 구별되지 않는다. 실제로 ③의 0.98이 ⑤ 직전 0.85로 이미 내려와 있는데, 그 하락은 ④의 코치 대화가 일으킨 것이다. 그래서 판정은 **targeted problem 한 회차의 전후 차이**(0.85 → 0.74)로만 한다.

**감소가 실제로 일어나는 자리(실측)**: 감쇠 시계는 `POST /v1/me/attempts`가 오개념 훑기를 *돌린* 회차에만 돈다. 그 회차의 후보가 비어 있어도 호출 자체는 유효하고, 그것이 "이번엔 그 오개념이 관측되지 않았다"를 신뢰 하락으로 바꾸는 경로다. 그래서 targeted problem은 **그 오개념을 인스턴스화하지 않는 오답**으로 제출한다.

## 2. 결함 주입 검증 (RED 확인)

정상 입력에서 초록인 것은 보호의 증거가 아니므로, 판정 포인트마다 **막으려는 상태를 주입해 실제로 RED가 나는지** 확인했다. 하네스는 순수 Python(셸 이스케이프 배제)이고, 주입 실재(`치환 count==1` · `mutated != original` · 디스크 sha256 변화)와 원복 바이트 동일(sha256 일치)을 각각 단언한다.

| # | 주입 | 겨냥한 축 | 결과 |
|---|---|---|---|
| 기준선 | 무주입 | 전건 | exit **0** |
| M1 | `decay()` 무력화 | C ⑤ confidence 감소 | **RED** |
| M2 | `reinforce()` 무력화 | C ③ 강화 | **RED** |
| M3 | 오개념 훑기 전면 차단 | C ② 탐지 | **RED** |
| M4 | `PREREQUISITE_GAP` 액션 매핑 파괴 | B ⑤ 하위 concept 이동 | **RED** |
| M5 | `NEXT_CONCEPT` 액션 매핑 파괴 | A ⑤-a `advance_next` | **RED** |
| M6 | BKT 갱신 무력화(숙달 불변) | A ④ 숙달 상승 | **RED** |
| M7 | `weak_only` 결손 필터 무력화 | B ⑦ 결손 해소 | **RED** |
| M8 | 약점 가중 부호 반전 | B ⑧ **원래 concept 복귀** | **RED** |
| M9 | 정답 회차에도 감쇠 구동 | C ⑥ 정직한 공백 동결 | **RED** |

**9종 전건 RED · 생존 0.**

**M8을 왜 따로 만들었는가(중요)**: 처음엔 M7만 있었다. 그런데 M7은 ⑦에서 먼저 터져 **⑧ 절에 주입이 닿지 않았다** — 실패 지점을 확인해 알아냈다. ⑦을 살려 둔 채 선택 축만 뒤집는 M8을 추가하고 나서야 "복귀" 단언에 주입 커버리지가 생겼다.

**M9를 왜 만들었는가**: ⑥은 *현행 무변화*를 동결하는 단언이라, 그것이 공허하지 않은지(해소되면 실제로 실패하는지)를 따로 확인해야 했다. `EOS-123`이 해소되는 방향으로 주입하자 RED가 났다 — 동결이 살아 있다.

**전건 RED는 커버리지의 증거가 아니다**(CLAUDE.md v0.2.19). 위 9종은 내가 *열거한* 축만 검사한다. 픽스처가 없는 절은 애초에 주입 목록에도 오르지 않았다.

## 3. 발견 결함 — 고친 것 / 등재한 것

### 3.1 고친 것: **없음**

프로덕션 코드는 한 줄도 바꾸지 않았다. 지시문의 범위 규율("새 엔진을 추가하지 마라 · 안정화만 한다")에 따른 것이고, 아래 두 건은 각각 **선행 판정이 필요한** 사안이라 안정화 세션이 단독으로 정할 수 없다(§4).

### 3.2 등재한 것

#### `EOS-123` — 정답 회차가 오개념 감쇠 시계를 돌리지 않는다 (채점 ↔ 코치 반증 비대칭) · EOS P2

- **증상**: 교정 문항을 *맞혀도* misconception confidence가 1도 내려가지 않는다. 실측 — 오개념 미관측 **오답** 회차는 `0.85 → 0.74`, 바로 뒤 **정답** 회차는 `0.74 → 0.74`.
- **기전**: `_scan_attempt_misconceptions`가 `correct=True`에서 `NOT_RUN`을 돌려주고(`api/me.py:745-746`), 호출부가 그 값으로 `apply_candidates`를 건너뛴다(`api/me.py:1110`).
- **핵심은 비대칭**: 같은 반증을 코치 경로는 이미 반영한다 — `_log_refutation_evidence`(`api/coach.py:1895-1959`)가 clean verify + 무매치일 때 −1 증거를 적재한다. 즉 "학생이 그 오개념을 쓰지 않고 맞혔다"가 대화에서는 반증인데 채점에서는 무신호다. 두 쓰기 경로가 같은 학습자 상태를 서로 다른 규칙으로 갱신한다.
- **현행 설계의 자인**: `api/me.py:1106-1109`가 "훑지 않은 회차(정답·답안 없음)에 부르면 관측하지도 않은 것을 근거로 신뢰를 깎는 셈이라 부르지 않는다"고 적는다. 이 판단은 *답안 없음*에 대해선 옳다. 쟁점은 *정답이면서 답안이 있는* 회차다 — 그 회차는 관측이 없는 것이 아니라 **반증이 있는** 것이다.

#### `EOS-124` — next-problem의 정책 축과 선택 축 불일치 · EOS **P1**

- **증상(양방향)**:
  - Persona A — 숙달 0.98인데 `action=advance_next`의 `target_concept`이 **방금 숙달한 현재 개념**이고 문항도 현재 개념 것이다(전진을 선언하며 전진하지 않음).
  - Persona B — 결손이 해소됐는데 `action`은 여전히 `practice_prerequisite`, `target_concept`은 이미 숙달된 선수 개념이다(문항은 올바르게 복귀했는데 설명만 낡음).
- **기전**: `resolve_target_concept`(`l2/recommendation_policy.py:195`)은 `target_concept`만 정하고 문항 선택에 관여하지 않는다. 문항은 `l2/next_problem_selection.py`의 약점 가중(`1 + BOOST·(1−최저숙달)`)이 고른다. 두 축이 독립 계산되고 **서로를 보지 않는다**.
- **학생에게 닿는 피해**: 이 두 필드는 Recommendation Explanation(계획서 §8 "추천 이유")의 입력이다. 학생은 "선수 개념을 연습하세요"라는 설명과 함께 원래 개념 문항을 받는다. 설명과 콘텐츠가 어긋나면 추천 이유는 신뢰를 쌓는 대신 깎는다. 그래서 P1로 올렸다.

### 3.3 정직한 공백 동결

두 결함은 하네스가 **현행 동작을 단언**해 동결한다(Persona A ⑤-b · Persona B ⑧-b · Persona C ⑥). 해소되면 그 단언이 실패하고, **실패 메시지가 해당 태스크 id와 승격 방법을 지목한다** — 판정 하네스가 통과하면서 낡는 일이 없게.

## 5. 하네스가 드러낸 픽스처 함정 2건 (다음 세션용)

1. **`atom_node` 없이는 선수가 보이지 않는다** — `/v1/me/weak-concepts/{cid}/prerequisites`는 선수 후보를 `atom_node`(code 조인)의 안전 메타와 함께 돌려준다. 그 행이 없으면 `concept_edge`가 멀쩡해도 응답이 **빈 배열**이다. 처음 픽스처가 엣지만 심어 `[]`를 받았는데, 그것은 "선수가 없다"가 아니라 "메타가 없다"였다.
2. **난이도 대역이 벌어지면 θ가 개념 판정을 가로챈다** — §1.2의 변별력 장치 참조. 개념 축을 재려는 픽스처에서 난이도를 벌리면 θ 상승만으로 같은 결과가 나온다.

## 6. 재현 명령

로컬에서 실 PG(pgvector 포함)를 띄우고 마이그레이션을 올린 뒤:

```bash
cd src/backend
WHYMATH_RUN_INTEGRATION=1 WHYMATH_DB_DISABLE_POOL=1 \
WHYMATH_DATABASE_URL=postgresql+asyncpg://whymath@127.0.0.1:5432/whymath \
python -m pytest -c pyproject.toml -m integration -s \
  ../../tests/backend/api/test_e2e_persona_journeys.py
```

`-s`를 빼면 표가 안 보인다(판정은 그대로 exit code). PG 미도달이면 **skip**이 나는데, **skip은 통과가 아니다** — 하네스가 그 문구를 명시한다.
