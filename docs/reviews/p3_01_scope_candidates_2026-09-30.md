## §2. ① 실측 표

### 2.1 무엇을 어떻게 셌나

**축**: 학년·과목·단원은 2022 개정 성취기준 코퍼스(`standards_v1`, `curriculum_revision="2022 개정"`
435행)의 `subject`(과목 코드)·`domain`(영역=대단원)·`sub_domain`(소단원)을 따랐다. 학년은 원자
백본의 `grade_band`에서 가져왔다(고교는 고1·고2·고3). 중학교는 2022 성취기준이 1~3학년군 단위라
중1·중2·중3으로 나눌 수 없다. 원자·오개념·문항은 전부 **성취기준 코드**로 이 축에 귀속했다
(EOS-52 §2와 같은 축, 새 ID 체계 없음).

**네 엔티티**:

| 엔티티 | 무엇을 셌나 | 축 |
|---|---|---|
| Concept | 원자 백본 리프(`atom_graph_v1`, `level=세부개념`) — **런타임 정본 축**(S4-11). 구 437 `concept_graph_v1`은 참고 열("/437") | 원자 `standard_codes` |
| Skill | `skill_graph_v1` 27종. 원자 `behavior_skills`(SKB-02 병합분)로 원자와 연결 | 원자 경유 |
| Problem | 문항 은행 37개 14,034문항. **파일** = 문항 `achievement_standard_codes` 태그. **런타임** = `problem_concept → atom_node.standard_codes`(`api/gating.py::_fetch_achievement_codes`) | 둘 다 |
| Misconception | M-id 오개념 DB(`misconceptions_v1`) 843행 | M-id `standard_code` |

원자 유래 오개념(`ATOM:<code>`, 1,823건)은 원자 리프마다 1:1로 있어서 변별력이 없다. 그래서 밀도
계산에서 뺐고 총량만 적는다.

**연결(명시 링크만 센다 — 같은 성취기준에 속하는 것은 '보유'이지 '연결'이 아니다)**:

| 연결 | 정의 | 근거 코드 |
|---|---|---|
| C↔P | 문항 `concepts[].concept_src_id`(구 437 src) → 크로스워크 `primary_atom_code` → 원자 | `l1/problem_bank/populate.py::derive_src_to_primary_atom`(스크립트가 그대로 호출) |
| C↔M | M-id `concept_src_id` → 같은 다리 → primary 원자 | 같은 다리·같은 귀속 규칙 |
| P↔M | 문항 `distractor_map[].misconception_id`(L4 kebab) → crosslink → M-id | `misconception_crosslinks_v1` 64행 |
| C↔S | 원자 `behavior_skills` | `atom_graph_v1` |
| P↔S | 문항 `problem_type_codes` → 문제유형 `behavior_skills`(간접) | `problem_type_graph_v1` |

**밀도(대리 지표)** — "삼각 연결"은 개념이 C↔S·C↔P·C↔M을 모두 가진 상태다. 두 입도로 낸다.

- **원자 삼각**: 원자 리프 중 삼각 연결인 비율.
- **437 삼각**: 구 437 개념 중 삼각 연결인 비율. 문항·M-id가 그 개념 src로 태깅돼 있고 `behavior_skills`가 있으면 센다. 고교에서 437 개념은 성취기준과 거의 1:1이다(= 성취기준별 primary 원자 1개).

이 밀도는 **P3-01의 대리 지표**다. P3-02가 "완전 연결"(Prerequisite·Misconception·Solution·Hint·Pedagogy
포함)을 코드 한 곳에 정의하면 그 값이 정본이 된다.

**보조 열**:

- **문면고유**: 문항 본문에서 숫자를 `#`로 접은 뒤 센 고유 문면 수다. 근사 중복의 대리 지표이며 P3-05 기준을 대신하지 않는다. 부호나 변수명이 다르면 다른 문면으로 세므로 다양성이 과대계수될 수 있다.
- **고아 개념**: 문항과 M-id 명시 연결이 둘 다 없는 원자.
- **고아 문항**: 단원 안 원자와 연결되지 않았고 오개념 연결도 없는 문항.
- **M 문항연결**: 문항 distractor가 닿는 M-id 수.
- **6슬롯 결손(437·문면)**: 437 개념마다 max(0, 6 − 그 개념 문항의 고유 문면 수)를 더한 값. P3-04/05의 6슬롯(대표·기본·응용·오개념 유발·진단·숙련도 확인)을 채우는 데 필요한 신규 문항의 하한이다.

표 1·2에서 다음을 모두 만족하는 범위를 골랐다.

- ⓐ 437 삼각 밀도가 있다.

## §5. 계수 범위의 한계 — 운영 DB와 다를 수 있는 지점

로컬 DB 적재 수치는 파일 수치와 53항목 전건 일치했다. 즉 "저장소를 지금 적재하면 이렇게 된다"는
검증됐다. 운영 DB(`whymath-pg`)는 다음 이유로 다를 수 있다.

1. **재적재 시점**:
   - 문항 은행 30개(11,396문항)는 EOS-52(2026-08-30) 뒤에 추가됐다.
   - SKB-02 behavior_skills 병합(2026-09-11) 이후에 운영 DB에 `populate --all`과 크로스워크
     populate가 다시 돌았는지는 확인하지 않았다.
   - 돌지 않았다면 운영 런타임의 문항 수·스킬 연결은 표보다 적다.
2. **런타임 쓰기**: 운영 DB에는 적재 CLI 밖의 쓰기가 있을 수 있다.
   - 검수 상태 변경.
   - crosslink 승인 적재(L4 검수 흐름).
   - `concept_content`·힌트.
   - 로컬 DB는 이것들을 적재하지 않았다. crosslink는 파일 64행으로 계산했다.
3. **스키마 버전**: 로컬은 alembic head `9d3e7b1c5a20`다. 운영이 이보다 뒤처져 있으면 컬럼이 다를 수 있다.
4. **대조 방법**: `p3_01_db_crosscheck.py`는 SELECT만 쓰고 `default_transaction_read_only`를 켠다.
   운영 DB URL로 돌리면 이 표와의 드리프트가 exit 3과 X 칸으로 나온다.
   - 스크립트가 아직 main에 없으므로 Kiki 머신용 실행 안내는 이 문서에 넣지 않았다.
   - 머지 뒤 별도로 안내해야 한다. 미머지 파일을 쓰는 명령을 안내하지 않는다는 규칙 때문이다.

레포 루트에서 실행한다. `$PY`는 백엔드가 설치된 Python 3.12다(이 세션은 스크래치패드 venv).

### A-1. 파일 기준 계수 (표 1·2·후보 표의 출처)

```bash
python scripts/analysis/p3_01_scope_inventory.py            # 표 1·2·후보 코드별 표 출력 + JSON
python scripts/analysis/p3_01_scope_inventory.py --json-only
```

종료 코드: 0 = 전 단계 성공, 1 = 측정 실패(결과 JSON `errors`에 예외 타입명). 빈 코퍼스를 주입하면
exit 1이 나고 6단계 전부 `error:FileNotFoundError`/`ValueError`로 기록되는 것을 확인했다.

### A-2. 로컬 DB 적재 (격리 클러스터 — 이 컨테이너 기준)

docker 데몬은 없고(`/var/run/docker.sock` 부재) PostgreSQL 16 + pgvector 바이너리는 있다.

```bash
D=/var/lib/postgresql/p301_pgdata
runuser -u postgres -- /usr/lib/postgresql/16/bin/initdb -D $D -A trust -U postgres -E UTF8 --locale=C.UTF-8
runuser -u postgres -- /usr/lib/postgresql/16/bin/pg_ctl -D $D -o "-p 55433 -k /tmp" -l /var/lib/postgresql/p301.log -w start
psql -h 127.0.0.1 -p 55433 -U postgres -c "CREATE ROLE whymath LOGIN SUPERUSER;" -c "CREATE DATABASE whymath OWNER whymath;"
export WHYMATH_DATABASE_URL="postgresql+asyncpg://whymath@127.0.0.1:55433/whymath" WHYMATH_VECTOR_STORE=pgvector
(cd src/backend && $PY -m alembic -c alembic.ini upgrade head)
$PY -m whymath_backend.l1.atom_graph.populate --graph data/corpus/atom_graph_v1/graph.json
$PY -m whymath_backend.l1.standards.populate --standards data/corpus/standards_v1/standards.json --skip-links
$PY -m whymath_backend.l1.concept_atom_crosswalk.populate --crosswalk data/corpus/concept_atom_crosswalk_v1/crosswalk.jsonl --concept-graph data/corpus/concept_graph_v1/graph.json --concepts data/corpus/concept_graph_v1/concepts.jsonl
$PY -m whymath_backend.l1.misconception.populate --misconceptions data/corpus/misconceptions_v1/misconceptions.json
$PY -m whymath_backend.l1.misconception.populate_atom --graph data/corpus/atom_graph_v1/graph.json
$PY -m whymath_backend.l1.skill_graph.populate --graph data/corpus/skill_graph_v1/graph.json
$PY -m whymath_backend.l1.problem_type_graph.populate --graph data/corpus/problem_type_graph_v1/graph.json
$PY -m whymath_backend.l1.problem_bank.populate --all
```

  - `concept_content` K-12 대상 행 437건은 부재 경고가 났다. concept_content를 적재하지 않았으므로 예상된 경고다.
