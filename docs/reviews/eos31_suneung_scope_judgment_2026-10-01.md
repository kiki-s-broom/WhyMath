# EOS-31 판정 — 수능 적격 게이트가 출제 범위를 본다 (`suneung_v1` → `suneung_v2`)

판정 기준: 브랜치 `claude/brave-turing-bpytzd`(분기 main `0f74a7bc` · 미머지) · 작성 2026-10-01 · 태스크 `EOS-31-suneung-gate-grade-scope-blind`

> **결론 한 줄**: 수능 적격 게이트에 **출제 범위(2028학년도 = 2022 개정 대수·미적분Ⅰ·확률과 통계)를 선결 조건으로** 넣었다.
> 범위는 성취기준 고시 코드의 접두어로 판정하고, 게이트(파이썬)와 SQL 사전필터가 **같은 접두어 상수 하나**를 읽는다.
> 승인 문항 2,480건 중 수능 적격은 **2,480 → 974건**이 됐고(초·중 전용 888건·미적분Ⅱ 등 진로 선택 포함 96건 제외), 후보 규칙이 바뀌었으므로
> 정책 버전을 `suneung_v2`로 올렸다. **공통수학 문항 522건이 함께 빠진 것은 이 판정의 가장 큰 판단 지점이라 Kiki 확인이 필요하다(§6).**

---

## §0 무엇을 정해야 했나

EOS-25 독립 비판(F1)이 지적했다: 수능 게이트 ③(c) `persona_fit ≥ 0.5`가 난이도 구간 하나만의 함수라, 난이도 라벨이
있는 승인 문항은 전부 페르소나 A(일반고 고3)에게 수능 적격이다. 정할 것은 셋이었다.

1. **무엇이 "수능 적합"인가** — 범위를 무엇으로 판정할 수 있는가.
2. **어디에서 막는가** — persona_fit을 고칠지, 게이트에 별도 조건을 둘지.
3. **두 곳(게이트·SQL)이 같은 정의를 쓰게 하는 법**.

## §1 결함 실재 확인 (acceptance ①)

판정 기준 코드(수정 전)에서 **실 PostgreSQL 16**에 저장소 코퍼스를 적재해 집계했다. Kiki 운영 DB(Phaiakes9)가 아니라 이 세션 컨테이너의
일회용 DB이며, 적재는 저장소 자신의 적재기를 썼다(`l1.atom_graph.populate` → `l1.problem_bank.populate --all`: 원자 2,683 · 문항 14,034).
**운영 DB 집계는 하지 못했다**(§6).

집계 명령(저장소에 둔다 — 어느 DB든 같은 숫자를 낸다):

`WHYMATH_DATABASE_URL=postgresql+asyncpg://… python3 scripts/analysis/suneung_scope_census.py`

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 승인 문항 | 2,480 | 2,480 |
| 수능 적격(페르소나 A) | **2,480 (전부)** | **974** |
| 그중 초·중 성취기준 전용 | 888 | 0 |
| 범위 밖으로 갈린 승인 문항 | — | 1,506 = 초·중 전용 888 + 공통·기본수학 522 + 진로·융합 선택(미적분Ⅱ 72·기하 24) 96 |
| 범위 판정 `unknown`(코드 없음) | — | 0 |
| 기출 `exam_type` · 권위 가중 · 시그니처 | 0 · 0 · 30 | 같음(코퍼스 불변) |

**독립 비판의 숫자와 다른 점**: 비판은 초·중 전용 1,122건이라 했는데 실측은 888건이다. 비판은 **코퍼스 파일의**
`achievement_standard_codes`로 셌고, 서빙 경로는 `atom_node.standard_codes`를 조인해 쓴다(원자 축). 두 출처가 같은 문항에 다른
코드를 단다 — 이 판정은 **서빙이 실제로 읽는 쪽**(조인)을 기준으로 한다. 두 출처의 불일치 자체는 별건이다(§6).

## §2 선택지

| 안 | 내용 | 판정 |
|---|---|---|
| A | `persona_fit` 규칙에 범위를 넣는다 | 기각 — 적합도는 수능·학교진도·RT·메타인지·사고력·영재 6개 모드가 공유하는 신호다. 한 모드의 범위 개념을 넣으면 나머지 5개의 임계 계약이 함께 움직인다. 범위는 "적합도"가 아니라 **자격 조건**이다 |
| **B** | 게이트에 **별도 선결 조건(AND)**으로 둔다 + SQL 사전필터가 같은 정의를 읽는다 | **채택** |
| C | 교과 축(`Problem.subject`)으로 판정한다 | 기각 — 코퍼스 전량 "공통"이고 교과 축(E1-02)은 2027 이월이다. 기대면 막힌다 |

범위를 **신호(OR)가 아니라 선결 조건(AND)**으로 둔 이유: 시그니처 패턴이나 높은 persona_fit이 있어도 범위 밖 문항은 수능 문항이 아니다.
OR로 넣으면(뮤테이션 G03) 원 결함이 그대로 남는다.

## §3 판정 — 무엇이 "수능 적합"인가

- **학년도별 출제 범위가 올바른 추상이다**(독립 비판 놓친 것 2). 레지스트리 `SUNEUNG_SCOPES`는 학년도 → (교육과정 개정, 접두어 집합)이다.
  2028 한 줄만 등록했다 — 승인 코퍼스가 전량 `2022_REVISION`이고 2015 개정 성취기준 코드가 0건이라, 2027 규칙은 만들어도 검증할 입력이 없다.
- **접두어**: `[12대수…]`·`[12미적Ⅰ…]`·`[12확통…]`. **미적분은 `Ⅰ`까지 써야 한다** — 2022 개정에서 미적분Ⅱ(`[12미적Ⅱ-…]`)는 진로 선택이라 수능 범위 밖인데 접두어 `12미적`만 쓰면 통과해 버린다(초판의 결함 — §5). 교육과정 개정도 함께 일치해야 범위 안이다.
- **"하나라도"**: 범위 안 코드를 하나라도 가지면 안이다(교집합 비공집합 — 학교진도 게이트와 같은 의미). `[12대수…]+[9수…]` 브리지 문항은 안이다.
- **세 값**: `in_scope` · `out_of_scope` · `unknown`(코드 없음). 게이트는 `in_scope`만 통과시킨다(fail-closed) — **모른다 ≠ 아니다**이면서
  **모른다 ≠ 적격**이다. 사후 관측이 "범위 밖이라 거름"과 "범위를 몰라 거름"을 다른 글자로 읽는다.
- **`persona_fit` 규칙은 바꾸지 않았다**(안 A 기각). 그 사실을 `TestJudgmentPremiseFreeze`가 계속 동결한다 — 규칙이 바뀌면 그 테스트가
  실패해 6개 모드의 임계 계약을 다시 보게 한다.

## §4 집행 지점 (acceptance ④ — 정본화와 별항)

| 지점 | 무엇 |
|---|---|
| 정의 | `l6/suneung/scope.py` — 접두어·개정·세 값 판정(단일 정본) |
| 게이트 | `l6/suneung/gating.py` ②-c — `in_scope`가 아니면 False. 신호(③)보다 앞 |
| SQL 사전필터 | `api/_next_problem_policy.py::suneung_scope_clause` — 같은 접두어 상수를 읽어 `EXISTS(… unnest(atom_node.standard_codes) …)`로 조립 |
| 코드 주입 | 정책이 후보 풀 조회 직후 성취기준 코드를 조인으로 주입(미주입이면 `unknown`으로 전부 탈락 — 후보 소멸이 신호가 된다) |
| 다른 서빙 경로 | `GET /v1/gating/suneung`도 같은 게이트를 부른다 — 코드 주입이 없는 `CandidatesDep`를 쓰면 **운영에서 항상 빈 결과**가 되어(조용한 회귀) 수능 전용 의존성 `SuneungCandidatesDep`으로 바꿨다 |
| 정책 버전 | `POLICY_VERSION_SUNEUNG` `suneung_v1` → `suneung_v2` — 같은 입력에서 다른 문항이 나갈 수 있어 소급 평가가 두 판을 섞지 않게 한다(EOS-25는 설명만 바꿔 올리지 않았다) |

**사전필터가 범위를 모르면 생기는 일**(후보 풀 소멸): 풀은 θ 근방 50개로 잘린다. 범위 밖 문항이 θ에 더 가까우면 풀이 그것들로만 차고 게이트가 전부
탈락시켜, 범위 안 문항이 있는데도 추천이 없다. 통합 테스트가 이 시나리오를 만들고, **사전필터를 끈 대조군에서 실제로 소멸함**을 확인한다.

## §5 검증

- **실 코퍼스 전수 일치**: 14,034건에서 SQL 절이 고른 집합 = 파이썬 게이트가 `in_scope`로 본 집합 = **3,444건**(승인 여부 무관 · 같은 집합).
- **통합 테스트**(실 PG · 빈 DB — CI backend-migrations와 같은 조건): 신규 2건(성취기준 조합 매트릭스 15종에서 SQL·파이썬·손으로 적은 기대 3자 일치 · 후보 풀 소멸 방지와
  그 대조군) + 기존 수능 통합 6건 복구(수정 전 6 통과 → 수정 후 6 통과 · 잔여 행 0).
  기존 3개 파일은 문항이 개념 연결 없이 심겨 있어 범위를 알 수 없었다 — 범위 안 연결을 추가했다. **"임계 미달이면 제외" 대조 테스트는 범위 밖이어도 통과해 변별력을 잃으므로
  범위 안으로 고쳐야만 의미가 선다.**
- **결함 주입**: `scripts/analysis/mutate_eos31_suneung_scope_guards.py` — 17종 전건 RED(단위 13 · 실 PG 4). 대조군 무주입 GREEN.
  축: 범위 정의 6(진로 선택 유입 추가 · `unknown`↔`out` 붕괴·개정 무시·ANY→ALL·부분 일치·범위 확대) · 게이트 3(제거·unknown 통과·AND→OR) · SQL 4(절 삭제·개정 조건 삭제·앵커 상실·접두어 일부만) · 배선 3(주입 삭제·엔드포인트 의존성 원복·의존성 내부 주입 삭제) · 버전 1.
- **하네스 결함을 발견·정정했다**: 처음 판은 백업 파일명을 파일 이름만으로 만들어 `l6/suneung/gating.py`와 `api/gating.py`(이름이 같다)의 백업이 서로 덮어써졌고,
  원복 검증도 백업끼리 비교해 통과했다 — 실제로 `api/gating.py`가 다른 파일 내용으로 덮였다(실행 전 사본으로 복구·확인). 백업명을 상대경로로 유일화하고 원복 검증을
  **시작 시점 메모리 바이트와의 비교**로 바꿨다.

## §6 한계·미결 (판정하지 않은 것)

1. **공통수학(`[10공수…]`·`[10기수…]`) 제외 — Kiki 확인 필요, 초판 판정은 너무 엄격했을 가능성이 크다.** 2028 수능 직접 범위는 3과목이지만, 평가원 안내로 보도된 문구는 "공통수학1·2 내용은 **간접적으로 출제 범위에 포함**"이다(언론·입시업체 요약 2건으로 교차 확인, 교육부·평가원 원문은 네트워크 정책으로 열지 못했다). 영향은 공통수학 포함 문항 474건이고, 기본수학(`[10기수…]`) 단독 48건은 간접 포함 근거가 없다. 권고 = 직접 범위와 간접 범위(공통수학)를 나누어 게이트는 둘 다 통과시키고 정책이 직접 범위를 우선하게 한다. 결정 전까지 코드는 직접 범위 3과목만 통과시킨다.
2. **운영 DB 집계 미실시.** §1은 저장소 코퍼스를 적재한 일회용 DB의 숫자다. 운영 DB는 승인 수·원자 연결이 다를 수 있다. 같은 집계 명령을 운영 DB에서 돌려야 한다.
3. **코퍼스 파일의 성취기준 코드와 서빙 조인 코드가 다르다**(초·중 전용 1,122 vs 888). 어느 쪽이 정본인지는 이 판정이 정하지 않았다(서빙 쪽을 기준으로만 삼았다).
4. **수능 신호가 얕다.** 승인 문항에 기출 `exam_type`은 0건이고 시그니처가 30건뿐이라, 범위를 통과한 974건의 수능 적격은 거의 전부 `persona_fit`(난이도 구간)에서 나온다.
   즉 이 변경은 "범위 밖을 거른다"이지 "수능다움을 가린다"가 아니다.
5. **2027학년도(2015 개정) 규칙 없음** — 2015 개정 코드가 코퍼스에 없다.
6. **EOS-35에 넘기는 사실**: 재선택 보류의 근거 ①이 바뀌었다. 다만 EOS-25 초안이 예상했던 "선수 목표가 하위 학년이면 `target_unavailable` 강등이 잦을 것"은 이제 **그대로 사실이 된다**
   (선수 개념의 문항이 범위 밖이면 수능 후보가 없다). 근거 ②(숙달 구간 입력의 신뢰 하한)는 `EOS-33`이 그대로 소유한다.
7. **학생 영향**: 2026-09-28 현재 학생 앱은 `mode=suneung`을 호출하지 않는다 — 오늘 닿는 학생은 없다.
8. **정정 이력(2026-10-02)**: 초판은 접두어 `12미적`을 써서 **미적분Ⅱ(진로 선택) 72건이 범위 안으로 통과**했다(적격 1,046건). 연구보고서 표 Ⅱ-1-1·Ⅱ-1-2(과목 구조)를 대조하다 발견했고 `12미적Ⅰ`로 좁혀 974건이 됐다. 조합 매트릭스에 미적분Ⅱ·2015식 숫자형 코드가 없어 놓쳤다 — 매트릭스에 두 형태를 추가하고 뮤테이션 S06(접두어 확대)을 더했다.
