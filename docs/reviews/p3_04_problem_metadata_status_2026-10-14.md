## 2. 7필드 현황 — 범위 내 적격(approved) 문항 917건

범위 내 문항은 대표 과정(미적분Ⅰ 미분) 핵심 개념 10개에 PRIMARY로 달린 문항이다. 신규 문제은행
504건(P3-03)과 기존 문제은행에서 이 개념들에 붙은 413건의 합이다.

| 필드 | 있음 | 비어 있음 | 측정 불가 |
|---|---|---|---|
| `difficulty` | 917 | 0 | 0 |
| `skill` | 917 | 0 | 0 |
| `concept` | 917 | 0 | 0 |
| `solution` | 917 | 0 | 0 |
| `answer` | 917 | 0 | 0 |
| `misconception_signature` | 917 | 0 | 0 |
| `hint_strategy` | 0 | 0 | **917** |

- **7필드 전부 충족: 0건.** 이유는 단 하나 — `hint_strategy`를 파일 코퍼스로 잴 수 없다. 측정 불가는
  충족이 아니다. 비어 있는 필드가 있는 문항은 **0건**이다.
- **오개념 서명이 개념 상속만으로 채워진 문항: 681건**(917건 중 74%). 문항 자체 연결이 있는 문항은
  236건이다. 상속 인정은 문항 고유의 보증이 아니라는 점(계약 §3)이 이 비율로 보인다.
- 문항별 미충족 목록(결손 문항): **0건.** 전체 목록은 `--json`의 `problem_metadata.unmet`.

### 이 수치가 말하는 것과 말하지 않는 것

- 말한다: 파일로 잴 수 있는 6필드는 현재 코퍼스에서 결손이 없다 — 래칫(`test_phase3_problem_metadata_ratchet.py`)이
  이 상태를 하한으로 잠근다.
- **말하지 않는다: 이 문항들이 DB에 적재돼 있고 힌트가 생성됐다는 것.** 발행 게이트는 DB의 `hints`를 읽으므로
  코퍼스 문항이 DB에 없거나 힌트가 없으면 발행이 거부된다. 그 상태는 이 환경에서 확인하지 못했다
  (`P3-22`가 DB 적재 여부 확인을 첫 단계로 둔 이유와 같다).
