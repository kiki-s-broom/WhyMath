# P3-44 새 문항 틀 설계 — 보강 은행(경로 A) 4개 개념 (2026-10-16)

> **판정 기준: main `a91ea311`** (브랜치 `claude/gracious-noether-ikmlwq` 기준 · 원인 규명 문서 `p3_44_graph_connectivity_root_cause_2026-10-16.md`의 후속).
> 이 문서는 **설계**다. 코드·코퍼스·명세는 바꾸지 않았다. 아래 수치는 서브에이전트 4명이 개념별로 프로토타입을 실행해 얻은 값이고,
> 저는 (가) 저장소 무수정, (나) 실행 로그의 판정 줄이 보고와 일치함, (다) MISC-40 판정서 원문 인용을 직접 대조했다.
> **하지 않은 것**: 프로토타입을 제가 다시 돌리지 않았고(각 ~200초), 감사 판정자(LLM)의 판정은 측정하지 않았다.

## 0. 한 줄 결론

네 개념(02-05·02-06·02-08·02-10) **모두 선택지 값이 오개념 절차의 산출임을 SymPy로 못 박을 수 있는 정직한 틀이 있다.**
단 세 가지 선결 조건이 있다: ① **우회로 판정기에 M0673·M0674(개수형)·M0676·M0678 연결 검증 규칙이 없다**(주입 실험에서 라벨을 무관 오답·정답 선지에 붙여도 통과) — 규칙 추가가 구현의 첫 단계다.
② 오개념 설명이 절차를 적지 않은 omission형이거나 맥락 종속형이라 **"어떤 절차를 그 오개념의 절차로 인정할지"는 해석**이다 — 감사 전에 Kiki가 범위를 정한다(§8 결정 ①).
③ **문제유형이 사슬을 좌우한다** — 같은 문항의 유형을 바꾸면 사슬이 안 닫힌다(§2).

## 0.1 용어 (초보자용)

| 용어 | 뜻 |

| 변별 주입 | 일부러 틀린 라벨을 붙여 보고 가드가 그것을 잡는지 확인하는 실험 |

### 2.3 해석 위험 — 판정자가 보는 것

감사 판정자는 오개념 설명을 `canonical_statement + " — " + student_wrong_thinking`으로 본다(QUAL-14). 이를 놓고 읽으면:

- **M0673**: "…곡선 밖의 점에서 그은 접선의 접점을 미지수로 두는 것을 빠뜨린다" → 02-05 틀의 P*(주어진 점을 접점으로 쓴다)와 직접 맞닿는다.
- **M0678**: "속도의 부호(방향)를 무시하고 속력으로만 본다" → 02-10 방정식형의 P*(속력 k를 v = +k로 놓는다)가 글자 그대로의 적용이다.
- **M0674**: "…롤의 정리와 혼동한다" → 02-06 개수형의 P*(f'(c) = 0의 구간 안 근 수)가 이 둘째 문장을 구현한다. 첫 문장(조건 미확인)을 직접 구현하는 틀은 틀 B(보류).
- **M0676**: 첫 문장 "증감표 없이 몇 점만 찍어 잇는다"를 구현하는 틀(F1·F2)을 본선으로, 둘째 문장 "극값과 변곡점 구분 못 함"(F3)은 제외한다 — **MISC-40 판정서 F4가 같은 근거("M0675가 이미 그 오개념이라 중복 좌석, 약한 연결은 지표를 부풀림")로 크로스링크를 올리지 않았다.**
  (그 판단은 kebab↔M0676 좌석에 관한 것이라 오답 보기의 M-id 직접 연결과 대상은 다르지만, "지표를 부풀린다"는 우려는 그대로 적용되어 F3를 본선에서 뺀다.)

이 해석이 맞는지는 **측정하지 않았다.** 판정자가 M0678을 "답에서 부호를 빼먹음(V형)"으로만 읽으면 TD/CD를 인정하지 않을 수 있다(02-10 에이전트가 꼽은 최대 위험).

## 3. 개념별 틀

공통: 슬롯 = `misconception_trigger`, 객관식 4지(정답 1 + 오개념 1 + 미매핑 필러 2), 오답 보기에 **M-id 직접 기입**(계약 §3 허용 · 02-06 기존 선례), 동적 파라미터 거부 조건으로 "오개념 값 = 정답"을 배제.

### 3.1 [12미적Ⅰ-02-05] 접선 × M0673 — 유형 `ptype.solve-for-unknown`

오개념 절차 P*: 접점 t를 두지 않고 **주어진 점 (p, q)를 접점으로 삼아 f'(p)를 기울기로 쓴다**. 정답 절차: g(t) = f(t) + f'(t)(p − t) − q = 0을 풀어 접점을 구한다.

| 틀 | 묻는 것 | 오개념 선택지 | 고유 검산 조건 | 문면 골격 |
|---|---|---|---|---|
| A `mc-outer-point-tangent-slope`(본선) | 접선의 기울기 | f'(p) | 1,198 | 554 |
| B `…-y-intercept` | 접선의 y절편 | q − p·f'(p) | 800 | 441 |
| C `…-line-value` | 접선 y = g(x)에서 g(s) | P*로 만든 직선의 g(s) | 4,717 | 1,171 |

곡선은 삼차(이차는 판정기 `T05-quadratic-*`가 거부), **외점에서 접선이 정확히 하나**인 파라미터만 쓴다(정답을 판별식 경로로 독립 재계산해 대조). B·C는 학생이 (p, f(p))를 접점으로 읽는 해석에서 값이 달라지므로 그 값이 정답과 같은 파라미터는 거부하고 오답에서도 뺀다.
**탈락한 틀**: ① 접선 셋을 "접점 x좌표가 양수"로 유일화(수치 한도 안 후보 0건) ② "접점의 x좌표" 묻기(오개념 선택지가 발문의 p를 옮겨 적은 값이 되고 기존 두 틀과 수학 실체가 같다) ③ 이차 곡선(판정기 거부).
**위험**: P*가 M0673의 절차로 인정되는지(원문에 절차 없음 → 추론) · B·C에 `solve-for-unknown`을 다는 것이 정직한지(마지막 단계가 값 계산으로 읽힐 수 있다) · 수치가 두 자리까지 가서 기존 은행보다 무겁다.

### 3.2 [12미적Ⅰ-02-06] 평균값 정리 × M0674 — 유형 `ptype.count-solutions`

| 틀 | 내용 | 상태 |
|---|---|---|
| **A**(본선) | "열린구간에서 f'(c) = (f(b) − f(a))/(b − a)를 만족하는 c의 개수는?" 선지 0·1·2·3. 정답 = f' = m의 구간 안 근 수, **M0674 선지 = f' = 0의 구간 안 근 수**(롤 혼동). 삼차·사차에 선형항 s로 롤 값만 조절 | 용량: 방정식 263건·문면 골격 537종·발문 3종. 정답 n = 1이면 "존재 보장 ⇒ 가장 작은 양수" 추측이 통하므로 **n ≥ 2 층 167건을 권고** |
| B | "닫힌구간에서 평균값 정리의 조건을 만족하는 함수 ㄱㄴㄷ 중 개수는?" (`ptype.condition-satisfaction`). M0674 선지 = 나열 함수 총수 | **보류** — 새 `answer_kind` 검산기(`verify_mvt_hypothesis_count`)와 등록이 필요하고, 없으면 수용 게이트 0/40 |
| J(선지가 함수식인 판정형) | 후순위 — 기존 판정기가 숫자 선지만 읽고 검산 경로가 없다 | 제외 |

**출발 가설 3개가 실측에서 틀렸다**: ① 개수형 연결은 현행 판정기에서 **항상** 위반이다(48건 전부 + `P3DiffSlotGenerator` 빌드가 `ValueError`) ② "조건 안 보고 적용하면 1"은 계산 산출이 아니라 정리의 결론을 읽은 값이라 라벨만 바꾼 거짓이 된다 → 정직한 값은 롤 혼동 값 하나뿐 ③ 꺾인점 함수 개수형은 **검산이 안 된다**(두 조각 방정식을 곱해 넣으면 315건 중 306건이 틀린 개수를 통과시킨다; 정답 0은 후보 16,308건 중 442건뿐).
**데이터 정정 후보(Kiki 소유)**: M0674의 `distractor_rule`이 "끝점에서 미분 불가능한 함수"라 쓰는 것은 수학적으로 부정확하다(√x를 [0, 4]에 쓰면 평균값 정리가 성립; 위반은 열린구간 **안**의 꺾인점이다).
**위험**: A의 (정답, 함정) 쌍이 (1, 2)·(2, 1)·(3, 1) 세 가지뿐이라 정형적이다 · 독립 감사가 롤 혼동 해석을 M0674로 받아들일지 미측정.

### 3.4 [12미적Ⅰ-02-10] 속도·가속도 × M0678 — 유형 `solve-for-unknown`/`model-word-problem`

오개념 절차: "음의 방향으로 움직이면서 속력이 k"를 **v = −k가 아니라 v = +k로 놓는다**. 정답 = v = −k의 양의 근, 오개념 선택지 = v = +k의 양의 근.

| 틀 | 유형 | 내용 | 인스턴스 | 문면 골격 |
|---|---|---|---|---|
| TD | solve-for-unknown | "점 P가 음의 방향으로 움직이면서 속력이 k가 되는 시각 t (t > 0)" | 1,328 | 42 |
| TR | model-word-problem | 같은 질문을 레일 열차로 (규약 문장 "오른쪽을 양의 방향으로 할 때 왼쪽으로…") | 1,328 | 24 |
| CD | solve-for-unknown | 위치식의 상수 k 구하기 (v(T) = −S의 해 대 v(T) = +S의 해) | 20,843 | 96 |
| CR | model-word-problem | CD를 레일 문맥(상수 u)으로 | 20,843 | 48 |
| V(지원) | evaluate-expression | 정답 v < 0, M0678 선지 = \|v\| | — | — |

**V는 사슬에 기여하지 않는다**(유형이 개념 스킬과 겹치지 않음 — 시뮬레이션 대조군 5/10 유지). 병목은 문면 골격 수(사슬 틀 합계 210종)다.
위치·속도·가속도 단계 혼동(`student_wrong_thinking` 후반)은 `canonical_statement`·`distractor_rule`이 부호만 말하므로 **연결하지 않고 미매핑 필러로만** 쓴다.
기존 독스트링의 "속력 필러"는 `m1`/`m2` 틀에서만 나오고(`abs(v) if v<0 else x(t)`) 유형이 evaluate이며 연결은 M0671이다 — 그것을 M0678로 옮기는 것은 사슬에도 안 들고 기존 은행 수정이다.
**위험**: 판정자가 M0678을 부호 누락(V형)으로만 읽을 가능성 · TR/CR의 레일 껍질이 얇아 기각되면 `solve-for-unknown`으로 내려야 하고 그러면 word-problem-modeling 겹침이 사라진다 · 필러가 작은 정수 한 덩어리로 보인다.

## 4. 판정기 확장 설계

기존 `_misconception_rules`에 개념별 절을 더한다. 규칙 ID는 기존 `M-link-procedure`를 재사용한다(새 ID를 만들지 않으면 소비 지점이 적다).

| 대상 | 검사 | 시안 |
|---|---|---|
| M0673 | 발문만 읽어 P*를 독립 재도출 · 곡선 위의 점이면 거부 · 연결 선지 ≠ 정답 · fail-closed | `m0673_link_violations` |
| M0674 개수형 | 연결 선지 = f' = 0의 구간 안 근 수 · 정답과 다름 | `_rolle_count` 분기 ~25줄 |
| M0676 | 정답 아님 · 해설이 보이는 절차(점 찍기/영점 찍기)의 산출 · 극대/극소를 묻는 발문 · 함수를 못 읽으면 위반 · 해설에 절차 신호어 없으면 위반 | `M-link-m0676` |
| M0678 | 값 문항: 연결 선지 = \|v\|이고 정답 음수 · 방정식 문항: 우변 음수, 연결 선지 = lhs = −우변의 해이며 정답과 다름 | `m0678_link_violations` |

**규칙 집합 분류**: 5~8회차 규칙처럼 **빌드 가드 전용(`POST_QUALIFICATION_RULE_IDS`)**으로 둔다 — 자격 측정을 통과한 기계 투표 규칙 집합(`EXCLUDED_GUARD_RULES`)을 바꾸지 않아 승인된 자격이 유지된다. (에이전트들은 이 분류 위치를 확인하지 못했다고 보고했다 → 구현 때 `p3_audit_qualification.py` 상수를 읽고 확정한다.)
**소급 영향**: 두 기존 은행에 M0673·M0676·M0678 연결이 없고 M0674 연결 12건은 판정이 바뀌지 않음을 에이전트가 확인했다.
**검증 요건**(CLAUDE.md 「보호 장치는 실패 주입 없이 보호로 선언 금지」): 각 규칙마다 ① 무관 오답 ② 정답 선지 ③ 해설 절차 삭제 ④ 조건 위반(곡선 위의 점·v ≥ 0 등)을 주입해 RED, 정상 인스턴스 GREEN, **주입이 실제 적용됐는지(`mutated != original`)와 원복 sha256**을 단언한다. 에이전트의 변별 주입(02-05 6종·02-06 3종군·02-08 6종·02-10 13종)이 출발점이다.

## 5. 은행 구성안

승인 판정은 코퍼스 단위(라벨 n ≥ 200)이고 S5 허용 결함 수는 n에 따라 다르다(보정 상한 ≤ 0.02, 아래는 이 세션이 계산한 값이며 n = 204·k = 0 → 0.01907, n = 504·k = 3 → 0.0179로 기존 기록과 일치).

| n | k=0 | k=1 | k=2 | k=3 |
|---|---|---|---|---|
| 204 | 0.0191 ✔ | 0.0281 ✗ | | |
| **240** | 0.0163 ✔ | 0.0240 ✗ | | |
| 336 | 0.0117 ✔ | 0.0172 ✔ | 0.0221 ✗ | |
| 384 | 0.0102 ✔ | 0.0151 ✔ | 0.0194 ✔ | 0.0234 ✗ |

**제안: n = 240 = 4개념 × 60** (최종 회차에 결함 0건만 통과 · p3_fill 선례 204건과 같은 성격). 개념별 배분 초안:

| 개념 | 배분(60) | 근거 |
|---|---|---|
| 02-05 | A 24 · B 18 · C 18 | 본선 A가 사슬을 닫는다 |
| 02-06 | A 60 (n ≥ 2 층 167건 중) | 틀 B 보류 → 단일 틀. 쌍이 정형적이라 변별을 감사로 확인 |
| 02-08 | F1 30 · F2 30 | F3 제외 |
| 02-10 | TD 20 · CD 20 · TR 10 · CR 10 | TR/CR은 기각 위험 → 소량 |

n = 336(4 × 84)은 최종 회차에 결함 1건까지 허용하지만 검수할 문항이 40% 늘고 문면 골격 병목(02-08 F1 48·F2 72, 02-10 합 210)에 가까워진다 — **240을 권고**한다(결정 ②).
**02-09는 이 은행에 넣지 않는다.** 처분(게이트 `G-p345-m0677-link-disposition`)이 나기까지 기다리면 이 은행의 승인이 지연되고, 나중에 행을 더하면 은행 지문이 바뀌어 재감사다. 02-09 신규 문항이 필요해지면 **별도 은행**(≥ 200)이거나, 그때 이 은행을 새 회차로 감사한다 — 승계 태스크가 정한다.

## 7. 감사 설계

- 새 결함 부류를 만들 필요는 없다 — 자격 측정 ⑥ `distractor_misattribution`이 이미 있고 판정자가 **오개념 설명을 시험지에 싣고** 연결을 판단하도록 측정됐다(총 검출 120/120). 새 틀에서는 해설이 **오개념 절차를 명시**해야 판정자가 연결을 판단할 수 있다(02-08 에이전트가 규칙 ⑥으로 요구한 것과 같다).
- 새 판정기 규칙(§4)은 이 부류의 **기계 검출**을 처음으로 더한다(자격 측정에서 0/17). 단 위치가 `POST_QUALIFICATION`이므로 감사의 기계 투표에는 들어가지 않는다(자격이 측정한 규칙 집합 보존) — 이 비대칭은 한계로 남긴다.
- 해석 위험(§2.3)은 감사가 **사람 판정이 아니라 측정된 검출기**를 통과해야 하는 구조이므로, 판정자가 틀을 인정하지 않으면 k가 늘어 불합격으로 나타난다. 그 불합격이 틀 설계 문제인지 판정자 엄격도 문제인지는 판정자 간 일치(κ)로 가린다.

## 9. 기대 효과와 한계

- **기대**: 승인 각인 후 Graph Connectivity 5/10 → **9/10(90%)**, 목표 95% 미달. 02-09(승계 P3-52)가 닫혀야 10/10이다. 개념별 시뮬레이션은 02-05·02-06·02-10에서 사슬 폐쇄를 확인했고 **02-08은 코드로 재계측하지 못했다**(스킬 겹침만 확인). 네 개념을 한 번에 합친 시뮬레이션은 하지 않았다.

- 프로토타입은 기존 생성기의 비공개 헬퍼(`_dv`, `_render_with_param` 등)를 import한다 — 승격 때 공개 창구가 필요하다.
