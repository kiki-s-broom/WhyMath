## 0. 결론

**정직한 틀이 있다 — 단, "속도를 묻는" 가장 직접적인 문항(출발 가설 ①)은 사슬에 못 들어가고, "속력과 방향을 말로 주고 속도(식)로 번역시키는" 문항이 들어간다.**

- 사슬 조건 (c)(스킬 겹침) 때문에 `ptype.evaluate-expression` 문항("t=3에서의 속도는?")은 M0678을 정직하게 연결해도 사슬에 기여하지 못한다(§4 계측기 시뮬레이션이 실측으로 확인).
- 사슬에 드는 틀은 전부 **"음의 방향(왼쪽)으로 움직이면서 속력이 k"라는 말을 v = −k로 번역해야 푸는** 문항이다. 오개념 절차 = 방향을 무시하고 속력 k를 그대로 속도 v = +k로 놓는다. 이것이 M0678의 문장("속도의 부호(방향)를 무시하고 속력으로만 본다")의 글자 그대로의 적용이다.
- 틀 4종(사슬 기여) + 지원 1종(사슬 비기여). 인스턴스 60건(사슬 틀) 생성·전건 단언 통과, 실제 계측기로 02-10이 사슬에 들어 그래프 연결 5/10 → 6/10이 됨을 시뮬레이션으로 확인했다(approved 가정).

## 1. 오개념 원문 (misconceptions.json, `mis_id: M0678`)

| 필드 | 내용 |

| student_wrong_thinking | 속도의 부호(방향)를 무시하고 속력으로만 본다. 위치·속도·가속도의 미분 단계를 헷갈린다. |
| distractor_rule | 정답 대신, 학생이 '속도의 부호(방향)를 무시하고 속력으로만 본다'처럼 잘못 처리한 결과를 오답 보기로 배치 |

| behavior_skills | skill.word-problem-modeling · skill.equation-rearrangement |

`distractor_rule`과 `canonical_statement`가 가리키는 것은 **부호(방향) 무시 하나**다. "위치·속도·가속도의 미분 단계 혼동"은 `student_wrong_thinking`의 둘째 문장이다. MISC-40 판정(`docs/reviews/misc_40_calculus_diff_kebab_seat_judgment_2026-10-02.md`)은 M0678을 "`v = 3`의 참거짓은 문항의 위치함수에 달렸다 → 문항 맥락 종속형, 미승격"으로 봤다. 이 설계는 그 판정과 충돌하지 않는다 — **kebab을 만들지 않고, 문항마다 "이 문항에서는 그 주장이 틀린 값이다"를 구조(우변이 음수 + 방향이 문면에 있음)로 보증**하기 때문이다.

## 2. 기존 필러는 어디서 나오나 (독스트링의 "속력 필러")

`p3_diff_velocity_acceleration_skeleton_generator.py`의 오개념 유발 슬롯 틀 `m1`(`mc-velocity-at-time`)·`m2`(`mc-instantaneous-velocity`)에서만 나온다: `filler = abs(v) if v < 0 else _x_at(f, t)` — 즉 **속도가 음수일 때만 |v|, 아니면 위치 x(t)** 이고 연결 kebab은 `power-rule-step-omitted`(M0671)다. 문제유형은 `ptype.evaluate-expression`이다. `m3`(가속도)의 필러는 v(t), `m4`는 v − a, 시각을 묻는 `m5`·`m6`(t>0, x=t², t³)에는 속력 필러가 아예 없다. 즉 독스트링 문장은 "음수 속도 문항 일부"에 한해서만 참이다.

→ 그 필러를 M0678로 재라벨하는 것은 (1) 504건 결속(㉠)에 막히고 (2) 유형이 evaluate라 사슬 (c)도 어차피 안 닿는다. 새 틀에서는 **유형을 스킬이 겹치는 것으로 정직하게** 달 수 있는 문항으로 옮겨야 한다.

## 3. 출발 가설 판정

| 가설 | 판정 | 이유 |
|---|---|---|
| ① "시각 t=3에서의 속도는?" (v<0이면 |v|가 오개념 선지) | **오개념 연결은 정직, 사슬 기여는 0** | 선지 |v|는 "부호를 떼어 속력으로 답함"의 직접 산출이다. 그러나 이 문항의 인지 행동은 값 계산(`evaluate-expression`)이라 개념 스킬(`equation-rearrangement`·`word-problem-modeling`)과 겹치지 않는다. 유형을 solve로 바꾸면 거짓 유형이다. 시뮬레이션 대조군: V만 넣으면 5/10 그대로. **지원 틀 V**로만 둔다 |
| ② "속도가 −k가 되는 시각 t" (부호를 무시하면 v=+k를 푼다) | **조건부** | 절차는 맞지만, 문면에 "−k"가 *글자로* 적혀 있어 "부호를 떼는" 이유가 약하다(왜 학생이 쓰인 마이너스를 버리는가). 기존 은행에 이미 "속도가 −7이 되는 시각"(자유응답)이 있어 근사 중복 위험도 있다. 방향을 *말*("음의 방향")로 주고 속력으로 번역시키는 틀(TD)이 같은 절차를 더 정직하게 낳는다 → 채택하지 않고 TD로 대체 |
| ③ "운동 방향이 바뀐 후 …" | **채택 안 함** | 방향 전환 시각(v=0) 이후의 속도 부호를 말하는 문항은 결국 값 계산(V)이거나 부호 판정(개념 스킬 비중첩: `condition-satisfaction`)이라 새 정직한 틀이 늘지 않는다 |
| ④ 위치/속도/가속도 단계 혼동(x(t)·a(t)를 속도로 답함)도 M0678 후반부인가 | **텍스트상 M0678의 일부이지만 M0678에 연결하지 않는다** | `student_wrong_thinking` 둘째 문장에 있으나 `canonical_statement`·`distractor_rule`·`correction_point`는 부호만 말한다. 이 값들은 필러(미매핑)로 둔다 — 시각 틀의 필러가 "a(t)=−k의 해"·"a(t)=0의 해"이고 상수 틀의 필러가 "a(T)=−S로 푼 상수"다(기존 생성기가 필러를 미매핑으로 두는 방식과 같다). 연결하면 "절차 값에서 나왔다"는 증명이 두 절차로 갈려 연결 규칙이 약해지고, MISC-40이 이미 "복합 진술"로 본 문장을 한 id에 몰아 붙이는 셈이 된다 |

## 4. 틀 후보

공통: 슬롯 = **오개념 유발**(`misconception_trigger`) — 객관식 4지(정답 1 + M0678 연결 1 + 미매핑 필러 2), 문항의 연결 집합 = 정확히 {M0678}(슬롯 균일 조건 충족). 오답 보기는 `distractor_map`에 **M-id를 직접** 적는다(`phase3_coverage._reached_misconceptions`가 M-id를 그대로 인정; 02-06 생성기가 `M0674`를 같은 방식으로 쓴다). 위치함수는 삼차(`T10-linear-position`·`T10-quadratic-rest` 회피).

### TD — 시각 문항 (`ptype.solve-for-unknown`)

- **발문**: "수직선 위를 움직이는 점 P의 시각 t (t > 0)에서의 위치가 x = {삼차}이다. 점 P가 **음의 방향으로 움직이면서 속력이 {k}가 되는** 시각 t는?"
- **정답 절차**: 음의 방향이므로 v(t) = −k. v(t) = 3a t² + 2b t + c = −k의 양의 근 r (다른 근 r1 < 0은 t > 0으로 버림).
- **오개념 절차**: 방향을 무시하고 속력 k를 속도로 놓는다 → v(t) = +k의 양의 근 s. (s ≠ r, s > 0 — 오답이 t>0으로 걸러지지 않아야 "고를 만하다".)
- **선택지 산출**: 정답 r · **M0678 = s** · 필러 2(속도 0인 시각 / 가속도 0인 시각 / 가속도가 −k인 시각 / r1의 절댓값 중 정수 양수 2개).
- **Tier1 조건**: `("Derivative(F, t).doit().subs(t, s) = -k", "s > 0")`, `answer_map ((s, r),)` — 기존 `rep-time-when-velocity-given`과 같은 형식. 풀이 단계(`steps_of`)는 이 형식으로 도출됨(60건 전건 통과).
- **스킬 겹침 근거**: `ptype.solve-for-unknown`의 행동 스킬 = linear-equation-solving · quadratic-equation-solving · **equation-rearrangement** → 개념 스킬과 겹침(`graph.json`로 실측). 문항이 실제로 푸는 것은 이차방정식 v(t) = −k이므로 거짓 유형이 아니다.
- **파라미터 구조**: v(t)=3a t²+2bt+c, v(r)=−k, v(s)=+k, 두 방정식 모두 양의 근이 하나(근의 곱이 음). 정수 산술 탐색 후 SymPy 재확인.

### TR — 레일 열차 시각 문항 (`ptype.model-word-problem`)

- **발문**: "직선 레일 위를 움직이는 장난감 열차가 출발한 지 t초 후, 출발 지점에서 오른쪽으로 잰 위치는 s(t) = … (cm)이다. **오른쪽을 양의 방향으로 할 때, 열차가 왼쪽으로 움직이면서 속력이 k cm/초가 되는** 것은 출발한 지 몇 초 후인가? (단, t > 0)"
- 정답/오개념/조건/선택지는 TD와 동일. 다른 점은 **양의 방향 규약을 문면이 정하고, 학생이 "왼쪽으로 속력 k" → v = −k로 옮기는 것**이 번역 행위라는 점.
- **스킬 겹침 근거**: `ptype.model-word-problem` = word-problem-modeling · condition-extraction · constraint-interpretation → **word-problem-modeling** 겹침. 기존 `P3DiffMotionWordProblemGenerator`가 "방향을 바꾼다 ⇒ v = 0"의 번역을 같은 유형으로 달고 있고(감사 통과), 이 틀의 번역("왼쪽 ⇒ 음의 부호, 속력 ⇒ 크기")도 같은 수준이다. 정직한 한계도 같다 — 위치함수는 주어지고 번역하는 것은 조건의 말이다.

### CD — 상수 문항 (`ptype.solve-for-unknown`)

- **발문**: "수직선 위를 움직이는 점 P의 시각 t에서의 위치가 x = a t³ + **k** t² + c t + d이다 (k는 상수). t = T에서 점 P가 음의 방향으로 움직이면서 속력이 S가 될 때, k의 값은?"
- **정답 절차**: v(T) = 3aT² + 2kT + c = −S를 k에 대해 푼다. **오개념 절차**: v(T) = +S를 푼다 → k' = k + S/T.
- 선택지 = 정답 k · **M0678 = k'** · 필러 2(가속도 조건 a(T)=−S로 푼 값 / −k / v(T)=0으로 푼 값 / 위치 x(T)=−S로 푼 값 중 정수 2개).
- Tier1: `Derivative(F, t).doit().subs(t, T) = -S`, `answer_map ((k, 값),)` — 기존 `rep-find-coefficient-from-velocity`와 같은 형식.
- 스킬 근거: `solve-for-unknown`(equation-rearrangement). 기존 은행이 같은 모양의 문항("속도가 −81일 때 상수 k")을 `solve-for-unknown`으로 달고 있어 일관된다. (`determine-coefficient`도 가능하나 "여러 조건" 문구와 어긋나 쓰지 않았다.)

### CR — 레일 상수 문항 (`ptype.model-word-problem`)

CD와 같되 레일 문맥(상수 u, "오른쪽을 양의 방향으로 할 때 … 왼쪽으로 움직이면서 속력이 S cm/초였다고 하면 u의 값은?"). 기존 mastery 틀(`word-rail-constant-from-speed`)이 쓰는 상수 기호 u를 따른다.

### V — 지원 틀 (사슬 비기여, `ptype.evaluate-expression`)

"…위치가 x = F일 때, t = T인 순간 점 P의 속도로 알맞은 것은?" 선택지 = v(T) < 0 · **M0678 = |v(T)|** · 필러(a(T), x(T) 등). 오개념 절차의 가장 직접적 산출이라 오개념 연결은 정직하지만 §4 시뮬레이션처럼 사슬 기여 0. 은행 구성에 넣을지는 별도 판단(들어가도 "M0678에 닿는 문항" 폭을 넓힐 뿐 연결 지표는 안 오른다).

위반 시 기존 규칙 ID `M-link-procedure`로 낸다(새 규칙 ID 불필요 — `ROUND5_RULE_IDS`에 이미 있어 `EXCLUDED_GUARD_RULES` 집합도 변하지 않는다). 초안 구현: `proto_02-10.py::m0678_link_violations` (SymPy, 선지는 `probe.choices`, 조건은 `probe.conditions`만 읽는다). 기존 은행 두 개에 M0678 연결은 0건(grep 확인)이라 소급 위반 없음.

## 8. 위험 — 감사 판정자가 결함으로 볼 만한 지점

1. **해석 갈림(가장 큰 위험)**: 오개념 절차를 "방향을 무시하고 속력을 속도로 놓는다(v = +k)"로 읽었다. 판정자가 M0678을 "속도 값에 부호를 빼먹고 적는 답"(V 유형)으로만 읽으면 TD/CD의 오답 보기를 "M0678의 산출"로 인정하지 않을 수 있다. 반론: M0678 서술은 "속력으로만 본다" — 속력 k를 속도로 다루는 것이 바로 그 문장이다. 이 해석의 승인은 측정하지 않았다.
2. **방향이 말로 주어져 문제가 너무 직설적**이라는 지적: "음의 방향"이 문면에 있으므로 v=−k를 놓는 것은 쉬울 수 있다. 오개념이 발생하는 지점이 정확히 그 번역이므로 의도적이다. 난이도는 3.0 정도로 두는 것이 무난.
3. **TR/CR의 `model-word-problem` 유형 정직성**: 현실 맥락이 얇다(기존 레일 생성기와 같은 한계). "오른쪽을 양의 방향으로 할 때" 규약 문장을 넣어 번역 대상(방향 → 부호)을 명시했다. 판정자가 "수식만 있는 문제에 레일 껍질을 씌운 것"으로 보면 TR/CR만 `solve-for-unknown`으로 내려야 하고 그러면 `word-problem-modeling` 겹침이 사라진다 — 개념 스킬 두 개 중 하나만 행사된다.
4. **필러의 설명 가능성**: 시각 틀의 필러(속도 0인 시각·가속도 조건의 해 등)는 미매핑이라 연결 주장은 없지만, 위 "속도 0인 시각"이 우연히 정답 근처(예: 1·2·3·5 같은 작은 정수 집합)라 선지가 한 덩어리로 보인다 — 오답이 서로 변별 없이 작은 정수인 점은 문항 품질 지적 소지.
5. **표기**: 해설에 "t = −5 또는 t = 3", "−6(t + 5)(t − 3) = 0" 같은 인수분해를 쓰므로 `render_factored` 의존. 분수 근이 나올 수 있다(r1이 분수일 때 `5/2` 표기, 판정기 `W-notation`은 통과).
6. 해설이 "그 시각의 속도는 36이므로 양의 방향으로 움직여 조건에 맞지 않는다"로 오개념 선지를 짚는다 — 오답 해설의 문장이 길다.
