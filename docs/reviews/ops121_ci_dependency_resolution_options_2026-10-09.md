용어 풀이(초보자용):

- **canary(카나리아)**: 광산의 카나리아처럼 "새 버전이 깨지는지 미리 알려 주는 정기 검사". 알려 줄 뿐 막지는 못한다.
- **머지 큐**: 병합 직전에 전체 CI를 다시 돌려 통과한 PR만 main에 넣는 줄 서기 장치.

### 3-1. 판단 근거

1. **C는 이미 4번 해 봤다.** 사고마다 해당 패키지에 상한을 걸어 왔지만 다음 사고는 다른 패키지에서 났다. 상한을 좁히는 일은 "무엇이 깨질지 아는 사람"에게만 효과가 있고, 우리는 미리 알 수 없다.
2. **B는 늦다.** 이번 사고에서 PR은 릴리스 약 20분 뒤에, canary는 3시간 25분 뒤에 닿는다. PR 트래픽이 있는 한 PR이 항상 먼저 맞는다. B 단독으로는 막지도, 사고 시간을 줄이지도 못한다.
3. **A가 구조를 바꾼다.** 입력(의존 해석 결과)을 코드와 같은 저장소 안에 두면 "머지 큐는 코드만 바뀐다"가 성립한다. A의 갱신 PR은 전체 CI를 도므로 **canary의 탐지 기능을 흡수**한다 — 별도 B가 필요 없다.
4. A의 대가는 운영 부담(주간 갱신 PR)과 보안 패치 지연이다. 둘 다 수치로 한정할 수 있다(§5).

### 4-1. OPS-94·OPS-103 충돌 정리

- OPS-94의 검사기는 `pip install -r/-c`를 **지금 측정 실패(exit 2)로 막는다.** `PIP_CONSTRAINT` 환경변수 방식이면 `pip install` 명령줄은 그대로라 이 막힘에 걸리지 않는다. 다만 제약 파일이 "선언 지점"으로 오인되어 상한 검사에 걸리지 않도록 스캔 대상 제외를 명시해야 한다.
- OPS-103(todo)은 같은 파일(`check_dependency_upper_bounds.py`)의 `-r/-c` 승격(②)과 Dockerfile(①)을 소유한다. 이중 구현을 피하려고 다음을 제안한다.
  - OPS-121은 **새 게이트 파일**(`scripts/ops/check_ci_constraints.py`)을 만들고 OPS-94 검사기는 최소 수정만 한다.
  - OPS-103 ②의 `-c` 부분은 OPS-121이 소유하는 것으로 `amend`, `-r`(requirements) 부분만 OPS-103에 남긴다.
  - Dockerfile은 OPS-103 ①이 소유하되, 같은 제약 파일을 쓰도록 OPS-121이 파일 경로를 확정해 넘긴다(프로덕션 이미지와 CI가 서로 다른 해석을 쓰는 상태 방지).

## 5. 보안 패치 지연 — 제안 수치

| 경로 | 주기·시한 | 방식 |
|---|---|---|
| 정기 갱신 | **주 1회**(월요일) | 갱신 스크립트로 제약 파일 재생성 → 갱신 PR → 전체 CI 통과 시 병합 |
| 긴급 갱신 | 공지 확인 후 **당일(영업일 기준 1일 이내)** | 대상 패키지 1개만 올리는 갱신 PR. 정기 주기를 기다리지 않음 |
| 방치 상한 | 어떤 핀도 **30일** 이상 갱신 없이 두지 않음 | 야간(schedule) `constraints-freshness` 잡이 `generated`를 보고 30일 초과 시 **빨갛게**(만료 없는 유예 금지 원칙) |

위 수치는 Kiki가 승인했다(2026-10-09). **연령 검사를 PR 경로에 넣지 않은 것**이 설계 결정이다: 날짜는 시계에 따라 결과가 바뀌는 입력이라, PR·머지 큐 CI에 넣으면 같은 코드가 어제는 초록·오늘은 빨강이 되어 "머지 큐의 입력은 코드뿐이다"라는 이 고정의 목적이 깨진다. 그래서 정적 검사 전체는 `infra-contracts`(PR 경로)가, 연령은 야간 잡만 본다(`미래 날짜`로 연령 검사를 우회하는 값도 위반으로 막는다).

- A의 "이번 사고를 막는다"는 **추정**이다. 시연(완료 조건 ④)에서 수치로 확인하기 전까지 확정이 아니다.
- **갱신 PR을 누가 만드는가**는 미결이다. 자동 갱신 도구가 없고, 워크플로가 기본 토큰으로 만든 PR은 다른 워크플로를 자동으로 깨우지 않는 것으로 알려져 있어(이번 세션에서 이 저장소에 대해 실측하지 않음) 자동화에는 별도 자격 증명이 필요할 수 있다. 가장 단순한 경로는 사람 또는 세션이 갱신 스크립트를 돌려 PR을 여는 것이다. Dependabot의 제약 파일 지원 여부는 **미확인**이다.
- 이 세션이 `.github/workflows/ci.yml`을 푸시할 수 있는지는 **미확인**이다(완료 조건 ⑥의 첫 단계에서 실측).
- 149개 해석은 Python 3.13에서 한 근사치다. extras 합집합(`postgres`·`neo4j`·`playwright`·`xlsx` 등)은 아직 해석에 넣지 않았으므로 제약 파일은 이보다 몇 개 더 많아진다.
- 해시 고정(`--require-hashes`)은 범위 밖이다. 공급망 변조 방어는 SEC-22 소관이다.
- 사고 시각(14:54~15:12Z)·계열 이력은 태스크 notes 인용이며 이번 세션에서 CI 로그를 다시 열어 보지 않았다.
