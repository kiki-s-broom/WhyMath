## 2. 정의와 근거

### (a) 자동검증 1차 통과율

정본 문구는 `docs/standards/eos_verification_design_v1.md` §6 "Deterministic Gate pass ÷ 전체 생성 (수용 게이트 로그)"이다. 이 저장소에서 낱말마다 무엇을 가리키는지:

- **Deterministic Gate**: 동등문제 수용 게이트(`l3/equivalent/acceptance.py`)다. 저작권·SymPy 정확성·위생·동등성 4종을 결정론으로 보고 LLM은 쓰지 않는다.
- **pass**: `accepted_stored`와 `rejected_duplicate`다. 오케스트레이터(`l3/equivalent/orchestrator.py`)는 "생성 → 수용 게이트 → 중복 검사 → 저장" 순서로 돈다. 그래서 중복으로 거부된 후보도 게이트는 통과한 것이다.
- **전체 생성**: 생성기가 후보를 낸 시도다. `generation_failed`는 게이트가 판정할 후보가 없으므로 뺀다. 시도 전체 대비 값은 따로 낸다.
- **1차**: 게이트가 처음 판정한 결과다. 사람이 고친 뒤의 승인은 자동검증 통과가 아니다.
- **수용 게이트 로그**: `cu.jsonl`(저장분) + `cu.review.jsonl`(비저장분)이다. 두 파일의 행 합이 생성 로그 행 수와 다르면 측정 실패로 처리한다.

**우회된 통과는 통과로 세지 않는다.** 게이트의 정확성 축은 후보가 스스로 적은 검산식에 정답을 넣어 본다. 검산식이 `n = 3`처럼 정답 상수를 다시 적은 것이면, 정답이 틀렸어도 같은 틀린 값으로 적히므로 언제나 통과한다. `l3/equivalent/verify_bypass.py`가 이것을 판정한다. 기준은 식의 AST에 나오는 수(0·1 제외)가 정답 표기의 수와 정확히 같은가이다. 다시 계산할 재료가 없으면 재진술이다. 헌법 R13-01("재도출 검증은 생성 단계의 정답을 입력으로 받지 않는다")의 사후 판정이다.

이 판정기가 잡지 못하는 것도 있다. `2 = -4 + b`처럼 미리 구한 중간값을 쓴 검산이나, `M**2 - M - 182 = 0`처럼 거꾸로 만든 이차식은 재계산으로 센다. 이런 약한 검산은 블라인드 재도출(EOS-205)의 몫이다. 그러므로 0.1461은 **실제 검증의 상한**이다(약한 검산까지 빼면 더 낮아진다).

검수 메모의 실측과 대조했다. 메모가 "동어반복"으로 지목한 저장분은 17건이고(EOS-205 acceptance ①), 기계 판정도 저장 30건 중 재진술 17건이다. 회귀 테스트 `test_eos197_round_has_seventeen_restatements`가 이 값을 고정한다.

### (b) 힌트 정답 누설

CU 정의(§3)의 "3단계 힌트" 좌석은 S4-11 `hints` 표다. EOS-197 산출물(`cu.jsonl`)에는 힌트 필드가 없다. 같은 회차의 `hints` 표 내보내기도 없다. 그래서 측정 대상이 0건이다. 이것은 "누설 0"이 아니다(스캔 0건은 통과가 아니다).

측정 경로는 준비돼 있다. `--hints-jsonl`(Hint 모델 JSON 1행 1건)을 주면 힌트 게이트 B(`l4/hint_content/gates.check_answer_leakage`)를 그대로 돌린다. 이 게이트는 글자 축(정답 문자열)과 값 축(계산하면 정답이 되는 식)을 본다. 힌트 1건은 3상태로 판정한다. 누설이면 True, 두 축 모두 clean이면 False, 짧은 정답처럼 글자 축이 유보하면 None(사람 폴백)이다. 무관용 기준은 F8 정의대로 L1·L2이고, L3 누설은 따로 센다.

**의미 축은 이 도구가 재지 않는다.** §5 F-Ⅴ가 의미적 누설을 "자동 검사 밖"이라 정의했고, §6은 "전수 자동 + LLM 심판 + 인간 30건"을 요구한다. 기계 두 축이 clean이라는 것은 의미상 누설 0의 증명이 아니다. 그래서 출력은 항상 `HINT_SEMANTIC_AXIS=NOT_MEASURED`를 싣는다(`docs/standards/superhuman_verification_standard.md` — 측정 없는 기계 게이트를 사람 검수 대체로 선언하지 않는다).

### (c) 메타 누락

필수 목록과 출처는 다음과 같다.

## 6. 한계

- 재진술 판정은 가장 강한 우회 하나만 잡는다(§2 (a)). 약한 검산은 재계산으로 세므로 통과율은 실제 검증의 상한이다.
- 수 리터럴이 문항 본문에서 왔는지는 보지 않는다. `x = 2*3`(정답 6)도 재계산으로 센다.
- 힌트 의미 축은 측정하지 않는다(§2 (b)). 사람 표본 판정 기록의 좌석이 아직 없다.
- 이 CLI는 CI 차단 스텝에 배선하지 않았다. 현행 회차에서 exit 2가 정직한 설계값이라 차단 스텝이면 항상 red가 된다. 대신 backend 잡의 pytest(`tests/backend/ops/test_g3_content_measures.py::TestEos197FirstMeasurement`)가 실데이터 측정값을 고정한다. 선언≠배선 감사에는 `by-design`으로 등재했다.
