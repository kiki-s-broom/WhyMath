# EOS-25 판정 — 수능 모드 추천: 설명은 전달 문항에 맞추고, 콘텐츠 재선택은 보류한다

판정 기준: main `78a8edff` · 작성 2026-09-28 · 태스크 `EOS-25-suneung-policy-selection-alignment`

> **결론 한 줄**: 수능 정책에도 EOS-124의 **정렬 계약과 의도 판정**을 그대로 적용한다(진단은 하나다).
> 그러나 관계 행위(선수 복귀·전진)의 **콘텐츠 재선택은 수능 모드에서 보류**한다(`mode_withheld`).
> 수능 게이트가 학년·출제범위를 보지 않고(`EOS-31`), 숙달 구간의 입력에 신뢰 하한이 없어서(`EOS-33`),
> 지금 켜면 응답 1~2개로 모드 밖 콘텐츠로 옮겨 가기 때문이다. 재선택의 재판정은 `EOS-35`가 소유한다.
> 정렬 검증의 면제 경로(`intent_resolution=None`)는 소비처가 사라지므로 닫는다.

초안(안 A — 재선택 적용)은 pedagogy-designer 독립 비판에서 차단 2건을 받아 뒤집혔다. 판정 이력은 §8.

---

## §0 무엇을 정해야 하나

`GET /v1/me/next-problem?mode=suneung`은 `api/_next_problem_policy.py::SuneungRecommendationPolicy`가
처리한다. EOS-124는 기본 CAT의 "설명(action·target)과 콘텐츠(problem_id)가 따로 계산되는" 결함을
고쳤지만, 수능 정책은 일부러 건드리지 않았다(EOS-124 acceptance ⑥ — "별도 판정이 필요하다"). 이
문서가 그 별도 판정이다. 판정할 질문은 둘이다.

1. 기본 CAT의 구조(1차 선택 → 앵커 → 정책 의도 → 정렬 재선택 → 정직 강등)를 수능에도 적용하는가,
   수능 모드에 고유한 판정이 필요한가.
2. 적용한다면 재선택이 수능 모드의 세 장치(L6 적격 게이트 · persona_fit · 수능 우선순위 가중)와
   어떻게 맞물리는가.

## §1 결함 실재 확인 (acceptance ①)

main 코드 그대로의 수능 정책을 대역 세션으로 돌리고, 산출에 정렬 판정기(`check_intent_alignment`)를
걸었다. 1차 선택 문항이 그대로 나가므로 "전달 문항의 대표 개념"은 앵커다.

| 형태 | 입력 | main 산출 | 판정 |
|---|---|---|---|
| (가) 전진 제자리 | 앵커 숙달 0.98 | `advance_next` · target = 앵커 | **R3 위반** — 전진을 선언하면서 같은 개념 |
| (나) 낡은 선수 설명 | 앵커 0.12 · 선수 숙달 1.0 | `practice_prerequisite` · target = 선수 | **R2 위반** — 목표(선수) ≠ 받은 문항(앵커) |
| (다) 미측정 선수 | 앵커 0.12 · 선수 미측정 | `practice_prerequisite` · target = 앵커 | **R3 위반** — 선수 복귀를 선언하면서 제자리 |

세 경우 모두 `intent_resolution=None`이라 산출 검증기가 면제했고, 응답은 200으로 나갔다. 원인은
EOS-124 이전 기본 CAT과 같다. 문항을 수능 CAT으로 고른 **뒤** 그 문항 개념의 숙달 구간으로 행위를
붙이고, 목표는 `resolve_target_concept`(측정된 선수 중 최저 숙달 — 1.0이어도 고름 · 미측정이면 문항
개념으로 폴백)로 따로 계산했다. 두 축이 서로를 보지 않았다.

**학생에게 닿는 피해**: 수능 모드 학생이 "다음 개념으로 넘어가세요"와 함께 방금 숙달한 개념의 문항을
받고, "선수 개념을 연습하세요"와 함께 원래 개념 문항을 받는다. 설명이 콘텐츠와 어긋나면 추천 이유가
신뢰를 쌓지 못하고 깎는다(EOS-124 ②와 같은 피해).

## §2 선택지

| 안 | 내용 |
|---|---|
| A | EOS-124 구조를 그대로 적용. 관계 행위면 목표 개념의 문항으로 다시 고르되, 재선택 후보에 수능 게이트·가중·선택기를 건다 |
| B | 재선택하지 않고 관계 행위를 항상 강등. 강등 값은 기존 값(반증·근거 없음·콘텐츠 공백)을 빌려 쓴다 |
| C | 목표 개념에 수능 적격 문항이 없으면 기본 CAT 풀에서 가져온다(모드 이탈) |
| **B′** | 의도 판정·정렬 계약은 적용하되, 콘텐츠를 옮겨야 하는 관계 의도는 **전용 해소값**(`mode_withheld`)으로 강등한다. 콘텐츠를 옮기지 않는 판정(반증·근거 없음·제자리 서빙)은 그대로 싣는다 |

B′는 독립 비판 F4가 제안한 안이다. B와의 차이는 "안 했다"를 "못 했다"와 다른 값으로 남긴다는 것이다.

## §3 판정 — 안 B′

**진단과 처방을 나눈다(비판 F3).** 공유해야 할 것은 진단이다 — 숙달 구간 규칙(`select_reason_type`)과
그래프 근거로 의도를 세우는 `resolve_policy_intent`는 모드와 무관하게 하나로 둔다. 모드별 사본을 두면
한쪽만 고쳤을 때 같은 학생에게 두 모드가 다른 진단을 낸다. 논쟁 대상은 처방이다. 숙달 구간이 가리키는
곳으로 **콘텐츠를 옮길지**는 모드가 정해도 사본이 아니다. 저장소 스스로 같은 숫자를 목적에 따라 다른
축으로 쓴다(`recommendation_contract.py` 약점 컷 0.7 vs LTHC 0.8).

**안 A를 지금 채택하지 않는 이유 — 두 전제가 사실이 아니었다(코드로 확인).**

1. **"L6 수능 게이트가 재선택 콘텐츠를 좁힌다"가 성립하지 않는다(비판 F1).**
   - `l1/problem_bank/persona_fit_rules.py`의 `_BAND_BASE_FIT`는 **난이도 구간 하나만** 입력으로 받는다.
   - 페르소나 A(일반고 고3)는 라벨이 있는 모든 구간에서 0.70 이상이다.
   - `is_suneung_eligible` ③(c)는 persona_fit ≥ 0.5를 OR 신호로 인정한다. 따라서 **난이도 라벨이 있는 승인 문항은 전부 A에게 수능 적격**이다. 수능 SQL 사전필터도 같은 OR다.
   - 비판의 코퍼스 파일 집계(실 DB 미확인)는 다음과 같다.
     - 승인 2,480건이 전부 A 적격
     - 그중 초·중 성취기준 전용 1,122건
     - 기출 `exam_type` 0건, 권위 가중 전량 null, 시그니처 30건
   - 그러면 안 A의 "수능 모드 안에서 다시 고른다"는 사실상 안 C(모드 무관 재선택)와 같다.
   - 초안이 예상한 "선수 목표가 하위 학년이면 `target_unavailable` 강등이 잦을 것"은 **방향이 거꾸로**였다. 실제로는 그 하위 학년 문항이 나간다.
2. **구간 규칙의 입력에 신뢰 하한이 없다(비판 F2).**
   - 실제 `l2/bkt.py::update_mastery`와 기본 파라미터(p_init 0.3·p_transit 0.1·p_slip 0.1·p_guess 0.2)로 재계산했다.

     | 출발 숙달 | 오답 1개 | 정답 1개 | 비고 |
     |---|---|---|---|
     | 0.55 | 0.219 (선수 복귀) | 0.862 (전진) | |
     | 0.80 | 0.400 | — | 오답 2개면 0.169 |
     | 0.30 (미측정) | 0.146 | — | 신뢰 1/6 ≈ 0.17 |

   - `select_reason_type`·약한 선수 컷·열린 후행 판정 중 어느 단계도 신뢰를 보지 않는다.
   - 안 A라면 **응답 하나로 콘텐츠가 다른 개념으로 옮겨진다**.
   - EOS-24 판정문(l.82)은 같은 입력(숙달 0.15·신뢰 0.17)을 "선수 결손의 약한 증거"로 보고 라우팅에 쓰지 않았다.

**안 B(기존 값 재사용)를 버린 이유**: "처음부터 안 한다"를 `refuted`나 `target_unavailable`로 적으면
측정이 반증한 것과 콘텐츠가 없는 것과 모드가 보류한 것이 같은 글자가 된다. `IntentResolution`
docstring이 스스로 주장하는 "모른다 ≠ 아니다 · 원인별 값 분리"를 어긴다. 전용 값 하나로 해소된다(F4).

**안 C를 버린 이유**: 오늘은 A와 C의 콘텐츠 차이가 0이다(F1). 게이트가 학년·범위를 보게 되는
날(`EOS-31`) C는 학생이 고른 모드의 계약("수능 적격 문항만")을 조용히 깬다. 그때 필요한 것은 조용한
폴백이 아니라 구조 신호다(예: 모드 밖 선수 복습 제안 — 비판 F1의 C′). 그 설계는 재판정(`EOS-35`)의
몫이다. 초안이 C의 약점으로 적었던 "D·E 페르소나 게이트 우회"는 **도달할 수 없는 경로**였다. D·E면
1차 선택이 None으로 끝나 재선택이 생기지 않는다(F1 지적 · 정정).

**B′가 싣는 것과 보류하는 것** — 수능 산출의 해소값:

| 해소값 | 언제 | 콘텐츠 |
|---|---|---|
| `direct` | 연습·진단·미매핑 구간(관계 행위 아님) | 1차 문항 |
| `served` | 앵커 자신이 막힌 후행(< 0.4)의 직접 선수 — 1차 문항이 곧 목표 | 1차 문항(옮길 일 없음) |
| `refuted` | 측정이 관계 행위를 반증(선수 전부 숙달 · 후행 전부 숙달) | 1차 문항 |
| `unsupported` | 근거 없음(엣지 없음 · 선수 미측정) | 1차 문항 |
| `graph_timeout` | 그래프 조회 시간 예산 초과 | 1차 문항 |
| **`mode_withheld`** | 목표 개념이 섰고 콘텐츠를 옮겨야 하는 관계 의도(약한 선수 · 열린 후행) | **1차 문항 — 보류** |
| `no_candidate` | 추천 없음 | 없음 |

`target_unavailable`은 수능에서 나오지 않는다(재선택을 하지 않으므로). 보류 조건은 "관계 행위인가"가
아니라 **"콘텐츠를 옮겨야 하는가"**(`reselect_groups`가 비지 않았는가)다. 그래서 `served` 제자리
갈래는 보류하지 않는다.

**결과 — 수능 모드의 선택은 바뀌지 않는다.** 같은 입력에서 같은 문항이 나간다. 바뀌는 것은 설명
(reason·action·target)과 `intent_resolution`뿐이다.

## §4 집행 (acceptance ③)

- `SuneungRecommendationPolicy`는 1차 선택 뒤 `resolve_policy_intent`로 의도를 세운다.
  - `reselect_groups`가 있으면 `demote_to_current_concept` + `IntentResolution.MODE_WITHHELD`로 강등한다.
  - 산출은 `intent_resolution`·`delivered_concept`를 채운다.
- 산출 생성 시점 검증기(`NextProblemOutcome._aligned_when_declared`)가 수능 응답에도 걸린다.
  - 핸들러는 그 객체를 응답·처치 기록으로 옮기기만 한다(`api/me.py`).
  - 그래서 검증은 실제 서빙 응답이 반드시 지나가는 자리에 있다.
  - 해소값은 응답 필드와 처치 기록 meta 양쪽에 실린다.
- **면제 경로를 닫는다.** 검증기의 `intent_resolution is None → 면제`는 수능 정책 하나를 위해 있었다.
  - 그 소비처가 0이 됐으므로 남겨 두면 다음 정책이 None을 내는 순간 검증이 **조용히** 빠진다.
  - `NextProblemOutcome.intent_resolution`을 필수로 바꿨다. mypy strict + pydantic 플러그인이 생성 인자 누락도 정적으로 거부한다.
  - HTTP 응답 필드는 API 계약을 바꾸지 않으려고 선택형으로 두고 설명만 고쳤다(클라이언트 소비처 0건).
- `policy_version`은 **올리지 않는다**(`suneung_v1`). REC-11 식별자는 후보 생성·선택 규칙을 가리키는데, 그 규칙은 그대로다. 설명이 바뀐 기록은 `intent_resolution` 키의 존재가 구분한다. 재선택을 켜는 변경(`EOS-35`)이 값을 올린다.
- `resolve_target_concept`는 소비처가 0이 되어 제거했다. 알려진 결함을 품은 공개 함수를 남기면 다시 쓰인다.
  - 함께 정리한 것 1: 그 함수를 패치하던 무효 대역(`test_learning_state_recommendation.py`)
  - 함께 정리한 것 2: 면제를 단언하던 테스트
  - 함께 정리한 것 3: 면제 조건문에 앵커를 두던 뮤테이션 M14(재앵커, F6)

## §6 정직한 공백

- **수능 게이트의 학년·범위 맹점은 1차 선택에도 있다(기존 결함 · 비판 놓친 것 1)**: 오늘 수능 모드는 고3에게 중학교 성취기준 문항을 낼 수 있다. 이 태스크는 콘텐츠를 옮기지 않을 뿐 1차 선택을 고치지 않는다 → `EOS-31`.
  - 학년도별 출제 범위 체제 차이도 그 태스크에 적었다(놓친 것 2). 2027학년도는 2015 개정 수학Ⅰ·Ⅱ+선택이고, 2028학년도부터는 2022 개정 대수·미적분Ⅰ·확률과 통계다.
- **신뢰 하한 없는 구간 입력은 기본 CAT에도 있다**: 기본 CAT(`cat_v2`)은 이 입력으로 이미 콘텐츠를 옮긴다 → `EOS-33`(기본 CAT·수능 공통). 수능 가중의 난이도 가산이 BKT를 아래로 편향시킬 가능성(놓친 것 4)도 거기서 잰다.
- **제자리 `served`의 설명도 잡음 입력을 인용한다**: "원래 개념이 막혀서 선수를 연습한다"는 막힌 후행의 숙달(응답 1~2개일 수 있음)에 기댄다. 콘텐츠를 옮기지 않으므로 보류하지 않았다. 대신 근거의 신뢰도가 응답에 그대로 실린다.
- **학습 상태 머신을 읽지 않는다(비판 F5)**: EOS-24 판정문 §7-3과 이 판정의 초안이 서로에게 넘겨 **소유자가 0건**이었다 → `EOS-34`.
  - B′로 콘텐츠 수준 충돌은 생기지 않는다.
  - 설명 수준 충돌은 남는다. R5·R3를 결정한 회차에 숙달 구간 설명이 나간다.
- **재판정할 데이터가 모이지 않는다**: 학생 앱은 `mode=suneung`을 호출하지 않는다(`src/mobile/lib/features/problems/data/problems_api.dart`). 수능 고유 콘텐츠(기출형·킬러)도 서빙 집합에 사실상 없다. 그래서 `EOS-35`는 날짜가 아니라 두 선행 태스크의 착지와 콘텐츠·배선 변화를 트리거로 둔다(만료 없는 유예 금지).
- **교수학적 결과 검증 부재(놓친 것 8)**: 이 태스크는 콘텐츠를 옮기지 않으므로 수능 페르소나 여정의 발화율·학년 차를 잴 대상이 아직 없다. 재선택을 켜는 `EOS-35`의 acceptance ④로 넘겼다.
- **다개념 문항**: 앵커는 대표 개념(PRIMARY→TESTED 폴백) 하나다. 수능형 다개념 문항의 설명 정밀화는 범위 밖이다.

## §8 판정 이력

- **초안(안 A)**: EOS-124 구조를 그대로 적용하고, 재선택 후보에 수능 게이트·가중·선택기를 거는 설계였다.

  - 이 PR의 참고용 커밋 `97b7f992`에 남긴다. `EOS-35`가 재판정할 때의 출발점이다.
- **독립 비판**: 차단 2건(F1·F2)을 받았다. 두 전제를 코드와 실제 함수로 확인하고 안 B′로 전환했다.
- **교훈**: 초안은 "게이트가 콘텐츠를 좁힌다"를 게이트 **코드의 모양**(적격 조건 목록)에서 추론했다. 그 조건이 **실제 데이터에서 무엇을 통과시키는지**(persona_fit 규칙의 입력)는 보지 않았다. 게이트의 존재가 곧 게이트의 작동은 아니다 — 판정의 전제는 규칙 함수의 입력까지 따라가 확인한다.
