## 2. 불일치/모호 대표 예시

불일치 0건, 해석 모호 0건이므로 제시할 예시가 없다. 근거 없는 "일치" 단정을 피하기 위해 다음 두 가지를 실행으로 확인했다.

1. **판정기 변별력(뮤테이션) 확인** — 복사본(`mut/`, 저장소 아님)에 결함을 주입하고 스크립트를 돌렸다.
   - rounding: 552행(전체에서 ‘자리에서’식 해석과 달라지는 행)의 answer를 QUAL-11 사고형 값(한 자리 아래에서 처리)으로 교체 → `mismatch=552, match=48`, 종료 코드 1.
   - division: 몫→나머지 라벨 교체 50행 → `mismatch=20`(나머지 30행은 몫=나머지라 동값; 아래 정보 지표 참조), 설명 불일치 50.
   - gcd: 최대공약수→최소공배수 라벨 교체 30행 → `mismatch=30`.
   - unit 20행(배율 ×10), area 20행(겉넓이→부피 값), volume 10행(지름→반지름) → 각각 `mismatch=20/20/10`.
   - addsub 설명의 `더하면→빼면` 10행 → 설명 불일치 10.
   뮤테이션은 임시 디렉터리에서만 했으며 저장소는 `git status` 클린이다.
2. **해석 갈림 후보를 직접 조회** — 다음 잠재 모호 지점의 해당 행 수를 세었다. 전부 0건이다.
   - `A와 B의 차`에서 A<B (부호 해석 갈림): 0행. `A에서 B를 뺀`/`A - B`에서 A<B(음수): 0행.
   - rounding 올림·버림에서 대상 수가 이미 해당 자리의 배수(‘무조건 올려서’ 문자 해석과 올림 연산이 갈림): 0행.

## 3. 정보 지표 (불일치는 아니나 검출력·서술 관련 관찰)

1. **division_remainder: 몫=나머지 동값 행이 236/400 (59%)** — 고유 (A,B) 200쌍 중 118쌍에서 몫과 나머지가 같다(예: `1800÷49` 몫 36·나머지 36, `624를 25로 나누었을 때` 몫 24·나머지 24, `2016÷47` 몫 42·나머지 42). 즉 학생이 몫과 나머지를 뒤바꿔 이해해도 이 118쌍(236행)에서는 정답이 나온다. 코퍼스 오답은 아니지만 몫/나머지 개념 변별 문항으로는 약하다. 또한 모든 (A,B)가 몫·나머지 두 문항으로 쌍 출제된다(200쌍 전부).
2. **elementary_v0: 뺄셈 설명 200행이 `A과/와 B을/를 빼면 N이다` 형태** — 수치는 정확하지만 ‘A에서 B를 뺀다’는 순서 표지가 없는 서술이다(예: `56에서 20을 뺀 값` → `56과 20을 빼면 36이다.`). 정답 불일치 없음, 서술 품질 항목.
3. **rounding: 방향어 2개 이상이 같은 정답을 내는 행 400/600, 3방향 모두 동값인 행 0** — 반올림은 정의상 올림 또는 버림 중 하나와 같으므로 정상 성질이다. 3방향 모두 같아 방향어를 못 가리는 행은 없다. 저장 정답이 QUAL-11형(‘자리에서’식) 값과도 같은 행이 48건(두 해석이 겹침) 있으며, 나머지 552행은 두 해석을 구별하고 모두 표준 해석과 일치한다.

## 4. 사용한 독립 계산 규칙 (모두 question_text만 파싱)

- 덧뺄셈: `A + B`, `A - B`, `A에서 B를 뺀`=A-B, `A와 B의 차`=|A-B|(대안 A-B는 A<B에서만 달라지며 해당 행 0), `A에 B를 더하면`·`A와 B의 합`=A+B. 설명은 연산어(더하/빼)·피연산자·결과값 대조.
- 나눗셈: `A÷B의 몫/나머지`, `A를 B로 나누었을 때의 몫/나머지` → Python `divmod(A,B)`(정수 몫·나머지). 설명은 `구하는 몫은/나머지는` 대상어와 결과값 대조.
- 최대공약수/최소공배수: `math.gcd`, lcm=a*b/gcd. 설명은 대상어와 정의 문구(가장 큰/작은 수) 대조.
- 올림·버림·반올림: `N을 X하여 Y의 자리까지 나타내면` = Y 자리 숫자까지 남기고 그 아래를 처리(결과는 Y 자리 값의 배수; 천의 자리 → 1000의 배수). 반올림은 바로 아래 자리 5 이상이면 올림. 설명은 자리·기준 자리(바로 아래)·처리 방향 대조.
- 직육면체: 겉넓이 = 2(ab+bc+ca), 부피 = abc. 원주 = 지름 × 발문의 원주율(Decimal 정밀 산술). 설명은 대상어·원주율 값 대조.
- 단위 환산(통상 교과 관례): 1m=100cm, 1km=1000m, 1cm=10mm, 1L=1000mL, 1kg=1000g, 넓이·부피는 지수 e에 대해 배율^e (m²→cm² ×10⁴, km²→m² ×10⁶, m³→cm³ ×10⁶). 발문의 from/to 지수가 다르거나 표 밖 단위쌍이면 미검증으로 센다. 설명은 단위쌍 대조.
- 비교는 Decimal 수치 동등(`same_number`)이며 정답 문자열 정규성은 보조로 따로 점검.

## 5. 한계

- **설계상 단일 해석 템플릿**: 이번 코퍼스의 발문은 전부 한 가지 해석이 우세한 정형 문장이라, 해석 모호로 분류된 행이 0이다. 이는 ‘모호 어휘가 없다’는 증명이 아니라, 내가 둔 교과 관례 기준(예: `~의 자리까지`=그 자리 숫자까지 남김, `차`=큰 수-작은 수)에서 모호가 관측되지 않았다는 뜻이다. 다른 관례를 채택하면 판정이 달라질 수 있는 어휘는 rounding `~의 자리까지`, 덧뺄셈 `차`다.
- **기준 관례는 내가 정한 것**: 한국 초등 교과서 통상 해석을 기준으로 삼았으며, 교과서 원문 대조는 하지 않았다(저작권 금기 준수).
- **파서 의존**: 정규식에 완전 일치한 행만 계산했다. 미검증 0은 현재 템플릿 집합에 대해서만 참이고, 새 템플릿이 추가되면 미검증으로 드러나도록(통과로 위장되지 않도록) 설계했다.
- **josa(조사) 정합성·한국어 문법**(을/를, 과/와, 으로/로의 받침 일치)은 범위 밖이라 점검하지 않았다.
- **의도적 과소평가 위험**: 이 감사는 ‘발문 문장과 저장 정답’의 일치만 본다. 문항 난이도, 오답 분포, 교육과정 성취기준 태그 적합성, `verify.conditions`(생성기 조건식)의 독립성은 대상이 아니다. `verify.answer_map.x == answer`만 보조 확인했다.
- `data/corpus` 7개 이외의 코퍼스·템플릿은 다루지 않았다.
