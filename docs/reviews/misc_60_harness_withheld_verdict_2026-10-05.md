# MISC-60 — WH-1 하네스의 확신 진단 보류(귀속 불명) 실측·판정·집행 기록

> **판정 기준**: `main` `590a0759` (2026-10-05). 아래 사실은 이 커밋의 소스를 읽고 실제 하네스를 돌려
> 얻은 값이며, 미머지 브랜치의 내용은 근거로 쓰지 않았다.

## 1. 무엇이 문제였나 (MISC-18의 잔여 1번)

오개념 후보에는 **귀속 불명(`attribution_unclear`)** 이라는 플래그가 붙을 수 있다. 학생 풀이에 정정
어구("틀린", "잘못"…)가 *오개념 신호 앞*에 있을 때다. 이때 두 경우가 위치로는 구별되지 않는다 —
정당한 반박("틀린 풀이: (a+b)² = a²+b²")인지, 무관한 정정인지. Kiki의 MISC-28 판정은 이를 억제도
진단도 아닌 **판정 보류 + 한 번 확인**으로 정했다("학생에게 잘못된 확신을 주는 오류를 최소화").

코치 경로(`api/coach.py`)는 이 판정을 지켜, 보류 턴에 **가설 갱신·+1 증거·−1 반박을 전부** 건너뛴다
(`persisted_matches=[]`). WH-1 하네스는 플래그를 보지 않아 같은 입력에 확정 진단처럼 굴었다.

## 2. 하네스 결과가 어디까지 닿는가 (사실 지도)

- `wh1_primary_enabled` 기본값은 **True**(2026-07-20 GA) — 코치 세션·턴의 학생 대면 발화가 하네스
  (`run_wh1_primary_turn` → `run_tutoring_turn`)가 만든 발화로 대체된다.
- 코치에 돌아가는 것은 **발화 문자열뿐**이다. 하네스가 만든 가설·증거(`outcome.hypotheses`·
  `outcome.evidence`)는 영속되지 않는다 — 영속 좌석 `run_persisted_turn`은 **프로덕션 호출자가 0건**이다
  (문서 언급만 있음). 즉 지금의 영향은 DB 오염이 아니라 **그 턴의 발화 내용**이다.
- `curate_hypothesis`(가설 생성·강화)는 플래그를 보지 않는다. `log_evidence`는 카탈로그·극성만 검사한다.
  LLM 정책은 요약에서 매치 **id만** 보며 보류 플래그를 못 본다.

## 3. ① 실측 — 카탈로그 67종 전수

카탈로그 68종 중 정정 어구 없이 신호만 쓴 입력(B)에서 자기 자신이 top-1이고 floor 이상인 **67종**을
대상으로, 같은 신호에 정정 어구 위치만 바꾼 입력 3종을 *실제 하네스*(Match → Curate → LogEvidence(+1) →
EndTurn)로 돌렸다.

| 입력 | 의미 | 게이트 후 `attribution_unclear` | 가설 생성 (수정 전 → 후) | +1 증거 적재 (수정 전 → 후) |
|---|---|---|---|---|
| A `틀린 풀이: <신호>` | 정정이 신호 앞 | 67 / 67 | **67 → 0** | **67 → 0** |
| B `<신호>` | 대조군 | 0 / 67 | 67 → 67 | 67 → 67 |
| C `<신호> 라는 풀이는 틀렸다` | 정정이 신호 뒤(확정 반박) | 0 / 67 | 0 → 0 | 67 → 67 |

- A에서 수정 전 하네스는 학생이 "틀린 풀이"라고 **표시한** 주장을 했다고 단정했다.
  예: 입력 `틀린 풀이: (a+b) a² + b²` → 발화 `(a+b)² = a² + b²이 항상 맞다고 했지. 잠깐, a=1, b=1일 때는 어떻게 돼?`.
  수정 후에는 가설이 없으므로 중립 확인 질문(`방금 단계에서 무엇을 근거로 그렇게 했는지 말해줄래?`)이 나간다.
- C의 +1 증거 67건은 이 변경과 무관한 사실이다 — **`log_evidence`는 매치와 연결돼 있지 않고 정책이 고른
  id를 그대로 적재한다**(확정 반박 입력에서도 적재됨). 이 연결 부재는 범위 밖이며 §6에 적었다.

## 4. ② 판정 — 하네스에도 같은 보류를 **둔다**

근거:
1. **교육적 안전 우선**(CLAUDE.md 의사결정 우선순위 1·3): 실측에서 67종 전부, 틀렸다고 표시한 학생에게 그
   주장을 했다고 단정하는 발화가 나갔다. Kiki의 MISC-28 판정 취지와 정면으로 어긋난다.
2. **학생 대면 경로**다: `wh1_primary_enabled` 기본 ON.
3. **정책 선의에 의존할 수 없다**: LLM 정책은 보류 플래그를 볼 수 없고, 하네스는 §3.4 불변식을 정책
   선의가 아니라 직접 강제하는 설계다(정답 억제 백스톱·증거 게이트가 같은 계열).
4. **새 임계 0**: 기존 플래그를 소비할 뿐이다(floor 0.65·`intervene.py` 0.5·judge 기본값은 그대로).

기각한 대안:
- *정책(LLM) 책임으로 남김* — 근거 3에서 기각.
- *후보까지 숨김(`last_matches=[]`)* — 코치는 "매칭은 유지하되 확신 진단은 보류"다. 후보를 숨기면 계약이
  달라진다(뮤테이션 V8이 이 변형을 RED로 잡는다).
- *LLM 요약에 플래그 노출* — 정책 프롬프트 변경이라 범위 밖. 하네스 강제가 있으면 필요성도 줄어든다.

판정의 한계: 이 판정은 새 정책값이 아니라 **Kiki가 이미 내린 MISC-28 판정을 하네스에 적용**한 것이다.
다만 학생 대면 동작 변화라서 PR에서 Kiki 확인 항목으로 올린다(§6).

## 7. 정직한 공백

- **Kiki 확인 필요(학생 대면 동작 변화)**: 기본 ON 경로에서 귀속 불명 턴의 발화가 오개념을 겨냥한 질문에서
  중립 확인 질문으로 바뀐다. 실사용에서 얼마나 자주 발동하는지는 **미측정**이다 — 배포 후
  `n_match_attribution_unclear` 분포로 본다.
- **`attribution_unclear` 판정 자체는 어순 휴리스틱**이다(MISC-28 docstring이 명시) — 정정 어구가 신호
  앞 12자 안에 있고 뒤에는 없을 때. 이번 변경은 그 판정의 정확도를 높이지 않는다.
- **`log_evidence`가 매치와 연결돼 있지 않은 점**은 별개 사안이다: 확정 반박 입력(C)에서도 정책이 고른 id가
  적재된다. 이번에는 *보류 턴*만 막았다. 증거를 매치에 묶을지는 설계 판단이 필요해 이 PR에서 하지 않았다.
- **영속 좌석 미연결**: `run_persisted_turn`이 연결되면(후속) 이 보류가 영속 오염을 막는 장치가 된다 —
  지금은 발화 내용만 보호한다.
- 이 하네스는 OCR 신뢰도가 없어 게이트② `low_quality`는 dormant다. 술어는 둘을 함께 받으므로 OCR 입력이
  하네스에 생기면 별도 수정 없이 같이 보류된다.
