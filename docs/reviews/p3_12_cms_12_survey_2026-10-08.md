## 2. 설계를 좌우하는 발견

**F1 ★ 발행 게이트는 개념(Concept) 버전 전용이고, 운영에서 한 번도 호출된 적이 없다.**
`l3/publish_gate.py`의 `create_draft`·`apply_transition`·`rollback`은 `concept_version` 테이블만 다룬다. 문항 버전(`ProblemVersion`)은 없고(ARCH-31 미착수) 신규 Entity는 Phase 3에서 금지다. 따라서 "모든 수정은 P3-11 워크플로우 경유"는 **개념 외 10종에는 그대로 적용할 수 없다.** `concept_version` 행을 만드는 운영 코드는 `create_draft` 한 곳이고 그 호출처가 0건이라 테이블은 비어 있다(`ops/integrity_violations_gate.py:42`).

**F2 ★ 발행 게이트는 학생 노출과 연결돼 있지 않다.**
`eos50_publish_gate_axis_judgment_2026-09-29.md` §1 D행·B5: `concept_version`을 읽는 서빙 경로는 0건이다. 발행(publish)은 `concept_version.status`와 `concept.current_published_version_id`만 움직이고 **살아있는 `concept` 행을 바꾸지 않는다.** 이 PR은 서빙 경로를 연결하지 않는다 — 연결하면 B5에 따라 축 판정을 다시 해야 한다.

**F3 ★ 워크플로우 우회 경로가 이미 2건 있다.**
- `PATCH /v1/concepts/{id}`: 본문을 `merged.update(body)`로 병합해 `ConceptSchema`로 검증하는데, 이 스키마에 `current_published_version_id`가 있다(`schema/concept.py:214`). 그 키를 본문에 실으면 **발행 포인터가 `publish_gate`를 거치지 않고 써진다.** `test_publish_gate_enforcement.py`의 R2는 속성 대입·키워드 인자·dict *리터럴* 키만 보므로 런타임 dict로 들어오는 이 경로를 못 잡는다(그 파일 docstring이 한계로 명시). 이 포인터를 다루는 API 테스트는 0건이다.
- `PATCH /v1/problems/{id}`: `review_status`·`is_published`·`publish_at`·`quarantine_*`를 전이 검증 없이 쓴다. 이미 `ADMIN-16`(todo)이 소유한다.

**F4 ★ 역할은 2값이고 동결 테스트가 있다.**
`Role` = `student` · `content_admin`, DB는 PG 네이티브 enum `role_enum`(`ALTER TYPE` 마이그레이션 필요). `test_role_enum.py`가 멤버 수 2를 동결한다. 운영자 토큰 CLI는 `content_admin`에게만 발급한다(`operator_token_cli.py:109`).

**F5 감사 로그 형태.** `privacy_audit.resource_type`은 `String(32)`(PG enum 아님)라 감사 대상 확장에 마이그레이션이 필요 없다. 그러나 `resource_id`는 UUID 전용이고 diff는 남지 않는다(action만).

**F6 웹 셸 제약.** 화면 코드의 `/v1/...` 리터럴은 전부 `/v1/admin/`으로 시작해야 하고(셸 계약 ⑤), `fetch(`와 `Authorization` 헤더는 허용 파일 목록 밖에서 금지다. 레지스트리의 모듈 id·라벨은 화면 코드에서 정확 일치 문자열로 쓸 수 없다(계약 ④). 웹앱에는 테스트 러너가 없고 CI는 lint·typecheck·build·산출물 grep뿐이다.

## 5. 검증 증적

지시문 검증 ①②와 이 태스크가 추가한 두 축. 모든 "막힌다" 주장은 상태를 **주입해 RED를 확인**한 것이다.

| 검증 | 방법 | 결과 |

| ① 권한 없는 발행 요청 | 5개 역할 × 8개 동작 행렬 — 편집자·검수자·학생의 `publish`/`rollback` 요청 | 403, **게이트 호출 0 · DB 접근 0 · 감사 0 · commit 0**(권한 검사가 DB 접근 앞). 실 PostgreSQL 통합 7건도 거부 뒤 DB 상태를 SQL로 직접 읽어 불변 확인 |
| ② 워크플로우 우회 쓰기 | 정적: CMS 소스에 R1(ORM import)·R2(발행 포인터 쓰기 4형태)·R3(쓰기 SQL) 위반 12종을 **주입** → 스캐너 RED. 동적: 쓰기 라우트에 포인터·상태·승인자 키를 실으면 422 + 부작용 0 | 전건 RED/422. 기존 `PATCH /v1/concepts`의 포인터 우회(F3)는 값 비교로 차단 |

**종단 검증이 찾은 결함 1건(수정 완료)**: `to_jsonable`이 `(str, Enum)` 멤버를 그대로 통과시켜 개념 목록의 `level`과 관계의 `edge_type`이 `'ConceptLevel.단원'`·`'EdgeType.PREREQUISITE'`로 나갔다. 단위 테스트는 가짜 행이 평범한 문자열이라 이를 못 봤고, 기존 단언 `to_jsonable(ConceptLevel.단원) == "단원"`은 멤버 자신과도 참이라 결함에 변별력이 없었다. 수정 = Enum 분기를 원시형 분기 앞으로. 회귀 3건은 옛 분기 순서를 주입하면 RED.
