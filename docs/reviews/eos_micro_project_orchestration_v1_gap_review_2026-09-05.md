2. **가장 큰 문제는 미완이 아니라 동결 계약과의 충돌 5건이다.**
   설계서의 3단 게이트는 이미 **G0(9/6) 동결 대상인 실패코드 F1~F8과 겹치고**(G1↔F1·F2 / G2↔F5·F6·F7),

## §1. 방법

판정 규칙 4개를 고정 적용했다.

ⓐ **판정 근거는 실파일 경로·명령 출력·태스크 ID 중 하나여야 한다.** 문서 언급만으로 "충족"한 행은 없다.
ⓑ **trunk 부재 ≠ 미구현.** 다만 이번 세션은 **shallow 클론이라 원격 브랜치 교차 조회를 못 했다**
   (SessionStart 브리핑이 판정 보류를 명시). 따라서 아래 "갭" 판정은 **trunk 기준**이며, 병렬 세션
   인플라이트분이 있을 수 있다 — 이것이 본 대조의 최대 한계다.
ⓒ **식별자 부재 ≠ 기능 부재.** 설계서가 제안한 *이름*으로 0건이면 **역할로 재검색**한 뒤 판정했다
   (예: `canary`가 아니라 "소량 시범 후 임계 미달 시 대량 배치를 차단하는 장치").
ⓓ **부재 주장은 검색 범위를 명시한다.**

```bash
# 재현 — 자산 규모
ls src/backend/whymath_backend/harness/*_batch.py | wc -l      # 36
ls -d data/corpus/*/ | wc -l                                    # 59

ls backlog/tasks/*.yaml | wc -l                                 # 517

# 재현 — LLM 생성 배치 vs 결정론 배치
cd src/backend/whymath_backend/harness
grep -l  "router\|llm" *_batch.py | wc -l                       # 1
grep -L  "router\|llm" *_batch.py | wc -l                       # 35

# 재현 — 부재 판정(역할 기반)
grep -rn "canary\|abort_threshold\|fail_rate\|rolling_" src/ scripts/   # 배치 게이트 의미 0건
find . -name "golden*.json"                                     # 0건
grep -rn "import jsonschema" src/ scripts/ tests/               # 0건
```

### A. 골든셋을 "수동 작성"할 것인가 (가장 중요)

| 인간 시간 | 100건 신규 저작 | **≈ 0** (검수하며 부산물로 생김) |
| 현재 실측 | — | **0건** (`find -name "golden*.json"` 0 · `git log --all` 0) |

계약 §2가 별도 라벨링 캠페인을 금지한 이유는 비용이 아니라 **as-found fail-closed 규약**이다 —
수동 작성 골든은 "QA 엔진이 실제로 본 입력"이 아니므로 승격 경로 자체가 없다. 계약 §8-2의 자인:
*"골든은 검수가 쌓이는 동안에만 싸게 만들어진다. 나중에 만들면 as-found 상태가 복원 불가다."*

**판단이 필요한 지점**: 골든 0건의 원인은 방법론이 아니라 **상류 검수 이벤트가 0건**인 것이다.
설계서 방식으로 100개를 수동 작성하면 골든은 생기지만 **as-found 계약을 깨고**, 그러면
`qa_confusion_matrix`의 FN율 판정 근거가 무효가 된다. → **권고: 미채택**(§8).

### B. §5 G1·G2·G3을 신설하면 F1~F8 시계열이 오염된다

> (검증 중 분류 체계가 바뀌면 실패분포 시계열이 무효가 된다)

설계서 게이트는 이 코드들과 정확히 겹친다:

### C. §6 카나리 n=30 + 임계 0.95 — 만족 불가능한 명세

CLAUDE.md 검증 권위 규약: **"게이트 판정은 항상 CLI exit 0/1(Wilson 단측 경계) — 점추정 금지."**
설계서의 `pass_threshold: 0.95` · `min_score: 0.90` · `3% 초과`는 전부 점추정이다.

Wilson 95% 단측 하한(저장소 `harness/wilson.py` 규약):

| 카나리 결과 | 점추정 | Wilson 95% 하한 |
|---|---|---|
| **30/30 (만점)** | 100.0% | **91.7%** ← 95%에 못 미친다 |
| 29/30 | 96.7% | 86.4% |
| 28/30 | 93.3% | 81.7% |

**`size: 30` + `pass_threshold: 0.95`는 만점을 받아도 통과할 수 없다.** 참값 95%를 95% 신뢰로
입증하려면 **전건 통과 n≥60**(60/60 → 95.7%). 선택지는 둘 — **①n을 60으로** 또는 **②임계를 0.90으로**
(30/30 → 91.7% ≥ 90% 통과, 29/30은 탈락).

### D. §6 "본배치 10% 무작위 표본" — 보증 수준이 배치 크기에 따라 30배 흔들린다

결함 0건 관측 시 실제 보증 상한:

| 배치 | 표본(10%) | 결함 0건이어도 상한 |
|---|---|---|
| 300건 | 30 | **8.27%** |
| 1,000건 | 100 | 2.63% |
| 3,000건 | 300 | 0.89% |
| 10,000건 | 1,000 | 0.27% |

저장소는 이미 옳은 방식을 쓴다 — **Wilson min-n**
(`concept_content_review_batch.py::min_n_for_zero_defects`, `n ≥ z²(1−θ)/θ`): **목표 상한에서
필요 표본을 역산**한다.

| 목표 상한 | 필요 표본(결함 0건 기준) |
|---|---|
| F-Ⅱ 2% | **133건** |
| 내용 KPI 0.5% | **539건** |
| 설계서 3% | 88건 |

또한 그 배치는 **결함 주입 표본으로 루브릭 자신의 변별력까지 검증**한다
(CLAUDE.md「보호 장치를 실패 주입 없이 '보호 있음' 선언 금지」) — 설계서에는 이 축이 없다.

> **정정 주의**: 설계서의 "3% 초과 시 전량 격리"를 F-Ⅱ(2%)와 **직접 모순으로 보면 안 된다** — 축이 다르다.
> 저장소에도 3%가 있으나 대상이 다르다: `superhuman_verification_standard.md:134`는
> *"S5 감사 롤링 결함율 3% 초과 시 **게이트 자동 재잠금**"*(배치 격리가 아님).
> 즉 지금 **서로 다른 것을 재는 3% 두 개와 2% 하나**가 공존하며, 필요한 것은 모순 판정이 아니라 **정렬**이다.

## §5. 예시 코드의 결함 (설계서 §5)

예시 코드이므로 결함이 곧 설계 실패는 아니다. **그대로 옮기면 안 되는** 지점만 적는다.

### G-code-1. 검사 4)5)에 인덱스 어긋남 + 거짓 음성

```python
normalized = [str(sympy.simplify(sympy.sympify(c))) for c in choices if _is_math(c)]
if item.get("answer_expr") in normalized[1:]:      # ← 결함 2개
```

`if _is_math(c)` 필터가 리스트를 줄이므로 **`normalized[1:]`는 `choices[1:]`가 아니다**.
그리고 **원시 문자열 `answer_expr`을 정규형 리스트와 비교**한다. 재현(정규화 자리에 분수 정규화 대입):

```
choices    = ['해가 없다', '1/2', '2/4', '3/1']   (길이 4)
normalized = ['1/2', '1/2', '3']                  (길이 3)   ← 인덱스 어긋남
answer_expr='2/4' → '2/4' in normalized[1:] = False          ← 정답이 선지에 있는데 놓친다
```

**거짓 음성이라 조용히 통과한다.** 추가로 검사 3)의 `simplify(lhs-rhs) != 0`은 동치인데 0으로
못 줄이면 **거짓 양성**을 낸다 — 저장소가 3-tier와 도메인 술어 18종을 둔 이유가 이것이다.

### G-code-2. 예외 처리 비대칭 — 검사 2)만 try/except

검사 3)4)5)의 `sympify`가 보호되지 않아 깨진 입력에 **탈락이 아니라 크래시**한다. 설계서 스스로
"예상 탈락률 30~40%"를 말하는데 크래시는 탈락으로 집계되지 않는다 →
CLAUDE.md「측정·수집 도구를 성공 경로만 보고 설계 금지」 정면 위반.

### G-code-3. `sympify`에 신뢰할 수 없는 LLM 출력 투입

`sympify`는 문자열을 평가한다. AI 생성물을 그대로 넣는 것은 알려진 실행 위험 표면이다.

> ⚠️ **초판 정정(§10-2)**: 초판은 ~~"`parse_expr` + 제한된 `local_dict`로 좁혀야 한다"~~ 고 적었으나
> **이 권고는 위험을 제거하지 못한다** — `parse_expr`도 내부적으로 `eval`을 쓰고(SymPy 자체 docstring이
> 정제되지 않은 입력을 넣지 말라고 명시), `local_dict`만 제한해도 기본 `global_dict`가
> `from sympy import *`로 초기화된 채 남는다. 올바른 대책은 **엄격한 문법·토큰 허용목록** 또는
> **평가하지 않는 파서**다.

### G-code-4. G2가 심판에게 정답을 알려 준다 (유도 심문)

```
[의도한 오개념] {misconception}                         ← 알려 주고
1. tag_match: 의도한 오개념을 실제로 유발하는가          ← 그대로 묻는다
```

의도를 알려 준 뒤 "의도대로 됐냐"고 물으면 **tag_match가 부풀려진다**. 블라인드로
*"이 오답지는 어떤 오개념을 유발하는가"* 를 받고 **기계가 대조**해야 한다.
저장소 `cross_verify.py`가 이미 이 원칙을 쓴다 — `_judge_reconstruct`는 LLM에 *재구성*만 시키고
**판정은 기계가** 한다. 또한 `[:400]`·`[:800]` 절단이 **조용하다**(잘린 조각에도 심판은 확신 있는
점수를 낸다) — 절단 사실을 결과에 남겨야 한다. `r.json()["response"]`·`json.loads`·`score[…]`에
예외 처리가 없어 malformed 응답 1건이 배치를 죽인다.

### G-code-5. G3(a)가 SymPy 단일 권위와 충돌할 소지

CLAUDE.md는 SymPy를 동치·검증의 **단일 권위**로 못박았다. 로컬 모델 풀이로 정답을 재판정하면
SymPy가 검증한 건에는 잉여이고, SymPy가 못 푼 건에는 **더 약한 권위로 판정**하게 된다.

## §10. 리뷰 지적 수용 (PR #988 · Codex · 2026-09-05)

리뷰 봇이 4건을 지적했고 **3건을 수용, 1건을 부분 수용**했다. 봇 지적은 이 저장소에서 버그 리포트로
취급한다 — 검증 후 고친다.

### 10-1. G-3(격리 쓰기측)은 갭이 아니었다 [P1 · 수용]

**지적**: 격리 쓰기 경로가 이미 있다. **검증 결과 지적이 옳다.**

| 근거 | 실측 |
|---|---|
| 엔드포인트 | `api/problems.py:304` `@router.patch("/{problem_id}")` → `patch_problem`(`RequireContentAdmin`) |
| 계약 정본 | `problem_quarantine_contract.md` §5 — *"격리 설정 — 관리자 표면(`PATCH /v1/problems/{id}`)으로 세 필드를 함께 쓴다"* |
| 회귀 동결 | `tests/backend/api/test_problem_quarantine_serving.py::test_admin_patch_to_quarantined_performs_no_delete` |
| **결정적** | 같은 계약 §138이 전용 엔드포인트(`POST /problems/{id}/quarantine`)를 **의도적으로 미채택**했다 — *"관리자 PATCH로 충분하고, 표면을 늘리면"* |

마지막 행이 가장 중요하다. `EOS-94`를 진행했다면 **계약이 명시적으로 거절한 표면을 추가**했을 것이다.
갭을 잘못 본 것을 넘어 **정본 결정을 되돌리는 작업**이 될 뻔했다.

**왜 놓쳤는가(재발 방지 관점)**: 부재 판정을 `ReviewStatus.quarantined`의 **대입·UPDATE 형태**로만
검색했다. 격리 쓰기는 그 형태가 아니라 **`review_status`를 일반 필드로 받는 범용 PATCH**로 구현돼 있어
그 검색에 걸리지 않았다. CLAUDE.md「식별자 부재를 기능 부재로 단정 금지」가 요구하는 절차 —
①역할로 검색 ②**소비자(호출측) 역추적** — 중 ②를 하지 않았다. 관리자 표면을 한 번만 열어 봤으면
바로 보였다. **부재 주장은 검색 방법이 옳아야 성립하므로 존재 주장보다 오류율이 구조적으로 높다**는
규칙의 실례를 이 문서가 스스로 재생산했다.

**집행**: `EOS-94` 취소 · `EOS-96`은 죽은 의존 때문에 `EOS-97`로 이전 · 그 과정에서 드러난 CLI 공백을
`HARN-67`로 등재.

### 10-2. `parse_expr` 권고는 위험을 제거하지 못한다 [P1 · 수용]

**지적**: `parse_expr`도 `eval`을 쓰고, `local_dict`만 제한해도 `global_dict`가 `from sympy import *`로
남는다. **수용** — 권고를 **엄격한 문법·토큰 허용목록 또는 평가하지 않는 파서**로 교체했다(§5 G-code-3).
초판 권고는 "고쳤다는 착각"을 만드는 쪽이라 원 결함보다 나쁠 수 있었다.

### 10-3. `cache_control` 파라미터 위치 주장 [P2 · 부분 수용 — 철회]

**지적**: 설치된 SDK는 `cache_control`을 `AsyncMessages.create`의 top-level 키워드로 노출하므로
"API 계약 불일치"는 틀렸고, 방어 가능한 갭은 default off와 `_extract_usage`의 캐시 카운터 누락뿐이다.

**이 컨테이너에는 `anthropic` SDK가 설치돼 있지 않아 직접 검증하지 못했다.** 따라서 지적이 옳다고
확인한 것이 아니라, **내 주장을 뒷받침할 근거가 없음을 확인**했다. 검증 불가한 주장을 남기면 불필요한
재작성을 유발하므로 **철회**하고, 방어 가능한 두 갭만 남겼다. 재검증은 실 SDK가 있는 환경의 몫이다.

### 10-4. 분포 수치가 표와 맞지 않는다 [P2 · 수용]

**지적**: 표 1~26행에서 초판 분포(12·4·5·5)가 재현되지 않는다. **재집계 결과 지적이 옳다** —
실제는 충족 계열 11 · 부분 1 · 충돌 5 · 갭 8 · 미실증 1 = 26.

원인은 **행 단위와 축 단위를 섞어 센 것**이다. §6의 "진짜 갭"은 8개 갭 행을 4축으로 묶은 수인데,
초판은 그 계수 규칙을 적지 않은 채 행 분포까지 틀리게 적었다. §2에 **계수 규칙을 명시**했다.

### 10-5. 이 절이 말하는 것

지적 4건 중 **2건(10-1·10-4)이 이 문서의 중심 결과인 "진짜 갭 N건"을 직접 흔들었다.** 특히 10-1은
등재까지 마친 뒤에 잡혔다 — **대장에 잘못된 작업이 들어간 상태에서 되돌린 것**이다.

병렬 조사(서브에이전트 4건)로 넓게 훑고 결론을 떠받치는 항목만 직접 재검증했는데, **재검증 대상을
고르는 기준이 "결론에 중요한가"였지 "부재 주장인가"가 아니었다.** 10-1은 부재 주장이었고
재검증 목록에 없었다. 다음 대조에서는 **모든 부재 주장을 재검증 대상으로 삼는 것**이 맞다 —
존재 주장은 파일 하나를 대면 끝나지만 부재 주장은 검색 방법 전체가 옳아야 성립하기 때문이다.

### 11-3. 오등재 1건과 그 교훈 — `requires_gates`는 착수 조건이다

`MP-01`(회차 태스크)에 검수 게이트를 붙여 등재했다. **`requires_gates`는 `done` 조건이 아니라 착수 조건이다**
(`selector.py:6` — 후보 = 게이트 전부 cleared/waived). 그런데 그 게이트는 *회차 산출물*을 Kiki가 검수해야 clear되므로,
회차 전에는 검수할 것이 없고 검수 전에는 회차를 시작할 수 없는 **교착**이었다. 같은 등재의 notes가 EOS-98/99를
"소프트 선행"이라 적어 `audit-deps`(HARN-52)가 미집행 의존으로 red를 냈다 — 의존이 아니라고 적으면서 '선행'이라는
단어를 썼다.

둘 다 등재 직후 하네스가 잡았다(`next` 전건 모드에서 미노출 · `audit-deps` exit 1). 그러나 **고칠 CLI가 없었다** —
`amend`는 게이트·의존을 *부착만* 하고(`backlog.py:1483` "제거는 열지 않는다"), notes를 고치는 명령은 없다.
그래서 `cancel` 후 `MP-02`(회차·게이트 없음) + `MP-03`(골든 승격·게이트+의존)으로 나눠 재등재했다. 검수 게이트는
**산출물을 만드는 태스크가 아니라 그 산출물을 소비하는 후속 태스크에** 건다.

이것으로 **정정 경로 부재로 인한 번호 소모가 3회차**다(EOS-94·EOS-96·MP-01). HARN-67에 ⑤ 게이트 탈착 경로
⑥ notes 정정 경로 ⑦ 사고 경위를 추가했다 — *위반을 지적하면서 고칠 수단이 없는 게이트는 사람이 게이트를 끄게
만든다*(CLAUDE.md 2026-09-01 등재 사유와 동형).

### 11-6. 번호 충돌 — `EOS-98`이 두 태스크를 가리켰다 (병렬 등재의 가시성 창)

리뷰 상환 push 뒤 PR이 `mergeable_state: dirty`가 됐고 CI가 발화하지 않았다. `origin/main`을 머지하자 `validate`가
**`EOS-98` 번호 충돌**을 냈다 — 타 세션이 `EOS-98-age-band-explanation-generation`을 #994로 먼저 main에
올렸다(커밋 08:02 UTC). 이 세션의 `add EOS-98`(10:18)은 ①stale한 로컬 main ②원격 claim 대장(착수분만 실림 —
그쪽은 todo 좌석이라 claim이 없다)을 봤으므로 **구조적으로 볼 수 없었다**. `add`가 낸 "가드 통과 ≠ 충돌 없음"
고지가 정확히 이 경우다.

처분: 그쪽이 머지됐으니 **이쪽을 옮긴다**. 개명 CLI가 없고 손편집은 금지이며 EOS 접두는 *소진된 줄 알았으므로*(11-7), 미머지
브랜치를 최신 main에서 다시 세우고 CLI로 재등재했다 — 회차 스냅샷 태스크는 **`MP-04`**(MP 인프라 축). 문서
델타는 3-way 패치로 옮겼다. `validate`가 머지 직후 충돌을 잡은 것은 가드의 변별력 증거이며, 잡힌 지점이 **머지 뒤**
라는 것이 한계다(HARN-71 쓰기측 선검사가 이 창을 겨냥한다).

### 11-7. 정정 — "EOS 계열 소진"은 도구 오보고였다 (HARN-73 · #1002)

11-2·11-6이 전제한 "EOS 00~99 소진"은 **틀렸다**. `backlog.py add`의 거부 문구("00~99번을 모두 소진")를 실측 없이
사실로 옮겼고, 보강 근거로 쓴 `ls backlog/tasks | max`도 *최대 번호*를 봤지 *미사용 번호*를 보지 않았다. 타 세션(#1002 ·
HARN-73)의 실측(모든 ref 이력 전수): EOS 번호 **사용 59 · 미사용 40**(01~05·07~27·29~31·33~43) · 이력상 삭제 0. 제안기가
최대+1 방향으로만 찾다가 99 다음이 100이 되자 "모두 소진"이라 말한 것이다. **Kiki 결정 A**(하위 미사용 번호 재사용 + 제안기
폴백 · 새 접두 C는 기각) · 게이트 `G-eos-task-prefix-exhausted` clear.

이 문서에 남는 것: `MP` 접두는 "EOS 소진 대응"이 아니라 **회차 축 접두**라는 정의만 유효하다(11-2가 이미 그렇게 적었다 —
그 정의는 소진 여부와 무관하게 성립한다). `MP-04`(초판 EOS-98 충돌 회수)는 회차 인프라 축이라 그대로 두되, EOS 축 후속
태스크는 `EOS-nn`을 계속 쓴다. `build_harness.md` §8의 해당 금기는 "소진 시 새 접두"에서 **"제안기 문구를 실측 없이 등재
금지"**로 고쳐 썼다.

교훈은 §10-5·§11-5와 같은 계열의 세 번째다 — 부재 주장(§10-5)·존재 전제(§11-5)에 이어 **도구가 낸 판정 문구**도 열어 봐야
한다. 두 세션이 독립으로 같은 문구를 사실로 옮겼다는 것이 이 오류의 형태를 말해 준다: 도구 출력은 환경 사실이 아니라
도구의 주장이다.
