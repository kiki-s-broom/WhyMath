# CU 사후 힌트 패스 프롬프트 정본 (EOS-211)

> 소비 코드: `src/backend/whymath_backend/l4/hint_content/cu_hint_prompts.py`(상수 사본) →
> `l4/hint_content/cu_hint_pass.py`(패스 본체) · CLI `python -m whymath_backend.harness.cu_hint_pass`.
> 정합 동결: `tests/backend/l4/hint_content/test_cu_hint_pass.py`가 아래 `prompt:<id>` 블록과 코드 상수의
> **바이트 동일**을 단언한다. 문구를 바꿀 때는 이 문서를 먼저 고치고 코드를 맞춘다(doc-first).
> 코드가 내는 식별자 `prompt_version`은 두 블록 + 출력 JSON 스키마의 내용 해시다
> (`l4.cu_hint@sha256:<12hex>`).

## 왜 이 프롬프트가 있는가

동등문제 생성기(`l3/equivalent`)가 만든 CU에는 지문·정답·해설 문장·검산식만 있고 **단계별 풀이와
3단계 힌트가 없다**(EOS-197 A6 회차 30 CU 전부 힌트 0건 — EOS-207 첫 측정). 기존 힌트 생성기
(`l4/hint_content/generator.py`)는 LLM 0 템플릿이라 SymPy로 검증된 풀이 단계가 있어야 동작한다.
Kiki 결정(2026-10-29) "사후 LLM 힌트 패스"에 따라, 저장된 CU 하나당 LLM 호출 한 번으로
**단계 목록 + 핵심 개념 이름 + L1·L2·L3 힌트**를 받고, 기계 게이트 3종을 통과한 힌트만
`verified=true`로 둔다.

## 형식이 게이트 규칙에서 나온 이유

프롬프트가 요구하는 형식은 게이트 3종(`l4/hint_content/gates.py`)의 실제 판정 규칙을 거꾸로 읽어 정했다.

| 요구 | 근거가 된 판정 규칙 |
|---|---|
| L1에 '단계'·숫자·식 금지 | 게이트 A ③ 흐름 표지 정규식 `_FLOW_MARKERS`가 본문에서 흐름 노출을 파생한다 — L1은 흐름 노출이 없어야 한다 |
| L2에 "풀이는 모두 N단계로 이어져."·"지금은 첫 단계" | 같은 정규식 — L2는 흐름 노출이 *있어야* 한다 |
| L3에 첫 단계 식을 글자 그대로 | 게이트 A ③ 부분 시연 선언은 단계 본문(공백 무시)이 본문에 실재해야 성립한다 |
| L1·L2에 식 금지 | 같은 규칙의 반대 — 계산 노출을 선언하지 않은 레벨에 단계 본문이 실리면 거부 |
| L1에 개념 이름을 「」로 글자 그대로 | 게이트 A ③ 개념 이름 노출 선언 ↔ 본문 파생 일치 |
| 마지막 단계 = `변수 = 정답` 식 | 게이트 A ④ 값 축이 최종 단계를 목표 값으로 읽는다 — 한국어 문장이면 목표를 못 읽어 판정 불가 → 거부 |
| 정답 값·정답을 계산해 주는 식 금지 | 게이트 B 글자 축(`detect_answer_leakage`) + 값 축(`AnswerValueExposure`) |
| 잘못된·틀렸·못 하·실수·바보·포기 금지 | 게이트 C(`l4/tone_filter`) 부분 문자열 금지 패턴 — 개념 「실수」(real number)도 걸린다 |

## 합성 ID 규칙 (CU에는 실제 풀이 경로가 없다)

- `solution_path_id = "cu-" + <CU slug>` · `step_order = 1`(풀이를 시작하는 자리) ·
  `hint_id = hint-cu-<slug>-s1-l<level>`(`models.hint_id_for` 재사용) · `problem_id` = CU의 `problem_id`.
- `revealed_concept_ids = ("unmatched-concept:<개념 이름>",)` — 원자 백본 코드에 매칭되지 않은 이름임을
  이름공간으로 드러낸다(원자 코드를 지어내지 않는다).

## ⚠ 순환 측정 경고

측정기 `ops/g3_content_measures`의 힌트 **기계 축**은 이 패스가 거른 바로 그 게이트 B를 다시 돌린다.
그래서 `cu.hints.jsonl`(verified만)에 대해 기계 축 누설은 **구조적으로 0**이다 — 그 0은 누설이 없다는
증거가 아니다. 실질 검증은 **의미 축(사람 표본 검수 — EOS-210 · 검증 설계 §5 F-Ⅴ)**이다. 측정기는
`HINT_SEMANTIC_AXIS=NOT_MEASURED`를 항상 싣는다.

게이트 거부 CU는 같은 시도 예산(`--retries`) 안에서 **다시 생성**한다 — 즉 채택본은 게이트를 통과하도록
골라진 표본이다(선택 편향). 이 사실을 숨기지 않기 위해 패스 요약이 시도 수·게이트 거부율
(`HINT_ATTEMPTS_TOTAL`·`HINT_GATE_REJECT_RATE`·`CU_REGENERATED`)을 늘 싣고, 의미 축 표본은 재생성된 CU를
우선 포함해야 한다.

## 범위 밖

LLM이 낸 **단계 계산 자체의 SymPy 검증**은 이 패스가 하지 않는다(후속). 게이트 3종은 노출 정합·정답
누설·톤만 본다.

## SYSTEM 프롬프트

```prompt:l4.cu_hint.system
당신은 WhyMath의 **힌트 저작자**입니다. 이미 만들어진 자체 저작 수학 문항 하나를 받아,
그 문항의 풀이 단계 목록과 3단계 힌트(L1·L2·L3)를 JSON 객체 하나로만 출력하세요.

## 절대 금기
- 정답 값을 L1·L2·L3 어디에도 쓰지 마세요. 계산하면 정답이 되는 식도 쓰지 마세요.
- 마지막 단계의 식을 L1·L2·L3 어디에도 쓰지 마세요.
- 학생을 다그치거나 깎아내리는 말을 쓰지 마세요. 특히 다음 낱말은 어떤 뜻으로도 쓰지 마세요:
  잘못된, 틀렸, 못 하, 실수, 바보, 포기. (수 체계의 '실수'도 쓰지 마세요 — 다른 말로 바꿔 쓰세요.)
- 고등학교 교육과정 밖의 방법(예: 로피탈 정리)을 쓰지 마세요.
- 평가원·EBS·검정 교과서의 본문·문제·풀이를 인용하거나 복제하지 마세요.

## 출력 형식 — 아래 키만 가진 JSON 객체 하나. 다른 글·코드 펜스 금지
{"steps": ["...", "..."], "concept_name": "...", "hints": {"L1": "...", "L2": "...", "L3": "..."}}

### steps — 풀이 단계 (2개 이상 8개 이하)
- 각 단계는 **식 한 줄**입니다. 한국어 문장을 섞지 말고 식만 쓰세요.
- 곱셈은 `*`, 거듭제곱은 `^`로 씁니다. 예: f'(x) = 6*x^2 - 6*x + 4
- 해설이 주어지면 그 해설을 단계로 나누고, 해설이 없으면 직접 풀어 단계를 만드세요.
- **마지막 단계는 `변수 = 정답` 꼴의 식 하나**입니다. 예: b = -14
- 첫 단계와 마지막 단계는 서로 다른 식이어야 합니다.

### concept_name — 이 문항의 핵심 개념 이름
- 고등학교 교육과정 용어로 2~20자. 숫자·등호·식을 넣지 마세요.

### hints — 세 힌트 모두 학생에게 건네는 다정한 반말로 쓰고, 질문으로 끝내세요
- L1 (개념 이름만): concept_name을 「」로 감싸 글자 그대로 한 번 쓰고, 그 개념의 어떤 성질을
  쓸 수 있을지 묻습니다. '단계'라는 낱말, 숫자, 식을 쓰지 마세요.
- L2 (단계 흐름만): "풀이는 모두 N단계로 이어져."(N은 steps의 개수)와 "지금은 첫 단계"를 그대로
  포함하고, 각 단계에서 *무엇을 하는지*(예: 도함수를 구한다, 접점의 좌표를 정한다)만 말합니다.
  계산 결과·식·숫자 값을 쓰지 마세요.
- L3 (첫 단계 시연): "첫 단계"라는 말을 쓰고, steps의 첫 번째 식을 **글자 그대로** 한 줄로
  보여 준 뒤, 그다음은 학생이 이어 가도록 묻습니다. 첫 번째 식 말고 다른 단계의 식은 쓰지 마세요.
```

## USER 템플릿

자리표시는 `{{NAME}}`이고 `build_cu_hint_user()`가 치환한다. 해설이 없는 CU(로컬 좌석 EOS-197 산출물)는
`EXPLANATION` 자리에 "(해설 없음 — 직접 풀어 단계를 만드세요)"가 들어간다.

```prompt:l4.cu_hint.user
문항 (자체 저작 · WHYMATH_GENERATED)
{{QUESTION}}

정답: {{ANSWER}}
해설: {{EXPLANATION}}
과목: {{SUBJECT}} · 성취기준: {{STANDARDS}}

위 문항의 풀이 단계와 3단계 힌트를 형식 그대로 JSON 객체 하나로만 출력하세요.
```
