# 작업 지시서 형식

`scripts/golden_prompts/build_prompts.py`는 아래 구조의 markdown을 읽는다. 작은 예시는 `../assets/example-ped17-spec.md`, 큰 예시는 저장소의 `golden/prompts_src/spec.md`에 있다.

## 목차

1. 전체 구조
2. 공통 규칙 쓰는 법
3. 공유 계약 쓰는 법
4. 작업 항목 쓰는 법
5. 좋은 지시의 기준
6. 설정 파일(JSON) 항목

## 1. 전체 구조

```markdown
# <문서 제목>

<한 줄 소개>

## 공통 규칙과 보고 형식

**공통 규칙**

1. (스크립트가 표준 문장 "읽을 범위"로 바꾼다. 아무 내용이나 둬도 된다)
2. (스크립트가 표준 문장 "선행 작업 확인"으로 바꾼다)
3. **<규칙 이름>:** 프로젝트 고유 규칙
4. ...

**완료 보고 형식**

(스크립트가 작업별로 다시 만들어 넣으므로 참고용)

**용어**

| 용어 | 뜻 |
| --- | --- |
| ... | ... |

**공유 계약**

(선택) 모든 세션이 같은 모양으로 써야 하는 것 — 표·코드 펜스·문단 무엇이든. 다음 "## " 제목 전까지 전부 실린다.

## <레인 이름, 예: B0~B4: 데이터 형식, 생성, 검사>

<레인 소개 문단. 각 지시문의 "레인 메모"로 들어간다>

### <작업번호>. <작업 제목>

- **목적:** ...
- **선행 산출물:** ...
- **할 일:**
    1. ...
- **산출물:** ...
- **완료 기준:** ...
- **하지 말 것:** ...
- **막히면:** ... (선택)
```

스크립트가 찾는 표시는 네 가지다: `**공통 규칙**` 다음의 번호 목록, `**용어**` 다음의 표(`**공유 계약**` 또는 다음 `## ` 전까지), `**공유 계약**` 다음부터 다음 `## ` 전까지의 본문 전체, `### <번호>. <제목>` 제목. 작업번호는 설정 파일의 `tasks` 키와 정확히 같아야 한다.

## 2. 공통 규칙 쓰는 법

모든 작업에 똑같이 적용되는 안전·품질 규칙을 3번부터 쓴다. PED-17과 골든 패스에서 쓴 규칙들이 좋은 출발점이다.

- 사용자 노출 금지: 관문을 통과하지 않은 결과물을 실제 사용자 경로에 넣지 않는다.
- 숫자 기준은 확정값: 임의로 바꾸지 말고, 바꿔야 하면 근거와 함께 보고.
- 모르는 값은 추정 금지: 코드·문서에서 먼저 찾고, 없으면 "미확인". 지시서의 "사전 실측" 값도 재확인.
- 쓰기 범위 고정: 새 코드를 쓸 폴더를 명시하고 그 밖은 읽기 전용(예외 파일은 번호를 붙여 열거).
- 완료 기준은 기계 판정 하나(예: 특정 테스트 폴더 초록). 판정은 exit code로, `-q`·`| tail` 금지.
- 검증은 CI와 같은 명령으로(잡의 스텝 목록을 맞춘다).
- 개인정보 보호: 실제 사용자 식별 정보를 로그·산출물·프롬프트에 넣지 않는다.
- 하네스·커밋·PR 절차(이 저장소면 `backlog.py start` → 커밋 메시지 형식 → PR 본문 첫 질문).
- 종료 보고 형식(완료 보고 외에 세션이 꼭 남길 줄).

이유: 지시문을 받는 AI는 이 대화의 맥락을 모른다. 규칙이 지시문 안에 있어야 모든 세션이 같은 기준으로 움직인다.

## 3. 공유 계약 쓰는 법

여러 작업이 **같은 모양**을 전제로 할 때 쓴다. 예: HTTP 요청·응답 JSON, 데이터 파일 스키마, DB 표, 환경변수, 폴더 배치, 저장소 실측 사실(경로·패키지·CI 잡). 작업 본문마다 복사하면 세션마다 다르게 고쳐 쓰다 어긋난다 — 한 곳에 쓰고 생성기가 전 파일에 싣게 한다.

- 첫 문장에 "바꿔야 한다고 판단하면 바꾸지 말고 보고하고 멈춘다"를 넣는다.
- 소제목은 `*이탤릭*` 한 줄로 쓴다(`## `를 쓰면 거기서 계약이 끝난다).
- 표는 용어 표와 섞이지 않는다 — 생성기가 `**공유 계약**` 표식에서 용어 표 읽기를 멈춘다.
- 길어도 된다(골든 패스는 65줄). 모든 세션이 읽는 비용보다 어긋나는 비용이 크다.

## 4. 작업 항목 쓰는 법

| 항목 | 쓰는 법 |
| --- | --- |
| 목적 | 왜 이 작업이 있는지 한두 문장. 뒤 작업 중 무엇이 이것에 기대는지 |
| 선행 산출물 | 시작할 때 필요한 앞 작업의 결과물 이름 |
| 할 일 | 번호 매긴 단계. 한 단계에 한 가지 행동. 사람이 하는 단계는 "(Kiki)"처럼 주체를 앞에 적는다 |
| 산출물 | 끝나면 남는 파일·표·기능의 이름 |
| 완료 기준 | 실행해서 확인할 수 있는 문장. "잘 동작한다" 대신 "틀린 정답 예시는 불합격한다". 관문이면 go/no-go 조건 |
| 하지 말 것 | 이 작업에서 일어나기 쉬운 잘못 (예: 합격률을 높이려고 기준 완화, "이왕 하는 김에") |
| 막히면 | 무엇을 보고하고 어디서 멈출지, 또는 공식 대체안 |

관문 작업(go/no-go 판정을 하는 작업)은 할 일에 판정 기준 숫자와 no-go일 때의 조치를 적는다. "실패가 목표"인 관문(예: 일부러 빨간불 테스트 심기)은 그 사실을 목적 첫 줄에 적는다.

## 5. 좋은 지시의 기준

- **아는 것만 적는다.** 저장소 경로, 테이블 이름처럼 모르는 정보는 지어내지 말고 "먼저 찾고, 못 찾으면 미확인으로 보고"라고 쓴다. 아는 것은 실측 날짜·기준 커밋과 함께 적는다.
- **정해지지 않은 숫자는 "(제안값)"으로 표시**해 사용자에게 확인받는다. 확정되면 표시를 지우고 승인 기록에 남긴다.
- **사람만 할 수 있는 일**(외부 승인, 법무 회신, 권한자 조작, 피험자 섭외)은 AI가 질문을 정리해 전달하고 답을 기록하는 일로 쓴다. 설정의 `human_tasks`에도 적는다.
- **검사하는 작업은 판정만** 하고 내용을 고치지 않게 쓴다. 고치면 검사가 무의미해진다.
- **대체 피험자·대체 데이터**를 쓰는 작업은 출처를 분리 집계하고 결론을 "잠정"으로 적게 한다.
- 문장은 짧게(25단어 미만), 전문용어는 처음 나올 때 괄호로 풀어 쓴다.

## 6. 설정 파일(JSON) 항목

`../assets/example-ped17-config.json` 또는 `golden/prompts_src/config.json`을 복사해 고친다.

| 키 | 뜻 | 예 |
| --- | --- | --- |
| project | 프로젝트 이름 | "WhyMath 골든 패스" |
| session_prefix | 세션 이름 접두어 | "GP" |
| role_line | "너는 ___에서 작업 X만 맡은 AI다"의 빈칸 | "WhyMath 골든 패스 스켈레톤 3주 프로젝트" |
| plan_url | 원본 계획서 링크 또는 저장소 안 경로 | "golden/prompts_src/plan_golden_path_3weeks.html" |
| repo_location | 저장소 위치(채워서) — GitHub 경로 · 사용자 머신 경로 · 클라우드 경로 | "GitHub `kiki-s-broom/whymath` · `C:\\Users\\kiki\\...`" |
| output_root | 저장소 안 산출물(보고) 폴더 — 변형 묶음마다 다르게 | "golden/reports" |
| branch_prefix | 작업 브랜치 접두어 — 변형 묶음마다 다르게 | "golden" |
| background | 모든 지시문에 들어갈 배경 문장 목록 (5~7줄) | |
| tasks | 작업번호 → {short: 세션용 짧은 이름, lane: 레인, deps: 선행 작업 목록}. 적힌 순서가 표시 순서 | |
| gates | 관문 작업 → 표시 기호 | {"S5": "②"} |
| gate_table | README 관문 표 [기호, 작업, 기준] | |
| readme_notes | README에 덧붙일 문장(단계 재배열 이유·변형 묶음 전환 절차 등) | |
| human_tasks | 사람이 직접 해야 하는 일 | |

`short`에는 공백·슬래시 없이 짧은 한국어를 쓴다(파일 이름과 세션 이름이 되기 때문). 첫 줄 `세션 이름:`을 읽는 훅(`.claude/hooks/golden_session_register.py`)은 `session_prefix`가 `GP`·`GPN`일 때만 등록부를 쓰므로, 새 접두를 쓰면 훅의 정규식·묶음 표와 테스트 픽스처를 함께 고친다.
