# 작업 지시서 (AI 실행용)

작업 번호를 받은 AI는 이 탭의 공통 규칙과 해당 번호의 지시만 읽고 작업한다. 지시에 없는 값은 추정하지 않고 "미확인"으로 보고한다.

## 공통 규칙과 보고 형식

작업 번호를 받으면 아래 규칙을 먼저 지키고, 그다음 해당 번호의 지시를 수행한다. 규칙과 지시가 충돌하면 규칙이 우선한다.

**작업 부여 문장 (이 형식으로 받는다)**

```
작업 B3 수행. 계획서: <이 문서의 링크>
```

**공통 규칙**

1. **읽을 범위:** 이 공통 규칙, 받은 번호의 지시, 그 지시가 "선행 산출물"로 적은 문서만 읽는다. 받지 않은 번호의 작업은 하지 않는다.
2. **선행 작업 확인:** 선행 작업이 끝나지 않았으면 시작하지 않는다. 비어 있는 선행 작업 번호를 보고하고 멈춘다.
3. **학생 노출 금지:** 공개 관문(B6)을 통과하지 않은 개념은 학생에게 보이는 경로(앱 화면, API)에 넣지 않는다. 개념의 공개 상태는 B6, D4, D5가 정한 경로로만 바꾼다.
4. **숫자 기준은 확정값(2026-11-06 Kiki 확정):** 합격률 70%, 감사 오류율 2%, 신고 3건 등은 임의로 바꾸지 않는다. 바꿔야 한다고 판단하면 바꾸지 말고 근거와 함께 보고한다.
5. **모르는 값은 추정 금지:** 저장소 경로, 테이블 이름, API 주소, 개념 수처럼 지시에 없는 값은 먼저 코드와 문서에서 찾는다. 못 찾으면 "미확인"으로 적고 그 부분만 멈춘다.
6. **학생 정보 보호:** 실제 학생의 이름, 식별자, 학습 기록을 로그, 산출물, 프롬프트에 넣지 않는다. 필요하면 가명 ID만 쓴다.
7. **긴급 정지 우선:** Kiki의 긴급 정지나 심각 오류 신고 1건이 접수되면 진행 중인 공개 작업(D4, D5)을 즉시 멈추고, 해당 개념을 비공개로 돌린 뒤 보고한다.
8. **되돌릴 수 있게:** 데이터를 지우거나 덮어쓰지 않는다. 상태를 바꿀 때는 이전 상태를 함께 기록해 회수할 수 있게 한다.
9. **확인 없는 완료 금지:** "완료 기준"의 항목마다 실행한 확인 방법과 결과를 적는다. 하지 못한 확인은 "미확인"으로 적는다.

**완료 보고 형식**

```
작업 번호: B3
결과: 완료 | 일부 완료 | 중단
만든 것: 파일·테이블·화면 이름 (경로 포함)
완료 기준 확인: 항목별 통과/실패와 근거 (실행한 명령 또는 본 화면)
미확인·가정한 것: 없으면 "없음"
다음 작업이 알아야 할 것: 없으면 "없음"
```

**용어**

| 용어 | 뜻 |
| --- | --- |
| 개념 | 학생이 한 번에 배우는 학습 단위 1개 |
| 합격본 | 공개 관문(B6)의 검사를 모두 통과한 개념의 생성 결과 |
| 개념 상태 | 초안, 검증됨, 공개됨, 회수됨 중 하나 (정의는 A1) |
| 심각 오류 | 정답이나 풀이가 틀림, 학생에게 부적절하거나 해로운 내용, 근거 없이 사실처럼 단정한 내용 중 하나 |
| 신고 | 학생이 신고 버튼으로 남기는 기록. 심각 오류 신고는 1건, 그 밖의 신고는 같은 개념에 3건이 쌓이면 자동 비공개 |

## T0\~T2: 결정·확인

세 작업 모두 사람(Kiki)만 줄 수 있는 정보나 외부 회신에 기대므로, AI는 질문을 정리해 전달하고 답을 기록하는 일을 맡는다.

### T0. PED-17에 결정 기록

- **목적:** 왜 AI 생성 개념을 열었고 누가 무엇을 승인했는지를 나중에 설명할 수 있게 남긴다.
- **선행 산출물:** 없음. 입력은 이 계획서 본문 탭의 "결정 요약"과 "승인 기록".
- **할 일:**
  1. PED-17이 있는 곳(이슈 트래커나 Notion)을 찾는다. 못 찾으면 "미확인"으로 적고 2\~3단계의 기록을 초안으로 만들어 보고에 붙인다.
  2. 다음 7가지를 한 건의 결정 기록으로 쓴다: 채택안(C안), 승인일과 승인자(2026-11-06, Kiki), 카나리와 모든 사람 개입을 AI로 대체한다는 수정, 예외로 남긴 긴급 정지 권한(권한자 Kiki, 발동 기준 심각 오류 신고 1건), 안전장치 7가지 이름, 계획서 링크.
  3. "승인 기록" 표를 그대로 붙인다.
  4. 기록 링크를 보고에 적는다.
- **산출물:** PED-17에 추가된 결정 기록 1건(링크).
- **완료 기준:** 위 7가지가 모두 기록에 있고, 계획서 링크가 열린다.
- **하지 말 것:** 요약하면서 날짜, 수치, 결정 내용의 뜻을 바꾸지 않는다.

### T1. 입력 확인

- **목적:** A2(1차 범위)와 합격 기준에 필요한, 사람만 아는 3가지 사실을 확보한다.
- **선행 산출물:** 없음.
- **할 일:**
  1. 코드, 로그, 문서에서 직접 알 수 있는 것은 먼저 찾는다. 특히 현재 404가 나는 개념 수는 가능하면 집계하고, 집계에 쓴 쿼리나 로그 기간을 함께 적는다.
  2. 찾지 못한 것만 Kiki에게 묻는다. 질문은 이 3가지다: (a) Gate A와 Q1의 통과 기준 원문(404 몇 건 이하인지, 비율인지, 측정 방법, 제출처), (b) 현재 404 개념 수 확인, (c) 학생 연령대(학년).
  3. 받은 답을 표에 기록한다. 열: 항목, 값, 출처, 확인일.
- **산출물:** "T1 입력" 표 1개.
- **완료 기준:** 3항목 모두 값과 출처가 있다. 답을 못 받은 항목은 "미확인"으로 남기고, 그 값에 기대는 작업 번호를 함께 적는다.
- **하지 말 것:** 값을 추정해서 채우지 않는다.

### T2. 법무 확인

- **목적:** AI 생성물 표시 의무와, 미성년자 대상 서비스에서 사람 검수 없이 AI 생성물을 공개해도 되는지를 확인한다.
- **선행 산출물:** T1의 학생 연령대.
- **할 일:**
  1. 질문서를 만든다. 서비스 설명은 "AI가 개념을 미리 생성하고, 다른 AI가 검증하며, 사람 검수 없이 공개하고, 신고로 회수한다"로 쓴다.
  2. 질문은 4가지다: (a) 생성형 AI 결과물 표시 의무와 표시 방식·문구, (b) 미성년자 대상 AI 생성 교육 콘텐츠에 사람 검수가 법적으로 필요한지, (c) 신고와 회수 절차에 요구되는 요건, (d) 신고에 학생 정보를 저장할 때의 개인정보 요건.
  3. 질문서를 Kiki에게 전달한다. 법무 창구는 Kiki가 정한다.
  4. 회신을 받으면 "라벨 문구, 표시 위치, 사람 검수 필요 여부(예/아니오)"로 정리한다.
- **산출물:** 질문서 1건, 회신 요약 1건.
- **완료 기준:** C2가 쓸 라벨 문구와 위치가 확정돼 있고, 사람 검수 필요 여부가 예 또는 아니오로 적혀 있다.
- **하지 말 것:** AI가 법률 판단을 대신 확정하지 않는다. 회신이 오기 전에는 라벨 문구를 "초안"으로 표시하고 D4를 열지 않는다.
- **막히면:** 회신이 "사람 검수 필요"이면 즉시 Kiki에게 보고하고 D4와 D5를 멈춘다. 회신이 늦어지는 것도 일정에 걸리므로 바로 보고한다.

## A1\~A3: 기반 (저장 구조, 범위, 근거)

이 세 작업은 서로 독립적이라 동시에 진행할 수 있다. 이후 B, C, D 작업이 모두 여기서 만든 산출물에 의존한다.

### A1. 개념 상태 저장 구조와 노출 기록

- **목적:** 개념이 초안, 검증됨, 공개됨, 회수됨 중 어디에 있는지 저장하고, 누가 언제 상태를 바꿨는지와 학생이 언제 보았는지를 남긴다. B6, C작업, D작업의 바탕이다.
- **선행 산출물:** T0 완료.
- **할 일:**
  1. 저장소에서 개념(학습 단계 콘텐츠)이 저장되는 곳(테이블 또는 파일)과, 학생 화면이 개념을 읽는 코드 경로를 찾는다. 개념이 없을 때 404를 돌려주는 지점도 찾는다.
  2. 개념에 상태 필드를 추가한다. 값은 4개로 고정한다: 초안, 검증됨, 공개됨, 회수됨. 사람 검수를 거쳐 이미 학생에게 나가는 개념은 "공개됨"으로 옮기고, 출처 필드를 하나 더 둔다(값: 사람 검수, AI 생성). 필드 이름은 저장소의 기존 이름 규칙을 따른다.
  3. 상태 전환 규칙을 함수 하나로 만든다. 허용되는 전환은 다섯 가지뿐이다: 초안→검증됨(B6 통과 시에만), 검증됨→공개됨(D4 또는 D5 경로에서만), 공개됨→회수됨(킬스위치, 회수 기능, 긴급 정지), 검증됨→회수됨(D2·D4·D6에서 오류 발견), 회수됨→초안(다시 생성해 재검증). 그 외 전환은 거부하고 오류를 남긴다.
  4. 상태 변경 기록 테이블을 만든다. 열: 개념 ID, 이전 상태, 새 상태, 변경 주체(규칙 이름, 에이전트 이름, Kiki 중 하나), 사유, 시각. 추가만 하고 수정·삭제는 막는다.
  5. 노출 기록 테이블을 만든다. 열: 개념 ID, 가명 학생 ID, 시각, AI 라벨 표시 여부. 실제 이름은 저장하지 않는다.
  6. 학생 화면 쪽 조회가 "공개됨"인 개념만 돌려주도록 바꾼다.
- **산출물:** 스키마 변경(마이그레이션)과 되돌리는 방법, 상태 전환 함수, 기록 테이블 2개, 테스트.
- **완료 기준:**
  1. 허용되지 않은 상태 전환을 시도하면 거부됨을 테스트로 보인다.
  2. 이미 공개된 기존 개념의 학생 화면이 변경 전과 같은지 비교한다.
  3. 상태를 바꾸면 기록 테이블에 1건이 남는다. 학생이 개념을 열면 노출 기록이 1건 남는다.
  4. 마이그레이션을 되돌리는 방법을 문서로 적는다.
- **하지 말 것:** 기존 개념을 삭제하거나 덮어쓰지 않는다. "공개됨"이 아닌 개념이 학생 경로에서 반환되게 만들지 않는다. 운영 데이터에 바로 적용하지 말고 복사본이나 스테이징에서 먼저 실행한다.
- **막히면:** 개념 저장 위치를 못 찾으면 찾아 봤던 경로와 후보를 적어 보고하고 멈춘다.

### A2. 1차 범위 확정

- **목적:** 기계로 정답을 검산할 수 있는 개념만 1차로 열기 위해 목록을 확정한다.
- **선행 산출물:** T1의 "현재 404 개념 목록".
- **할 일:**
  1. 404 개념을 하나씩 열어 내용을 읽는다.
  2. 두 분류 중 하나로 판정한다. **검산 가능:** 정답이 수식, 수치, 논리 판정 하나로 정해지고 SymPy(파이썬 수식 계산 라이브러리)로 확인할 수 있다. 예: 방정식 풀이, 식의 전개와 인수분해, 값 계산, 단위 변환. **검산 불가:** 서술, 해석, 증명, 가치 판단이 필요하다.
  3. 애매하면 "검산 불가"로 둔다.
  4. 표를 만든다. 열: 개념 ID, 이름, 분류, 판정 이유 한 줄, 검산 방법(사용할 SymPy 기능 또는 규칙).
  5. 요약 한 줄을 더한다: 전체 N개, 검산 가능 n개, 검산 불가 m개, 가능 비율.
- **산출물:** 범위 표(CSV 또는 문서 표)와 요약.
- **완료 기준:** 404 개념 전부가 표에 있고 분류와 이유가 비어 있지 않다. 요약 숫자가 표와 일치한다.
- **하지 말 것:** 합격률을 높이려고 검산 불가 개념을 범위에 넣지 않는다.
- **막히면:** 내용을 읽을 수 없는 개념은 "미확인"으로 표시한다. 가능 비율이 T1의 Gate A 기준에 못 미치면 바로 Kiki에게 보고한다.

### A3. 근거 소스 정리

- **목적:** 생성에 근거로 쓸 수 있는 소스와, 개념별 연결 가능 여부를 정리한다.
- **선행 산출물:** T1의 "현재 404 개념 목록". A2와 같은 목록을 쓰므로 동시에 진행할 수 있다.
- **할 일:**
  1. 저장소와 문서에서 교육과정 성취기준 데이터와 지식그래프 데이터가 어디에 있는지 찾는다.
  2. 소스마다 식별자 형식(성취기준 코드, 지식그래프 노드 ID 등)을 기록한다.
  3. 404 개념마다 연결되는 근거 ID를 1개 이상 찾아 적는다. 없으면 "근거 없음"으로 적는다.
- **산출물:** 소스 목록 표(소스 이름, 위치, 식별자 형식), 개념별 근거 연결 표(개념 ID, 근거 ID 목록 또는 "근거 없음").
- **완료 기준:** 404 개념 전부가 표에 있다. 근거 ID 10개(전체가 10개 미만이면 전부)를 무작위로 뽑아 실제 소스에 존재함을 확인한다.
- **하지 말 것:** 근거를 지어내거나 비슷해 보이는 것을 억지로 연결하지 않는다. "근거 없음"이 정답일 수 있다.

## B0\~B4: 데이터 형식, 생성, 검사

B0이 끝나면 B1\~B4는 서로 기다리지 않고 동시에 만든다. 검사 작업(B2\~B4)은 판정만 하고 내용을 고치지 않는다.

### B0. 개념 데이터 형식 확정

- **목적:** 생성 결과의 모양을 먼저 고정해, B1\~B5를 동시에 만들 수 있게 한다.
- **선행 산출물:** A2 범위 표, A3 근거 연결 표.
- **할 일:**
  1. JSON 스키마(데이터 형식 정의 파일) 1개를 쓴다. 필수 필드: 개념 ID, 제목, 대상 학년, 설명 문장 목록(문장마다 본문과 근거 ID 목록), 예제 목록(문제, 풀이 단계, 정답, 검산용 식), 연습 문제 목록(같은 구조), 생성 정보(모델 이름, 프롬프트 버전, 생성 시각), 검사 결과 칸(근거, 검산, 교차 검토, 안전 필터 — 빈 값으로 시작).
  2. A2의 "검산 가능" 개념 3개로 예시 데이터 3개를 만든다.
  3. 스키마 검증 테스트를 만든다.
  4. 형식 문서 1장에 필드별 뜻과 채우는 작업 번호를 적는다.
- **산출물:** 스키마 파일, 예시 3개, 검증 테스트, 형식 문서 1장.
- **완료 기준:** 예시 3개는 검증을 통과하고, 필수 필드를 하나 뺀 예시는 실패한다.
- **하지 말 것:** B1\~B5가 시작된 뒤에는 형식을 말없이 바꾸지 않는다. 바꿔야 하면 버전 번호를 올리고 영향받는 작업 번호와 함께 보고한다.

### B1. 생성기

- **목적:** A2 범위의 개념을 B0 형식으로 미리 생성해 "초안"으로 저장한다.
- **선행 산출물:** B0 형식, A1 상태 전환 함수, A3 근거 연결 표, T1의 학생 연령대.
- **할 일:**
  1. 입력은 개념 ID, 그 개념의 근거 원문(A3), 대상 학년이다.
  2. 프롬프트에 4가지를 명시한다: 근거 원문에 있는 내용만 쓸 것, 문장마다 근거 ID를 달 것, 예제·연습마다 검산용 식을 넣을 것, 대상 학년이 이해하는 말을 쓸 것.
  3. A3에서 "근거 없음"인 개념은 생성하지 않고 거부 사유를 기록한다.
  4. 출력을 B0 스키마로 검증한다. 실패하면 최대 2번 다시 생성하고, 그래도 실패하면 실패로 기록한다.
  5. 통과한 결과는 A1 함수로 "초안" 상태로 저장한다.
  6. 생성 모델 이름은 설정값으로 둔다. B4의 검토 모델과 달라야 한다(예시: 생성 Claude Sonnet 5.5, 검토 Claude Opus 5.5와 다른 회사 모델 1개).
  7. 한 번에 여러 개념을 처리하는 배치 실행 명령을 만든다. 개념 ID 목록을 입력으로 받는다.
- **산출물:** 생성 스크립트, 설정 파일, 실행 로그(개념별 성공·실패·거부와 사유).
- **완료 기준:**
  1. A2 범위의 개념 5개로 시험 실행해, 각각 스키마를 통과하거나 실패 사유가 기록된다.
  2. "근거 없음" 개념 1개로 생성 거부를 확인한다.
  3. 생성된 개념이 학생 화면에 나타나지 않음을 확인한다.
- **하지 말 것:** 학생이 요청할 때 즉석에서 생성하는 경로를 만들지 않는다. "초안" 외의 상태로 저장하지 않는다.

### B2. 근거 연결 검사

- **목적:** 설명 문장이 근거에 실제로 뒷받침되는지 판정한다.
- **선행 산출물:** B0 형식, A3 근거 연결 표.
- **할 일:**
  1. 형식 검사: 모든 설명 문장에 근거 ID가 1개 이상 있고, 그 ID가 A3 표에 있는 실제 ID인지 확인한다.
  2. 내용 검사: 문장과 근거 원문을 함께 AI 모델(생성 모델과 다른 모델)에 주고 "뒷받침됨, 부분적, 없음" 중 하나로 판정하게 한다.
  3. "부분적"이나 "없음"이 하나라도 있으면 불합격이다.
  4. 결과를 검사 결과 칸에 쓴다: 합격 여부, 불합격 문장과 사유.
- **산출물:** 검사 함수와 테스트.
- **완료 기준:** 다음 4가지 테스트가 통과한다. 근거 ID가 없는 문장은 불합격, 존재하지 않는 ID는 불합격, 근거와 다른 수치를 넣은 문장은 불합격, B0 예시 3개는 합격.
- **하지 말 것:** 문장을 고쳐서 합격시키지 않는다.

### B3. 기계 검산 (SymPy)

- **목적:** 정답과 풀이를 SymPy로 확인한다. AI 판단과 독립된 유일한 검증이다.
- **선행 산출물:** B0 형식, A2의 개념별 검산 방법.
- **할 일:**
  1. 예제와 연습 문제마다 검산용 식을 SymPy로 확인한다.
  2. 확인할 것은 3가지다. (a) 정답이 문제를 만족하는지(방정식이면 답을 대입), (b) 풀이 단계마다 앞 단계와 수학적으로 같은지(두 식의 차가 0으로 정리되는지), (c) 숫자 답은 정확값으로 비교하고, 근사값이면 허용 오차를 문제에 적힌 대로 쓴다.
  3. 식을 읽을 수 없거나 실행할 수 없으면 불합격이다. 항목당 5초를 넘기면 불합격이다.
  4. 결과를 검사 결과 칸에 쓴다: 합격 여부, 실패한 항목과 사유.
- **보안:** AI가 만든 식을 파이썬 코드로 그대로 실행하지 않는다(eval 금지). 허용된 기호와 함수만 받는 파서를 쓰고, 격리된 별도 프로세스에서 실행한다.
- **산출물:** 검산 함수와 테스트.
- **완료 기준:** 틀린 정답, 틀린 중간 단계, 실행할 수 없는 식은 각각 불합격하고, B0 예시 3개는 합격한다.
- **하지 말 것:** 실행에 실패한 항목을 통과로 처리하지 않는다.

### B4. 다른 모델 2개의 교차 검토

- **목적:** 생성 모델과 다른 모델 2개가 서로 독립적으로 내용을 검토한다.
- **선행 산출물:** B0 형식.
- **할 일:**
  1. 검토 모델 2개를 설정값으로 둔다. 두 모델은 생성 모델과 달라야 하고 서로도 달라야 한다. 가능하면 서로 다른 회사의 모델을 쓴다.
  2. 두 모델에 같은 체크리스트를 준다: 개념 설명이 정확한가, 예제와 정답이 맞는가, 대상 학년이 이해할 수 있는가, 오해를 부르는 표현이 있는가.
  3. 출력 형식은 판정(합격 또는 불합격)과 문제 목록이다.
  4. 두 모델은 서로의 결과를 보지 않고 따로 실행한다.
  5. 둘 다 합격일 때만 합격이다. 결과를 검사 결과 칸에 모델별로 쓴다.
- **산출물:** 검토 함수, 체크리스트 프롬프트, 테스트.
- **완료 기준:** 일부러 오류를 심은 예시 5개를 돌려 몇 개를 잡는지 기록하고, 놓친 예시는 무엇을 놓쳤는지 보고한다. B0 예시 3개는 합격한다.
- **하지 말 것:** 검토 모델이 내용을 고쳐 쓰게 하지 않는다. 판정만 한다.

## B5\~B7: 안전 필터, 공개 관문, 파일럿

B6은 "검증됨"으로 가는 유일한 문이고, B7은 그 문을 실제로 통과하는 비율을 재는 첫 관문(①)이다.

### B5. 연령 부적합 표현 안전 필터

- **목적:** 대상 학년에게 부적절한 표현과 내용을 막는다.
- **선행 산출물:** B0 형식, T1의 학생 연령대.
- **할 일:**
  1. 차단 범주를 정한다: 폭력, 선정성, 차별·혐오, 위험 행동 조장, 실존 인물 비하, 개인정보 요구, 외부 링크·광고.
  2. 두 단계로 검사한다. 규칙 검사(금칙어 목록, URL·전화번호·이메일 패턴)와 AI 분류(범주별 해당 여부).
  3. 하나라도 해당하면 불합격이다.
  4. 금칙어 목록은 별도 파일로 두고 변경 이력을 남긴다.
  5. 결과를 검사 결과 칸에 쓴다: 합격 여부, 걸린 범주와 문장.
- **산출물:** 필터 함수, 금칙어 파일, 테스트.
- **완료 기준:**
  1. 범주마다 위반 예시 1개씩 넣으면 모두 불합격한다. URL이 들어간 예시도 불합격한다.
  2. B0 예시 3개는 합격한다.
  3. A2 범위의 개념 이름 전체를 넣어 정상 수학 용어(예: 음수, 절댓값)가 잘못 걸리지 않는지 확인한다. 걸리면 목록을 보고한다.
- **하지 말 것:** 걸린 표현을 자동으로 고쳐서 합격시키지 않는다.

### B6. `can_publish` 공개 관문 통합

- **목적:** B2\~B5 결과를 모아 "검증됨"으로 바꿀지를 함수 하나가 결정하게 한다.
- **선행 산출물:** A1 상태 전환 함수, A2 범위 표, B2\~B5 검사 함수.
- **할 일:**
  1. `can_publish(개념)` 함수를 만든다. 다음 5가지가 모두 참일 때만 참을 돌려준다: A2 범위 안(검산 가능), B2 합격, B3 합격, B4 두 모델 모두 합격, B5 합격.
  2. 검사 결과가 비어 있거나 오류이면 거짓을 돌려준다. 기본값은 거부다.
  3. 참이면 A1 함수로 "초안→검증됨"으로 바꾼다. 변경 주체는 "B6 관문", 사유는 검사 결과 요약이다.
  4. 거짓이면 상태를 그대로 두고 불합격 사유를 기록한다.
  5. 코드 전체를 검색해 이 함수 말고는 "검증됨"으로 바꾸는 경로가 없는지 확인한다.
- **산출물:** 관문 함수와 테스트, "검증됨 전환 경로" 검색 결과.
- **완료 기준:**
  1. 검사 하나만 실패하는 경우 4가지, 범위 밖 1가지, 결과가 비어 있는 경우 1가지가 모두 거짓을 돌려준다.
  2. 모두 합격이면 참을 돌려주고 상태 변경 기록이 남는다.
  3. "검증됨"으로 바꾸는 경로가 이 함수 하나뿐임을 검색 결과로 보인다.
- **하지 말 것:** 검사를 건너뛰는 옵션이나 테스트용 우회 장치를 운영 코드에 남기지 않는다.

### B7. 파일럿 50개 생성과 합격률 측정 (관문 ①)

- **목적:** 실제 합격률을 재서 전체 배치(D1)로 넘어갈지 결정한다.
- **선행 산출물:** B1 생성기, B6 관문.
- **할 일:**
  1. A2 범위에서 개념 50개를 무작위로 고른다(50개 미만이면 전부). 무작위 시드값을 기록한다.
  2. B1로 생성하고 B6에 통과시킨다.
  3. 집계한다: 생성 실패, 생성 거부, 검사별 불합격 수, 최종 합격 수, 합격률(최종 합격 수 ÷ 고른 개념 수).
  4. 불합격 사유 상위 3개를 예시와 함께 적는다.
  5. AI 릴리스 에이전트가 판정한다. 합격률 70% 이상이면 go, 아니면 no-go다.
  6. no-go이면 생성 프롬프트 수정이나 범위 축소를 제안하고, 새 50개 표본으로 다시 잰다.
- **산출물:** 파일럿 보고서(개념별 결과 표, 집계, 판정).
- **완료 기준:** 50개 모두 결과가 표에 있고 합계가 맞는다. 판정(go 또는 no-go)이 적혀 있다. 합격본은 "검증됨" 상태로 남고 공개되지 않는다.
- **하지 말 것:** 합격률을 높이려고 검사 기준을 느슨하게 바꾸지 않는다. 같은 개념을 합격할 때까지 다시 생성해서 합격한 결과만 세지 않는다. 재생성했다면 횟수를 함께 적는다.

## C1\~C5: 학생 화면·안전장치

C 작업은 검증 파이프라인(B)과 무관하게 동시에 만든다. 전부 끝나야 AI 카나리(D4)를 열 수 있다.

### C1. 404 대신 "준비 중" 안내

- **목적:** 학생이 미공개 개념에 들어가도 404 대신 안내 화면을 보게 한다. AI 생성과 상관없이 바로 학생 경험이 좋아진다.
- **선행 산출물:** A1(상태 필드와 404 반환 지점).
- **할 일:**
  1. 개념이 없거나 "공개됨"이 아니면 안내 화면을 보여주도록 404 반환 지점을 바꾼다. API라면 앱이 구분할 수 있는 상태 값을 돌려준다.
  2. 안내 문구: "이 단원은 아직 준비 중이에요. 앞 단원을 먼저 공부해 볼까요?" 문구는 설정값으로 분리한다.
  3. 이전 단원이나 학습 목록으로 돌아가는 버튼을 둔다.
  4. 개념 ID별 안내 화면 접근 횟수를 집계한다. 다음 생성 우선순위를 정하는 데 쓴다.
- **산출물:** 안내 화면, 바뀐 조회 코드, 테스트.
- **완료 기준:** 초안, 검증됨, 회수됨, 존재하지 않는 개념에 각각 접근하면 안내 화면이 나오고, 응답에 개념 본문이나 예제가 들어 있지 않다. "공개됨" 개념은 전처럼 정상으로 보인다.
- **하지 말 것:** 안내 화면에서 AI 생성을 즉석에서 부르지 않는다. 미공개 개념의 내용을 응답에 싣지 않는다.

### C2. "AI가 만든 설명" 라벨

- **목적:** AI가 만든 개념임을 학생에게 알린다.
- **선행 산출물:** A1(출처 필드, 노출 기록), T2(라벨 문구와 위치).
- **할 일:**
  1. 출처가 "AI 생성"인 공개 개념의 학습 화면에 라벨을 붙인다. 위치는 T2가 정한 곳이고, 정해지기 전에는 개념 제목 바로 아래에 둔다.
  2. 문구는 T2 확정 문구를 쓴다. 확정 전에는 초안 "AI가 만든 설명이에요"를 쓰되, 코드를 고치지 않고 바꿀 수 있게 설정값으로 둔다.
  3. 라벨이 표시됐는지를 A1 노출 기록의 "AI 라벨 표시 여부"에 남긴다.
  4. 화면 낭독기(시각장애인용 읽기 기능)에서도 라벨이 읽히게 한다.
- **산출물:** 라벨 컴포넌트, 문구 설정값, 테스트.
- **완료 기준:** AI 생성 개념에는 라벨이 보이고(화면 캡처), 사람 검수 개념에는 보이지 않는다. 설정값을 바꾸면 문구가 바뀐다. 노출 기록의 라벨 표시 여부가 참으로 남는다.
- **하지 말 것:** T2 확정 전에는 문구를 확정본으로 보고하지 않는다.

### C3. 신고 버튼과 신고 저장

- **목적:** 학생이 문제를 알릴 수 있게 하고, 심각 오류 신고를 구분해 저장한다. 사람 검수가 없는 이 계획에서 실제 학생 신호의 유일한 통로다.
- **선행 산출물:** A1.
- **할 일:**
  1. AI 생성 공개 개념의 화면에 신고 버튼을 둔다.
  2. 신고 유형 선택지는 4개다: "정답이나 풀이가 틀렸어요", "이상하거나 불편한 내용이 있어요", "설명이 이해가 안 돼요", "기타". 앞의 두 개를 **심각 오류 신고**로 저장한다. 이 구분은 2026-11-06에 확정됐다.
  3. 짧은 설명(최대 200자)을 선택으로 받는다. 입력란 옆에 "이름이나 연락처는 쓰지 마세요"를 표시한다.
  4. 저장 항목: 개념 ID, 개념 버전, 신고 유형, 심각 여부, 설명, 가명 학생 ID, 시각.
  5. 심각 오류 신고는 저장 즉시 C4가 받을 수 있는 이벤트를 보낸다.
- **산출물:** 신고 버튼과 입력 화면, 신고 테이블, 이벤트 발행 코드, 테스트.
- **완료 기준:** 4가지 유형이 모두 저장되고, 심각 유형만 이벤트가 발행된다. 200자를 넘는 설명은 거부된다. 실제 이름이 저장되지 않는다.
- **하지 말 것:** 신고를 어떤 경우에도 삭제하거나 숨기지 않는다.

### C4. 킬스위치 (자동 비공개)

- **목적:** 신고가 쌓이면 사람 없이 해당 개념을 자동으로 내린다.
- **선행 산출물:** C3.
- **할 일:**
  1. **규칙 1 (심각):** 심각 오류 신고가 1건이라도 들어오면 해당 개념을 즉시 "회수됨"으로 바꾸고(변경 주체 "킬스위치-심각"), Kiki에게 즉시 알린다. 알림 채널(이메일, 메신저 등)은 기존 설정을 찾고, 없으면 "미확인"으로 보고한다.
  2. **규칙 2 (누적):** 그 밖의 신고가 같은 개념에 서로 다른 학생 3명으로부터 들어오면 "회수됨"으로 바꾼다(변경 주체 "킬스위치-누적").
  3. 신고 저장부터 회수까지 1분 이내를 목표로 한다.
  4. 회수에 실패하면 다시 시도하고 Kiki에게 알린다.
  5. 심각 오류 1건으로 전체 공개를 자동으로 멈추지는 않는다. 전체 정지는 Kiki가 C5로 판단한다(2026-11-06 확정).
- **산출물:** 규칙 처리 코드, 알림 연결, 테스트.
- **완료 기준:**
  1. 가짜 심각 신고 1건으로 1분 안에 회수되고 Kiki 알림이 도착하며 기록이 남는다.
  2. 서로 다른 학생 3명의 일반 신고로 회수된다. 같은 학생의 3건으로는 회수되지 않는다.
  3. 회수 뒤 학생 화면이 C1 안내로 바뀐다.
- **하지 말 것:** 회수된 개념을 자동으로 다시 공개하지 않는다. 다시 공개는 "회수됨→초안→B6→D 경로"로만 한다.

### C5. 회수·긴급 정지 기능

- **목적:** 개념 하나를 내리는 회수와, AI 생성 개념 전체를 멈추는 긴급 정지를 만든다. 긴급 정지는 Kiki만 쓴다.
- **선행 산출물:** A1.
- **할 일:**
  1. **개념 회수:** 개념 ID, 사유, 주체를 받아 "회수됨"으로 바꾸는 명령을 만든다. 자동 규칙(C4), AI 릴리스 에이전트, Kiki가 쓸 수 있다.
  2. **전체 긴급 정지:** 스위치 하나로 출처가 "AI 생성"인 모든 개념을 학생 경로에서 즉시 숨긴다. 개념 상태를 하나씩 바꾸지 말고 전역 스위치로 막아 즉시 적용되고 되돌리기 쉽게 한다.
  3. **권한:** 전체 긴급 정지와 해제는 인증된 Kiki 계정만 할 수 있다. AI 릴리스 에이전트와 자동 규칙은 개념 회수만 할 수 있고, 전체 정지를 켜거나 끌 수 없다.
  4. **Kiki가 쓰기 쉬운 수단:** 휴대폰에서 한 번에 누를 수 있는 버튼이나 명령을 둔다. 기존 관리 도구를 먼저 찾고, 없으면 후보를 적어 보고한다.
  5. 회수, 정지, 해제를 모두 A1 기록에 남긴다.
- **산출물:** 회수 명령, 전체 정지 스위치와 권한 검사, Kiki용 버튼 또는 명령, 테스트.
- **완료 기준:**
  1. 개념을 회수하면 곧바로 학생 화면이 C1 안내로 바뀐다.
  2. 전체 정지를 켜면 AI 생성 개념이 모두 숨고, 사람 검수 개념은 그대로 보인다. 끄면 원래대로 돌아온다.
  3. Kiki가 아닌 계정이나 에이전트가 전체 정지를 켜거나 끄려 하면 거부된다.
  4. 모든 조작이 기록에 남는다.
- **하지 말 것:** 회수를 데이터 삭제로 구현하지 않는다.

## D1\~D7: 공개 (순서 고정)

D 작업은 순서를 바꾸거나 건너뛸 수 없다. 관문(②③)을 못 넘으면 다음 번호를 시작하지 않는다.

### D1. 전체 배치 생성

- **목적:** A2 범위 전체를 생성하고 검사해 "검증됨" 개념을 만든다. 아직 아무에게도 공개하지 않는다.
- **선행 산출물:** B7 판정 go.
- **할 일:**
  1. A2 범위 중 B7에서 쓰지 않은 개념 전부를 B1로 생성하고 B6에 통과시킨다.
  2. 합격본은 "검증됨"으로 남는다.
  3. B7과 같은 형식으로 개념별 결과를 집계한다.
  4. 합격률이 B7보다 10%p 이상 낮으면 멈추고 원인과 함께 보고한다.
- **산출물:** 전체 배치 결과 표와 집계.
- **완료 기준:** 범위의 모든 개념에 결과가 있고 합계가 맞는다. "공개됨"으로 바뀐 개념은 0개다.
- **하지 말 것:** 개념의 공개 상태를 바꾸지 않는다.

### D2. AI 감사관의 표본 감사 (관문 ②)

- **목적:** 검사를 통과한 개념을 다른 AI가 다시 풀어보고 오류율을 잰다.
- **선행 산출물:** D1.
- **할 일:**
  1. "검증됨" 개념에서 5% 이상을 무작위로 고른다. 최소 20개이고, 전체가 20개 미만이면 전부다. 시드값을 기록한다.
  2. 감사관 모델은 B1(생성), B2(근거 판정), B4(교차 검토)에 쓰지 않은 모델 계열과 별도 프롬프트를 쓴다.
  3. 감사 항목: 예제와 연습 문제를 직접 다시 풀어 정답 비교, 설명의 정확성, 대상 학년 적합성, 심각 오류 해당 여부(공통 규칙의 용어 표 정의).
  4. 오류율 = 오류가 발견된 개념 수 ÷ 감사한 개념 수.
  5. AI 릴리스 에이전트가 판정한다. 2% 이하면 go, 초과면 no-go로 공개를 보류하고 오류 유형을 분석해 보고한다.
  6. 오류가 발견된 개념은 판정과 상관없이 "회수됨"으로 바꾼다.
- **산출물:** 감사 표(개념, 결과, 사유), 오류율, 판정.
- **완료 기준:** 표본 개념 전부에 결과가 있고 오류율 계산이 표와 맞는다. 판정이 적혀 있다.
- **하지 말 것:** 감사관이 오류를 고쳐서 합격시키지 않는다. 표본을 고른 뒤에 바꾸지 않는다.

### D3. 킬스위치 훈련

- **목적:** 문제가 생겼을 때 실제로 내릴 수 있는지 공개 전에 확인한다.
- **선행 산출물:** C4, C5.
- **할 일:** 운영과 같은 구성의 스테이징에서, 테스트 계정만 쓰고 아래 4가지를 실행한다.
  1. 테스트용 개념 1개를 공개하고 가짜 심각 신고 1건을 넣는다. 1분 안 회수와 Kiki 알림 도착을 확인한다.
  2. 다른 테스트 개념에 서로 다른 테스트 학생 3명의 일반 신고를 넣고 회수를 확인한다.
  3. Kiki가 전체 긴급 정지를 직접 켜고 끄는 것을 확인한다. 이 단계는 Kiki에게 요청해 진행한다.
  4. AI 릴리스 에이전트가 전체 정지를 켜려 하면 거부되는지 확인한다.
- **산출물:** 훈련 보고서(시나리오별 결과와 걸린 시간).
- **완료 기준:** 4가지 모두 통과하고, 걸린 시간이 기록되며, Kiki가 알림을 받았다고 확인해 준다.
- **하지 말 것:** 실제 학생이 보는 운영 개념으로 훈련하지 않는다.

### D4. AI 카나리 (관문 ③)

- **목적:** 실제 학생에게 열기 전에, AI 학생 에이전트가 실제 학습 화면으로 모든 검증됨 개념을 끝까지 공부해본다.
- **선행 산출물:** D2 go, D3 통과, C1\~C5 완료, T2 완료(회신에서 사람 검수 필요 = 아니오).
- **할 일:**
  1. AI 학생 에이전트를 대상 학년 수준으로 3유형 만든다: 잘하는 학생, 자주 헷갈리는 학생, 처음 배우는 학생.
  2. 스테이징의 테스트 계정으로, 실제 앱 화면을 거쳐 설명 읽기, 예제, 연습 문제 풀기를 끝까지 한다. 스테이징에서만 개념을 공개하고 운영 상태는 바꾸지 않는다.
  3. 에이전트가 문제를 발견하면 C3 신고 버튼으로 신고한다. 실제 경로를 쓰므로 킬스위치도 함께 검증된다.
  4. 측정한다: 세션 수, 심각 오류 신고 수, 경미 오류 비율(심각이 아닌 신고가 나온 개념 수 ÷ 학습한 개념 수), 화면 오류(로딩 실패 등).
  5. AI 릴리스 에이전트가 판정한다. 심각 오류 0건이고 경미 오류 1% 이하면 go, 아니면 no-go다. no-go이면 문제 개념을 회수하고 보고한다.
- **산출물:** 카나리 보고서(유형별 세션 결과, 수치, 판정).
- **완료 기준:** 모든 검증됨 개념을 3유형 에이전트가 각각 1회 이상 학습했고, 수치와 판정이 적혀 있다.
- **하지 말 것:** 실제 학생 계정이나 운영 환경을 쓰지 않는다. 에이전트가 신고 대신 내용을 직접 고치지 않는다.

### D5. 단계적 전체 공개 (1% → 10% → 100%)

- **목적:** D4를 통과한 개념을 실제 학생에게 1%, 10%, 100% 순서로 넓혀 공개한다. 실제 학생에게 처음 노출되는 단계라서, 문제가 있으면 적은 학생에게서 먼저 드러나게 한다.
- **선행 산출물:** D4 go.
- **할 일:**
  1. 공개 직전에 전체 긴급 정지가 꺼져 있는지, 킬스위치가 동작 중인지 확인한다.
  2. 노출 비율 설정을 만든다. 가명 학생 ID로 학생을 고정 배정해, 1% 그룹은 10% 그룹에, 10% 그룹은 100%에 포함되게 한다. 비율을 늘려도 이미 보던 학생이 빠지지 않는다. 그룹 밖 학생에게 AI 생성 개념은 C1 안내로 보인다. 비율은 설정값으로 둔다.
  3. 운영에서 D4 통과 개념을 "검증됨→공개됨"으로 바꾸고(변경 주체 "AI 릴리스 에이전트", 사유 "D4 통과"), 노출 비율 1%로 시작한다. 공개 시작을 Kiki에게 알린다.
  4. 각 단계는 최소 24시간 유지한다. 단계가 끝나면 AI 릴리스 에이전트가 판정한다. 확대 조건은 그 단계에서 심각 오류 신고 0건, 경미 오류 비율(심각이 아닌 신고가 나온 개념 수 ÷ 노출된 개념 수) 1% 이하, 화면 오류가 공개 전 24시간보다 늘지 않음이다. 모두 충족하면 10%, 다음에 100%로 넓힌다.
  5. **자동 축소:** 경미 오류 비율이 1%를 넘으면 직전 단계 비율로 줄이고 Kiki에게 알린다. 심각 오류 신고가 들어오면 해당 개념은 C4가 자동 회수하고, 확대를 멈춘 채 Kiki에게 알린다. 확대는 그 단계의 24시간을 다시 채운 뒤 다시 판정한다.
  6. 단계마다 보고한다: 단계, 시작·종료 시각, 노출 학생 수(가명 집계), 노출 개념 수, 신고·회수 수, 판정.
- **산출물:** 노출 비율 설정 기능과 테스트, 단계별 보고 3건(1%, 10%, 100%).
- **완료 기준:**
  1. 1% 설정에서 약 1%의 가명 학생만 AI 생성 개념을 보고, 나머지는 C1 안내를 보는 것을 테스트로 확인한다.
  2. 비율을 늘려도 기존 그룹 학생이 빠지지 않는다.
  3. 세 단계의 보고와 판정이 있고, 100% 도달 후 24시간 보고가 있다.
  4. 공개된 개념 수가 D4 통과 수와 같다(회수된 개념은 따로 적는다).
- **하지 말 것:** 판정 없이, 또는 24시간을 채우지 않고 다음 단계로 넓히지 않는다. D4를 통과하지 않은 개념을 공개하지 않는다. 긴급 정지가 켜져 있는 동안에는 공개하거나 넓히지 않는다. 전체 긴급 정지를 직접 켜지 않는다(Kiki 권한).

### D6. AI 감사관의 표본 감사 2회차

- **목적:** 공개 후에도 오류율을 계속 확인한다.
- **선행 산출물:** D4. D5와 동시에 진행한다.
- **할 일:**
  1. D2와 같은 방식으로, D2 표본을 제외한 새 무작위 표본을 감사한다.
  2. 공개 후 신고가 들어온 개념은 표본에 반드시 포함한다.
  3. 오류가 발견된 개념은 C5로 즉시 회수한다.
  4. 오류율이 2%를 넘으면 Kiki에게 즉시 보고한다. 전체 긴급 정지를 판단할 자료다.
